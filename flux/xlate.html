Translation tables

Translation tables are managed in Flux using online XLate tool.

This can be found here.

Refer this for usage of this online translation tool.

To keep the translations updated, a developer has to:

  • Update the remote translation database with the new phrases from a new release which have to be translated.
  • Pull the remote translation updates and synchronize the local dictionaries. This will update the .txt files in X:\Wad\Lang.

Steps

  • Refer this for installing XL tool and the commands to use.

  • After installing, do CLI sign-in.

  • Now, switch to the product Flux as shown below: [source] xl sw Flux "X:\Wad\lang" "Y:\Xlate\0"

  • To upload the translation phrases that have to be translated:

.. Use xl out to see the changes going to the remote server [source] xl out Flux -diff .. Use xl put command to seed the translation phrases from the local translation dictionaries [source] xl put Flux "X:\Wad\lang" "Y:\Xlate\0"

  • To download the translated texts for the phrases uploaded earlier:

.. Use xl in and xl recent commands to check the incoming and recently updated translations [source] xl in Flux .. Use the xl get command to download and apply the remote changes to the local dictionaries [source] xl get Flux

Handling translation case for a Flux version

  • Use xl get to get the translation from the server.
  • If there are any changes in English translation (.txt) files revert them.

NOTE: There may be some changes we have to do. For example, sometimes a string id will be removed from English txt file but not in other language files. So we need to remove it from other languages before updating the server.

  • Use xl put to update the server with latest English translation

[NOTE]

  • If there are relevant changes like string id being removed, create a branch and commit the changes.
  • Other changes like empty lines etc need to be restored in the branch.
  • Keep the branch as draft. ====
  • Assign the respective FogBugz case to the case opener to get the translated strings for other languages.
  • Once the translation is completed, use xl get and update the other language translation and commit to the repository.

[NOTE]

  • If the respective branch is created then switch to that before xl get.
  • While committing make sure only the respective area related changes are committed. i.e. if the bend translation has to be updated, push only the .txt files related to bend and not cut files.
  • Verify the deletions in .txt files carefully. ====
