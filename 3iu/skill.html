TRUMPF UX UI Community Design System — Quick Skill

name: trumpf-ux-styleguide description: Use this skill whenever building, reviewing, or documenting UI for TRUMPF software products (MES, OSEON, CAD/CAM, HMIs, machine dashboards) that must follow the TRUMPF UX UI Community Design System (@trumpf/ux.ui-community, also called "UIC"). Triggers on "TRUMPF UI", "UIC", "uic-theme-responsive", "Touchpoint Design System", "tr-blue", "Open Sans", "tr-grey", requests to create Trumpf-styled screens, or when checking a screen against the Trumpf style guide. Provides: the 9 canonical design rules (atomic design, 13×13 mm touch areas, 8×8 px grid, 5:4 ratio), the 8-layer layout model, the responsive-pattern catalog (Column Drop, Reveal/Hide, Expand, Divide, Transform), 401 design tokens (colors, typography, spacing, shadows), the full Atomic-Design component catalog (76 components: Atoms, Molecules, Organisms) with Figma-canonical taxonomies, page-level templates (Error pages, Filter dialog, List with Search, Non-modal dialog, Hierarchy visualisation) and a gap-filled File Browser pattern.

TRUMPF UX UI Community Design System — Quick Skill

Sources combined:

  • Storybook build master (https://trumpf-ux.ui-community-storybook…) — Web Components code library, extracted 2026-04-24.
  • Figma library Lib_Software Styleguide_* (Design Principles · Basics · Atoms · Molecules · Organisms · Templates) — canonical design rules, extracted 2026-05-19.

Combined coverage: 401 CSS tokens · 76 Web Components · 9 design rules · 8 layout layers · 5 responsive patterns · 6 templates.

1. Identity & philosophy

  • Name: TRUMPF UX UI Community Design System (shortform UIC).
  • Philosophy: Atomic Design (Atoms → Molecules → Organisms), touch-first HMI, responsive.
  • Contacts (design management & UX engineering): Dina Gallo (Design Mgmt), Manuel Radziwill (UXE Laser), Sebastian Heidfeld (UXE Werkzeugmaschinen).
  • Deliverables: Figma libraries (primary), Web Components (this library), React wrapper package. Sketch & Axure are deprecated.

2. The only theme class you need

Every page must be wrapped in a container that carries the theme class:

<body class="uic-theme-responsive">
  <!-- all uic-* components live in here -->
</body>

That one class drives all 401 CSS custom properties. Without it, components are unstyled.

3. Responsive rules (touch-first)

--uic-dim-height (the canonical row / field / button height) changes by breakpoint:

Breakpoint Media query --uic-dim-height
Desktop (default) ≥ 1600px 48 px (touch)
Tablet ≤ 1599px 40 px
Tablet-small / handheld ≤ 1023px 30 px

Never hard-code heights on interactive elements — always use var(--uic-dim-height) (or the component-specific token). Minimum touch target on a HMI screen is 48 px.

4. Core tokens at a glance

Colours (palette roles)

Full table in references/tokens.md. The most-used roles:

Token Value Role
--uic-color-blue2 #51a7eb Primary accent / interactive — hover, focus, selected borders
--uic-color-blue3 #177ac9 Active / pressed, important links
--uic-color-blue4 #285172 Dark brand navy (headings on light)
--uic-color-blue5 #142939 Deepest navy — app shell backgrounds
--uic-color-grey1 #e7ecf0 Light surface / divider
--uic-color-grey2 #a1a1a1 Default border
--uic-color-grey3 #363636 Default text
--uic-color-grey7 #f7f7f7 App background (light)
--uic-color-white #fff Card surface
--uic-color-red1 #ff1e00 Error / critical
--uic-color-red2 #cc292d Danger button
--uic-color-green1 #348e30 Success / running
--uic-color-green2 / -3 #a1c049 / #a5c049 Positive status
--uic-color-light-orange #f27b26 Warning

Accent / category colours (for tags, status dots, charts): light-purple, light-violet, light-pink, limone, light-brown plus dark-* variants for dark-theme contexts.

Alpha tints exist with suffix a##, e.g. --uic-color-blue2a10 = rgba(116,185,239,0.1) — used for subtle hover / selected backgrounds.

Typography

  • Font family: "Open Sans", sans-serif (the ONLY allowed face — Regular 400, Semibold 600, Bold 700). Do not use Nunito Sans (that is the Storybook chrome only).
  • Sizes (rem, root = 16 px): extrasmall 0.625 · small 0.8 · normal 1 · medium 1.5 · large 2.
  • Weights: light 300 · normal 400 · semibold 600 · bold 700 · extrabold 800.
  • Line heights: extrasmall 1rem · small 1.2 · normal 1.3 · medium 1.8 · large 2.2.

Spacing / sizing (component-level)

Trumpf does not publish a generic --uic-space-* scale. Spacing lives inside component tokens. Common primitives:

  • Button height 48 px, min-width 159 px; icon-button 60×48; stretched 77×48.
  • Header / menu height 68 px; icon height 36 px.
  • Checkbox box 24×20 px; radio outer 24 px; switch thumb 60×48.
  • Table cell height 64 px.
  • List item default height 77 px.
  • Scrollpanel track width 8 px, spacing 4 px.

Shadows

--uic-button-shadow:  0 2px 4px rgba(0,0,0,.05), 0 2px 8px rgba(161,161,161,.4);
--uic-flyout-shadow:  0 4px 4px rgba(0,0,0,.05), 0 8px 8px rgba(161,161,161,.4);
--uic-list-box-shadow:0 2px 4px rgba(0,0,0,.05), 0 2px 8px rgba(161,161,161,.4);
--uic-tile-box-shadow:0 2px 4px rgba(0,0,0,.05), 0 2px 8px rgba(161,161,161,.4);

Shadow colours live in --uic-atom-shadow-color-primary / -secondary / -error.

Z-index scale

header 400 → popover 1000 → tooltip 1000 → dialog 2000 → footer-menu-button 3001.

5. Component catalogue (76 components)

Full names & Storybook links in references/components.md. Headline structure:

  • Atoms (27): Accordion · Badge · Button (Content / Footer / Icon-Only) · Checkbox · Icon · IconSet · Image · Input Field (Value / Number / Multiline) · Loader · Output · Popover · Profile · Progress Bar · Radio · Scroll Panel · Scroll Picker · Sidebar Footer · Switch · Tab · Tag · Text · Textlink · Thumbnail Item · Tree Item · Virtual Scroll.
  • Molecules (23): Breadcrumb · CheckList · ComboBox · Dropdown · Empty State · Filter · Flyout · Footer Menu · Function Menu · List · Menu (root + Item) · Minimap · Pagination · Search Field · Segmented Control · Sidebar · Slider · Stepper · Thumbnail · Tile · Tooltip · Tree · Wizard Header Step.
  • Organisms (12): App Header (+ Integration) · Dialog · Footer · Header (Root / Menu / Menu Item) · Horizontal Flyout Menu · Message List · Message Toast · Table (+ Lazy rendering variants) · Tabs.
  • API: I-HUB Access Token.

Naming: every Web Component tag is <uic-*>. There are 287 tokens and 42 tag prefixes: uic-accordion, uic-button, uic-list, … (see references/components.md).

6. Layout / arrangement rule

The design-system docs state: "Components are prepared for complex arrangements … when put together on a page they flow horizontally." The default layout primitive is:

display: flex;
flex-flow: row wrap;
gap: 8px;   /* or a component-specific token */

Do not invent a grid system. Compose with uic-sidebar, uic-header, uic-footer-menu, uic-list, uic-tile and flex-row-wrap.

7. Framework integration (quick snippets)

Angular

// angular.json assets
{ "glob": "**/*", "input": "node_modules/@trumpf/ux.ui-community/dist/ux-ui-community/svg", "output": "svg" }

// main.ts
import { defineCustomElements } from '@trumpf/ux.ui-community/loader';
defineCustomElements(window);

// styles.css
@import "@trumpf/ux.ui-community/dist/ux-ui-community/ux-ui-community.css";

Add CUSTOM_ELEMENTS_SCHEMA to every NgModule using <uic-*>.

React

npm install @trumpf/ux.ui-community-react

Sample app: https://gitlab.com/com.trumpf.ux/examples/react

Vue

Vue cannot use camelCase events; wrap event names to lowercase:

app.config.compilerOptions.isCustomElement = tag => tag.startsWith('uic-');

Plain HTML (useful for mocks)

<script type="module" src="https://cdn/.../ux-ui-community.esm.js"></script>
<link  rel="stylesheet" href="https://cdn/.../ux-ui-community.css">
<body class="uic-theme-responsive">
  <uic-button variant="primary-content">Save</uic-button>
</body>

8. When coding a new screen — the pre-flight checklist

  1. Wrap the root container in uic-theme-responsive.
  2. Pick components from the Atomic catalogue before inventing new ones.
  3. Reference colours / sizes via CSS custom properties, never hex literals.
  4. Verify touch targets ≥ var(--uic-dim-height) (48/40/30 px).
  5. Use flex-flow: row wrap for arrangements.
  6. Use the documented uic-color-* roles for state (hover = blue2, active = blue3, error = red1, success = green1).
  7. Respect z-index scale (dialog 2000, popover 1000, header 400).
  8. Font = Open Sans (Regular / Semibold / Bold) only.
  9. Shadows only via the --uic-*-shadow tokens — no custom box-shadow: 0 10px 20px black.
  10. border-radius: 0 on every surface (buttons, inputs, panels, dialogs, tags, cards, tiles). Only exceptions: switch/pill thumb (≥20 px pill) and avatar/profile (50 %).
  11. Run the results past references/conformance-checklist.md before declaring "Trumpf style".

9. The 9 canonical design rules (always check)

The Figma master 1.2 Rules to Design a TRUMPF GUI lists exactly nine rules. Treat them as non-negotiable:

# Rule Verification
01 The system is built on Atomic Design. Components compose from published atoms only.
02 Use the font, colors and controls as defined. npm run lint:tokens and the conformance checklist.
03 Touch areas are ≥ 13 × 13 mm. --uic-dim-height × pixel size ≥ 13 mm.
04 Build on an 8 × 8 px grid (icons/typography on 4 × 4). gaps and paddings are multiples of 8.
05 UI is derived from TRUMPF machine product design. Either Touchpoint or Website pattern, applied consistently.
06 Keep 5 : 4 proportion for icon-style controls. 50 × 40 px = Tablet "Base".
07 Calculate control sizes against your screen via the scaling factor. §1.5 formula in design-principles.md.
08 High contrast + minimum touch sizes = accessible baseline. WCAG AA at minimum, AAA for :default.
09 Share new use-cases / GUIs back to the styleguide team. PR description references the gap filled.

Full details: references/design-principles.md (§1.x), references/basics.md (§2.x).

10. The 8-layer layout model

Every TRUMPF GUI is a stack of these layers (tr-* are color names):

1. Background           tr-white
2. TRUMPF Design element (5:4 brand marker, optional)
3. Main navigation       tr-blue5 (#142939) — Organism 5.01 App Header
4. Sub navigation +
   content area          tr-white
5. Nested content areas  tr-white + outer shadow
6. Footer bar            tr-blue4 (#285172) — Organism 5.08 Footer (64 px, never 52 px)
7. Overlay               tr-white + outer shadow (tooltip, popover)
8. Popups / modals       tr-white + outer shadow + backdrop blur (fallback ≈ 80–90 % white)

Two integration variants exist: GUI integrated in Touchpoint (lighter chrome) and stand-alone GUI (full chrome).

12. Fast recall (how to use this skill)

  • "Check X against TRUMPF style guide" → §9 + conformance-checklist.md.
  • "What are the TRUMPF design rules?" → §9 (the 9 rules) + load design-principles.md.
  • "How do I lay out a TRUMPF screen?" → §10 (8-layer model) + design-principles.md §1.4 + file-browser.md if listing/files.
  • "Give me the TRUMPF primary button colour" → fill = blue4 #285172, hover = blue3 #177ac9, text white (components.md §3.05). The interactive accent/border colour (hover border, focus) is blue2 #51a7eb; blue3 = active text/links. Never use blue2 as a fill.
  • "What's the border-radius?" → 0 everywhere. Only switch/pill thumb (≥20 px pill) and avatar/profile (50 %) are rounded (tokens.md §5).
  • "Switch ON/OFF colours?" → ON = blue2 track+border, white thumb right; OFF = white track, grey2 border+thumb left (basics.md §2.3).
  • "Status tag colours?" → released=green1, draft=grey1, in-progress=orange, archived=grey1/grey2, error=red1 — always + icon + label (components.md §3.20).
  • "Which focus colour?" → standard blue2 2 px outline; Tile is the only exception (blue1).
  • "What component for a file list?" → load file-browser.md (uses uic-list, uic-table, uic-tile, uic-app-header, uic-sidebar, uic-dialog, uic-message-toast).
  • "How do I render a TRUMPF header?" → uic-app-header (Organism 5.01), horizontal or vertical layout, with uic-header-menu items slotted; height 68 px, tr-blue5 background.
  • "Minimum touch target?" → ≥ 13 × 13 mm. On Tablet Base ≈ 64 × 64 px, visual ≈ 48–50 px (button height var(--uic-dim-height)).
  • "How many button kinds exist?" → 5: Applauncher · Content · Icon Only · Footer · Button with Menu (components.md extension).
  • "Footer height?" → 64 px. The old 52 px is deprecated; never use it.
  • "What states does an interactive control need?" → 8: :default, :disabled, :focus, :hover, :active, :selected, :selected-focus, :selected-hover (basics.md §2.3).
  • "What responsive pattern should I use?" → pick from Column Drop · Reveal/Hide · Expand · Divide · Transform (design-principles.md §1.9).
  • "Single-touch HMI?" → pair every gesture with a Gesture-Replacement icon button (design-principles.md §1.8).
  • "How do I render a hierarchy in a table?" → templates.md §6.06: column-1 indent 8 px / level, parent row tr-grey1 @ 20 %, divider white.
  • "What about Smartphone?" → all the rules apply; the styleguide marks Smartphone as in progress, so use the documented sizes as a starting point and document any deviation back to the team (Rule 09).
