Material Flow Systems (KB40 / CS05 / Robots)

Description

The concept paper names KB40, CS05, and generic robots as material-flow systems that move parts between the cutting machine and the next process step (typically a bending machine, per the backward-planning diagram — see 06-process-and-collision-constraints/01-backward-planning-concept.md). The factory-route diagram shown in the paper (Factory Settings → routes) lays out: Raw Material → cutting machine (e.g. L49-3kW) → robot → punching machine (e.g. TruPunch 5000) → robot → bending machine (e.g. TBC-5030-V2) → Finished Parts.

Implication for palletizing

  • These systems are the physical link between "where cutting deposits the part" and "where bending picks it up." A pallet/stack plan that is valid for the unloader but not reachable/collision-free for the KB40/CS05/robot step feeding the next machine is not a valid plan — this is precisely the backward-planning requirement in chapter 06.
  • The routes view (Factory Settings) already models machines as nodes with properties (Name, NC Extension, Output Destination, Enabled, Auto Tooling — seen for a "Bending Machine" node). The palletizing module should read the route's next-machine identity to know which downstream reach/orientation constraints apply, rather than requiring the programmer to re-enter them.

Module responsibilities

  • Resolve, for a given job, the configured downstream route (next machine after cutting) from factory settings.
  • Fetch that machine's gripper/automation binding (its unloader/pickup automation) so its reach envelope and rotation capability can be applied as a constraint on this module's stacking output — not merely on its own input.

Conveyor-based palletizing: direct vs. indirect linking

Conveyor systems in this material-flow layer come in two linking kinds:

  • Direct linking — the conveyor connects cutting's unload point straight to the next process step's pickup point; parts move through with no intermediate storage, so this module's stack/pile plan for that leg is effectively pass-through.
  • Indirect linking — the conveyor feeds an intermediate stack-building point (pallet/pile) rather than handing parts straight to the next process.

Indirect linking is what makes stack building double as a buffer against downstream bottlenecks: when the next process (e.g. bending) is slower or temporarily stopped, piles accumulate at the indirect linking point instead of stalling the cutting machine. This is the same priority-based stack building idea used elsewhere in this spec (making pallets available earlier, smoothing material flow) applied specifically to conveyor-fed lines, and it means the module must know which linking kind a given route segment uses to decide whether buffering capacity is even available on that leg.
