Container / Box Sorting (SortMaster Box Linear)

Description

The concept paper explicitly separates pallet sorting from container sorting: "Neben dem Absortieren auf eine Palette muss auch das Absortieren in Behälter berücksichtigt werden" — besides sorting onto a pallet, sorting into containers must also be considered. The named machine is SortMaster Box Linear, which "sorgt für kratzerarmes Sortieren von Gutteilen in linear verfahrbare Behälter" — provides scratch-free sorting of good parts into linearly-movable containers.

Implication for the data model

A "deposit site" is not always a flat pallet footprint with X/Y stacking:

  • A container/box is a discrete slot in a linearly indexed sequence, not an (x, y) pile location. Containers still have a max fill (count or weight) analogous to max pile height, but no 2D arrangement problem.
  • The module's pallet/deposit-site abstraction (chapter 04) must therefore support two site kinds:
    1. Pallet — 2D footprint, piles arranged by (x, y), governed by chapter 05.
    2. Container/box lane — 1D sequence of slots, each holding one part-type's pile, indexed by lane position rather than (x, y).

[Target] scope note

Full container/box-lane modeling is a [Target] item; [V1] only needs the pallet/2D-footprint case (matching the existing Deposit Editor), but the data model should not preclude adding a container site kind later without reshaping the pallet definition (see 04-pallet-definition/01-pallet-data-model.md).
