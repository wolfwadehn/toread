Rule-Based Output Recommendation

[Target]

Covers UC-32 (rule-based output strategy: define output method according to quality, speed, downstream process, weight, and size; receive output recommendations automatically) and UC-29 (split palletizing by downstream automation: route parts according to the target downstream process and automation type).

Relation to manual selection

02-selection-workflow.md and 03-selection-rules-and-constraints.md describe how a programmer manually picks (or accepts a pre-selected) automation profile for a job, and the compatibility rules that constrain that choice. Rule-based output recommendation is an automatic recommendation layer on top of that workflow — it does not replace manual selection, and every recommendation it produces still resolves to one or more ordinary automation profiles bound the normal way (01-automation-profile-model.md). The programmer can always accept, override, or ignore a recommendation exactly as they would a pre-selected default from step 1 of 02-selection-workflow.md.

Purpose

Instead of the programmer deciding which automation profile fits a job, the module evaluates weighted output-selection criteria per part (or per part group) and recommends — or, once confidence is high enough, auto-selects — the matching automation profile(s). Where parts within one job disagree on the best output, the job is split across multiple automation profiles/downstream targets rather than forcing one profile for the whole job.

Proposed fields

Field Type Description
OutputRuleId string Unique key for a recommendation rule (master data).
Criteria list of (Factor, Weight) Weighted factors evaluated per part/part group: Quality, Speed, DownstreamProcess, Weight, Size (per UC-32).
Factor enum One of the criteria above. DownstreamProcess reads the job's configured route/next machine, same source as 01-automation-types/05-material-flow-kb40-cs05-robots.md. Weight/Size read part attributes already available at import (07-import-lst).
Weight float Relative importance of the factor in the recommendation score, 0–1.
CandidateAutomations list of reference Automation profiles (01-automation-profile-model.md) eligible to be recommended by this rule; still subject to the compatibility rules in 03-selection-rules-and-constraints.md.
RecommendationMode enum Suggest (programmer must confirm) | AutoSelect (applied without confirmation, still overridable).

Recommendation and split workflow

  1. At job import (same trigger point as 02-selection-workflow.md step 1), the module scores each part/part group against the active Criteria for every CandidateAutomations entry compatible with the job's machine.
  2. If all parts in the job score the same best automation profile, the result is a single recommendation — surfaced the same way as today's pre-selected default, per RecommendationMode.
  3. If parts score differently (e.g. some parts' DownstreamProcess differs, or Weight/Size push some parts to a different automation), the job is split: each part is grouped by its winning automation profile, and 02-selection-workflow.md steps 2–5 run once per group, each initializing its own deposit-site canvas (chapter 04, chapter 05).
  4. Splitting by downstream automation (UC-29) is the special case where the only differentiating Factor is DownstreamProcess — parts destined for different next-machine routes are separated into distinct automation groups even if all other factors are equal.
  5. Recommendations are re-evaluated if the job's part mix changes (e.g. "Add to palletizing", see 09-user-interface/01-palletizing-ribbon-and-commands.md).

Interaction with existing constraints

A recommended or auto-selected automation profile is still subject to every rule in 03-selection-rules-and-constraints.md (Family installed, SiteKind match, CanRotatePart, gripper reach). The recommendation engine only narrows which compatible profile is chosen; it never bypasses compatibility validation. Changing a recommended selection afterward follows the same destructive-change handling as 04-impact-of-automation-change.md.

Scope

[Target] — CS28 first version uses manual/pre-selected automation choice only, per 01-automation-profile-model.md's [V1] simplification; no scoring or auto-split is performed.
