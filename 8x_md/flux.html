Architecture

Project layout (Src/Flux.sln)

Project Depends on Role
Flux.Base (none) Foundation: geometry (Geo, Mesh, Pline), the Au metadata serialization system (Attribute.cs, BStruct.cs), 2D/3D rendering (Lux/), low-level WPF controls, BHub event hub.
Flux.Core Base The domain model and CAM business logic — Part, NestJob, bend/fold/punch/cut/laser/trim "Tech" objects, simulation. Defines Hub (extends BHub) and the global FX static class.
Flux.UI Base, Core Reusable WPF panels/controls organized per domain (UI/Bend, UI/Fold, UI/Job, UI/Laser, etc.) plus shared Controls/, Dialogs/, Settings/. No dependency on App.
Flux.App Base, Core, UI, API The actual application (WinExe) — App.xaml, MainWindow.xaml, MenuCmds.cs, domain dialogs under App/Bend, App/Job, App/CAM, App/Workflow.
Flux.API Base, Core, UI Public SDK surface (built with _FLUXSDK define) that external consumers (see SDK/Samples) build against. Public-API changes require regenerating code via APIGen.
Flux.Console Base, Core, UI Headless CLI batch processor for CAM operations (part processing, nesting, NC generation) — root namespace FConsole.
Flux.Migrate Base, Core, UI Import/migration tool for legacy file formats — root namespace Flume.
Test (Flux.Test) API, Base, Core, UI The Flit test suite (see Tests above).

Src/Hula is a separate native C++ project (Hula64.vcxproj) providing a native interop layer, loaded by managed code via Flux.Hula64.dll.

Core domain model (Src/Core/)

The domain generally flows Part → Tech → Sequence → CAM/NC output:

  • Part/ — a sheet-metal part; can carry a 3D model, a 2D drawing, or both, and owns one or more "Tech" objects.
  • Model/ — 3D geometry (Model3, entities, planes, flexes for bend lines).
  • Bend/ — BendTech/BendOp, press-brake tooling, machine DB (BCell/).
  • Fold/ — FoldTech, panel-bender (folding) technology and gripper config.
  • Punch/ — PunchTech, punch-press technology and tooling.
  • CAM/ — CutTech/CutSequence, cutting tool geometry, step sequencing, machine/material DB.
  • Laser/ — laser-specific cut path logic (vector paths, slicing).
  • Nest/ — NestJob/NestData/NestSheet, nesting parts onto sheets.
  • Trim/ — CNC trim machine technology and step sequencing.
  • Sim/ — physics simulation for bend/fold operations (inverse kinematics, collision/"smash" detection).

Key patterns

  • FX (Src/Core/FX.cs) is the central static class holding global app state, settings (FX.Settings), the data directory, unit system, licensing, and stream locators (wad:, mc:, btool: schemes). Nearly every entry point calls FX.Init() first; UI.Init() follows for anything with a UI. Both Flux.App and the Flit test runner call this pair at startup.
  • Hub / BHub — an event/notification hub. BHub (Base) holds generic callbacks (selection, clipboard); Hub (Core) extends it with domain events (PartSaved, JobSaved, profile changes). Used to decouple layers instead of direct references.
  • "Au" serialization (Src/Base/Attribute.cs, BStruct.cs) — a custom metadata/attribute-driven serialization system ([AuDefault], [AuPrimitive], [AuInclude]) used for persistence and undo/redo via CURL-format files. Fields cached for this system use the _ prefix instead of m (see codestyle.md) and are auto-excluded from serialization.
  • Lux (Src/Base/Lux/) — the 2D/3D drawing/viewport engine (Lux, LuxDraw, LuxPanel, Scene); both the app's model viewport and the Flit test runner's snapshot window are built on it.

Tools (Tools/, separate solution FTools.sln)

  • APIGen — generates Flux.API's wrapper code; must be re-run after any public API change (see Code style above).
  • FShip — build/release packaging.
  • XLate — translation table management for lang/*.txt files.
  • XNCSign — code/file signing.
  • FDoc — documentation generation.
  • Sim5K / Sim7K — standalone 5-axis/7-axis bend-machine simulation apps.
  • Flux.Log, FMatrix, FTex, FluxLines, Annotate-C — smaller supporting utilities.

SDK (SDK/)

A separate public-facing package: SDK/Samples holds example consumers of Flux.API (bend profile, nesting job, model viewer, part details), and SDK/Ship builds the shippable SDK package.
