Machine-Side Manual Sorting UI

[Target] — no shopfloor UI exists today; MetaCAM/Deposit Editor and the current Praxis "Palletizing" view (chapter 09) are both CAM-programmer tools run at a desk, not on the machine HMI. Covers UC-23 ("Machine-side palletizing UI") and UC-26 ("Shopfloor palletizing adjustments").

Purpose

Where manual removal is the automation type (see 01-automation-types/index.md), or where an automated cell is down and a worker must sort by hand, this view runs on the machine HMI and guides the worker to reproduce the same stacking result the palletizing plan would have produced automatically. It is the shopfloor counterpart of chapter 09: chapter 09 is where the plan is authored; this chapter is where the plan is executed by a person, part by part.

What the view shows

Driven by the same stack data model as chapter 05, filtered down to next-action information a worker needs at the machine, not the full plan:

Item Source
Next part to remove (identity, orientation) Current Members entry due next, per pile's drop order — see 05-stack-and-pile-management/01-stack-data-model.md.
Target pile / pallet / position PalletRef, PositionXY of the pile this part belongs to.
Remaining piles on the current pallet(s) TotalNumber vs. current count per pile, so the worker can see what is left to sort.
Pile status Same red/yellow/green/gray/blue convention as 05-stack-and-pile-management/02-stack-status-visualization.md — a full pile (green) tells the worker to start the next one without checking a screen at the desk.

This is deliberately a narrower, sequential, "what do I do right now" view — not the full canvas/ribbon experience of 09-user-interface/01-palletizing-ribbon-and-commands.md.

Fields exposed for editing on the machine HMI vs. CAM-side only

UC-26 asks for on-the-spot adjustment authority at the machine, not just passive guidance. Of the Stack data dialog fields:

Field Machine HMI Rationale
PositionXY (Position on pallet) Editable Worker places the part somewhere on the pallet; must be reconcilable with plan or overridden.
DisplaceXY (Displace parts) Editable Staggered/brick placement is a physical act the worker performs.
MaxPileHeight (per pile) Editable Worker may need to cap a pile early (e.g. transport height limit discovered at the machine).
StackingMode Editable Worker may switch e.g. from Regular dropping to a gentler mode if quality is at risk.
PalletRef / carrier type Editable UC-26 explicitly calls out reassigning carrier type and pallet assignment from the shopfloor (e.g. swapping to a partially filled carrier, see 05-stack-and-pile-management/index.md).
StackId, PartTypeRef, TotalNumber, SheetStackNumber, BaseWeight Read-only Identity/derived fields computed from the plan and LST import — not something a worker should be able to desynchronize from the underlying job data.

Any HMI edit is functionally equivalent to a manual Pick/drop or a Stack Data dialog edit performed at the CAM desk — it must go through the same validation and re-coloring rules, not a separate code path. See 05-stack-and-pile-management/05-manual-pick-split-and-merge.md ("manual override always wins, but the pile must still be re-colored...") and 09-user-interface/02-stack-data-dialog.md ("OK commits edits... must trigger the same re-validation").

Reconciliation with the stack data model

Manual sorting actions must be booked back into the same stack data model the automated path writes, so the plan stays a true record of what physically happened:

  1. Each worker action (remove part, deposit onto a pile) updates that pile's TotalNumber/TotalHeight/TotalWeight immediately — the machine HMI is a second writer to the same model chapter 05 defines, not a shadow record reconciled later.
  2. A worker deviating from the suggested target pile/position (e.g. dropping on a different pallet than planned) is the machine-HMI equivalent of a manual Pick: the destination pile's status must be recomputed (05-stack-and-pile-management/02-stack-status-visualization.md), and if a split/merge results (e.g. worker consolidates two partial piles), the same split/merge feasibility rules apply — a pile tied to a single NC deposit location cannot be split even by a manual worker action.
  3. Export LST (chapter 08) must reflect the as-executed result, not the as-planned one, once manual sorting has touched a job — the Unload Sequence/Pallet Name fields (08-export-lst/02-populated-fields-reference.md) are re-derived from the post-edit pile state.

Open question

Whether machine-HMI edits are booked in real time (part-by-part, as the worker works) or batched and reconciled at end-of-job — see 11-requirements-and-traceability/02-open-questions-and-assumptions.md. Real-time booking is required if 02-notifications-and-carrier-change-alerts.md is to fire accurately during manual sorting.
