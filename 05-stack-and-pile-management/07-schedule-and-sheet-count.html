Schedules and Sheet Count

Schedules (from intro.htm)

A Schedule is a collection of layouts whose deposit locations are edited collectively. Two ways to build one:

  1. Manual: File → New → Schedule, then add layouts.
  2. From a nesting job: the nesting job editor's "Make Schedule" button creates a Schedule from all layouts of a nesting run in one step.

Sheet Count

Each layout in a Schedule carries a Sheet Count: how many physical sheets repeat that layout, to reach the required nesting quantity. Sheet Count is essential for pile-height computation — pile heights depend directly on how many sheet repeats' worth of parts must be deposited.

  • When a Schedule is created from a nesting job, Sheet Counts are copied automatically.
  • When a Schedule is assembled manually from existing layouts, Sheet Counts must be set manually: click the Sheet Count indicator (column 1 of the Schedule window) to make it editable, then type the value.

Stacking Thickness

A dynamic field in Custom Settings that overrides the default piling thickness (normally the sheet thickness) for a part — e.g. to account for forming that increases a part's effective stacked height. If unset, sheet thickness is used as-is. This feeds TotalHeight/SheetStackHeight in the Stack Data Model.

Opening the palletizing view

Clicking Edit Unloader Deposit Sites (Deposit Editor) / the equivalent Palletizing entry point (Praxis ribbon, see 09-user-interface/01-palletizing-ribbon-and-commands.md) opens the palletizing canvas showing deposit operations aggregated from all layouts in the Schedule.

Relationship to LST import

For this module, the Schedule's aggregated layouts/parts correspond to the BEGIN_PARTS_IN_PROGRAM (part master) and BEGIN_PARTS_IN_PROGRAM_POS (per-instance) tables of the imported LST — see 07-import-lst/03-relevant-lst-sections-reference.md. Sheet Count corresponds to how many times a given Main Program Name (sheet program) executes; where a single LST represents one sheet, Sheet Count is supplied by the surrounding scheduling context (e.g. the machine's job queue) rather than by a field inside sample.LST itself.
