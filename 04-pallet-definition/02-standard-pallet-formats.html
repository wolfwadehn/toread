Standard Pallet Formats

Rationale

The concept paper flags pallet-format diversity as a significant issue: "One significant issue with palletizing is a very diverse format landscape: Europallets, US pallets etc. and multiples." The module must ship a library of standard formats so the programmer is not forced to enter dimensions by hand for common cases, and so Format in the Pallet Data Model can be validated/looked up.

Standard formats table (from the concept paper)

Pallet Type Size (mm) Main Regions
Euro (EPAL) 1200 × 800 Europe
ISO / UK 1200 × 1000 Global / UK
GMA (US) 1219 × 1016 US / Canada
Australia 1165 × 1165 Australia
Asia (JIS) 1100 × 1100 Japan, Korea
Container 1140 × 1140 Air & container cargo

Requirements

  1. Ship this table as seed data (Format enum values with default SizeX, SizeY).
  2. Support multiples of a standard format (e.g. two Euro pallets end to end) as a first-class case in multi-pallet layout — see 03-custom-pallets-and-multi-pallet-layout.md — rather than requiring the programmer to define a new custom size for every combination.
  3. Allow a Custom format that behaves identically but with free-entry SizeX/SizeY, for site-specific carriers not in the table.
  4. Region metadata (Main Regions) is informational only (helps the programmer pick the right default for their factory's locale) and carries no behavioral constraint.

Rule-driven automatic layout selection [Target]

The requirements above cover the programmer manually picking a Format. Separately, the module should be able to automatically select an unloading layout/format based on customer or order requirements (e.g. a given customer's orders always ship on a specific pallet format), rather than requiring the programmer to choose it every time. This is a rule lookup (order/customer attribute → Format or saved layout) layered on top of manual selection, not a replacement for it — the programmer can always override the automatically selected layout.
