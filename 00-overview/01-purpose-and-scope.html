Purpose and Scope

Purpose and Scope

Purpose

The Palletizing module plans where and how cut/bent parts are unloaded and stacked once a sheet-metal cutting (and optionally bending) job runs on an automated machine. It answers, for every part instance in a job:

  • Which automation unloads it (gripper robot, SheetMaster, SortMaster, conveyor/box sorter, or manual)?
  • Which pallet (or container) does it land on, and at what X/Y position?
  • Which stack does it join, in what sequence, and does that stack stay within height/weight/collision limits?
  • Is the resulting pickup reachable and safe for the next process step (typically a bending machine / robot cell), not just for the unloader itself?

The module is standalone: it consumes a finished cutting job (sheet + part positions + NC program) and produces a palletizing plan that is (a) visualized and editable by the programmer, and (b) written back into the job's NC/setup-plan file so the automation executes it. It does not perform nesting and does not compute gripping points/collision geometry from scratch — gripping point calculation is already implemented in TZC (see 00-overview/03-source-material-and-references.md).

Scope

In scope:

  • Automation type selection and capability modeling (chapter 02).
  • Gripper and pallet master data (chapter 03, chapter 04).
  • Interactive stack/pile arrangement, equivalent to and extending the MetaCAM Deposit Editor (chapter 05).
  • Backward-planning constraints from downstream processes (bending, robot reach, collision, orientation) (chapter 06).
  • Import and export of the setup-plan/NC-list (LST) file format (chapter 07, chapter 08).

Out of scope:

  • Nesting/layout generation (upstream of this module).
  • Gripping-point and part-collision geometry calculation (owned by TZC).
  • Bending program generation (downstream; this module only supplies constraints and the pickup/stack plan bending consumes).

Two scope tiers

Per the concept paper's disclaimer, delivery is staged:

  • [V1] CS28 first version — functionality close to the existing MetaCAM Deposit Editor: manual/assisted stacking on a single pallet type, sheet-count aware pile building, auto-arrange/equalize/lower/split/merge, deposit settings, LST import/export of the fields the format already reserves for unload/pallet assignment.
  • [Target] Praxis end concept — adds automation-type-aware selection, gripper/pallet master data management, backward-planning reachability and orientation checks against the next machine (not just the unloader), collision-hazard checking for repositioned parts, and auto-suggested stacking patterns analogous to nesting auto-arrange.

Every chapter in this spec labels its subsections [V1] or [Target] where the distinction matters.

Design principle: one application [Target]

The module is designed as one application covering all automation solutions (gripper robot, SheetMaster, SortMaster, conveyor/box sorter, manual), not a separate tool per automation type. This avoids system disruptions in a Smart Factory ecosystem, where a programmer or operator should not need to switch applications when the target automation changes. Automation-specific behavior is expressed as data/configuration (see chapter 02) within this one application, not as forked implementations.
