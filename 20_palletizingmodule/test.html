01 · Configuration parsing

Test: TnReadConfigurationTest::readLayoutsFromJsonFile_L76

Input: testdata/unloadingarea/L76.json

Parses the L76 unloading area JSON and verifies the in-memory model matches exactly. This is the contract test for the JSON reader — every other L76 test depends on this passing.

Assertions:

  • Layout ID 1 present with exactly 4 unloading area units
  • Unit "2" at (515.0, −555.0) → 7 container sections (IDs 1–7), each 300×400 mm, max 200 mm, corner (30, 30)
  • Unit "3" at (4000.0, −500.0) → section ID 8, 1000×1900 mm
  • Unit "4" at (5000.0, −500.0) → section ID 9, 1000×1900 mm
  • Unit "5" at (6000.0, −500.0) → section ID 10, 1000×1900 mm
  • All 10 sections allow goodPart and scrapPart

02 · Baseline stacking data

Reads a sheet with 1 good part and 2 scrap parts and verifies the stack item list. Establishes the expected output shape that all other LST-based L76 tests build on.

  • Good part (item 0): rotation 0.0°, mode drop
  • Destination: unloadingAreaUnit ID 3, stack ID 2
  • Good part COG in unit coords: (472.936, 778.594)

03 · Offset grip point

Test: TnPalletizingDataTest::readFromLst_L76_one_good_part_two_scrap_parts_lift_position_not_on_part_center_of_gravity_stacking_data
File: lstdata/fromlst/algorithm/test/TnPalletizingDataTest.cpp:240
Input: l76_onegoodpart_twoscrapparts_liftnotonpartcenterofgravity.lst

Tests the case where the gripper attaches at a point that is not the part's center of gravity. The algorithm places by COG; the arm moves to the grip point. Conflating these causes parts to land in the wrong position.

Assertions:

  • Exactly 3 stack items
  • Good part COG: (263.991, 754.337) — differs from the lift position in the LST
  • Destination: unloadingAreaUnit ID 3, stack ID 3
  • Mode: drop

04 · Destination-only rotation

Test: TnPalletizingDataTest::readFromLst_L76_lift_rotation_only_in_destination_region_stacking_data
File: lstdata/fromlst/algorithm/test/TnPalletizingDataTest.cpp:277
Input: l76_lift_rotation_only_in_destination_region.lst

A part exits the sheet in its original orientation, then the arm rotates it 90° in the destination region before placing it. Tests that destination rotation is stored separately from sheet-level rotation — these are distinct transforms in the coordinate pipeline.

Assertions:

  • 1 stack item
  • Rotation in sheet: 0.0 rad
  • Rotation in destination: π/2 rad (tolerance 1.0e-14)
  • COG in unit coords: (119.904, 1636.545)
  • Destination: unloadingAreaUnit ID 3, stack ID 1

05 · Accumulated rotation (sheet + destination)

Test: TnPalletizingDataTest::readFromLst_L76_lift_rotation_in_sheet_and_destination_region_stacking_data
File: lstdata/fromlst/algorithm/test/TnPalletizingDataTest.cpp:319
Input: l76_lift_rotation_in_sheet_and_destination_region.lst

Extends TC 04: the arm reorients the part in both the sheet phase and the destination phase. Tests that the reader accumulates both rotations and that the final position in container unit ID 2 is computed correctly.

Assertions:

  • 1 stack item
  • Rotation in sheet: 0.0 rad
  • Accumulated rotation at destination: (225/180)·π rad = 225° (tolerance 1.0e-14)
  • COG in unit coords: (78.715, 153.410)
  • Destination: unloadingAreaUnit ID 2 (container, not pallet)

06 · Material thickness

Test: TnPalletizingDataTest::readFromLst_L76_one_good_part_two_scrap_parts_palletizing_thickness
File: lstdata/fromlst/algorithm/test/TnPalletizingDataTest.cpp:362
Input: l76_onegoodpart_twoscrapparts.lst

Verifies that material thickness is read and attached to every stack item. Palletizing thickness drives stack height calculations — a wrong value causes the gripper to collide with previously placed parts.

Assertions:

  • All 3 stack items carry palletizing thickness 2.0 mm

07 · PAPA with two related PAUD entries

Test: TnPalletizingDataTest::readFromLst_L76_part_center_of_gravity_one_papa_two_related_paud_entries_for_scrap1_and_scrap2
File: lstdata/fromlst/algorithm/test/TnPalletizingDataTest.cpp:384
Input: l76_twogoodparts_fourscrapparts_onepapatworelatedpaud.lst

Tests a structurally unusual LST where a single PAPA entry has two related PAUD entries for scrap parts — multiple scrap parts share a stacking destination but differ in position. The reader must map each PAUD back to its PAPA without mixing COG coordinates.

Assertions:

  • Exactly 6 stack items (2 good parts + 4 scrap parts)
  • Good part 0 COG in destination: (470.0, 130.0) (tolerance 0.0, exact)
  • Scrap parts (items 2, 3, 4) COG in destination: (120.0, 80.0) (exact)

08 · Multi-part simultaneous removal

Test: TnPalletizingDataTest::readFromLst_L76_part_multipartremoval
File: lstdata/fromlst/algorithm/test/TnPalletizingDataTest.cpp:426
Input: l76_multipartremoval.lst

The most complex L76 test. The arm removes up to 4 parts simultaneously across 5 discrete removal operations. Stack IDs repeat, meaning later groups stack on top of positions already used by earlier groups. Verifies grouping, ordering, COG coordinates in sheet space, and stack-position reuse.

Assertions:

  • 12 stack items, 5 removal groups
  • Removal numbers: 1,1 | 2,2 | 3,3,3,3 | 4,4 | 5,5 — group 3 is the largest (4 simultaneous)
  • Stack IDs: 1,1 | 3,3 | 5,5,5,5 | 3,3 | 1,1 — groups 4 and 5 reuse stacks from groups 2 and 1
  • Item 0 COG in sheet: (1154.15, 444.87)
  • Item 1 COG in sheet: (1368.63, 444.87)
  • Item 2 COG in sheet: (999.53, 858.77)
  • Item 3 COG in sheet: (1314.01, 858.77)
  • Items 9–12 land on same positions as items 3–0 (stack position reuse)

09 · Grip position relative to COG

Test: TnPalletizingDataTest::readFromLst_L76_one_good_part_two_scrap_parts_unloading_device_position
File: lstdata/fromlst/algorithm/test/TnPalletizingDataTest.cpp:670
Input: l76_onegoodpart_twoscrapparts_liftnotonpartcenterofgravity.lst

Tests the unloading device (gripper) position relative to each part's COG. For L76, the device is a simple lift with a single component (no shuttle arm). Positions are offsets from the part COG in the device's coordinate frame. Uses the same LST as TC 03.

Assertions:

  • Each of 3 stack items has exactly 1 device component (single-lift configuration)
  • Item 0 grip offset: (−37.650, −1.582)
  • Item 1 grip offset: (−63.521, −57.394)
  • Item 2 grip offset: (85.892, 16.176)
  • Angle difference device vs. part rotation: 0.0 for all items
  • Tolerance: 0.0 (exact match)
