multipartdemoUI — Algorithm Documentation

demo/multipartdemoUI/main.cpp reads a TRUMPF LST file through the lstdata library and writes a self-contained HTML file that visualises both the sheet layout and the pallet destination in detail.

1 Functional View

1.1 Top-level pipeline

main()
 ├─ CLI parse (cxxopts)              --file / --output / --dir / --help
 ├─ selectLstFile()                  interactive numbered list if --file omitted
 ├─ TnPalletizingData::readFromLst() LST → TcSheet (full domain model)
 ├─ generateHtml()
 │   ├─ buildVizData()               TcSheet → vector<ItemViz>
 │   ├─ generateSheetSvg()           sheet layout SVG string
 │   ├─ generateDestSvg()            destination layout SVG string
 │   ├─ generateLegend()             HTML legend bar
 │   ├─ generateTable()              HTML item table
 │   └─ generateJsonData()           ITEMS[] JS array for the detail panel
 └─ write to output file

1.2 Key data structures

Type Role
Pt 2-D point in world coordinates (mm). Plain struct {x, y}.
Vp Viewport transform. Maps world mm → SVG pixels with Y-axis flip. Stored as {x0, y0, scale, svgH}.
ItemViz All data needed to render one TcStackItem. Holds both the sheet polygon and the destination polygon (already in world mm), the lift-point positions, and metadata strings for tooltips/table.

1.3 Geometry extraction pipeline (worldPolygon)

The part outline comes from the GEO binary blob parsed by TcGeoReader inside readFromLst. The resulting TcRegion holds a TcCurve (the outer boundary) made of TcLineSegment and TcArcSegment objects.

TcRegion::outerCurve()
  └─ curvePoints()                   polygon approximation in LOCAL frame
      ├─ TcLineSegment  → start point only
      └─ TcArcSegment   → sample arcPts=24 points uniformly by angle
  ↓
  center at bounding-box centre      removes local-frame translation offset
  ↓
  rotate(angle)                      2-D rotation matrix, angle in radians
  ↓
  translate(cogX, cogY)              place at world COG
  ↓
  worldPolygon result                ready for SVG

Bounding-box centering — the local coordinate frame of the geometry blob has no guaranteed origin. Subtracting the bbox centre before rotating ensures the rotation is about the visual centre of the part, which matches the physical COG for symmetric sheet-metal parts.

Arc sampling — absoluteStartAngle() gives the angle of the first arc point in radians. signedSpanAngle() is negative for CW arcs. The parametric formula is a = a0 + t * da for t ∈ [0, 1). The end point of the arc is the start point of the next segment and is therefore not emitted here (it will be emitted as the start of the next line or arc).

1.4 Viewport transform (makeVp / Vp)

Goal: fit the entire world-coordinate scene into an 800 × 560 pixel canvas with a 10 % padding margin.

1. Compute tight AABB over all world points.
2. pad = max(dx, dy) * 0.10
3. Expanded AABB: [xmn-pad, xmx+pad] × [ymn-pad, ymx+pad]
4. scale = min(svgW / expandedDx, svgH / expandedDy)   ← preserves aspect ratio
5. Center within canvas:
     offX = (svgW - expandedDx*scale) / 2 / scale       ← extra space in world units
6. World origin: x0 = xmn - pad - offX,  y0 = ymn - pad - offY
7. toX(wx) = (wx - x0) * scale
   toY(wy) = svgH - (wy - y0) * scale                   ← Y-flip

The Y-flip converts from the mathematical convention (Y up) used by the machine model to the SVG convention (Y down).

1.5 Layer computation

Parts in the same stack column are physically stacked on top of each other in removal-group order. The layer number drives the painter's algorithm in the destination SVG and provides the L badge.

1. Group items by stackId  →  stackGroups[id] = [group, group, ...]
2. For each stackId: sort groups, deduplicate          (ascending → lowest group first)
3. For each item: layer = indexOf(item.group in sorted list) + 1

Layer 1 is the first removal into that column (placed deepest on the pallet or the first item picked from the sheet, depending on device type). Layer N items are drawn on top in the destination SVG.

1.6 Sheet layout SVG (generateSheetSvg)

Rendering order (painter's algorithm — last drawn is on top):

1. Background rect (#161e28, dark blue-grey)
2. Grid lines (50 px intervals, 4 % opacity white)
3. Per item:
   a. Part polygon   — group colour, 55 % fill opacity
   b. Lift arms      — dashed line COG→liftPt + arrowhead + diamond at tip
   c. COG cross      — white ± 4 px crosshair
   d. Label          — "G<group>·<idx>" above COG

The lift arms originate at item.sheetCog and end at each entry in item.liftPts. liftPts are already in sheet world coordinates (see §1.7), so they map directly through Vp.

1.7 Destination layout SVG (generateDestSvg)

The destination SVG uses a visual layer offset of 8 mm per layer to separate physically-stacked parts from each other on screen.

kLayerOffset = 8.0 mm
visualOffset = (layer - 1) * 8 mm  → applied to BOTH x and y (diagonal shift)

Rendering order:

1. Background rect (#1a1608, dark amber-black — pallet surface)
2. Grid lines (3 % opacity)
3. Stack column bands (per stackId: dashed rounded-rect + label)
4. Parts — outer loop over targetLayer 1..maxLayer:
   a. If layer > 1: ghost outline of the same polygon at the previous
      layer offset (dashed, 30 % opacity) — shows what is underneath
   b. Part polygon — group colour, 60 % fill (layer 1) or 45 % (layer N)
   c. COG circle — 3 px radius
   d. Layer badge — "L<n>" next to COG for layer > 1
   e. Group·index label above COG
   f. Destination coordinates in small text below COG

The outer targetLayer loop is painter's algorithm: all layer-1 parts are drawn first, then all layer-2 parts on top, so higher layers always appear in front regardless of their draw position.

1.8 HTML assembly (generateHtml)

The function concatenates raw string literals (C++11 R"(...)") with generated substrings. Structure of the emitted document:

<html>
  <head> <!-- CSS: dark industrial theme, 2-column grid layout --> </head>
  <body>
    <header>  <!-- filename, sheet name, machine, thickness, part count, group count -->
    <section class="panels">
      <!-- generateSheetSvg() + generateDestSvg() side by side -->
    </section>
    <!-- generateLegend() -->
    <section>  <!-- generateTable() -->
    <script>
      <!-- generateJsonData() → const ITEMS = [...] -->
      <!-- inline JS: hi/unhiAll/showDetail/filterGroup event handlers -->
    </script>
  </body>
</html>

The embedded ITEMS array mirrors the ItemViz fields so that the JavaScript detail panel does not need to re-read the SVG attributes.

1.9 JavaScript interaction model

All SVG elements that represent parts carry data-item="N" and data-group="G" HTML attributes. Table rows carry only data-item.

mouseenter on .part or tr[data-item]
  → hi(id):    querySelectorAll('[data-item="N"]') → add class "hi"
               CSS: filter:brightness(1.6) drop-shadow(...)
  → showDetail(id): render ITEMS[id-1] fields into <div id="detail">
mouseleave
  → unhiAll(): remove class "hi" from all elements

click on legend-item
  → filterGroup(g):
      if already active → clear filter
      else → set [data-group != g] opacity=0.15, [data-group == g] opacity=1

  → { p.x*cos(a) - p.y*sin(a),
      p.x*sin(a) + p.y*cos(a) }

Standard 2-D rotation matrix. Angle a is in radians, CCW positive (matching the domain model convention).

2.3 curvePoints (lines 138–163)

// line 141
for (const auto& seg : curve.segments())

Iterates the ordered segment list of the outer curve. Segments share endpoints: the end of segment i equals the start of segment i+1, so only the start point is emitted for line segments to avoid duplicates.

// lines 143-146  — line segment branch
auto* line = dynamic_cast<const TcLineSegment*>(seg.get())
pts.push_back({ line->startPoint().x(), line->startPoint().y() })

startPoint() returns TyPoint3D = TcVector3D. Only x/y are used; z is always 0 for 2-D sheet geometry.

// lines 147-160  — arc segment branch
double a0 = arc->absoluteStartAngle();  // radians from positive X axis
double da = arc->signedSpanAngle();     // negative = CW arc
for (int i = 0; i < arcPts; ++i)       // arcPts = 24 default
  t = i / arcPts                        // t in [0, 1)
  a = a0 + t * da                       // uniform angle parameter
  pts.push_back({ cx + r*cos(a), cy + r*sin(a) })

The open interval [0, 1) means neither the start nor the end angle of the arc is exactly emitted. The start coincides with the end of the previous segment (already emitted as a line start or arc start). The end coincides with the start of the next segment (will be emitted there).

2.4 worldPolygon (lines 166–186)

// lines 172-174  — bounding box centre in local frame
const auto& bbox = region.boundingBox();
double lcx = (bbox.getXMin() + bbox.getXMax()) / 2.0;
double lcy = (bbox.getYMin() + bbox.getYMax()) / 2.0;

The GEO blob coordinate system has an arbitrary origin. Subtracting the bbox centre re-centres the polygon at the origin before rotation.

// lines 176-185  — transform loop
auto localPts = curvePoints(*region.outerCurve());
for (const auto& lp : localPts)
  Pt centered = { lp.x - lcx, lp.y - lcy }   // re-centre
  Pt rot      = rotate(centered, angle)         // rotate in-plane
  world.push_back(translate(rot, cogX, cogY))  // place at world COG

The three-step transform (centre → rotate → translate) is the standard rigid-body placement for a part that sits at (cogX, cogY) in world coordinates and is rotated angle radians around its own COG.

3 Key Invariants

# Invariant Source
1 TcStackItem::getStackingOperation() is never null inside buildVizData. Items with unresolved operations are filtered out by CHECKANDREPORT in readStackItems. TcReadFromLst::readStackItems
2 getRemovalNumber() ≥ 1 for all palletizing items. Group 0 is reserved for the scrap skeleton. TcReadFromLst::readStackItems field 190
3 curvePoints does not emit the final closing point. The SVG <polygon> element closes the path automatically. SVG spec §10.6
4 worldPolygon uses the bounding-box centre as the local-frame origin. This is exact only if the COG equals the geometric centre. For asymmetric parts the visual rotation centre may differ slightly from the physical COG. buildVizData line 172–174
5 The destination polygon (destPoly) uses the COG from getPartCenterOfGravityInDestinationRegion(), which is the actual part COG as computed by device-type dispatch in readStackingOperations. It is not the device target position. TcReadFromLst::readStackingOperations
