CRA GAP analysis https://trumpf.atlassian.net/wiki/spaces/TTBC/pages/1943046449/Cut+Gap+Analysis+Workflow

This page describes the workflow used to create a gap analysis for the software component TruTops Boost Cut. This workflow can be adapted for any other software component to create an IEC 62443-4-2 based gap analysis.

Stage 1: Initial preparation (required only once per software component) Step 1: Create a markdown document describing the software component to assess Step 2: Create AI prompts and a report template to conduct the assessment Stage 2: Perform the gap analysis Step 1: Provide analysis data Step 2: Perform the analysis Prompt 1: Context priming Prompt 2: Applicability mapping Prompt 3: Evidence correlation Prompt 4: Gap list and risk Prompt 5: Mitigation roadmap Prompt 6: Full report generation Prompt 7: Review and refinement Stage 1: Initial preparation (required only once per software component) For the first assessment it is recommended to apply this stage first. This stage will result in a gap analysis template and a series of AI prompts to generate the gap analysis result.

Step 1: Create a markdown document describing the software component to assess This markdown document will serve as input for the blueGPT Agent CyberResilienceAct_MT_Product_Advisor_GBL_0326 to prepare the analysis. It should contain information about

The software component to assess

The software system it is embedded in

Add CRA relevant facts

Example for Cut (generated using blueGPT Opus 4.6, manually revised, additional facts added): trutops_boost_intro_and_cut_facts.md

Step 2: Create AI prompts and a report template to conduct the assessment Give the blueGPT Agent CyberResilienceAct_MT_Product_Advisor_GBL_0326 the software component description created in Step 1 and the following prompts have been used to generate templates and AI prompts (adjust as required, i.e. component name):

We have to perform a gap analysis for the component TruTops Boost Cut based on IEC 62443-4-2. The attached document gives a high level description of the programming system TruTops Boost containing the component Cut and provides additional facts about Cut. Please generate a detailed description of the recommended documents to be considered in the analysis (source code, architecture documentation, etc.), the objectives of the analysis, the required content and structure of the analysis report and additional recommendation in particular to properly condition an AI to perform the analysis and write the report.

Please prepare a template report structure in markdown format. Also generate markdown files for each assessment step prompt and generate a zip file containing all markdown documents for download. Markdown-Resultate:

iec62443_4_2_fr_cr_paraphrased_list.md

cut_iec62443_4_2_gap_analysis_template.md

prompt_1_context_priming.md

prompt_2_applicability_mapping.md

prompt_3_evidence_correlation.md

prompt_4_gap_list_and_risk.md

prompt_5_mitigation_roadmap.md

prompt_6_full_report_generation.md

prompt_7_review_and_refinement.md

Stage 2: Perform the gap analysis Step 1: Provide analysis data A directory named AnalysisDocuments has been created and the following data has been copied into this directory:

Directory CutArc42ArchitectureDocumentation: Full Arc42 documentation of TruTops Boost Cut taken from https://trumpf.atlassian.net/wiki/x/HI5xB including threat analysis data

Product.Cut: complete source code of Cut including pipeline definitions

Regulations: regulations and norm documents IEC_62443-4-2-01_02_2019-en_fr-Aktuell.pdf, GL30_G025_Standard-Secure_Project_and_Product_Management.pdf, GL30_G027_Standard-Secure_Product_Design_Guidelines.pdf, GL30_G028_Standard-Secure_Development.pdf, GL70_G152_Policy_Product_Security.pdf (Sources: TDM and WISDOM)

File iec62443_4_2_fr_cr_paraphrased_list.md from Stage 1, Step 2

File cut_iec62443_4_2_gap_analysis_template.md from Stage 1, Step 2

File sbom_cut_22.1.14.json: latest available SBOM file of TruTops Boost Cut

File trutops_boost_intro_and_cut_facts.md from Stage 1, Step 1

Step 2: Perform the analysis The AnalysisDocuments directory has been opened with Visual Studio Code. The gap analysis has been conducted using Copilot with Opus 4.8 applying subsequently revised versions of the prompts generated in Stage 1, Step 2:

Prompt 1: Context priming

You are an assistant helping with an IEC 62443-4-2 gap analysis for a TRUMPF Machine Tool software component named TruTops Boost Cut (short Cut). Read and understand the follwong context documents:

  • trutops_boost_intro_and_cut_facts.md: Short introduction to the programming system TruTops Boost and its component Cut. Contains additional gap analysis relevant facts about Cut.
  • All files in directory CutArc42ArchitectureDocumentation: Contains architecture documents for Cut following the Arc42 architecture documentation template.
  • All files in directory Regulations: Contains all relevant standards and regulations to follow.
  • During the assessment process stay strictly within the current workspace folder AnalysisDocuments and its subfolders. You are not allowed to access data outside or request access to it Assume:
  • Cut is an IEC 62443-4-2 component.
  • CRA applies; product is non-important/non-critical.
  • TRUMPF internal standards (GL70 Product Security, GL30_G025/G027/G028) must be considered for process aspects. Tasks:
  1. Restate this architecture and security context in your own words to show understanding.
  2. Identify the main trust boundaries (e.g., Cut ↔ HomeZone, Cut ↔ DB, Cut ↔ helper apps, Cut ↔ customer environment).
  3. List the main security-relevant assets and interfaces of Cut. Answer concisely but clearly. Follow my instructions as I lead you through the analysis process prompt by prompt. Prompt 2: Applicability mapping

We are now focusing on IEC 62443-4-2 technical security requirements for IACS components. You have a paraphrased list provided by the file iec62443_4_2_fr_cr_paraphrased_list.md of:

  • Function Requirements FR 1 to FR 7 (identification/authentication, use control, system integrity, data confidentiality, restricted data flow, timely response to events, resource availability).
  • Component Requirements CR x.y under each FR. Task: For each IEC 62443-4-2 requirement (FR/CR pair):
  1. Classify its applicability to the Cut component as one of:
    • "Directly applicable to Cut (component level)" – Cut itself must implement the measure.
    • "Fulfilled at system level (TruTops Boost / OS / enabler)" – Cut relies on the surrounding system or OS.
    • "Not applicable" – truly out of scope for Cut (must be justified).
  2. Provide a short justification for your classification, specifically referencing:
    • The fact that Cut is invoked by other applications like HomeZone but not by the user.
    • The client/server runtime split.
    • The existence of helper applications and external DB.
    • The CRA and TRUMPF product security context. Additional sources of information:
  • You can access the source code of Cut including build pipeline code located under Product.Cut (very large codebase)
  • Current Cut SBOM file sbom_cut_22.1.14.json Important constraints:
  • Do NOT mark a requirement as "Not applicable" just because it is difficult; only do so if it clearly does not logically apply to a component like Cut.
  • If you are unsure, classify as "Directly applicable" or "System-level" and explicitly state uncertainty. Output:
  • A table with columns: IEC Ref, Requirement Title, Applicability (Component/System/N/A), Justification. Prompt 3: Evidence correlation

Now evaluate whether Cut currently meets each IEC 62443-4-2 requirement that you classified as "Directly applicable to Cut" or "Fulfilled at system level". You have the following types of evidence:

  • Architecture and design descriptions
  • Source code
  • CI/CD pipeline YAML files in the subdirectory Product.Cut/pipelines
  • SBOM (CycloneDX) content for Cut in sbom_cut_22.1.14.json
  • Test documentation (unit tests, system tests code in Product.Cut/SystemTest)
  • TRUMPF internal process descriptions (GL70 Product Security, GL30_G025/G027/G028) Task: For each requirement classified as "Component" or "System-level":
  1. Assess implementation status using the evidence you have:
    • "OK" – clearly implemented with sufficient evidence.
    • "Partial" – some aspects implemented; gaps or unclear areas remain.
    • "Gap" – not implemented or evidence suggests non-compliance.
    • "Unknown" – no sufficient evidence available.
  2. Provide:
    • A short description of the current implementation.
    • References to specific evidence (e.g. "CI/CD file Y", "module Z.cpp", "SBOM vX").
    • A short explanation for the chosen status. Important constraints:
  • When in doubt, prefer "Partial" or "Unknown" rather than "OK".
  • Do not assume TRUMPF Product Security has granted exceptions unless explicitly stated; treat all IEC 62443-4-2 and CRA-related requirements as applicable by default. Output:
  • A table with: IEC Ref, Requirement Title, Applicability, Current Implementation & Evidence, Status (OK/Partial/Gap/Unknown), Short Explanation. Prompt 4: Gap list and risk

Using the requirement status table you produced, extract all entries with status "Partial", "Gap", or "Unknown". Task:

  1. Create a consolidated gap list:
    • Assign an ID (G1, G2, …) to each gap.
    • For each gap, state:
      • Related IEC 62443-4-2 reference(s).
      • Short description of the gap.
      • Root cause or context (e.g., lack of logging, missing encryption, reliance on OS without documented assumptions).
  2. For each gap, assess potential impact:
    • Which properties may be affected (Confidentiality, Integrity, Availability, Authenticity, CRA compliance)?
    • Qualitative risk level: Low / Medium / High, based on your understanding of Cut's role (programming system, customer environment, interfaces).
  3. If a TARA or threat model description is available, link gaps to:
    • Known threats.
    • Attack paths.
    • Security goals that are not fully met. Output:
  • A gap table with columns: Gap ID, IEC Ref, Gap Description, Root Cause/Context, Impact, Risk Level.
  • A short narrative summarising which FR areas (FR 1–FR 7) are most affected. Prompt 5: Mitigation roadmap

Based on the consolidated gap list and your risk assessment, propose a mitigation roadmap for Cut. Constraints and context:

  • Technical requirements must align with TRUMPF internal standards:
    • GL70_G152 Product Security Policy.
    • GL30_G025 Secure Project and Product Management.
    • GL30_G027 Secure Product Design Guidelines.
    • GL30_G028 Secure Development.
  • Some central enablers may be available (IAM, logging, PKI, SAST, vulnerability management, risk assessment via SECIRA) but are not necessarily fully ready; where enablers are mentioned, also note integration effort.
  • Product-level accountability lies with the business centre leads of the corresponding MT product; you may mention generic roles (architect, developer, LPSO) but not individuals. Task: For each gap:
  1. Propose one or more mitigation actions:
    • State whether the action is technical, organisational, or process-related.
    • Reference relevant TRUMPF standards and, where applicable, CRA essential requirements.
    • Mention whether central enablers can be used (e.g. M-/F-IAM, TSI Syslog Server, PKI & code signing, vulnerability management tool).
  2. Assign:
    • Priority (P1=high, P2=medium, P3=low), based on risk level and implementation effort.
    • Indicative target timeline (e.g. quarter/year).
  3. Map each action to TRUMPF CRA reporting categories:
    • Conformity declaration.
    • Secure software development lifecycle.
    • CI/CD requirements.
    • Communication across trust boundaries.
    • Technical product requirements. Output:
  • A mitigation table: Gap ID, Recommended Action, Type, Dependencies, Priority, Target Timeline, CRA Category.
  • Short narrative explaining which actions are most critical. Prompt 6: Full report generation

You now have:

  • The IEC 62443-4-2 applicability and status mapping.
  • The consolidated gap list and risk assessment.
  • The mitigation roadmap.
  • The TruTops Boost Cut context and architecture description.
  • The markdown template structure for the report. Task: Generate a complete IEC 62443-4-2 gap analysis report based on the template file cut_iec62443_4_2_gap_analysis_template.md under AnalysisResult for TruTops Boost Cut by filling the template sections:
    1. Executive Summary
    1. Scope, Context and Assumptions
    1. System and Component Description
    1. IEC 62443-4-2 Requirement Mapping
    1. Gaps and Risk Assessment
    1. Recommended Mitigation Roadmap
    1. Evidence and Traceability
    1. Appendices Constraints:
  • Use concise but technically precise language.
  • Clearly distinguish facts (based on evidence) from assumptions. Mark assumptions explicitly.
  • When describing responsibilities, refer only to "business centre leads of the corresponding MT product" and generic roles (architect, developer, LPSO, tester).
  • Do not reproduce full standard text of IEC 62443-4-2; use references and short paraphrased headings.
  • Keep the markdown structure (headings, tables) intact. Output:
  • A single markdown report file cut_iec62443_4_2_gap_analysis.md located in AnalysisResults. Prompt 7: Review and refinement

Review the generated report critically. Task:

  1. List any sections where:
    • The reasoning seems speculative.
    • Requirements have been classified as "Not applicable" without strong justification.
    • Evidence references are missing or vague.
  2. Suggest corrections or mark items that need human expert review (e.g. LPSO, architect).
  3. Propose 3–5 targeted questions to be answered by human experts to improve the accuracy of the gap analysis. Output an additional markdown file in the AnalysisResults directory containing:
  • a list of issues to review.
  • a bullet list of expert questions.
  • Show these two lists also in this chat.
