Cell7000 Detail — NC Values, Defaults & Relationships

Non-normative reference. The concrete parameter values, their defaults, meanings and cross-table relationships that feed the TruBend Cell 7000 automation NC (the bncx / KemroK2 output and the coordinated press program). Derived from the Bend SQL schema DDL (DEFAULT constraints + German MS_Description); treat as a data map, not an authoritative spec.

0. Scope, provenance & how to read

What this document is. A function-grouped reference of every NC-relevant parameter the source defines for the Cell 7000, giving for each: the exact default value, the meaning (German original → English), the unit where derivable, and the relationship (which table/field it joins or which NC step it feeds). It consolidates, from an NC-output angle, the fields specified table-by-table in [[16.4 - Cell7000 — Robot, Process & Motion Data]], [[16.3 - Cell7000 — Machine & Cell Configuration]] and [[16.1 - Bending — NC Code Generation]].

[!warning] The bncx wire format itself is not in this source snapshot bncx is registered only as a file type — e_bncx = 125, "Bend B06" (tc_ToPsFileScanner/TcToPsFileTypeSettings.h; PDM tsp_PDM_ShowFileAttributes) — the bend-NC file for B06-generation machines (the Cell 7000 class; cf. WZG_OW_ATTRIBUTE.TypGreifnut 0 = B06). There is no .bncx sample, XSD, writer, or NC template (NC_SATZ) seed data in the snapshot. The file's field-level layout is produced by the compiled ToPs 600 / BendMaster runtime (see [[16.1 - Bending — NC Code Generation]] FR-BEND-NC-017). This document therefore documents the parameters that populate the NC — their values, defaults and relationships — not the bncx element layout. Related bend-NC interchange types: bnc(40), bmt(30), bif(62 "general NC interface"), bmtm(138 "interface to Flux — ZIP with extended GEO, BNC + Info XML"), geox(137 "interface to TruBend Center"), arvxttc(133 archive).

Value-typing convention. Numeric defaults are shown as-is. '' = empty string default. bit/flag defaults are 0/1. Units are inferred from context (mm for distances, mm/s for speeds, degrees for angles, seconds for times) and marked (inf.) — confirm against the post-processor; the schema does not state units.

Keying. All per-machine parameters key on the machine-configuration name (ROBOTERPROZESSDATEN.MASCHINE_KONF_NAME, PROZESSDATEN.(MASCHINE_KONF_NAME, USERKENNUNG), NC_VOREINSTELLUNG.(Maschinenname, Userkennung)); the robot motion tables key on (Maschine, Bezeichnung). See [[16.3 - Cell7000 — Machine & Cell Configuration]] FR-CELL-CFG-001.

Caveat. Many coded (int) fields are enumerations whose value→meaning tables (Bend.ENUMWERTE, checks.tsf_CheckBendEnums) are not enumerated here; those are flagged (enum).

  DEF --> ENG
  RG -. Referenznummer .-> AUT
  AUT --> FMT
  PR --> FMT
  FMT --> LIM
  TPL --> ENG
  VOR --> ENG
  UN --> ENG
  ENG --> OUT
  • Machine-config name is the spine: it ties ROBOTERPROZESSDATEN, PROZESSDATEN, NC_VOREINSTELLUNG and the cell layout to one Cell 7000.
  • ROBOTGESCHWINDIGKEIT.Referenznummer and ROBOTPOSITION.Bezeichnung are the named handles the NC emits to pick a motion profile / pose.
  • NC_FORMATE.AUS1_NUMMER ↔ the $n placeholders in NC_SATZ is the only place the schema reveals NC field structure — but the template rows themselves are runtime data.
  • FlagBendprogramNew bit 4 + RobotIF*/TransferIFPfadname are the switches that make the Cell 7000 automation/bncx output happen and route it.
  • Units (EINHEIT_NC_TEXT, decimal shift, ST_AUTO_INCH) and crowning (BOMB_EINSTELLWERTE) are applied to the emitted numeric values.

11. Open questions

  1. bncx element layout — not derivable from the source (compiled). A sample .bncx (B06) or its XSD is needed for a true field-by-field map.
  2. Units are inferred throughout; the schema states none. Confirm mm / mm·s⁻¹ / deg against the post-processor.
  3. Enum decodings — X_OEFFNUNGSCODE, ABSTAPELOPTIONEN, MESSVORGABE, FlagRobotInterface, FlagTransfer, BAHNBERECHNUNGSMETHODE, PUNKTBERECHNUNGSART, KoordSystem, KRAFT_EINHEIT etc. resolve against Bend.ENUMWERTE / tsf_CheckBendEnums, not enumerated here.
  4. Actual template rows (NC_SATZ, NC_FORMATE formats) are data, absent from the DDL; the concrete $-placeholder set per controller is unknown from source.
  5. AbstandFingerURueckzug / RollBend authoritative semantics live in the internal PDFs cited by PROZESSDATEN (not in the snapshot).
