Cell7000 Detail — Bend Automation Data Model (Reference)

Non-normative companion. A catalogue of the Bend and BendGripperConf database tables that constitute the bend/cell technology and automation model, with one-line purposes, origin, and the document that specifies each. Derived from static analysis of the SQL schema; treat as a map, not an authoritative spec.

How to read this reference

The bending technology and automation model lives in two SQL schemas (both present in Databases/SQLServerDatabase/Tables/ and mirrored in Databases_SQL_2019/DatabaseStructure/TruTopsMaster/Tables/, differing only in collation and GRANTs):

  • Bend — ~101 tables (plus the 13 in BendGripperConf below, giving ~114 bend tables in total), almost all migrated from the ToPs 600 bend database (extended property MS_SSMA_SOURCE = T600_V100.*). A handful carry no SSMA source and are natively-authored (newer) TruTops tables — flagged [native] below.
  • BendGripperConf — 13 natively-authored tables (no SSMA source): the modern UUID-based gripper configurator.

Cell 7000 grounding. Only three tables carry a literal "Cell 7000"/"BendMaster" string: Bend.ROBOTERPROZESSDATEN (FahrenBalkenSimultanBM "Speziell für Cell7000"; table doc "…Defaults für den BendMaster"), Bend.PROZESSDATEN (AbstandFingerURueckzug "Besonderheit der Cell 7000"), and BendGripperConf.GRIPPER (HandlingSystemTypeID "Typ des Bendmasters"). Everywhere else the Cell 7000 relationship is structural/inferred — the Cell 7000 is one instantiation of this generic ToPs 600 automation model.

Referential integrity. Real foreign keys are relatively rare (most are in the ENTNAHMESTATION family, the gripper carrier→element tables, the PARAMETER text/number extensions, and AKF_BENDFACTORS). The majority of cross-table links are name/number strings resolved in application code. Coded integer columns (*ID) resolve against Bend.ENUMWERTE / checks.tsf_CheckBendEnums(...).

6. Bend tool catalogue & factors (context) — see [[16 - FR - Bending (ToPs 600)]] and [[19 - FR - Tools, Machines, Materials & Technology]]

The press-brake tool catalogue and bend-factor tables are the technology backbone already introduced by doc 16 / doc 19. They connect to the automated cell functionally via WerkzeugwechslerFlag (automatic tool-changer suitability, on WZG_OW/GESENK/ZBIEG/FLACH/MA/MA_SCHWENK/HALTER/ADAPTER) and via the *_ATTRIBUTE siblings that carry the grip points, centre of gravity and gripper-groove type the cell's handling uses.

Bend.WZG_MA_SCHWENK Swivel dies (rotating jaws). T600
Bend.WZG_FALZ Hemming rails. T600
Bend.WZG_ZBIEG Z-bend tools. T600
Bend.WZG_SCHWENKBIEGER Swivel-bending units. T600
Bend.WZG_WELLE Bending shafts/rolls. T600
Bend.WZG_FLACH Flat coining/joining tools. T600
Bend.WZG_SCHARNIER Hinge-forming tools. T600
Bend.WZG_ADAPTER / WZG_HALTER / WZG_AUFNAHME Adapters / holders / machine-side receivers. T600
Bend.WZG_TABELLEN Catalogue table registry (UI/search). T600

7. Data-quality caveats (consolidated)

The following are transcribed verbatim from the source metadata and should not be relied upon where they conflict with the column name:

  • Bend.FOERDERER — PositionX/Y/Z descriptions are cross-wired ("Position kart. X/Y/Z" shifted).
  • Bend.WZG_AUSLEGER — Breite/Hoehe both described "Länge des Auslegers".
  • Bend.WZG_PRATZENPOSITION.Typ — described "Bezeichnung des Saugers" (it is the claw designation).
  • Bend.WZG_MESS_BEREICHE — the "Bereich N" band min/max descriptions mislabel the band index; MinWzgRadius/MaxWzgRadius described as "…Festigkeit".
  • Bend.WZG_WENDESTATION.Typ — described "Bezeichnung des Foerderers".
  • Bend.PARAMETER_ZAHL USE_MIN/USE_MAX — descriptions appear swapped; PARAMETER_UNIT_NUMMER description copied from PARAMETER.PARAMETER_NUMMER.
  • Index naming bugs — e.g. WZG_WELLE$GruppeID indexes LageID; WZG_SCHARNIER$MotnageID (typo) indexes MontageID; several NC_AUSGABE_* index names ($NC_MATYP_IDX, $NC_MANAME_IDX) are vestigial.
  • Reserved columns — NC_ST_VERSION_MIN/MAX, NC_NUMMER, NC_ZEIT, AUS1_FAKTOR documented "für die Zukunft" (reserved/inert).
