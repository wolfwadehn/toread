Cell7000 — Overview

Reverse-engineered orientation page — derived from static analysis of legacy source, NOT an authoritative specification. This is the entry point to the Cell7000 detailed sub-suite (Tier-2 detail refining [[16 - FR - Bending (ToPs 600)]]).

1. What the TruBend Cell 7000 is

The TruBend Cell 7000 is a TRUMPF automated press-brake bending cell: a press brake plus a handling robot ("BendMaster") that loads raw blanks, threads the part into the tool gap, holds/repositions it through the bend sequence, re-grips it as needed, measures bend angles, and stacks or conveys the finished parts — running unattended. Its role in the TruTops offline programming world is to be programmed and simulated offline: TruTops (via the ToPs 600 bend application) produces the press NC program and the coordinated automation/robot program for the cell.

Within this reverse-engineered SRS, the Cell 7000 is important precisely because it is where the bending automation model is fully expressed — grippers, regripping, stations, robot motion, and a second (automation) NC stream — even though most of that model is inherited generic ToPs 600 data that the Cell 7000 instantiates.

2. Evidence boundary (read this first)

This sub-suite is reconstructed from a May-2024 source snapshot with two important limits:

  1. The behaviour is delegated to compiled code. There is no readable C++ in this snapshot that generates bending NC, computes bend sequence, drives robot motion, or does press-brake collision. The bend/automation application is a separate, compiled program (ToPs 600 / BendAPI / "BendMaster"), driven headlessly through a single generic AutomationCommand(AutomationData: string) over .NET Remoting. The C++ that mentions "bending" is exclusively CAD flat-pattern unfolding (Abkantfaktor) math. See [[16.1 - Bending — NC Code Generation]] (FR-BEND-NC-017) and [[30 - External Interface Requirements]].

  2. What IS reverse-engineerable is the data contract. The Bend SQL schema (migrated from the ToPs 600 database T600_V100) plus the newer BendGripperConf schema fully parameterise the cell: NC output templates, robot process defaults, robot dynamics/positions, gripper/handling tooling, regripping rules, stations, pallets and conveyors. Many tables carry German MS_Description documentation strings that are the primary evidence used here.

  3. "Cell 7000" is named in only three tables. Bend.ROBOTERPROZESSDATEN (FahrenBalkenSimultanBM "Speziell für Cell7000"; the table defines "all defaults for the BendMaster"), Bend.PROZESSDATEN (AbstandFingerURueckzug "Besonderheit der Cell 7000", citing internal PDFs AnschlagpositionenCell7000.pdf / ZusatzdatenRollBend.pdf), and BendGripperConf.GRIPPER (HandlingSystemTypeID "Typ des Bendmasters"). Everywhere else the Cell 7000 relationship is structural/inferred — it is one instantiation of the generic ToPs 600 automation model. Requirements that rest on inference are marked (inferred).

A configured machine ([[16.3 - Cell7000 — Machine & Cell Configuration]]) resolves to a cell configuration of components. The BendMaster defaults and press process defaults ([[16.4 - Cell7000 — Robot, Process & Motion Data]]) parameterise handling and bending. The robot picks/holds the part with a gripper ([[16.5 - Cell7000 — Gripper & Handling Tooling]]) and, between bends, uses a regrip console and stations ([[16.6 - Cell7000 — Regripping, Stations & Part Flow]]) to re-orient, measure and stack it. The compiled runtime turns all of this into a press NC program and an automation/robot program using the NC output model ([[16.1 - Bending — NC Code Generation]]).

5. Key domain terms (Cell 7000 specific)

Defined here and cross-referenced from [[04 - Domain Model & Glossary]]:

  • BendMaster — the bending-cell handling robot; its defaults are Bend.ROBOTERPROZESSDATEN.
  • LoadMaster — the loading robot/system the BendMaster must avoid (SafetyMinZPos).
  • Umgreifen (regripping) — laying the part on a console to change grip/orientation between bends.
  • Einfädeln / Ausfädeln (thread-in / thread-out) — inserting/withdrawing the part into/out of the tool gap; the Cell 7000 can travel the BendMaster simultaneously with the beam (FahrenBalkenSimultanBM).
  • Durchleuchtstation (transillumination station) — a backlight table for part recognition/measurement (DURCHLEUCHTTISCH, DURCHLEUCHTEN_FLAG).
  • Wendestation (turning station) — flips/re-orients the part.
  • Entnahmestation (unload station) — camera- and thickness-measurement-equipped part removal with segmented/sloped system pallets.
  • KemroK2 — the automation controller (Keba KeMotion family) targeted by the automation NC stream.
  • RollBend — referenced only in an internal PDF filename (ZusatzdatenRollBend.pdf); no dedicated schema object; relationship to the Cell 7000 unresolved.

6. Open questions (sub-suite level)

  • Which MASCH_CELL component set, HANDLING_SYSTEM_TYPE row and station Typ values specifically denote a TruBend Cell 7000 (runtime data, not in the DDL).
  • The grammar of the AutomationData payload and the $-placeholder NC syntax (compiled/undocumented).
  • Whether BendGripperConf supersedes the legacy Bend.WZG_* grippers for Cell-7000-class machines.
  • The authoritative Cell 7000 semantics behind AbstandFingerURueckzug / RollBend (internal PDFs, not in the snapshot).
