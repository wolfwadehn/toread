Cell7000 Detail — Gripper & Handling Tooling

Reverse-engineered requirement draft — derived from static analysis of legacy source, NOT an authoritative specification. Treat SHALL statements as reconstructed intent. Tier-2 detail refining [[16 - FR - Bending (ToPs 600)]]; not added to the 603-item register.

1. Purpose & Scope

This document specifies the robot end-effector (gripper) tooling the bending cell uses to pick, hold, separate, weigh, turn and re-grip sheet-metal parts, and the in-process angle-measuring tooling. Two generations of model coexist in the schema:

  1. Legacy Bend.WZG_* gripper tables — SSMA-migrated from ToPs 600 (T600_V100): typed carrier/plate → mounted-element tables for clamps, suction plates, magnet plates, multi-grippers, booms, and angle-measuring discs.
  2. BendGripperConf configurator schema — a newer, natively-authored (no MS_SSMA_SOURCE), UUID-based model that builds a gripper as an assembly tree of library components bound to a handling-system type ("Typ des Bendmasters").

Provenance & evidence note. No literal "Cell7000" appears in either model. The only "BendMaster" reference is BendGripperConf.GRIPPER.HandlingSystemTypeID ("Foreign Key auf Handlingsystem Type (Typ des Bendmasters)"), which is the natural binding point where a BendMaster/Cell 7000 handling system is enumerated (as data rows in HANDLING_SYSTEM_TYPE, absent from the DDL). All gripper geometry here is an input to the cell's robot motion/collision planning — it constrains how a part can be gripped and re-gripped — and is not itself bend-by-bend NC. Several MS_Descriptions in the legacy tables are copy-paste artefacts (noted inline); rely on column names where they conflict.

2. Capability Overview

  • Model a gripper clamp (Greifzange) with a TCP pose, turntable, payload and opening, and its claw positions (Pratzenposition) built from reusable claw definitions (Greifpratze).
  • Model a suction gripper: a suction plate (Saugerplatte) carrying suction-cup placements (Sauger) drawn from a cup-type catalogue (Sauger_Typ), with vacuum timings, pressure monitoring and valve control.
  • Model a magnet gripper: a magnet plate (Magnetplatte) carrying magnet placements (Magnet) with pickup/release hold times.
  • Model a multi-gripper (Multigreifer): a base carrying several swivel arms (MultigreiferArm), each with an inner and outer telescoping profile and embedded suction cups.
  • Model a boom/cantilever (Ausleger) that extends a gripper's reach, with generic typed parameters.
  • Classify each vacuum element by task and type (vacuum cup / separating cylinder / weighing module / magnet cup / sheet sensor) and hold force.
  • Model in-process angle measurement tooling: feeler discs (Tastscheiben) and measuring-capability ranges/legs (Mess-Bereiche / Mess-Schenkel) paired with an upper-tool type.
  • Provide the BendGripperConf configurator: assemble a gripper from a component library (robot coupling, assembly bracket, vacuum/vibrate/peel/extrude components, profiles) as a UUID-referenced structure tree with per-node 3D transforms and ACIS .sat geometry, bound to a handling-system type, with owner/lock/change governance.

4. Functional Requirements

FR-CELL-GRP-001 — Model a gripper clamp with TCP pose

  • Requirement: The system SHALL model a gripper clamp with its bounding geometry, turntable, maximum payload, opening width and a full tool-centre-point pose (position + orientation about X/Y/Z).
  • Priority: Conditional
  • Rationale: The TCP pose and geometry define the tool frame the robot path planner uses; payload/opening gate part suitability.
  • Source: Databases/SQLServerDatabase/Tables/Bend.WZG_GREIFZANGE.sql (Tcp{X,Y,Z,Alpha,Beta,Gamma}, Oeffnungsweite, TraglastMax, HoeheDrehteller/RadiusDrehteller, MitAusleger/AuslegerName).
  • Verification: Inspection.

FR-CELL-GRP-002 — Model gripper claws and their positions

  • Requirement: The system SHALL define reusable gripper-claw (Greifpratze) geometry — jaw opening, contact-surface footprint, movement interval — and place numbered claws at X/Y/Z positions on a clamp, recording upper/lower and left/right placement.
  • Priority: Conditional
  • Rationale: A clamp grips through positioned claws; the claw definition is reused across positions.
  • Source: Bend.WZG_GREIFPRATZE.sql (Maulweite, Laschenhoehe, Auflagenflaeche*, Bewegungsintervall); Bend.WZG_PRATZENPOSITION.sql (Pratzennummer, Pratzenlage, PositionX/Y/Z; FK ID → WZG_GREIFZANGE.ID ON DELETE CASCADE).
  • Verification: Inspection.

FR-CELL-GRP-003 — Model a suction plate carrying suction cups

  • Requirement: The system SHALL model a suction gripper as a suction plate carrying numbered suction-cup placements, each cup positioned in X/Y, assigned to a vacuum group and a task (grip, or grip + separate).
  • Priority: Conditional
  • Rationale: Vacuum gripping of sheet is the primary handling method; cups are grouped for common valve switching.
  • Source: Bend.WZG_SAUGERPLATTE.sql (carrier geometry, MittenVersatzX/Y, payload, material/strength range); Bend.WZG_SAUGER.sql (Saugernummer, PositionX/Y, Gruppennummer, Aufgaben; FK ID → WZG_SAUGERPLATTE.ID ON DELETE CASCADE; Typ → WZG_SAUGER_TYP.Typ).
  • Verification: Inspection.

FR-CELL-GRP-004 — Suction-cup type catalogue with function classification and holding force

  • Requirement: The system SHALL maintain a suction-cup type catalogue classifying each type by function (unknown, vacuum cup, separating cylinder, weighing module, magnet cup, sheet sensor) with effective diameter, height (free and suctioned), holding force, 3D drawing and a UUID for the configurator.
  • Priority: Conditional
  • Rationale: The cup type determines suction/sensing behaviour and holding force used in grip-feasibility and NC action selection.
  • Source: Bend.WZG_SAUGER_TYP.sql (Saugertyp "0=Unknown, 1=Vakuumsauger, 2=Separierzylinder, 3=Waegemodul, 4=Magnetsauger, 5=Blechsensor", Durchmesser, Hoehe, HoeheAngesaugt, HalteKraft, Uuid).
  • Verification: Inspection.

FR-CELL-GRP-005 — Vacuum timing, pressure monitoring and valve control

  • Requirement: The system SHALL hold, per suction gripper, the vacuum timing parameters (suction time, blow-off minimum and hold-release times), a separation time and type, a pressure-monitoring flag and a valve-control flag.
  • Priority: Conditional
  • Rationale: Timing and control parameters become dwell/valve commands in the generated automation NC (pick, separate, release).
  • Source: Bend.WZG_SAUGERPLATTE.sql (Ansaugzeit, AusblaszeitKeinVakuum, AusblaszeitKeinHalten, Separierungszeit, Separierungstyp, Druckueberwachung, MitVentilsteuerung).
  • Verification: Inspection.

FR-CELL-GRP-006 — Model a magnet gripper

  • Requirement: The system SHALL model a magnet gripper as a magnet plate carrying numbered magnet placements, each positioned in X/Y with a task, and hold pickup/release hold times.
  • Priority: Conditional
  • Rationale: Magnet gripping is an alternative to vacuum; hold times govern activation timing in NC.
  • Source: Bend.WZG_MAGNETPLATTE.sql (Separierungstyp/-zeit, HaltezeitAufnahme, HaltezeitLoesen); Bend.WZG_MAGNET.sql (Magnetnummer, PositionX/Y, Aufgaben, HaltezeitGreifen, HaltezeitLoslassen; FK ID → WZG_MAGNETPLATTE.ID ON DELETE CASCADE).
  • Verification: Inspection.

FR-CELL-GRP-007 — Model a multi-gripper with swivel arms

  • Requirement: The system SHALL model a multi-gripper as a base carrying swivel arms, each arm defined by its rotation axis and angle limits on the base, an inner and outer telescoping profile (dimensions + min/max translation), and an embedded inner and outer suction cup (type, task, group, X/Y/Z offset).
  • Priority: Conditional
  • Rationale: Multi-grippers reconfigure to different part sizes; the arm kinematics and cup layout are needed for grip planning and collision.
  • Source: Bend.WZG_MULTIGREIFER.sql (carrier); Bend.WZG_MULTIGREIFER_ARM.sql (DrehachseX/Y, Drehwinkel{Min,Max}, inner/outer profile dims + Min/MaxTransl*, SaugerInnen_*/SaugerAussen_* referencing WZG_SAUGER_TYP.Typ; FK ID → WZG_MULTIGREIFER.ID ON DELETE CASCADE).
  • Verification: Inspection.

FR-CELL-GRP-008 — Model a boom/cantilever with generic parameters

  • Requirement: The system SHALL model a boom/cantilever that a clamp or suction plate mounts onto (referenced by name), with its geometry, turntable, weight and payload, and an extensible typed key/value parameter set.
  • Priority: Optional
  • Rationale: A boom extends the robot's reach; grippers declare boom attachment by name.
  • Source: Bend.WZG_AUSLEGER.sql (Klasse, geometry, TraglastMax); Bend.WZG_AUSLEGER_PARAMETER.sql (ParamName/VReal/VLong/VString; FK ID → WZG_AUSLEGER.ID ON DELETE CASCADE); referenced by WZG_GREIFZANGE.AuslegerName/WZG_SAUGERPLATTE.AuslegerName.
  • Verification: Inspection.

FR-CELL-GRP-009 — Gate gripper assignment by payload, suitability and workpiece strength

  • Requirement: The system SHALL gate whether a gripper may be assigned to a part using maximum payload, a suitability flag, the cup holding force and the workpiece material/strength range.
  • Priority: Conditional
  • Rationale: A gripper must be able to lift and hold the part; these limits are feasibility preconditions checked before motion/NC generation.
  • Source: Bend.WZG_SAUGERPLATTE.sql/Bend.WZG_MAGNETPLATTE.sql/Bend.WZG_MULTIGREIFER.sql (TraglastMax, Eignung, WerkstoffID, FestigkeitVon/FestigkeitBis); Bend.WZG_SAUGER_TYP.sql (HalteKraft); with Bend.ROBOTERPROZESSDATEN.FAKTOR_SAUGKRAFT_PRUEFUNG (see [[16.4 - Cell7000 — Robot, Process & Motion Data]]).
  • Verification: Analysis.

FR-CELL-GRP-010 — Model in-process angle-measuring tooling

  • Requirement: The system SHALL model in-process bend-angle measuring tooling: feeler discs (Tastscheiben) with form, radius/thickness and matching upper-tool type, and a measuring-capability window (per upper-tool + disc combination) giving radius range, "can-press-shut" flag, and up to three bands of (tensile-strength, sheet-thickness min/max, measurable-angle min/max) plus the minimum flange length per measuring angle.
  • Priority: Conditional
  • Rationale: Whether and how a bend can be measured (and thus whether angle-correction steps appear in the NC) depends on this tooling and its capability window.
  • Source: Bend.WZG_TASTSCHEIBEN.sql (MessformID, Messwert, Scheibendicke, Eckradius, OwTyp, TypMesswerkzeug); Bend.WZG_MESS_BEREICHE.sql (OwTyp, TypScheibe1/2, MinWzgRadius/MaxWzgRadius, ZudrueckFlag, Min/MaxBlechdicke{1,2,3}, Min/MaxMesswinkel{1,2,3}, MaxZugfestigkeit{1,2,3}); Bend.WZG_MESS_SCHENKEL.sql (Messwinkel, MinSchenkellaenge; FK ID → WZG_MESS_BEREICHE.ID ON DELETE CASCADE).
  • Verification: Inspection.

FR-CELL-GRP-011 — Provide a component-based gripper configurator

  • Requirement: The system SHALL provide a gripper configurator in which a gripper is a root record naming the gripper, binding it to a handling-system type, and pointing at the root node(s) of an assembly structure tree; availability (physical vs. virtual) and editability flags SHALL be recorded.
  • Priority: Conditional
  • Rationale: Modern cells configure a gripper from components rather than selecting a fixed catalogue gripper; the configurator is a distinct, newer subsystem.
  • Source: Databases/SQLServerDatabase/Tables/BendGripperConf.GRIPPER.sql (Name, HandlingSystemTypeID, ConstructedRoot/IntegratedRoot, IsAvailable, IsChangeable, Position_*; FK HandlingSystemTypeID → HANDLING_SYSTEM_TYPE.M_id; no MS_SSMA_SOURCE).
  • Verification: Demonstration.

FR-CELL-GRP-012 — Represent the gripper as an assembly structure tree

  • Requirement: The system SHALL represent a configured gripper as a tree of structure items, each with its own UUID and a parent UUID, optionally referencing a library component or an integrated-body geometry file, and carrying a full 3D transform payload (position + matrix/vector/scalar/boolean blocks) that places the component in the cell frame.
  • Priority: Conditional
  • Rationale: A composed gripper is a hierarchy of positioned components; the transform payload supplies the kinematic placement the cell needs for simulation/collision.
  • Source: BendGripperConf.GRIPPER_STRUCT_ITEM.sql (StructID, ParentStructID, ComponentID "ID auf Bibliothekselement, Profil, Sauger etc.", IsIntegratedItem, SatPath "Referenz auf Acsis FileName", Position_*, Matrix{1,2,3}_*, Vector{1,2,3}_*, Double{1,2,3}, Bool{1,2,3}_*; soft UUID joins, no DB FKs).
  • Verification: Inspection.

FR-CELL-GRP-013 — Maintain the gripper component library

  • Requirement: The system SHALL maintain a library of gripper components — robot coupling, assembly bracket, vacuum, vibrate, peel and extrude components, and structural profiles — each identified by a UUID, with a name, ACIS geometry reference, display colour, order number, and a translatable description with a data-provider (customer/TRUMPF) marker.
  • Priority: Conditional
  • Rationale: Components are the reusable building blocks of a configured gripper; the shared record shape supports a common catalogue.
  • Source: BendGripperConf.ROBOT_COUPLING.sql, ASSEMBLY_BRACKET.sql, VACUUM_COMPONENT.sql, VIBRATE_COMPONENT.sql, PEEL_COMPONENT.sql, EXTRUDE_COMPONENT.sql, PROFILE.sql (shared columns Uuid, Name, SatPath, Color, OrderNo, Description/Description_Textnr, TRUMPF_DataProvider; Uuid ← GRIPPER_STRUCT_ITEM.ComponentID).
  • Verification: Inspection.

FR-CELL-GRP-014 — Bind a gripper to a handling-system (BendMaster) type

  • Requirement: The system SHALL enumerate handling-system (robot/cell) types and bind each configured gripper to exactly one such type via a foreign key.
  • Priority: Conditional
  • Rationale: A gripper is built for a specific machine/cell model; this binding scopes gripper applicability to a handling system (the "Typ des Bendmasters", where a Cell 7000 entry would be enumerated).
  • Source: BendGripperConf.HANDLING_SYSTEM_TYPE.sql (Name "Name des Roboters", Beschreibung); BendGripperConf.GRIPPER.HandlingSystemTypeID "Foreign Key auf Handlingsystem Type (Typ des Bendmasters)" (FK, default 1).
  • Verification: Inspection.

FR-CELL-GRP-015 — Configurator governance (owner, locking, change tracking)

  • Requirement: The configurator SHALL record the cell owner/operator (with address and logo for reporting), enforce per-table pessimistic record locking during editing, and maintain a per-table change counter for cache invalidation.
  • Priority: Optional
  • Rationale: Multi-user editing of a shared gripper library needs ownership metadata, locking and change detection.
  • Source: BendGripperConf.OWNER.sql, BendGripperConf.LOCK.sql (Table_id, Time, Record_id, User_id), BendGripperConf.CHANGES.sql (Table_id, Check_id).
  • Verification: Inspection.

5. External Interfaces (area-specific)

  • ToPs 600 bend database — legacy Bend.WZG_* gripper/measuring tables. See [[16.7 - Cell7000 — Bend Automation Data Model (Reference)]].
  • BendGripperConf schema — the newer configurator (GRIPPER, GRIPPER_STRUCT_ITEM, component libraries, HANDLING_SYSTEM_TYPE, OWNER/LOCK/CHANGES).
  • ACIS geometry files — SatPath columns reference external ACIS .sat solid models used for display and collision.
  • Robot process defaults — Bend.ROBOTERPROZESSDATEN.GREIFERTYP/GREIFERNAME selects the active gripper (see [[16.4 - Cell7000 — Robot, Process & Motion Data]]).
  • Upper-tool catalogue — angle-measuring tooling joins the bend upper tools via OwTyp; upper-tool grip points / centre of gravity live in WZG_OW_ATTRIBUTE (see [[16.7 - Cell7000 — Bend Automation Data Model (Reference)]]).
  • Text/enum infrastructure — *_Textnr → TruTops text table (Alte_tab = 62); TRUMPF_DataProvider → CONST_TRANSLAT (CO_GROUP = 179).

6. Assumptions & Constraints

  • A1. Gripper geometry constrains robot motion/collision planning; it is an input to NC generation, not NC itself. (inferred)
  • A2. The BendGripperConf configurator and the legacy Bend.WZG_* gripper tables model overlapping domains but are separate subsystems with no cross-schema FKs; BendGripperConf is the newer (native, UUID-based) model, likely a generation change for newer cells. (inferred)
  • C1. WZG_TMP_* gripper tables are transient working copies used during interactive configuration and are not authoritative masters.
  • C2. Several legacy MS_Descriptions are copy-paste artefacts (e.g. WZG_AUSLEGER.Breite/Hoehe = "Länge des Auslegers"; WZG_PRATZENPOSITION.Typ = "Bezeichnung des Saugers"; WZG_MESS_BEREICHE band descriptions mislabel the Bereich index); column names govern.

7. Open Questions & Ambiguities

  1. No product tagging. Nothing ties a gripper to the TruBend Cell 7000 except (indirectly) HANDLING_SYSTEM_TYPE; the actual rows (a "Cell 7000"/"BendMaster" entry and its id) are runtime data absent from the DDL.
  2. Configurator vs. legacy. Whether BendGripperConf supersedes the Bend.WZG_* gripper tables for Cell-7000-class machines, and whether both are populated concurrently, is unresolved.
  3. GRIPPER_STRUCT_ITEM transform blocks — the per-block semantics (mount frame vs. TCP vs. gripping-zone envelope) of the three Matrix/Vector/Double/Bool blocks are placeholder-documented and require the configurator client code.
  4. Polymorphic ComponentID — how the client resolves which library table a ComponentID UUID belongs to (no type discriminator column) is not in the schema.
  5. Enum code catalogs. Aufgaben, Separierungstyp, MitAusleger (default 5), MitVentilsteuerung (default 4), Eignung (default 3), Pratzenlage, TypMesswerkzeug and the WZG_TASTSCHEIBEN *ID fields resolve against separate description/enum tables not covered here.
