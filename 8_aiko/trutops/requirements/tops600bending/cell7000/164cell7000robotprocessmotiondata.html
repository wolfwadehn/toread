Cell7000 Detail — Robot, Process & Motion Data

Reverse-engineered requirement draft — derived from static analysis of legacy source, NOT an authoritative specification. Treat SHALL statements as reconstructed intent. Tier-2 detail refining [[16 - FR - Bending (ToPs 600)]]; not added to the 603-item register.

1. Purpose & Scope

This document specifies the BendMaster robot process defaults and the press-brake process defaults that parameterise an automated bending cell, plus the robot motion data (named positions, speed/accel/decel/jerk profiles, legacy speed overrides). It is the most Cell 7000-specific part of the bending sub-suite: two of its tables carry the only verbatim "Cell 7000"/"BendMaster" documentation in the whole schema.

Provenance & evidence note. Bend.ROBOTERPROZESSDATEN is a native TruTops table (it has no MS_SSMA_SOURCE) whose table comment reads "Werte in dieser Tabelle definieren alle Defaults für den BendMaster"; it contains the Cell 7000-specific column FahrenBalkenSimultanBM. Bend.PROZESSDATEN (migrated from T600_V100) contains the column AbstandFingerURueckzug whose comment names "Besonderheit der Cell 7000" and cites two internal PDFs (20160401_TW544ek_AnschlagpositionenCell7000.pdf, ..._ZusatzdatenRollBend.pdf). These are defaults consumed by the compiled ToPs 600 / BendMaster runtime; the motion/handling planner that turns them into robot NC is not readable C++ in this snapshot (see [[16.1 - Bending — NC Code Generation]] FR-BEND-NC-017). Coded columns (enums) and units are largely undocumented in the schema — see Open Questions.

2. Capability Overview

  • Hold all BendMaster defaults per machine configuration in one row (ROBOTERPROZESSDATEN): gripper selection, camera/sensor recognition distances, beam-opening and thread-in/out clearances, load/unload stations and conveyors, interlayer handling, destacking, regrip geometry, safety Z-position and simulation/collision options.
  • Support a Cell 7000-specific simultaneous beam+robot travel mode during thread-in/out.
  • Hold the press-brake process defaults per machine and user (PROZESSDATEN): force/pressure, beam speeds and dwell times, backgauge (Anschlag) positioning and priorities, angle measurement, hemming (Falzen), support (Auflage) positions, per-axis speeds and automated thread-in finger distances (incl. the Cell 7000 special).
  • Hold named robot positions (ROBOTPOSITION), full dynamics profiles with jerk (ROBOTGESCHWINDIGKEIT), and a legacy percentage-speed override (ROBOTERDYNAMIKDATEN), each selectable by name and (for dynamics) by an NC reference number.

3. Domain Entities

4. Functional Requirements

FR-CELL-ROB-001 — Hold all BendMaster process defaults per machine

  • Requirement: The system SHALL hold, in one record per machine configuration, the default handling/process parameters for the BendMaster robot.
  • Priority: Essential
  • Rationale: The cell's automated behaviour is driven by a coherent set of per-machine defaults; the table's own comment states it "defines all defaults for the BendMaster".
  • Source: Databases/SQLServerDatabase/Tables/Bend.ROBOTERPROZESSDATEN.sql (table MS_Description "Werte in dieser Tabelle definieren alle Defaults für den BendMaster"; PK on MASCHINE_KONF_NAME; native table, no MS_SSMA_SOURCE).
  • Verification: Inspection.

FR-CELL-ROB-002 — Cell 7000 simultaneous beam/robot travel during thread-in/out

  • Requirement: Where the machine is a Cell 7000, the system SHALL support a mode in which the BendMaster travels simultaneously with the press-beam motion during thread-in and thread-out.
  • Priority: Conditional
  • Rationale: Coordinated simultaneous beam+robot motion shortens cycle time and is called out as a Cell 7000 speciality.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (FahrenBalkenSimultanBM "Kennflag, ob der BendMaster beim Ein- und Ausfädeln immer zeitgleich zur Bewegung des Pressbalkens gefahren werden soll. (Speziell für Cell7000)"; default 1).
  • Verification: Test.

FR-CELL-ROB-003 — Gripper selection defaults

  • Requirement: The system SHALL record the default gripper type and gripper name used by the BendMaster.
  • Priority: Essential
  • Rationale: The robot must know which end-effector it carries to plan gripping and collision.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (GREIFERTYP, GREIFERNAME; joins gripper configuration — see [[16.5 - Cell7000 — Gripper & Handling Tooling]]).
  • Verification: Inspection.

FR-CELL-ROB-004 — Camera and sensor recognition distances

  • Requirement: The system SHALL record the distances at which the cell's camera performs coarse and fine part recognition, and the distance to the backgauge sensor.
  • Priority: Conditional
  • Rationale: Vision-based part recognition and sensor probing require configured stand-off distances.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (ABSTAND_KAMERA_GROB "Abstand der Kamera zur Groberkennung", ABSTAND_KAMERA_FEIN "…Feinerkennung", ABSTAND_SENSOR "Abstand zum Anschlagsensor").
  • Verification: Inspection.

FR-CELL-ROB-005 — Beam-opening and thread-in/out clearances

  • Requirement: The system SHALL record the minimum beam opening and, for bumping bends where no thread-out is needed, the beam-opening travel between successive bumping bends; and SHALL record the thread-out clearance of the bend's lowest point to the die top.
  • Priority: Conditional
  • Rationale: Beam opening governs whether/how far the part must be withdrawn between bends; too small collides, too large wastes time.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (BALKENOEFFNUNG "Minimale Balkenoeffnung", BalkenoeffnungOhneAusfaedeln [bumping], AbstandZurMatrizeAusfaedeln "Abstand des unteren Punktes der Biegung zur Matrizenoberseite beim Ausfädeln").
  • Verification: Inspection.

FR-CELL-ROB-006 — Load and unload station configuration (incl. alternate unload)

  • Requirement: The system SHALL record the type, name, position and rotation of the load and unload stations, and SHALL support an alternate (second) unload station, each with its own type/name/position/rotation and invert-stacking flag.
  • Priority: Essential
  • Rationale: Automated loading/unloading needs deterministic station identity, placement and orientation; a second unload station supports sorting or overflow.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (LOADTYP, LOADSTATION, LOAD_ROTATE, LOAD_POSITION_X/Y; UNLOADTYP, UNLOADSTATION, UNLOAD_ROTATE, UNLOAD_POSITION_X/Y, ABLAGEINVERTIERT; alternate UNLOADTYP2, UNLOADSTATION2, UNLOAD_ROTATE2, UNLOAD_POSITION_X2/Y2, ABLAGEINVERTIERT2). See [[16.6 - Cell7000 — Regripping, Stations & Part Flow]].
  • Verification: Demonstration.

FR-CELL-ROB-007 — Load/unload conveyor configuration

  • Requirement: The system SHALL record whether a conveyor is present at loading and at unloading (including the alternate unload) and the name of each conveyor.
  • Priority: Conditional
  • Rationale: Conveyor-fed loading/unloading changes the pick/place logic and must be modelled.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (HAVE_LOAD_CONVEYOR, LOAD_CONVEYOR; HAVE_UNLOAD_CONVEYOR, UNLOAD_CONVEYOR; HAVE_UNLOAD_CONVEYOR2, UNLOAD_CONVEYOR2). See Bend.FOERDERER in [[16.6 - Cell7000 — Regripping, Stations & Part Flow]].
  • Verification: Inspection.

FR-CELL-ROB-008 — Interlayer (Zwischenlage) handling

  • Requirement: Where finished parts are stacked with separator sheets, the system SHALL record the interlayer designation, its pickup source (type, name, position, rotation) and whether that source stands on a conveyor.
  • Priority: Conditional
  • Rationale: Interleaving protects stacked parts; the cell must pick and place separator sheets from a defined source.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (INTERLAYERNAME, INTERLAYERLOADTYPE, INTERLAYERLOADNAME, INTERLAYERLOADPOSX/Y, INTERLAYERLOADROTATE, INTERLAYERCONVEYER, INTERLAYERCONVEYERNAME). See Bend.ZWISCHENLAGE.
  • Verification: Inspection.

FR-CELL-ROB-009 — Destacking / palletising options

  • Requirement: The system SHALL record destacking options and the palletising direction (inside-out vs. outside-in) for unloading.
  • Priority: Conditional
  • Rationale: How parts are laid into a pallet affects reachability and stack stability.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (ABSTAPELOPTIONEN "Abstapel Optionen"; ABLAGEINVERTIERT/ABLAGEINVERTIERT2 — invert deposit direction on unload: 0 (false) = palletise inside-out, 1 (true) = outside-in).
  • Verification: Inspection.

FR-CELL-ROB-010 — Regripping geometry defaults

  • Requirement: The system SHALL record the clearances governing an automated re-grip: distance after release, distance before gripping, part-avoidance distance during repositioning, distance from the console at the wait position, gripping-pliers stand-off, and whether the gripper re-grips from below to above.
  • Priority: Conditional
  • Rationale: Safe, collision-free re-gripping on a console depends on these configured clearances and the re-grip direction.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (AbstandNachLoslassen, AbstandVorGreifen, AbstandUmfahrenTeil, AbstandTeilZurAblage, DISTANCEGRIPPINGPLIERS, NeugreifenVonOben, UMGREIFTYP, UGSKONFIGURATIONSAENDERN). See [[16.6 - Cell7000 — Regripping, Stations & Part Flow]].
  • Verification: Inspection.

FR-CELL-ROB-011 — Safety Z-position for collision avoidance with the LoadMaster

  • Requirement: The system SHALL provide a default minimum Z-position of the BendMaster linear axis, used during automatic path calculation to reduce the likelihood of collision with the LoadMaster.
  • Priority: Conditional
  • Rationale: In a combined load/bend cell the BendMaster and LoadMaster share space; a safety floor on the linear axis reduces collision risk.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (SafetyMinZPos "…minimale Z-Position der Linearachse des BendMasters … Kollisionswahrscheinlichkeit mit dem LoadMaster niedrig zu halten."; default 600; check >0 not present — value constrained by app).
  • Verification: Analysis.

FR-CELL-ROB-012 — Path- and support-point calculation mode; PTP; reduced collision check

  • Requirement: The system SHALL allow selecting a "safe vs. fast" mode for path calculation and for support-point calculation, enabling PTP motion, and a reduced simulation/collision check when depositing a part.
  • Priority: Conditional
  • Rationale: Operators trade cycle time against safety margin; these switches tune the motion planner and the deposit-time collision check.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (BAHNBERECHNUNGSMETHODE "Art der Bahnberechnung sicher oder schnell", PUNKTBERECHNUNGSART, PTPAKTIVIERUNG, SimuKollPruefReduziert [enum, validated via checks.tsf_CheckBendEnums(...,482)], VerteilPunktZPosGesperrt).
  • Verification: Test.

FR-CELL-ROB-013 — Backgauge free-travel and safeguarding defaults

  • Requirement: The system SHALL record backgauge (Anschlag) safeguarding defaults for the robot process, including the free-travel opening in Y, whether the gauges are always retracted, whether fingers gauge only after thread-in, and the tool-gap opening distance.
  • Priority: Conditional
  • Rationale: Backgauge retraction/gauging timing interacts with automated thread-in and part safety.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (ANSCHLAGOEFFNUNG, FREIFAHRFLAG, AnschlagenNachEinfaedeln, ABSTAND_OEFFNUNG "Abstand zwischen den Werkzeugen", X_OEFFNUNGSCODE, ABSTAND_SEPARIERUNG).
  • Verification: Inspection.

FR-CELL-ROB-014 — Grip-position calculation and part turning

  • Requirement: The system SHALL record grip-position calculation defaults (look-ahead, search direction) and part-turning defaults (turn if first bend is upward, turn angle on the load station).
  • Priority: Conditional
  • Rationale: Choosing where the robot grips and whether/how the part is turned before bending are core automated-planning inputs.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (VORAUSSCHAU_GREIFPOSBERECHNUNG, BERECHNUNGSRICHTUNG_GREIFPOS, TEILWENDE_FLAG, TEILDREHWINKEL, WINKELINKREMENT_BERECHNUNG).
  • Verification: Inspection.

FR-CELL-ROB-015 — Suction-force check and press speed with the BendMaster

  • Requirement: The system SHALL record a suction-force check factor and the press speed used when working with the BendMaster.
  • Priority: Conditional
  • Rationale: Automated handling validates suction force against part weight and runs the press at a coordinated speed.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (FAKTOR_SAUGKRAFT_PRUEFUNG, PRESSGESCHWINDIGKEIT "Pressgeschwindigkeit beim Arbeiten mit BendMaster").
  • Verification: Inspection.

FR-CELL-ROB-016 — Transillumination-station usage flag

  • Requirement: The system SHALL record whether a BendMaster program runs with or without the transillumination (Durchleucht) station.
  • Priority: Conditional
  • Rationale: Programs may or may not include the backlight recognition/measuring step; the flag selects the behaviour and the DURCHLEUCHTTISCH geometry.
  • Source: Bend.ROBOTERPROZESSDATEN.sql (DURCHLEUCHTEN_FLAG "Kennung ob BendMasterprogramm mit/ohne Durchleuchtstation"). See Bend.DURCHLEUCHTTISCH in [[16.3 - Cell7000 — Machine & Cell Configuration]].
  • Verification: Inspection.

FR-CELL-ROB-017 — Hold press-brake process defaults per machine and user

  • Requirement: The system SHALL hold the press-brake process defaults per machine configuration and user, including force/pressure factors and corrections, beam speeds and dwell/relief travel, and general angle/sheet corrections.
  • Priority: Essential
  • Rationale: These defaults parameterise every bend the press performs; they are per-machine and per-operator.
  • Source: Bend.PROZESSDATEN.sql (PK (MASCHINE_KONF_NAME, USERKENNUNG); KRAFT_EINHEIT, FAKTOR_PRAEGEKRAFT, KRAFTFAKTOR_FREIBIEGEN, DRUCKKORREKTUR, DRUCKKORR_PROZENT, DRUCKGESCHWINDIGKEIT, SCHLIESSGESCHWINDIGKEIT, OEFFNUNGSGESCHWINDIGKEIT, ENTSPANNGESCHWINDIGKEIT, DRUCKHALTEZEIT, OEFFNUNGSWEG, ENTSPANNWEG, WINKELKORREKTUR, BLECH_KORREKTUR).
  • Verification: Inspection.

FR-CELL-ROB-018 — Backgauge positioning, priorities and corrections

  • Requirement: The system SHALL hold backgauge positioning defaults, including clamp/open behaviour, per-axis corrections (X1/X2 = left/right stop in Y), stop-selection priorities, step width, R-direction offsets, and Z-before-X approach behaviour.
  • Priority: Conditional
  • Rationale: Accurate, prioritised backgauge positioning is central to bend accuracy and collision avoidance.
  • Source: Bend.PROZESSDATEN.sql (X_OEFFNUNGSCODE, KLEMM_VOR_OEFFNEN, KORREKTUR_X1, KORREKTUR_X2, ANSCHLAG_KLEMMOEFFNUNG, PRIORITAET_ANSCHLAG_1..3, ANSCHLAG_SCHRITTWEITE, ANSCHLAG_POSITION_OFFSET_R_AKTIV, ANSCHLAG_POSITION_OFFSET_R1/R2, ImmerZVorXAnschlagen, ABSTAND_ECKE_ANSCHLAG, ABSTAND_BLECHECKE_ANSCHLAG, NULLKORREKTUR_R_ACHSE/KANTE/FLAECHE).
  • Verification: Inspection.

FR-CELL-ROB-019 — Angle measurement defaults

  • Requirement: The system SHALL hold angle-measurement defaults, including the measuring strategy, overbend prevention (Vorhaltewinkel), measuring interval within a lot, sensor correction and measurable-range limits (min/max angle, min flange, min length).
  • Priority: Conditional
  • Rationale: In-process angle measurement and springback compensation depend on these configured limits and strategy.
  • Source: Bend.PROZESSDATEN.sql (MESSVORGABE [Viel Messen/Viel Lernen/Nie Messen], VORHALTEWINKEL, INTERVALL_WINKELMESSUNG, SENSORKORREKTUR, MESSEN_STANDARD, MESSEN_BIEGEHILFE, MIN_MESS_LAENGE, MIN_MESS_SCHENKEL, MIN_MESS_WINKEL, MAX_MESS_WINKEL, LCB_MIN_SCHENKELLAENGE, LCB_MIN_ABSTAND_TEILKANTE, PrueffaktorSchenkellaenge). See angle-measuring tooling in [[16.5 - Cell7000 — Gripper & Handling Tooling]].
  • Verification: Inspection.

FR-CELL-ROB-020 — Per-axis speeds

  • Requirement: The system SHALL hold per-axis speed defaults for the backgauge and support axes: X1 (positive/negative), X2 (positive/negative), R1, R2 and Z1/Z2.
  • Priority: Conditional
  • Rationale: Axis speeds parameterise motion emitted into the press program and affect cycle time.
  • Source: Bend.PROZESSDATEN.sql (SPEED_X1_POS, SPEED_X1_NEG, SPEED_X2_POS, SPEED_X2_NEG, SPEED_R1, SPEED_R2, SPEED_Z1_Z2).
  • Verification: Inspection.

FR-CELL-ROB-021 — Hemming (Falzen) and Z-bend defaults

  • Requirement: The system SHALL hold hemming defaults (preferred hemming kind, fast-hemming flag, pre-fold angle, closing correction/opening, double-hem max distance) and Z-bend height limits.
  • Priority: Conditional
  • Rationale: Hemming and Z-bends are distinct forming operations with their own default parameters.
  • Source: Bend.PROZESSDATEN.sql (FALZART, FASTHEMMING, FALZWINKEL, KORREKTUR_ZUDRUECKEN, ZUDRUECKOEFFNUNG, MAX_ABSTAND_DOPPELFALZ, MIN_HOEHE_ZBIEGUNG, MAX_HOEHE_ZBIEGUNG).
  • Verification: Inspection.

FR-CELL-ROB-022 — Support (Auflage), tool-list and mute-point defaults

  • Requirement: The system SHALL hold support-arm (Auflage) positions and usage, a default tool list and standard fixture, tool-length flag, and beam mute-point/speed defaults.
  • Priority: Conditional
  • Rationale: Part support during handling, the loaded tool set, and the mute (safe-approach) point are needed for planning and program generation.
  • Source: Bend.PROZESSDATEN.sql (ARBEITEN_MIT_AUFLAGE, AUFLAGE_LINKS_X/Y, AUFLAGE_RECHTS_X/Y, WERKZEUGLISTE, STANDARD_AUFNAHME, START_AUFNAHME, ABST_AUFNAHMEN, WZGLAENGENFLAG, MAX_DIFF_WZG_BIEGUNG, BALKEN_MUTEPUNKT, MUTE_SPEED, WZGLAENGE_SENSOR_2/3).
  • Verification: Inspection.

FR-CELL-ROB-023 — Cell 7000 automated thread-in finger positions

  • Requirement: For automated thread-in the system SHALL hold the finger clearances that define "flying gauging" (fliegendes Anschlagen), the finger wait position, the finger safeguarding position and — as a Cell 7000 speciality — the finger withdrawal distance.
  • Priority: Conditional
  • Rationale: Automated thread-in with flying gauging is faster and requires precise finger clearances; the withdrawal distance is documented as a Cell 7000 speciality.
  • Source: Bend.PROZESSDATEN.sql (AbstandFliegendesAnschlagen, AbstandFingerWarteposition, AbstandFingerSicherungsposition, and AbstandFingerURueckzug — MS_Description "Besonderheit der Cell 7000:" citing 20160401_TW544ek_AnschlagpositionenCell7000.pdf and ..._ZusatzdatenRollBend.pdf; ABSTAND_ANSCHLAG_EINFAEDELN, SICHERHEITSABSTAND_X, SICHERHEITSABSTAND_Z).
  • Verification: Test.

FR-CELL-ROB-024 — Named robot positions (6-DOF poses)

  • Requirement: The system SHALL store named robot positions per machine as a Cartesian position (X/Y/Z) plus rotations about each axis, tagged with a coordinate-system id.
  • Priority: Conditional
  • Rationale: Robot programs reference named poses (approach, wait, deposit) by designation; the pose plus coordinate frame defines them.
  • Source: Bend.ROBOTPOSITION.sql (Maschine, Bezeichnung, KoordinateX/Y/Z, WinkelX/Y/Z, KoordSystem; PK (Maschine, Bezeichnung)).
  • Verification: Inspection.

FR-CELL-ROB-025 — Robot dynamics profiles with jerk

  • Requirement: The system SHALL store named robot dynamics profiles per machine, giving acceleration, velocity, deceleration and jerk for the rotary (Drehen), linear-travel (Fahren) and orientation-at-PTP (Orient) motion groups, and SHALL make each profile selectable in the generated NC by a reference number.
  • Priority: Conditional
  • Rationale: Realistic robot motion and cycle time require full jerk-limited dynamics per motion group; the NC selects a profile by handle.
  • Source: Bend.ROBOTGESCHWINDIGKEIT.sql (Beschleunigung/Geschwindigkeit/Verzoegerung/Jerk × Drehen/Fahren/Orient; Referenznummer "Referenznummer zur Ausgabe im NC"; RampentypId documented as a dead/dummy column). See [[16.1 - Bending — NC Code Generation]] FR-BEND-NC-014.
  • Verification: Inspection.

FR-CELL-ROB-026 — Legacy percentage-speed dynamics override

  • Requirement: The system SHALL also support a legacy named per-machine dynamics record expressing a percentage speed value with length/angle/cartesian discriminators.
  • Priority: Optional
  • Rationale: A simpler percentage-speed model coexists with the full dynamics profiles for backward compatibility.
  • Source: Bend.ROBOTERDYNAMIKDATEN.sql (Geschwindigkeit "Geschwindigkeitswert in Prozent", Laenge, Winkel, Kartesisch; PK (Maschine, Bezeichnung) — same key shape as ROBOTPOSITION/ROBOTGESCHWINDIGKEIT).
  • Verification: Inspection.

5. External Interfaces (area-specific)

  • ToPs 600 bend database — ROBOTERPROZESSDATEN, PROZESSDATEN, ROBOTPOSITION, ROBOTGESCHWINDIGKEIT, ROBOTERDYNAMIKDATEN, all keyed by machine configuration. See [[16.7 - Cell7000 — Bend Automation Data Model (Reference)]].
  • Stations / grippers / conveyors — the station, gripper, conveyor and interlayer names in ROBOTERPROZESSDATEN reference the tooling/handling masters in [[16.5 - Cell7000 — Gripper & Handling Tooling]] and [[16.6 - Cell7000 — Regripping, Stations & Part Flow]].
  • NC post-processor / robot program — dynamics reference numbers, positions, beam speeds and thread-in parameters feed the automation NC (see [[16.1 - Bending — NC Code Generation]]); execution is compiled ToPs 600 / BendMaster code.
  • Cell 7000 reference PDFs — AnschlagpositionenCell7000.pdf, ZusatzdatenRollBend.pdf (internal, not in the snapshot) hold the authoritative semantics behind the Cell 7000 finger-withdrawal and RollBend data.

6. Assumptions & Constraints

  • A1. These tables are defaults consumed by the compiled BendMaster/ToPs 600 runtime; the motion/handling planner that consumes them is not readable here. (inferred)
  • C1. Units are undocumented in the schema: speeds appear to be mm/s (linear) or %/deg-s (per axis); confirm against the post-processor.
  • C2. The Cell 7000 relationship is grounded in FahrenBalkenSimultanBM and AbstandFingerURueckzug only; other columns are generic BendMaster/press defaults applicable to the Cell 7000 by instantiation. (inferred)
  • C3. ROBOTPOSITION, ROBOTGESCHWINDIGKEIT and ROBOTERDYNAMIKDATEN share the (Maschine, Bezeichnung) key, so a named entry can carry a matching pose, full dynamics and legacy speed together.

7. Open Questions & Ambiguities

  1. Enum meanings. SimuKollPruefReduziert (enum id 482), UMGREIFTYP, PUNKTBERECHNUNGSART, BAHNBERECHNUNGSMETHODE, MESSVORGABE, MESSEN_STANDARD/BIEGEHILFE, FALZART, ABSTAPELOPTIONEN (bit set?), X_OEFFNUNGSCODE — decode against ENUMWERTE/lookup tables (not in this cluster).
  2. ROBOTERDYNAMIKDATEN vs ROBOTGESCHWINDIGKEIT — the legacy percentage model's runtime role vs. the richer jerk profile is unclear; RampentypId is explicitly dead.
  3. Units for PRESSGESCHWINDIGKEIT, beam speeds and SPEED_* are unconfirmed.
  4. Cell 7000 PDFs (AnschlagpositionenCell7000, ZusatzdatenRollBend) are on an internal NAS and were not accessible; they define the authoritative Cell 7000 backgauge-position and RollBend semantics.
  5. "RollBend" appears only inside the PDF filename; there is no dedicated RollBend column/table in this cluster — its relationship to the Cell 7000 is unresolved.
  6. No FK constraints in this cluster; all cross-table links are inferred from shared keys/names.
