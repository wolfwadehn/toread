FR — Import, Export & File Formats

Reverse-engineered requirement draft — derived from static analysis of legacy source, NOT an authoritative specification. Treat SHALL statements as reconstructed intent.

1. Purpose & Scope

This area covers how the TruTops CAD/CAM suite reads and writes external CAD and exchange file formats and turns them into (or out of) the internal Dbase drawing model (S_draw → parts → contours → elements). It spans:

  • Vector CAD import: DXF, DWG (via an external converter), IGES, ME10 MI (HP ME10 Macro Interchange), and DSTV (Deutscher Stahlbau-Verband steel-construction NC).
  • Native TRUMPF formats: GEO / GEO_102, GMT (ToPs 1000) and TAF, handled by the converter as ordinary source/target formats (the on-disk GEO parser itself lives in tc_dbase — see [[12 - FR - Part & Data Management]]).
  • Export: DXF, ME10, IGES, SVG, HPGL, GEO/GEO_102, XML calculation info, XCAD, and GMT drawing-number stamping.
  • Raster import & vectorization: BMP / JPG / PNG / TIF / GIF are vectorized by the external ToPsVectorize program (from MCS) into a GEO that is then loaded.
  • The converter framework (convmain): a shared library (readDrawingFromFile / doDrawingConversion / writeDrawingToFile) plus two standalone command-line executables — tc_conv.exe (file-based) and pdmConvert.exe/.dll (PDM/CORBA-connected).

Editions served: ToPsCad (full CAD import/export incl. raster vectorization), ToPs 300 (punching) and ToPs 100 (laser) consume the same importers; each external format is gated by a per-format licence/password key.

Several modules named in the assignment were found to belong to other functional areas; they are captured in §7 (Open Questions) rather than specified here, because another analyst owns them (tc_scan, tc_bitm, tc_gts, tc_mrif, tc_stl, tc_ein).

2. Capability Overview

  • Import vector CAD from DXF (full AutoCAD entity set), DWG, IGES, ME10/MI and DSTV into the Dbase drawing model.
  • Fine-grained DXF import control: layer selection / frozen-layer / off-layer suppression, single block or single layout loading, spline conversion (ignore / interpolate / approximate / control-polygon), text & font handling, Z-coordinate suppression, and a detailed load-error report (optionally HTML).
  • Raster-to-vector import of BMP/JPG/PNG/TIF/GIF via the external ToPsVectorize tool.
  • Automatic part extraction from imported drawings (strips drawing frames, arrows, crosses; closes small gaps; identifies the part contour).
  • Export to DXF, ME10, IGES, SVG, HPGL, GEO/GEO_102, XML, XCAD; stamp a drawing/part number into a GMT.
  • Standalone batch converter (tc_conv.exe / pdmConvert.exe) driven by command-line options and @response files, converting one input to one or several output formats at once.
  • Conversion post-processing pipeline: duplicate-point merging, open-contour closing, geometry thinning, thin-slot contour preparation, coordinate scaling, unit conversion (auto/metric/inch), automatic bend-notching, and colour handling.
  • Licensing: every external format is protected by a dongle/Wibu + password-list check (DXF_PASSWORD, DWG_PASSWORD, IGES_PASSWORD, MI_PASSWORD, DSTV_PASSWORD); a superuser mode disables the check.

4. Functional Requirements

FR-IMPEX-001 — DXF geometry import

  • Requirement: When the system imports a DXF file, the system shall translate the supported AutoCAD entities — LINE, POLYLINE, LWPOLYLINE, CIRCLE, ARC, ELLIPSE, SPLINE, POINT, TEXT, MTEXT, INSERT (block reference), SOLID, HATCH and DIMENSION — into corresponding Dbase geometry elements of a drawing.
  • Priority: Essential
  • Rationale: DXF is the primary interchange format for accepting customer part geometry into ToPsCad/ToPs 300/ToPs 100.
  • Source: tc_dxf/dxf_enti.cpp, tc_dxf/dxf_lese.cpp (entity dispatch on "LINE","LWPOLYLINE","ARC","SPLINE","ELLIPSE","HATCH","INSERT",…); tc_dxf/TcDxfPartExtractor.h; convmain/convert.cpp lese_dxfdwg_format() → tc_lese_dxf().
  • Verification: Test (import reference DXF files covering each entity type and compare resulting Dbase geometry).

FR-IMPEX-002 — DXF layer filtering

  • Requirement: Where a DXF file is imported, the system shall allow the operator to select which layers are read, and shall by default ignore layers marked frozen or off, and where the ignore-list mode is inverted (ToPs 300), the system shall instead read only the layers not in the selection list.
  • Priority: Conditional
  • Rationale: Customer DXFs mix geometry, dimensioning and frames on different layers; only production-relevant layers must reach the CAM model.
  • Source: tc_dxf/dxf_konf.cpp (add_dxf_layer, ignoreAllDxfLayers, add_dxf_frozen_layer, add_dxf_off_layer, pruefe_layer_bedingung, IgnoreLayers "Kruecke fuer ToPs 100"); converter option -c ( layername1 layername2 ), -z (ignore frozen layers) in convmain/tc_conv.cpp ShowHelp.
  • Verification: Test (import a multi-layer DXF with layer selections and frozen/off layers; verify only selected/thawed geometry appears).

FR-IMPEX-003 — DXF/MI spline conversion mode

  • Requirement: Where a DXF or MI file containing B-splines is imported, the system shall convert each spline according to a configurable mode — 0 ignore, 1 linear interpolation, 2 adaptive approximation, 3 output control polygon — using configurable maximum chord distance and minimum segment length parameters.
  • Priority: Conditional
  • Rationale: Cutting/punching geometry must be reduced from analytic splines to machine-processable segments at a controllable accuracy.
  • Source: tc_dxf/dxf_konf.cpp (set_DxfConvertSpline, default 2; DxfConvertSplineDistance=0.05, DxfConvertSplineLength=0.1); tc_mi/tc_mi.h (get_MiConvertSpline*); converter options -a 0|1|2|3, -g Distance, -h Length.
  • Verification: Test (import a spline in each mode and measure segment count / deviation).

FR-IMPEX-004 — DXF text and font handling

  • Requirement: Where a DXF file is imported, the system shall optionally suppress loading and display of text entities, and when text is retained the system shall map it to a configurable font (ISO / ISOPROP / BOLD or a named font file).
  • Priority: Conditional
  • Rationale: Text may be irrelevant or must be normalized to a marking-capable font for the machine.
  • Source: tc_dxf/dxf_konf.cpp (set_DxfConvertText, set_DxfFontType 1=ISO/2=ISOPROP/3=BOLD, set_DxfFontName); converter options -d (suppress text), -n ISO.FNT|ISOPROP.FNT|BOLD.FNT.
  • Verification: Test (import DXF with text using -d and with each font and inspect result).

FR-IMPEX-005 — DXF single block / single layout import

  • Requirement: Where a DXF file is imported, the system shall support loading only a single named block or only a single named layout while ignoring all other content.
  • Priority: Optional
  • Rationale: Multi-layout / block libraries must be reduced to the one relevant part.
  • Source: tc_dxf/dxf_konf.cpp (set_single_block_name, set_single_layout_name, get_single_block_name, get_single_layout_name); converter options -b (load block section), -L layoutname.
  • Verification: Test (import a DXF with several blocks/layouts selecting one).

FR-IMPEX-006 — DXF Z-coordinate suppression (2D projection)

  • Requirement: Where a DXF file is imported, the system shall by default ignore the Z coordinate of entities (treating geometry as 2D at Z=0) and shall provide a mode to honour the file's Z coordinates.
  • Priority: Conditional
  • Rationale: Sheet-metal geometry is 2D; stray Z values in customer files must not distort the flat part.
  • Source: tc_dxf/dxf_konf.cpp (Dxf_Ignore_Z_Koord = 1, set_dxf_ignore_z_koord).
  • Verification: Test (import a DXF with non-zero Z and confirm flattening).

FR-IMPEX-007 — DXF import error reporting

  • Requirement: When a DXF (or DWG) import produces load errors, the system shall record them in a load report and, where detailed logging is enabled, shall write a <inputfile>.LOG report (optionally as HTML with a link) while continuing the load for non-critical errors.
  • Priority: Conditional
  • Rationale: Operators need diagnostics for imperfect customer files without losing a recoverable import.
  • Source: tc_dxf/TcDxfLoadReport.h, tc_dxf/TcDxfLoadReport.cpp (reportLineError, getReport, getErrorCount); convmain/convert.cpp lese_dxfdwg_format() (.LOG handling, t_htmlOutput); converter option -v.
  • Verification: Test (import a malformed DXF with -v and inspect the .LOG).

FR-IMPEX-008 — DWG import via external converter

  • Requirement: When the system imports a DWG file, the system shall invoke the external DWGConverter.exe (with Wibu licensing) to convert the DWG into a temporary DXF and shall then read that DXF through the DXF importer.
  • Priority: Conditional
  • Rationale: DWG is a proprietary binary format handled by a licensed external converter rather than a native reader.
  • Source: tc_dwg/TcDwgConverter.h; tc_dwg/DwgConverterStaticCall/TcDwgConverter.cpp (getDwgConverterPath() → %ProgramFiles(x86)%\TRUMPF\Utils\DWGConverter\DWGConverter.exe, a_useWibuLicence=true, CreateProcess); DB-call variant tc_dwg/DwgConverterDBCall; convmain/convert.cpp lese_dxfdwg_format(..., isDxf=false).
  • Verification: Demonstration (import a DWG with the converter installed) / Inspection (invocation path).

FR-IMPEX-009 — IGES import

  • Requirement: When the system imports an IGES file, the system shall translate the supported IGES entity types — 100 circular arc, 106 copious data, 110 line, 116 point, 124 transformation matrix, 126 rational B-spline, 212 general note (text), and 308/408 subfigure definition/instance — into Dbase geometry, applying transformation matrices and views.
  • Priority: Conditional
  • Rationale: IGES is a common neutral CAD exchange format for 2D contour geometry.
  • Source: tc_iges/ig_defin.h (entity codes KREISE 100, COPIOUS 106, LINIEN 110, PUNKTE 116, MATRIZE 124, BSPLINE/CURVE 126, IG_TEXT 212); tc_iges/ig_struc.h; tc_iges/ig_lese.cpp, ig_store.cpp; convmain/convert.cpp lese_iges_format() → tc_lese_iges().
  • Verification: Test (import reference IGES files covering the listed entities).

FR-IMPEX-010 — ME10 MI geometry import

  • Requirement: When the system imports an HP ME10 MI file, the system shall parse its geometry records (construction lines/circles, points, lines, arcs, circles) into Dbase geometry and shall interpret the MI format version.
  • Priority: Conditional
  • Rationale: ME10/MI is a legacy TRUMPF/HP CAD exchange format still present in customer data.
  • Source: tc_mi/mi_lese.cpp ("MI-Interpreter"), tc_mi/mi_def.h (CLINE, CKREIS, PUNKT, LINIE, BOGEN, KREIS), tc_mi/tc_mi.h (MI_Version_Nr, MI_RELEASE_1 2.21, MI_RELEASE_2 2.4); convmain/convert.cpp lese_mi_format() → tc_lese_mi().
  • Verification: Test (import MI files of both format versions).

FR-IMPEX-011 — MI single-stroke (CAPT) attribute conversion

  • Requirement: Where an MI file is imported in CAPT mode, the system shall convert its single-stroke (Einzelhub) information into Dbase single-stroke attributes using configurable, file-driven conversion rules.
  • Priority: Conditional
  • Rationale: CAPT/MI files carry punch technology that must be reconstructed as machining attributes, not just geometry.
  • Source: tc_mi/TcMiStrokeConversionManager.h/.cpp, TcMiStrokeConversionRule.*, TcMiStrokeDefinition.*; convmain/convert.cpp readDrawingFromFile() (set_capt_gra_konvert(TRUE) for M_mi_capt).
  • Verification: Test (import a CAPT MI file and verify stroke attributes).

FR-IMPEX-012 — DSTV import

  • Requirement: When the system imports a DSTV file, the system shall read its 2D geometry information and build a Dbase drawing, ignoring non-2D data (e.g. bending or powder-marking instructions).
  • Priority: Conditional
  • Rationale: DSTV is the steel-construction NC standard; only its 2D contour data is needed for cutting.
  • Source: tc_dstv/db_dstv.cpp (header: "Liest eine Datei aus dem DSTV-Format … liest die 2D-Informationen … weitere Informationen (z.B. zum Biegen oder Pulvern) werden vorerst ignoriert"); convmain/convert.cpp leseDstvFormat() → leseDstvDatei().
  • Verification: Test (import a DSTV file and inspect the extracted contour).

FR-IMPEX-013 — Raster import and vectorization

  • Requirement: When the system imports a raster graphic (BMP, JPG, PNG, TIF or GIF), the system shall invoke the external ToPsVectorize program to vectorize the image into a temporary GEO, shall load that GEO into the drawing, and shall then delete the temporary file.
  • Priority: Conditional
  • Rationale: Lets ToPsCad users derive cuttable contours from scanned or pixel drawings.
  • Source: tc_interface/tc_cad/cad_vectorize/vectorize.h, tc_cad/cad_vectorize/vectorize.cpp (vectorizeRasterFile, calls %TOPS_VECTORIZE_PATH%\ToPsVectorize.exe <ini> <in> <out.geo>); tc_cad/cad_util/cad_load.hpp (RASTER_FORMAT 2048 // BMP, JPG, PNG, TIF, GIF); ini_files/ToPsCad/topsCad.org (TOPS_VECTORIZE_PATH).
  • Verification: Demonstration (import a bitmap with ToPsVectorize installed).

FR-IMPEX-014 — Native GEO / GMT / TAF read

  • Requirement: When the system opens a native TRUMPF file in GEO, GMT or TAF format, the system shall load it into the Dbase drawing model through the native reader.
  • Priority: Essential
  • Rationale: GEO is the internal exchange/storage format; GMT (ToPs 1000) and TAF are sheet/table variants that the converter must accept as sources.
  • Source: convmain/convert.cpp readDrawingFromFile() (M_gmt/M_geo/M_taf → lese_tco_format()); convmain/tc_conv.h (input formats "GEO, GMT, TAF"); on-disk parser in tc_dbase (see [[12 - FR - Part & Data Management]]).
  • Verification: Test (round-trip a GEO/GMT/TAF file).

FR-IMPEX-015 — Automatic part extraction from CAD import

  • Requirement: Where automatic part extraction is enabled during a DXF/DWG import, the system shall analyse the drawing to identify the part geometry, remove drawing frames, arrows and crosses, close small contour gaps, and colour the identified part while marking non-part elements for deletion, offering alternative part proposals if the first result is unsatisfactory.
  • Priority: Optional
  • Rationale: Customer drawings contain title blocks and annotations; automatic extraction yields a clean part without manual cleanup.
  • Source: tc_dxf/TcDxfPartExtractor.h/.cpp (extractPart, removeFrames, removeArrows, removeCrosses, closeContours, getFirstAlternativePart, extractPartWithMarking); convmain/convert.cpp (m_extractPart → deleteElementByColor(...e_blue)); converter option -E.
  • Verification: Test (import a framed customer DXF with extraction on).

FR-IMPEX-016 — DXF export

  • Requirement: When the system exports a drawing to DXF, the system shall write the Dbase geometry as DXF entities (lines, arcs, circles, points, texts and block inserts), optionally applying contour preparation before writing.
  • Priority: Essential
  • Rationale: DXF is the primary format for returning geometry to external CAD systems.
  • Source: tc_dxf/dxfschr.cpp (schr_entities), dxfenti.cpp, dxfhead.cpp, dxftabl.cpp; convmain/convert.cpp schreibe_dxf_format() → tc_schreibe_dxf() (with bereite_datei_auf() when contour preparation requested); TAF→DXF special path tc_export_taf_to_dxf().
  • Verification: Test (export a drawing to DXF and re-import / validate in AutoCAD).

FR-IMPEX-017 — ME10 export

  • Requirement: When the system exports a drawing to ME10 format, the system shall write an ME10 input file containing lines, arcs, points, circles, construction lines/circles, splines, arrows, texts and rectangles, together with their ME10 element and text attributes.
  • Priority: Conditional
  • Rationale: Supports customers who continue to use HP ME10/CoCreate.
  • Source: tc_me10/tc_hpgeo.h (db_geo_daten_to_me10_input), me_elem.h (me10_linie/bogen/punkt/kreis/hilfskreis/hilfslinie/spline/pfeil/text/viereck), me_attr.h (setze_me10_attribute); convmain/convert.cpp schreibe_me10_format(); converter output -o me10.
  • Verification: Test (export to ME10 and open in a compatible viewer).

FR-IMPEX-018 — IGES export

  • Requirement: Where IGES export is invoked, the system shall write the Dbase drawing as an IGES file, applying the configured viewport, help-geometry level and text font.
  • Priority: Conditional
  • Rationale: Provides a neutral CAD hand-off format for downstream systems.
  • Source: tc_iges/ig_ausg.cpp/ig_ausg.h (ig_ausgabe(Draw_ptr), set_iges_viewport, Level_fuer_Hilfsgeo, get_IgesFontName).
  • Verification: Test (export to IGES and validate entities). Note: the convmain converter's schreibe_iges_format() is a stub — see §7.

FR-IMPEX-019 — SVG export

  • Requirement: When the system exports a drawing to SVG, the system shall produce a scalable vector graphic and shall apply a configurable stroke width (absolute, percentage of viewport, or pixel value).
  • Priority: Optional
  • Rationale: SVG supports documentation, web viewing and calculation previews.
  • Source: convmain/convert.cpp schreibe_svg_format() (via db_svg.h); convmain/tc_conv.h (setSvgStrokeWidth); TsConvertParameter::m_svgStrokeWidth.
  • Verification: Test (export to SVG and render).

FR-IMPEX-020 — HPGL export

  • Requirement: When the system exports a drawing to HPGL, the system shall write an HPGL plot file, optionally applying contour preparation.
  • Priority: Optional
  • Rationale: Supports plotting/legacy output devices.
  • Source: convmain/convert.cpp schreibe_hpgl_format() (via tc_plot.h).
  • Verification: Test (export to HPGL and plot/inspect).

FR-IMPEX-021 — Native GEO / GEO_102 export with contour preparation

  • Requirement: When the system exports a drawing to the native TRUMPF format, the system shall write it as GEO or GEO_102 according to the requested version identifier and shall apply contour preparation when requested.
  • Priority: Essential
  • Rationale: GEO is the internal storage/exchange format consumed by the CAM chain; two versions must be selectable.
  • Source: convmain/convert.cpp schreibe_tco_format(filename, drawing, format, konturAufbereitung); writeDrawingToFile() (M_geo/M_geo_102); converter output -o geo|geo_102.
  • Verification: Test (export to GEO and GEO_102, reload each).

FR-IMPEX-022 — XML calculation-info export

  • Requirement: When the system exports XML calculation information, the system shall analyse the first real part of the drawing and write its calculation-relevant contour data as XML.
  • Priority: Conditional
  • Rationale: Feeds the ToPs 1000 calculation/costing tool.
  • Source: convmain/convert.cpp writeXmlCalculationInfo() (TcDbaseKalkulationsTool::analysiereTeil, xmlExport); format enum e_xml.
  • Verification: Test (export XML for a known part and validate against the calculation schema).

FR-IMPEX-023 — XCAD export

  • Requirement: Where XCAD export is invoked, the system shall write the Dbase drawing to the XCAD exchange format.
  • Priority: Optional
  • Rationale: Internal TRUMPF exchange format for specific downstream tooling.
  • Source: convmain/convert.cpp writeDrawingToFile() (M_xcad → exportDbaseToXCad() via db2XCad.h); format enum e_xcad.
  • Verification: Inspection / Test (export and validate against XCAD consumer).

FR-IMPEX-024 — GMT drawing-number update

  • Requirement: When the system is asked to set a drawing number on a GMT file, the system shall rewrite the file's GEO section so that the part identity number is inserted/replaced (creating the text-info block if absent) without otherwise altering the geometry.
  • Priority: Conditional
  • Rationale: In the Blechfabrik / NC-Link flow the drawing number is the through-going part identifier for the cutting order.
  • Source: convmain/convert.cpp setGmtDrawingNumber() (edits #~11, #~30/#~TTINFO_END, KEY_TEILEIDENTNR); output M_gmt; converter option -Z.
  • Verification: Test (stamp a number into a GMT and re-read the identity).

FR-IMPEX-025 — Standalone batch converter (command line / response file)

  • Requirement: The system shall provide a command-line converter that reads an input file in a specified format (-i geo|iges|dxf|dwg|mi|mi_capt|dstv) and writes it to one or more output formats (-o geo|geo_102|dxf|me10|…), accepting either an explicit file list or an @response_file, and setting the message language via -s deu|eng|frz|spa|ita.
  • Priority: Essential
  • Rationale: Enables unattended batch conversion and integration into external workflows (see [[23 - FR - Automation, Scripting & Integration]]).
  • Source: convmain/tc_conv.cpp (Handle_All_Options, ShowHelp, convmain(), @-response handling); convmain/convert.cpp convert_file(), writeDrawingToFile() loop over getNextGrafikFormatId; convmain/tc_conv.h (TeGrafikFormat, TsConvertParameter).
  • Verification: Demonstration (run tc_conv.exe -i dxf -o geo,dxf file.dxf).

FR-IMPEX-026 — Per-format licence / dongle check

  • Requirement: While password checking is active, the system shall verify the dongle/Wibu licence and password entry for the specific format being read or written (DXF_PASSWORD, DWG_PASSWORD, IGES_PASSWORD, MI_PASSWORD, DSTV_PASSWORD) and shall abort the operation with a diagnostic if the licence is missing.
  • Priority: Conditional
  • Rationale: Each import/export format is a separately licensed option.
  • Source: convmain/convert.cpp (checkModulePassword("DXF_PASSWORD" / "DWG_PASSWORD" / "IGES_PASSWORD" / "MI_PASSWORD" / "DSTV_PASSWORD") in each lese_*/schreibe_*); TsConvertParameter::m_passwordCheck (superuser off). See [[19 - FR - Tools, Machines, Materials & Technology]] and [[40 - Non-Functional Requirements]].
  • Verification: Test (attempt each format with and without the licence).

FR-IMPEX-027 — PDM-connected conversion

  • Requirement: Where the converter is built as the PDM variant (pdmConvert.exe/.dll), the system shall connect to a PDM system via a CORBA naming service specified by -A hostname:port, using a named PDM service (-S) and a data cache directory (-C), and shall route file access through the PDM file-system interface.
  • Priority: Conditional
  • Rationale: Integrates conversion with TruTops PDM/PLM data management rather than the local file system.
  • Source: convmain/tc_conv.cpp ShowHelp (-A/-C/-S, guarded by S_pdmBootStrapPtr->isPdmConvert()); convmain/pdmConvert.*, convmain/pdmImplementation/, convmain/filesystemImplementation/; TeExitCode::e_errorPdmConnect.
  • Verification: Demonstration (run pdmConvert against a PDM naming service).

FR-IMPEX-028 — Contour cleanup on conversion

  • Requirement: During conversion the system shall merge coincident points within a configurable tolerance and replace geometrically critical elements, and where enabled shall close open contours whose gaps are within a configurable closing tolerance.
  • Priority: Conditional
  • Rationale: Imported geometry frequently has duplicate points and small gaps that must be healed before CAM processing.
  • Source: convmain/convert.cpp doDrawingConversion() (suche_doppelte_punkte, ersetzeKritischeElemente, TcDbaseClipCommand::closeAllContours under m_closeOpenContours); converter options -O/-t (tolerances).
  • Verification: Test (convert a file with duplicate points and gaps; verify healing).

FR-IMPEX-029 — Geometry thinning

  • Requirement: Where a thinning level is selected (rough / middle / fine), the system shall reduce the element/point density of the converted drawing using level-specific segment-angle, maximum-distance and minimum-length parameters, converting hard-coded tolerances to inch when the drawing unit is inch.
  • Priority: Optional
  • Rationale: Reduces oversized vectorized/spline geometry to a manageable element count.
  • Source: convmain/convert.cpp doDrawingConversion() (TcDbaseThinCommand, m_ausduennStufe 1/2/3); converter option -T 0|1|2|3.
  • Verification: Test (thin a dense contour at each level and compare element counts).

FR-IMPEX-030 — Thin slotting-contour preparation

  • Requirement: Where thin-contour preparation is enabled, the system shall reduce standard contours narrower than a configurable width to a single line, selectable for rectangles, oblong holes, and/or contour-section enlargement.
  • Priority: Optional
  • Rationale: Very narrow slots (e.g. from Bystronic-format migrants) whose equidistants would overlap must be reduced to a cuttable line.
  • Source: convmain/convert.cpp doDrawingConversion() (TcDbaseSlitContourCommand, TcDbaseSlitStretchCommand, m_preparationThinStdContourMode/Width); convmain/tc_conv.h (setPreparationThinStdContourMode/Width); converter options -M 0-7, -W width.
  • Verification: Test (convert narrow rectangle/oblong contours with each mode).

FR-IMPEX-031 — Coordinate scaling and unit conversion

  • Requirement: During conversion the system shall optionally scale the drawing by a configurable factor and shall set the target unit to metric or inch, or auto-derive it from the source (GEO/GMT/TAF/IGES/MI), re-initializing the tolerance container when the unit changes.
  • Priority: Conditional
  • Rationale: Cross-system exchange requires unit normalization (formats such as DXF/IGES carry no unit) and geometry scaling.
  • Source: convmain/convert.cpp doDrawingConversion() (TcDbaseTransformCommand::scaleDrawing, m_scaleDrawingFactor) and reinitToleranzContainer() (m_unitConversionMode, TcToleranzContainer::init); converter options -r scalingFactor, -U auto|metric|inch.
  • Verification: Test (convert with -U inch and -r factor; verify coordinates/units).

FR-IMPEX-032 — Automatic bend-notch generation

  • Requirement: Where automatic notching is enabled, the system shall create relief notches at bend lines of the converted drawing.
  • Priority: Optional
  • Rationale: Prepares imported bent-part geometry for downstream bending/cutting without manual notching.
  • Source: convmain/convert.cpp doDrawingConversion() (createBendLineAutoNotch()->executeOnDrawing, m_autoNotchOn); convmain/tc_conv.h (setAutoNotch); converter option -N. See [[16 - FR - Bending (ToPs 600)]].
  • Verification: Test (convert a part with bend lines and verify notches).

FR-IMPEX-033 — Output filename resolution, overwrite protection and auto drawing number

  • Requirement: When writing conversion output, the system shall derive the output path/name (source name with the format-specific extension, or an explicit output path/name), shall refuse to overwrite an existing file unless the force option is set, and shall optionally derive the part/drawing number from the source filename using a regular expression or from an explicit override.
  • Priority: Essential
  • Rationale: Batch conversion must produce predictable, non-destructive output and consistent part identification.
  • Source: convmain/convert.cpp writeDrawingToFile() (getGrafikFormatFileExtension, teste_ob_name_okay, "Set option -force"), setzeAutomatischeZeichnungsnummer() (TwCRegexp, KEY_TEILEIDENTNR, 39-char cap); converter options -f, -x, -Z.
  • Verification: Test (convert without/with -f to an existing file; verify auto drawing number).

6. Assumptions & Constraints

Cross-cutting items belong in [[50 - Constraints & Assumptions]] and [[40 - Non-Functional Requirements]].

  • External-tool dependency: DWG import and raster vectorization require separately installed executables (DWGConverter.exe, ToPsVectorize.exe) located via a fixed path / the TOPS_VECTORIZE_PATH environment variable. If absent, those imports fail gracefully with an error code.
  • Legacy C code with global state: the DXF/MI/IGES interpreters use static configuration globals (layer lists, spline mode, fonts); options set for one load persist until reset (gib_konf_var_frei, remove_all_dxf_layers). Temporary layer selections are cleared after a single load.
  • Encoding: legacy sources are ISO-8859-1 with CRLF; domain identifiers and comments are German.
  • Licensing: each format is a separately licensed option; superuser mode disables the password check (m_passwordCheck=false).
  • Two converter deployments are built from the same code: file-based tc_conv.exe and PDM-connected pdmConvert.exe/.dll; PDM help/options only appear in the PDM build.
  • Tolerances default to 0.001–0.005 mm (TOLERANZ, m_toleranz); the converter needs only TEXTE.DAT and TOLERANZ.ASC plus a dongle to run standalone.

7. Open Questions & Ambiguities

  • Module scope corrections (belong to other areas):
    • tc_scan (SlPtsTab, "Automatische Trennschnitte", Gitter auftrennen) is scanline-based skeleton/scrap-grid parting-cut generation, not raster/vectorization — it belongs to Nesting/NC ([[17 - FR - Nesting & Palletizing]] / [[18 - FR - NC Generation & Motion Optimization]]). Actual raster vectorization lives in tc_cad/cad_vectorize.
    • tc_bitm is a nesting/collision bitmap (bit_taf, bitmfill, bitmkoll), not raster image I/O → Nesting.
    • tc_gts is the geometry-parts interface that builds part/nest structure trees and cut structures (gts(), Teile_baum, Nester_baum, Schnitt), not a file format → Nesting/NC.
    • tc_mrif caches the machine rule set from DB table MAS_REGEL → Tools/Machines/Technology ([[19 - FR - Tools, Machines, Materials & Technology]]).
    • tc_stl/stl_tech is Stanz-Laser (punch-laser combi) technology (tech_la, koll_la, bahn_la), not stereolithography STL → Laser/Technology ([[14 - FR - Laser Cutting (ToPs 100)]]). No true 3D STL file import/export was found in the snapshot.
    • tc_ein contains TcBarcode, TcEinrichteplan (setup plan) and TcSinglePartGrafik — operator-document/barcode generation, not CAD file import → Visualization/Production Planning ([[21 - FR - Visualization, Viewing & Plotting]] / [[20 - FR - Production Planning & Projects]]).
  • IGES/MI export path: ig_ausgabe() implements IGES output and tc_mi contains write helpers, but the convmain converter's schreibe_iges_format() and schreibe_mi_format() are stubs (return 0). The exact application path that reaches ig_ausgabe (interactive "Save As IGES") was not traced; MI export may be effectively unavailable.
  • DXF/DWG version coverage: the range of AutoCAD DXF versions the native reader accepts, and the DWG versions handled by the external converter, cannot be determined from source.
  • TAF and XCAD internal formats were only observed at the dispatch level; their record structures were not examined.
  • getNextGrafikFormatId bit-flag output: multiple output formats are encoded as OR-ed bits (TeGrafikFormat), so a single run can emit several files; the precise CLI syntax for requesting multiple outputs was inferred, not confirmed end-to-end.
  • Error-code aggregation: convert_file sums error codes across steps ("Fehlercodes werden aufsummiert"), so the returned integer is not a single enumerated status — downstream interpretation is unclear.
