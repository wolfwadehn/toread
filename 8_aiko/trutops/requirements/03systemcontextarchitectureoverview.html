03SystemContextArchitectureOverview

product: trutopscad org: trumpf title: "System Context & Architecture Overview" doc: "03 - System Context & Architecture Overview" id-prefix: "-" srs-standard: "ISO/IEC/IEEE 29148:2018" status: reverse-engineered-draft source: "TruTopsCAD legacy source snapshot (files dated May 2024)" related: ["[[00 - Index & Reading Guide]]", "[[01 - Vision & Scope]]", "[[02 - Stakeholders & Actors]]", "[[04 - Domain Model & Glossary]]", "[[30 - External Interface Requirements]]", "[[50 - Constraints & Assumptions]]"] tags: [requirements, trutops, architecture]

System Context & Architecture Overview

[!info] Purpose and scope This document establishes the system context and architecture overview for the reverse-engineered TruTops CAD/CAM SRS suite. It is a non-normative, structural companion to the functional-requirement documents [[10 - FR - CAD Geometry & Drawing Editing]] through [[23 - FR - Automation, Scripting & Integration]]: it does not itself carry requirement IDs, but it frames how the system is decomposed, deployed and technologically constrained so that the FR/NFR/interface documents can be read against a shared mental model. Behavioural detail lives in the linked FR documents; interface contracts live in [[30 - External Interface Requirements]]; platform and legacy constraints live in [[50 - Constraints & Assumptions]]; domain vocabulary is defined once in [[04 - Domain Model & Glossary]].

TruTops is TRUMPF's legacy 2D CAD/CAM suite for sheet-metal fabrication. A single shared C++ code base (the tcolib library set) is compiled into several per-technology executables (editions), all sharing one UI framework (GRIT), one geometry/data model (Dbase), and a common relational database and PDM back end. The suite prepares parts and sheets for punching, laser cutting, bending and tube laser machining, nests them onto raw sheets, and generates controller-specific NC programs and production plans for the shop floor.

1. System Context

TruTops sits between CAD design inputs (customer geometry in neutral exchange formats) and the shop floor (physical TRUMPF machines and their controllers), with a master-data / PDM / MES environment around it. The context diagram below shows the human actors (detailed in [[02 - Stakeholders & Actors]]), the TruTops suite as one logical system, and the external systems it exchanges data with (each interface is specified in [[30 - External Interface Requirements]]).

Context summary. The suite is a desktop CAD/CAM programming station. Upstream it consumes customer geometry (via the format converters of [[11 - FR - Import, Export & File Formats]]) and master/technology data (via [[12 - FR - Part & Data Management]] and [[19 - FR - Tools, Machines, Materials & Technology]]). Downstream it emits controller-specific NC programs, setup plans and production plans (via [[18 - FR - NC Generation & Motion Optimization]] and [[20 - FR - Production Planning & Projects]]) to TRUMPF machines, mediated by NcLink/DNC. Laterally it integrates with the TRUMPF.NET PDM vault for file storage, the ITM/SW06 network for live tool availability, and TruTops Fab (MES) for order import and job-state feedback. Every import/export format and most technology areas are individually gated by dongle/Wibu licensing.

Subsystem responsibilities (each links to its owning FR document):

  • [[10 - FR - CAD Geometry & Drawing Editing]] (FR-CAD) — the interactive 2D CAD editor and geometry kernel: primitives, hole macros, transformations, trim/split/merge, fillet/chamfer/notch, offset, boolean contour arithmetic, dimensioning and parametric variants. Core of ToPsCad and the drawing front end of the technology editions.
  • [[11 - FR - Import, Export & File Formats]] (FR-IMPEX) — reads/writes DXF, DWG, IGES, ME10/MI, DSTV and TRUMPF-native GEO/GMT/TAF; raster vectorisation; the shared converter framework and its standalone tc_conv.exe / pdmConvert.exe executables.
  • [[12 - FR - Part & Data Management]] (FR-DATA) — persistence of parts, drawings, sheets and orders across two storage worlds: native geometry (MI) files on the file system or PDM vault, and the relational database defined by the DATADICT data dictionary.
  • [[13 - FR - Punching (ToPs 300)]] (FR-PUNCH) — punch/nibble tool assignment, contour processing, common cutting, micro-joints, forming, marking, clamp/repositioning, hit optimisation, scrap/skeleton handling.
  • [[14 - FR - Laser Cutting (ToPs 100)]] (FR-LASER) — cutting-technology assignment, lead-in/lead-out, piercing, part-retention, marking, kerf correction, sheet dividing, gas/cooling, cutting-sequence optimisation and automated unloading/sorting.
  • [[15 - FR - Tube & Profile Machining (ToPs 400)]] (FR-TUBE) — 3D tube modelling and unrolling, the profile library, machining-case assignment, tube technology lookup, guiding/support elements and ToPs 400 NC/APD output.
  • [[16 - FR - Bending (ToPs 600)]] (FR-BEND) — bend definition, bend-deduction factors and flat patterns from the ToPs 600 database, punch/die assignment, the profile editor and the bend-tool assistant.
  • [[17 - FR - Nesting & Palletizing]] (FR-NEST) — automatic/interactive true-shape and rectangular nesting (GSSL NestLib), utilisation optimisation, remnant management, and palletising of parts/scrap/skeleton for LiftMaster/SortMaster automation.
  • [[18 - FR - NC Generation & Motion Optimization]] (FR-NC) — constrained-TSP processing-order sequencing, travel-time optimisation, collision-free path finding, cycle-time estimation, data-driven NC post-processing, setup-plan and multiple-up generation, and NC transfer.
  • [[19 - FR - Tools, Machines, Materials & Technology]] (FR-TECH) — the master-data foundation: machine definitions, tool catalogues, material/sheet inventory and technology tables shared by all technology editions.
  • [[20 - FR - Production Planning & Projects]] (FR-PLAN) — programming projects (PPJ workbooks), production plans (via external NcLink), grouping parts into nesting orders, and job hand-off to TruTops Fab.
  • [[21 - FR - Visualization, Viewing & Plotting]] (FR-VIS) — on-screen 2D rendering, view navigation, toggleable display classes, raster/GDI printing, HPGL plotting and the embeddable GeoViewer.
  • [[22 - FR - UI Framework, Dialogs & Interaction (GRIT)]] (FR-UI) — the GRIT masks/dialogs, the embedded MMK interpreter with mini_sql data binding, input validation, selection, undo/redo, multi-language/unit rendering and the Qt tc_guiAdapter bridge.
  • [[23 - FR - Automation, Scripting & Integration]] (FR-AUTO) — the embedded Python 2.5 interpreter, the ASM/MMK command interpreters, the per-edition Xidl external component API, the TruTops Fab adapter and headless P/Invoke DLLs.

3. Module Map

The following maps each functional area to the source modules that implement it. Sizes (approx. LOC) indicate the relative weight of the module. Several modules are deliberately shared across areas — most notably tc_dbase (geometry/data model), tc_maschine (machine master data), tc_profil (profile geometry, shared by CAD and Tube) and the whole grit/tc_bof UI stack. Open boundary questions raised by the analysts are noted where relevant.

CAD Geometry & Drawing Editing → [[10 - FR - CAD Geometry & Drawing Editing]] (FR-CAD)

tc_cad (154k LOC, interactive editor + TrueType text), GeoAlgorithmsKernel (113k, .NET managed geometry kernel — boolean/hull/shape ops), tc_geoUtils, tc_geoPlan (topological plan/graph model), tc_math, tc_aprox (curve approximation), tc_fou (Fourier contour description/similarity), tc_poly, tc_profil (bent-profile model + unfolding — shared with Tube), tc_contourArithmeticTool (131k, boolean contour arithmetic) + tc_contourArithmeticToolTest, tc_vgl (geometry comparison/versioning), tc_forml (formula/parametric collection — note: analyst flags this as a machine-technology formula collection likely belonging to Bending/Technology, not CAD variants).

Import, Export & File Formats → [[11 - FR - Import, Export & File Formats]] (FR-IMPEX)

tc_dxf (DXF import/export), tc_dwg (DWG import via external DWGConverter.exe), tc_iges (IGES), tc_stl (95k — analyst note: this is Stanz-Laser combi technology, not stereolithography STL), tc_me10 (HP ME10 / MI CAD, incl. CAPT single-stroke), tc_dstv (steel-construction NC, 2D geometry only), tc_ein (analyst note: operator-document/barcode generation, not file import), convmain (converter main: readDrawingFromFile → doDrawingConversion → writeDrawingToFile, packaged as tc_conv.exe and pdmConvert.exe), tc_scan (analyst note: scanline parting-cut generation — belongs to Nesting/NC), tc_bitm (analyst note: nesting collision bitmap), tc_mrif (machine rule-set cache — belongs to Technology), tc_gts (geometry-parts interface — belongs to Nesting). Real raster vectorisation lives in tc_cad/cad_vectorize via external ToPsVectorize.exe.

Part & Data Management → [[12 - FR - Part & Data Management]] (FR-DATA)

tc_dbase (492k — the in-memory geometry/data model S_draw/S_teil/S_kontur/S_element and the GEO/GEO_102 on-disk parser; the single most widely shared module), tc_dbif (DB interface + rule-set cache SRObj), tc_verw (Verwaltung/management, TcGeoInfos file-attribute reader + part-property checks), tc_mi (MI-Interpreter, versioned native text geometry format), tc_mem, tc_list, tc_tab (tables + table upgrades), tc_xml (Xerces DOM read/write), Databases/ (1773 SQL files across the SQL Server schemas and locally attachable MDB). The TruTopsGeoInterface.dll C/.NET binary geometry API and the OmAdapter/TiPdmFacet PDM facade also belong here.

Punching / Nibbling (ToPs 300) → [[13 - FR - Punching (ToPs 300)]] (FR-PUNCH)

tc_stz (Stanzen / punch — ~840k LOC, the largest single module), plus the shared tc_bof GRIT masks aPnLas* / aTco* and muster.gritx (processing patterns). Punch technology tables live in the Punch.* SQL schema (92 tables).

Laser Cutting (ToPs 100) → [[14 - FR - Laser Cutting (ToPs 100)]] (FR-LASER)

tc_las (Laser — ~590k LOC; also hosts the parallel water-jet/H2O technology), tc_lift (lift / loading & unloading automation — 22k, holding-device modelling), tc_liftMachineSimulationData (kinematics for unloading simulation), the aLas*/tec_acut (AutoCut) GRIT masks and the Laser.* SQL schema (59 tables, with parallel _inch variants).

Tube & Profile Machining → [[15 - FR - Tube & Profile Machining (ToPs 400)]] (FR-TUBE)

tc_rohr (Rohr / tube — ~234k LOC: 3D tube model, unrolling, machining cases, penetrations, guiding/supports, tube optimiser), tc_profil (shared with CAD). Backed by the Tube.* / Tube_inch.* SQL schema (48 tables) and file formats ROT/RMT/RPF/TEO; integrates SolidWorks via the TubeSwAddin and TRUMPF PDM.

Bending (ToPs 600) → [[16 - FR - Bending (ToPs 600)]] (FR-BEND)

The tc_bof GRIT masks bendappl.gritx / bendassi.gritx (bend application & bend-tool assistant), the tops/topsmain T300 edition wiring, BendTools file store (TOPS_BENDTOOL_PATH), and the ToPs 600 bend-data database (SERVER_TOPS600; the Bend.* schema is the largest at 101 tables, plus BendGripperConf.* and Common.AKF_BENDFACTORS). Automatic bend-sequencing/collision are largely delegated to the separate ToPs 600 / TruTops Bend product.

Nesting & Palletizing → [[17 - FR - Nesting & Palletizing]] (FR-NEST)

tc_nest (366k — wraps the GSSL NestLib true-shape engine via nestlib_interface, plus the newer NestCore/JobModel/Xidl pipeline), tc_palettierung (palletising — 111k, LiftMaster/SortMaster), tc_bsort (batch sort), tc_fsel, tc_optimizer (analyst note: tc_optimizer and tc_bsort/tc_fsel are cutting-sequence/thermal/batch-sort optimisation and likely belong to NC Generation, doc 18). Backed by the Nest.* SQL schema.

NC Generation & Motion Optimization → [[18 - FR - NC Generation & Motion Optimization]] (FR-NC)

tc_nc (77k — data-driven controller-specific NC generation from NCZYKLEN/AUS_FORMAT tables; SIN840D observed), tc_wegzeit (jerk-limited travel/cycle-time), tc_pathf (collision-free rapid-traverse path finding), tc_wopt (way/processing-order optimisation), tc_constrainedTspSolver (14k — nearest-neighbour + Ant-Colony + post-optimisation), tc_mfn (multiple-up / Mehrfachnutzen), tc_maschine (machine — shared with FR-TECH).

Tools, Machines, Materials & Technology → [[19 - FR - Tools, Machines, Materials & Technology]] (FR-TECH)

tc_wzg (Werkzeug / tools — 72k, WZG3 tool records + XML import/export + ITM/SW06 connection), tc_maschine (machines — TcMaschinenSchluessel, work area, axis dynamics, peripherals), tc_materialVerwaltung (material management), tc_mtl (analyst note: actually a nesting collision bitmap, not material master), tc_tec (technology tables — analyst note: laser/NC processing concerns), and the technology tables in Databases/ (MAS_ALLG, AUTOCUT_KONFIG, LASERTECHNO, STANZ_REGELN, MAT_*, …). The Common.* schema (27 tables) plus Text.* localisation underpin this area.

Production Planning & Projects → [[20 - FR - Production Planning & Projects]] (FR-PLAN)

tc_prodplan (production planning / NcListe), tc_aps (analyst note: misattributed — actually lead-in/Anfahrfahnen variant generation, belongs to NC/Laser), tc_programmierProjekt (programming project / PPJ workbook — 23k, versioned .ppj XML). Real cross-machine scheduling is external (TruTops Fab).

Visualization, Viewing & Plotting → [[21 - FR - Visualization, Viewing & Plotting]] (FR-VIS)

tc_viewer (47k — embeddable/standalone GeoViewer, ActiveX/OCX), tc_visualize (backend-independent 2D visualizer: vis_gdi/vis_grit/vis_none), tc_plot (HPGL/HPGL2 plotting + GDI printing), tc_bitm (raster export — also used for nesting collision), grit/drive (device/rendering layer: elem_win.cpp GDI, elem_ux.cpp X11).

UI Framework, Dialogs & Interaction (GRIT) → [[22 - FR - UI Framework, Dialogs & Interaction (GRIT)]] (FR-UI)

grit/ (src, tco_api, win, drive), tco_grit_tools (GritDialog/GritFile/mask converters), tc_bof (the .gritx masks + .olb binary dialogs + MMK interpreter scripts), tops/topsgrit, tc_selection, tc_undo, tc_text (vector stroke fonts), tc_guiAdapter (AppState/Qt bridge), GUI, tc_tab.

Automation, Scripting & Integration → [[23 - FR - Automation, Scripting & Integration]] (FR-AUTO)

tc_python (embedded Python 2.5 + ToPs/ToPsGraphics modules), API (per-edition Xidl external component API), tc_interface (cross-module public-header hub + tc_fabAdapter), tc_fabAdapter (TruTops Fab / MES adapter), tc_reproduction (headless batch re-nesting for regression), TruTopsDllNET (.NET interop), tc_asm (ASM command state machine), tc_catch (pick / hit-testing — analyst note: arguably FR-UI/FR-CAD).

[!note] Cross-cutting infrastructure modules Several modules are infrastructure used by all areas and are not owned by a single FR document: tc_sys, tc_umgeb (environment), tc_util (utilities + pdmUtilities PDM file streams), tc_log, tc_issue, tc_pwd (password/licence checks), tc_mem, tc_list, tc_stub. The build harness (all_*makefile, tcolib_win_VS2010.sln, Build_tcolib_win_05XX*) and Perforce/Red Gate DB source-control tooling (CommandLineHooks.xml, RedGate.ssc) are developer tooling, not runtime.

4.1 Per-edition executables

The topsmain project links the shared tcolib code base into distinct edition executables. The snapshot confirms these executable targets under topsmain/:

Editions are further parameterised at runtime by per-edition configuration directories under ini_files/: ToPs100, ToPs100Lite, ToPs2000, Tops300, ToPs400, ToPs400Cad, ToPsCad, ToPsNest. Each contains *.ORG files (e.g. ToPs100.ORG, ToPs100Inch.ORG, Grit100.ORG) that switch feature/menu exposure, metric-vs-inch operation and the GRIT mask set, so one binary family covers several product SKUs. Tube machining runs on the ToPs 400 platform (aTubeFunc/aTulasFunc/aTucadFunc masks; ToPs800 painter also present) — see [[15 - FR - Tube & Profile Machining (ToPs 400)]].

Standalone / auxiliary executables shipped alongside the editions: tc_conv.exe and pdmConvert.exe (batch/PDM format conversion — [[11 - FR - Import, Export & File Formats]]), ToPsVectorize.exe (external raster vectorisation), DWGConverter.exe (external DWG→DXF), ToPs400Export.exe (tube NC/APD export), and the external NcLink / NCLINK_GUI production-plan tool ([[20 - FR - Production Planning & Projects]]).

4.3 Database back end

Persistence uses ODBC to SQL Server, deployable either as a networked server or as locally attached MDF/MDB files (AttachSqlServerLocalMdb.bat, createSqlServerLocalMdb.bat, createSqlServerOdbcEntry.bat). The schema is organised by technology into named schemas — confirmed table counts in the snapshot: Bend (101), Punch (92), Laser (59), Tube (48), Common (27), DATADICT (20, the data dictionary), BendGripperConf (13), Text (9, localisation), Logging (6), Nest (5), InchPort (4), CAD (3), TubeCAD (2), Updates (1), plus a parallel *_inch family for imperial operation. The DATADICT data dictionary drives physical table creation, validation and per-schema versioning/migration (see [[12 - FR - Part & Data Management]]). Bending additionally consults the separate ToPs 600 database (SERVER_TOPS600). Total: 1773 SQL files across the Databases/ and Databases_SQL_2019/ trees.

4.4 PDM & MES integration

File access is abstracted by the OmAdapter / TiPdmFacet facade (tc_util/pdmUtilities) so that geometry files transparently resolve to either the local file system or the TRUMPF.NET PDM vault over CORBA. pdmConvert.exe connects to the PDM naming service (-A hostname:port, -S service, -C cache). Order import and job-state feedback to TruTops Fab flow through tc_fabAdapter and registry-discovered, licence-checked PPS plugins (see [[23 - FR - Automation, Scripting & Integration]]). Interface contracts are specified in [[30 - External Interface Requirements]].

5. Technology Stack & Platform Constraints

[!warning] Legacy platform This is a mature, historically HP-UX-origin C++ code base now built for Windows. Many constraints below are load-bearing for the requirements and are catalogued in full in [[50 - Constraints & Assumptions]].

Languages & runtimes. Predominantly C++ (built with Visual Studio 2010 / VS2010 toolset — tcolib_win_VS2010.sln, vc100.pdb), with a managed .NET layer for the GeoAlgorithmsKernel geometry kernel, the Xidl component API, TruTopsDllNET interop, and the ITM/SW06 tool-management wrapper. An embedded Python 2.5 interpreter (python25.dll, with Tk/Tkinter for ToPsGraphics and the MMK debugger) provides scripting and parametric-variant evaluation. The legacy MMK interpreter (a lex/yacc language with a mini_sql data-binding subset) and the ASM command state machine drive dialog behaviour and command dispatch.

UI framework. GRIT (Graphics Interactive Tool, GfT/Graphics mbH, since ~1989) — masks stored as .gritx (XML v2.63, UTF-8), .olb (binary runtime) and .a26 (legacy ASCII); rendering over Win32 GDI (vis_gdi, elem_win.cpp), with a legacy X11 path (elem_ux.cpp) and a headless backend (vis_none). A modern Qt front-end (ApplicationModel) is bridged to the legacy layer via tc_guiAdapter AppStates. Multi-language (up to 30 languages incl. CJK) and metric/imperial unit rendering are built in.

Persistence & data. SQL Server / attached MDB over ODBC; Xerces-based XML (.ppj projects, settings, reports); TRUMPF-native GEO/GEO_102/MI/GMT/TAF geometry files; the DATADICT-defined relational schema.

Third-party & external engines. GSSL NestLib (true-shape nesting), external ToPsVectorize (raster→vector) and DWGConverter (DWG→DXF), NcLink/DNC (NC transfer), SolidWorks (tube add-in), and the TRUMPF.NET PDM vault (CORBA).

Machines & controllers. Output is controller-specific and data-driven from the NCZYKLEN/AUS_FORMAT tables; Siemens SIN840D is directly observed, with other controllers driven through the same tables (full set not enumerated — see the open questions in [[18 - FR - NC Generation & Motion Optimization]]).

Licensing. Per-format and per-technology dongle / Wibu + password gating (TcLicenseCheck, *_PASSWORD keys), with a superuser bypass — a cross-cutting constraint recorded in [[50 - Constraints & Assumptions]] and detailed as an interface in [[30 - External Interface Requirements]].
