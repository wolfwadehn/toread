FR — Punching / Nibbling (ToPs 300)

Reverse-engineered requirement draft — derived from static analysis of legacy source, NOT an authoritative specification. Treat SHALL statements as reconstructed intent.

1. Purpose & Scope

This document specifies the functional requirements for the Punching / Nibbling technology area of the TruTops CAD/CAM suite, marketed as ToPs 300. This area assigns punching and nibbling technology to a sheet-metal part (or a populated sheet/nest) so that a coordinate-guided punch press can produce it: it selects punch/nibble tools, generates hits and nibble tracks along contours, manages micro-joints, common cutting, forming, marking, sheet clamping and repositioning, tool-hit optimization, scrap/skeleton handling and NC-relevant switching cycles.

The primary evidence module is tc_stz (German Stanzen = punching), the single largest module in the codebase (~840k LOC across stz_asm, stz_tech, stz_grit, stz_util, punchSelectionModel). Its interactive command and dialog set lives in the shared aPnLas* ("a Punch-Laser") GRIT masks under tc_bof — the punch and laser technologies share one interactive framework and one processing document model (see [[22 - FR - UI Framework, Dialogs & Interaction (GRIT)]]). Processing patterns are held in tc_bof/muster.gritx and the bearbeitungsmuster sources. Configuration and rules live in the Punch SQL schema (Databases/SQLServerDatabase/Tables/Punch.*.sql).

Editions served: ToPs 300 (full punch/nibble programming), ToPs 100 Lite (reduced-feature edition; separate ini_files/ToPs100Lite/ configuration) and ToPs 2000 (ini_files/ToPs2000/). Because the punch technology model is shared with laser, combined punch-laser machines are also programmed through this area but the laser-only capabilities are documented in [[14 - FR - Laser Cutting (ToPs 100)]].

Requirements are grounded in source directories, GRIT mask names, MMK-interpreter/mini_sql snippets, the technology-type enums in tc_stz/stz_tech/techno/tec_enum.h, and Punch database tables. Where a behaviour is inferred rather than directly read it is marked (inferred).

2. Capability Overview

  • Tool assignment — automatic (rule-driven, STANZ_REGELN) and manual activation of punch/nibble tools; multi-tool support; applicability filtering (collision, length, radius, sheet-edge, direction, clamp, no-rotation).
  • Punch & nibble along contours — single hits, "apply cutting edge to element/contour" (Anlegen), linear and circular nibbling, slitting, bolt-hole circles, hole rows and hole patterns.
  • Automatic pattern recognition — detection/conversion of single holes into hole rows and circles.
  • Common cutting (AutoCut) — shared separating cuts between nested parts, driven by named configurations.
  • Micro-joints — parametric bridges (Mikrosteg) that keep parts in the skeleton.
  • Forced sequences — user-defined mandatory processing order (Zwangsfolge).
  • Forming — forming tools including thread forming (Gewindeformen), louver/notch forming (Klinkung).
  • Marking / engraving — text and marking with punch tools (Beschriftungstext, Signieren).
  • Sheet clamping & repositioning — clamp (Pratzen) placement, dead zones, and automatic repositioning (Nachsetzen) for parts exceeding the working range.
  • Tool-hit optimization & simulation — hit-sequence / travel optimization with collision checking, interactive reordering, and step-through NC simulation.
  • Scrap & skeleton handling — destruction punching (Zerstanzen), residual strips (Reststreifen), small-parts and part disposal (Kleinteile, Ausschleusen via flap/chute/suction/lift/grip), skeleton-free processing, edge trimming (Besäumen).
  • Switching cycles — lubrication, suction, flap, punch-head position, tool-change position, sheet-thickness, calibration and customer cycles; idle strokes (Leerweg).
  • Processing patterns — store and reapply parametric processing patterns (Bearbeitungsmuster).

4. Functional Requirements

FR-PUNCH-001 — Automatic rule-based tool assignment

  • Requirement: The system shall automatically assign punch/nibble tools and generate the corresponding hits/tracks for a part's geometry by evaluating punch technology rules ordered by processing case and priority.
  • Priority: Essential
  • Rationale: Automatic technology is the core value of ToPs 300; users expect a programmable part to be machinable without manual per-element tool selection.
  • Source: Databases/SQLServerDatabase/Tables/Punch.STANZ_REGELN.sql (keys STZ_BEARB_FALL = processing case, STZ_PRIORITAET = priority, STZ_INDEX); rule tables Punch.REGEL_ALLG/REGEL10/REGEL11/REGEL12/REGEL20*; tc_stz/stz_tech/manag_ap/ (automatic placement), tc_stz/stz_tech/techno/.
  • Verification: Test — program a representative part and confirm every eligible contour receives technology per the rule set.

FR-PUNCH-002 — Guided automatic programming (technology assistant)

  • Requirement: When the user starts guided programming, the system shall present a technology assistant that drives fully automatic assignment of technology for the active sheet or programming project.
  • Priority: Essential
  • Rationale: Provides the one-click automatic path most operators use.
  • Source: GRIT mask aPnLasStartEasyProgramming → dialog_box(M_StzTechnoAssistent) (tc_bof/aPnLasAllg.gritx); tc_stz/stz_tech/assistant/.
  • Verification: Demonstration — invoke the assistant and observe an automatically technologized result.

FR-PUNCH-003 — Manual tool activation

  • Requirement: The system shall allow the user to manually activate a punch/nibble tool, including activation by picking an existing tool in the drawing and re-activation of the last-used punch tool.
  • Priority: Essential
  • Rationale: Manual override of tool choice is required whenever the automatic result is unsuitable.
  • Source: GRIT masks aPnLasActivateToolViaPick, aPnLasActivateLastPunchTool (→ FUNC_AktiviereLetztesWerkzeug, c_stanzen), tPnLasActivateTool, aPnLasOpenToolManagement (tc_bof/aPnLasProcess.gritx); tc_stz/stz_tech/manag_te/.
  • Verification: Test — pick a tool and confirm subsequent operations use it.

FR-PUNCH-004 — Tool applicability filtering

  • Requirement: When selecting a tool for an operation, the system shall reject tools that fail applicability tests for collision, edge length, radius, sheet-edge proximity, cutting direction, clamp interference, or no-rotation restriction.
  • Priority: Essential
  • Rationale: Prevents assigning physically or geometrically unusable tools; ensures manufacturable output.
  • Source: tc_stz/stz_tech/wzg_applicability/ — TcWzgKollisionTest, TcWzgLengthTest, TcWzgRadiusTest, TcWzgSheetEdgeTest, TcWzgDirectionTest, TcWzgClampTest, TcWzgNoRotTest (interface TiWzgApplicabilityTest).
  • Verification: Analysis — for each test, supply a geometry that should exclude a candidate tool and confirm exclusion.

FR-PUNCH-005 — Multi-tool support

  • Requirement: Where a multi-tool station is present, the system shall support tools that hold several punches selectable by index and rotation, and shall compute the effective punch position and offset for the selected insert.
  • Priority: Conditional
  • Rationale: Multi-tools increase station capacity but exist only on machines/tooling that support them.
  • Source: tc_stz/stz_tech/wzg/ — TcMultiTool, TcMultitoolOffset, TcAssembledPunch, TcAssembledPunchPosition, TcMultiCut, TcMultiShearBerechner; view flag tPnLasShowMultitoolCenter.
  • Verification: Test — assign a multi-tool insert and verify the resulting hit position/offset.

FR-PUNCH-006 — Single-hit punching

  • Requirement: The system shall create a single punch hit (Einzelloch) at a picked position or on a picked element using the active tool.
  • Priority: Essential
  • Rationale: The most elementary punch operation; basis for holes and standard features.
  • Source: E_tb_art::einzel_loch (tec_enum.h); GRIT mask tPnLasCreateEinzelloch; tc_stz/stz_asm/stz_hole.hpp, techno/Stanzen.h.
  • Verification: Test — place a single hit and confirm one stroke is generated.

FR-PUNCH-007 — Apply cutting edge along an element/contour

  • Requirement: When the user applies a tool cutting edge to a contour, the system shall offer single-hit, full-nibbling, partial-nibbling, and single-hit-at-two-elements modes and generate the corresponding processing along the selected geometry.
  • Priority: Essential
  • Rationale: "Anlegen" is the principal way an operator programs edges and open contours with punch/nibble tools.
  • Source: GRIT mask aPnLasCreateAnlegen (M_BearbAnlegen; branches c_einzelhub, c_nibbeln, c_nibbeln_teilw, c_eh_2_elemente; asm_call(single|t2_teilw|wzgan2elemente)); tc_stz/stz_asm/stz_hole.hpp, manag_te/TcAnlegenAn2Elemente.h.
  • Verification: Test — apply each mode to a contour and verify the generated hits/tracks.

FR-PUNCH-008 — Linear nibbling

  • Requirement: The system shall produce a straight contour segment by linear nibbling (nibb_lin) using overlapping strokes with a configurable feed/overlap between strokes.
  • Priority: Essential
  • Rationale: Nibbling straight edges with a small tool is a fundamental punch-press capability.
  • Source: E_techno_art::nibb_lin, E_tb_art::nibbeln_lin (tec_enum.h); techno/TcNibbeln.h, TcNibbelstrecke.h; GRIT tPnLasCreateElement, params aPnLasModifyParamNibbeln, aPnLasModifyUlapNibbeln (overlap/Überlappung).
  • Verification: Test — nibble a straight edge and confirm stroke spacing matches the feed setting.

FR-PUNCH-008b — Circular nibbling

  • Requirement: The system shall produce arc and circular contours by circular nibbling (nibb_cir) with configurable stroke count or feed per stroke and start/end angle.
  • Priority: Essential
  • Rationale: Round holes and arcs larger than the tool require circular nibbling.
  • Source: E_techno_art::nibb_cir, E_tb_art::nibbeln_cir (tec_enum.h); GRIT aPnLasCreateLochkreis (M_StanzenLochkreis; asm_call(t2_hole t2_circle …) with offset angle, tool co-rotation, feed-or-count, start/end angle).
  • Verification: Test — create a bolt-hole circle and verify stroke count and angular span.

FR-PUNCH-009 — Hole rows, hole patterns and slitting

  • Requirement: The system shall create parametric hole rows (Lochreihe), hole patterns/grids (Lochmuster), line-to-line features (LinLin) and slits (Schlitzen) from a single tool definition.
  • Priority: Essential
  • Rationale: Repetitive perforations and slots are common punch features that must be defined compactly.
  • Source: GRIT aPnLasCreateLochreihe, aPnLasCreateLochmuster, aPnLasCreateLinLin (tc_bof/aPnLasPunch.gritx); E_tb_art::t2_schlitzen (tec_enum.h).
  • Verification: Test — generate a hole grid and confirm hit count and spacing.

FR-PUNCH-010 — Automatic hole-row / hole-circle recognition

  • Requirement: The system shall detect collinear or co-circular single holes within user-defined angle and distance tolerances and offer to convert them into hole-row or hole-circle operations.
  • Priority: Optional
  • Rationale: Convenience that condenses many single hits into an efficient, editable operation.
  • Source: GRIT aPnLasSearchLochreihen (M_AutoChangeEinzelToLochreih; asm_call(t2_auto row parameter #angleTol #distTol), asm_call(t2_auto row …)).
  • Verification: Test — place aligned holes and confirm they are proposed as a row within tolerance.

FR-PUNCH-011 — Common cutting (AutoCut)

  • Requirement: Where the machine supports it, the system shall generate common separating cuts shared between adjacent parts according to a named AutoCut configuration.
  • Priority: Conditional
  • Rationale: Common cutting saves strokes/material but depends on machine capability and configuration.
  • Source: GRIT tPnLasStartAutoCut, tPnLasStartAutoCutEf, aPnLasParamAutoCutAusschl, aPnLasParamAutoCutEf, aPnLasReduceTool (→ FUNC_ACUT_Start); Databases/SQLServerDatabase/Tables/Punch.AUTOCUT_KONFIG.sql.
  • Verification: Test — enable AutoCut on a two-part layout and confirm a shared cut is produced.

FR-PUNCH-012 — Micro-joints (bridges)

  • Requirement: When the user creates a micro-joint on a contour, the system shall leave an uncut bridge of the specified width so the part remains attached to the skeleton.
  • Priority: Essential
  • Rationale: Micro-joints prevent parts tipping/jamming during processing and are essential for reliable production.
  • Source: GRIT aPnLasCreateMicroJoint (M_Auss_MicrojointBreite; asm_call(t2_micro_joint #width)); tc_stz/stz_asm/stz_mijo.hpp, techno/TcMicrojoint.h; E_tb_art::micro_joint.
  • Verification: Test — set a micro-joint width and measure the uncut bridge on the contour.

FR-PUNCH-013 — Forced processing sequence

  • Requirement: The system shall let the user define, invert, record and remove a forced processing sequence (Zwangsfolge) that constrains the order in which selected operations are executed.
  • Priority: Conditional
  • Rationale: Certain parts require a mandatory order (e.g. bridges cut last) that optimization must not reorder.
  • Source: GRIT aPnLasSetZwangsfolge (asm_call(t2_zwangsfolge)), aPnLasInvertZwangsfolge, aPnLasDeleteZwangsfolge, aPnLasRecZwgsfolgeStartStop, tPnLasSplitZwangsfolge (tc_bof/aPnLasProcess.gritx).
  • Verification: Test — define a forced sequence and confirm optimization preserves it.

FR-PUNCH-014 — Forming tools

  • Requirement: Where forming tooling is available, the system shall assign forming operations (Umformung) such as louvers/embosses to geometry.
  • Priority: Conditional
  • Rationale: Forming extends the punch press beyond cutting but requires specific tooling.
  • Source: E_tb_art::umformung, E_techno_art forming entries (tec_enum.h); GRIT tPnLasPushPull; tc_stz/stz_tech/wzg2/gewind.*.
  • Verification: Test — assign a forming tool and confirm a forming operation is created.

FR-PUNCH-015 — Thread forming

  • Requirement: Where thread-forming tooling is available, the system shall create thread-forming operations (Gewindeformen) using an extrusion (pre-punch) and forming tool with configurable rotation count, rotational speed, working-height offset, lubrication pulses and gear ratio.
  • Priority: Conditional
  • Rationale: In-machine thread forming eliminates a secondary tapping step but is licence/tool dependent.
  • Source: tc_stz/stz_tech/techno/Gewinde_Umformung.h (M_numberOfRotations, M_rotationalSpeed, M_workingHeightOffset, M_numberOfLubricationPulses, M_gearRatio, M_extrusionToolKey, M_prepunchingToolKey); E_techno_art::t_gewind_form; Databases/…/Punch.GEWINDEFORMER.sql, Punch.GEWINDE_WS_DICKE.sql, Punch.GEWINDE_WS_MAS.sql.
  • Verification: Test — configure a thread-forming operation and verify the pre-punch + forming pairing.

FR-PUNCH-016 — Notching / clinching (Klinkung)

  • Requirement: The system shall create notch operations (Klinkung) along contours, including undercut and notch-area analysis.
  • Priority: Conditional
  • Rationale: Corner and edge notching is a distinct punch feature with its own geometry analysis.
  • Source: GRIT aPnLasCreateKlinkung (asm_call(t2_hole klinkung)), aPnLasParamUlapKlinkung; tc_stz/stz_tech/klinkung/ — TcNotch, TcNotchAnalyzer, TcNotchArea, TcNotchUndercut.
  • Verification: Test — apply notching to a corner and confirm the notch geometry.

FR-PUNCH-017 — Marking / engraving with punch tools

  • Requirement: The system shall add marking text and scribe-marking operations (Beschriftungstext / Signieren) to a part using marking/punch tools at a specified position.
  • Priority: Conditional
  • Rationale: Part identification/marking on the press is a common requirement but depends on marking tooling.
  • Source: GRIT aPnLasCreateZyklusBelText (M_SchaltfktBelText; asm_call(t2_schalt t2_bel_text @text #pos)); techno/Signieren.h, Bel_Text_Schalten.h; E_tb_art::t2_signieren, E_techno_art::bel_text_schalten.
  • Verification: Test — add marking text and confirm the marking operation and position.

FR-PUNCH-018 — Clamp positioning

  • Requirement: The system shall determine and let the user adjust clamp (Pratzen) positions on the sheet and shall represent clamp dead zones so that operations do not collide with clamps.
  • Priority: Essential
  • Rationale: Clamp collisions damage tooling and parts; correct clamp placement is mandatory for safe NC output.
  • Source: GRIT aPnLasModifyClampPos; tc_stz/stz_asm/stz_clmp.hpp (TcClamps), maschine/ap_data.h (S_AP_Data_Fixpra: slots, used/max clamps); Databases/…/Punch.MAS_PRATZEN.sql, Punch.MAS_PRAKONT.sql, Punch.MAS_PRATZEN_DEF.sql.
  • Verification: Test — move a clamp and confirm the dead zone and collision test update.

FR-PUNCH-019 — Automatic sheet repositioning (Nachsetzen)

  • Requirement: If a part or operation lies outside the machine working range, then the system shall generate automatic sheet repositioning (Nachsetzen) moves that split processing into reachable setups (Aufspannungen).
  • Priority: Conditional
  • Rationale: Parts larger than the working range are only producible if the sheet is re-gripped; behaviour depends on machine repositioning capability.
  • Source: GRIT aPnLasStartNset (asm_call(t2_nachsetz t2_sheet auto …)), aPnLasChangeNsetPos, aPnLasRearrangeNsetAuto/Manu; tc_stz/stz_asm/stz_nset.hpp, stz_tech/nachsetzen/ (TcNachsetzer, TcAufspannung, TcAufspannungen); Databases/…/Punch.MAS_NACHSE.sql.
  • Verification: Test — program an oversized part and confirm repositioning moves are generated.

FR-PUNCH-020 — Setup (Aufspannung) navigation

  • Requirement: The system shall let the user activate, add, delete and step between individual clamping setups (Aufspannungen) of a repositioned program.
  • Priority: Conditional
  • Rationale: Editing per-setup content is required to correct repositioning results.
  • Source: GRIT aPnLasActivateAufspannungNr/Next/Prev/Pick, aPnLasDeleteAufspannung, aPnLasCreatePositionieren (tc_bof/aPnLasOptimize.gritx); stz_tech/nachsetzen/TcAufspannungsListe.h.
  • Verification: Demonstration — step through setups and confirm each shows only its operations.

FR-PUNCH-021 — Tool-hit sequence and travel optimization

  • Requirement: When the user starts optimization, the system shall compute an efficient tool-hit / head-travel sequence, honouring forced sequences and collision constraints, before NC output.
  • Priority: Essential
  • Rationale: Cycle time and tool-change count depend directly on hit ordering; optimization is core to punch programming.
  • Source: GRIT aPnLasStartOptimierung (FUNC_STZ_StartOptimierung, preceded by FUNC_StartPruefungen, c_opti collision check); tc_stz/stz_asm/stz_srt.hpp, stz_grit/stz_opti.fun, stz_tech/bea_sort/; see [[18 - FR - NC Generation & Motion Optimization]].
  • Verification: Test — optimize a program and confirm reduced/valid ordering with sequences preserved.

FR-PUNCH-022 — Interactive optimization editing

  • Requirement: The system shall allow interactive optimization in which the user reorders individual operations (first/last/before/after), inverts direction, steps to the next tool and re-optimizes travel.
  • Priority: Optional
  • Rationale: Fine manual control complements automatic optimization for special cases.
  • Source: GRIT aPnLasStartOptiInteraktiv, aPnLasInvertOptiInteraktiv, aPnLasNextToolOptiInteraktiv, aPnLasWegoptOptiInteraktiv, tPnLasRearrangeFirst/Last/Before/After (tc_bof/aPnLasOptimize.gritx).
  • Verification: Demonstration — reorder an operation interactively and confirm the sequence updates.

FR-PUNCH-023 — Processing simulation

  • Requirement: The system shall simulate the punch processing sequence with start, step, pause, continue, back, jump-to-begin/end and speed controls.
  • Priority: Conditional
  • Rationale: Visual verification of the hit sequence and collisions before machining reduces scrap.
  • Source: GRIT aPnLasStartSimulation, aPnLasStepSimulation, aPnLasPauseSimulation, aPnLasBackSimulation, aPnLasSimuJumpToBegin/End, tPnLasSetSimuSpeed (tc_bof/aPnLasOptimize.gritx); tc_stz/stz_asm/stz_simu.hpp, stz_tech/simulation/.
  • Verification: Demonstration — run the simulation and confirm stepwise playback.

FR-PUNCH-024 — Destruction punching of scrap (Zerstanzen)

  • Requirement: The system shall break scrap and internal waste into removable pieces by destruction punching (Zerstanzen), optionally as a forced sequence.
  • Priority: Conditional
  • Rationale: Large slugs/scrap must be reduced so they fall through or can be removed without jamming.
  • Source: E_tb_art::zerstanzen (tec_enum.h); GRIT tPnLasCreateZerstanzen, tPnLasSmashNibbeln (asm_call(t2_hole smash #zwf)), aPnLasSmashGts; tc_stz/stz_asm/stz_zer.hpp.
  • Verification: Test — apply destruction punching to a scrap area and confirm the breaking pattern.

FR-PUNCH-025 — Residual strip handling (Reststreifen)

  • Requirement: The system shall create, remove and cut residual skeleton strips (Reststreifen) into disposable pieces, including vertical cuts, separation strokes and clamp-turn handling.
  • Priority: Conditional
  • Rationale: Controlled skeleton disposal is needed for reliable automated material handling.
  • Source: GRIT aPnLasCreateReststreifen (asm_call(t2_ausschleussen reststreifenents)), aPnLasCreateReststrEntnehmen; tc_stz/stz_asm/TcReststreifen* (…Nibbler, …VertikalSchnitte, …Trennstrecke, …KlemmenDrehen, …Verwalter).
  • Verification: Test — create residual-strip processing and confirm the cutting pattern.

FR-PUNCH-026 — Small-parts disposal

  • Requirement: The system shall assign small-parts disposal (Kleinteile) operations that eject small cut parts via flap/chute or suction to a sorting unit, with parameters for the disposal device.
  • Priority: Conditional
  • Rationale: Small parts cannot be removed by hand economically; device availability is machine dependent.
  • Source: GRIT aPnLasParamKleinteile, tPnLasCreateKleinteile, aPnLasDeleteKleinteile (queries MAS_KLAPPE light-barrier); E_tb_art::entsorgung_kleinteile; techno/Kleinteile_Entsorgung.h; Databases/…/Punch.KLEINTEILSORTIEREINHEITEN.sql, Punch.MAS_KLAPPE.sql, Punch.SORT_EINHEIT.sql.
  • Verification: Test — assign small-parts disposal and confirm device parameters are applied.

FR-PUNCH-027 — Part ejection / disposal (Ausschleusen)

  • Requirement: The system shall assign part ejection/disposal operations (Ausschleusen) using the applicable removal method — manual removal, ejection via ejector/push-out, lift/suction unloading, or gripper — and let the user set the ejection path, position, container number and suction-cup selection.
  • Priority: Conditional
  • Rationale: Finished-part removal method depends on the machine's automation (ejector, lift, gripper) and must be programmed per part.
  • Source: GRIT aPnLasParamAusstoss, aPnLasParamHandentnahme, aPnLasParamLiftentsorgung, aPnLasModifyAusschlWeg/Pos/Modus, aPnLasModifyBehaelterNr, aPnLasModifySaugeranwahl, tPnLasCreateAusstoss/Handentnahme/Liftentnahme (tc_bof/aPnLasAusschl.gritx); E_tb_art::tb_ausschleusen, entsorgung_manuell, t2_entsorgung_lift, t2_entsorgung_grip; techno/Ausschleusen.h, Grip_Entsorgung.h, Manuell_Entsorgung.h, TcBeladenLift.h; Databases/…/Punch.AUSSCHLEUSEN.sql, Punch.SAUGER.sql, Punch.GRIP.sql.
  • Verification: Test — assign each ejection method available on a machine and confirm the generated disposal operation.

FR-PUNCH-028 — Skeleton-free processing

  • Requirement: Where enabled, the system shall support skeleton-free processing that removes all parts without leaving a coherent skeleton, and shall provide a test to check part suitability.
  • Priority: Conditional
  • Rationale: Skeleton-free running improves automation reliability but is a machine/strategy option.
  • Source: GRIT aPnLasSkeletonfreeTest (tc_bof/aPnLasRGF.gritx); tc_stz/stz_asm/stz_skeletonFreeProcessing.h; tc_stz/stz_tech/UnplannedMiniScrapPreventer/.
  • Verification: Test — run the skeleton-free test on a suitable and an unsuitable part.

FR-PUNCH-029 — Edge trimming (Besäumen)

  • Requirement: The system shall trim outer sheet edges (Besäumen) to the required format using punch (and, on combi machines, laser) trimming stations with selectable single/L-form strategies.
  • Priority: Conditional
  • Rationale: Trimming raw-sheet edges to size is required when working from oversized blanks.
  • Source: GRIT aPnLasStartBesaeumen (M_Besaeumen; asm_call(t2_besaeumen check|set …)); E_tb_art::besaeumen; tc_stz/stz_asm/stz_besaeumen.*, stz_tech/besaeumen/ (TcBesaeumManager, TcBesaeumStrategie*, TcBesaeumBearbStationStanzen).
  • Verification: Test — trim a sheet and confirm the trimmed format matches the target size.

FR-PUNCH-030 — Switching-function cycles

  • Requirement: The system shall let the user insert switching-function cycles at defined positions, including lubrication, suction, flap, punch-head position, tool-change position, sheet-thickness, calibration and customer-defined cycles.
  • Priority: Conditional
  • Rationale: Machine-specific auxiliary functions must be triggered at the right point in the program.
  • Source: tc_stz/stz_asm/stz_scht.hpp (TeSchaltFunktionTyp: bel_text, stanzkopf_lage, schmierung, absaugung, klappe, wzg_wechsel_pos, kunden_zyklus, mess_punkt, clamp_retract); GRIT aPnLasCreateZyklusAbsaugung/Klappe/Kalib/Blechdicke/WzgWechselPos, aPnLasCreateCycleClampRetract; techno/Schmierung_Schalten.h, Absaugung_Schalten.h, Klappe_Schalten.h, Stanzkopflage_Schalten.h, Wzg_Wechsel_Position.h, Kunden_Zyklus.h; Databases/…/Punch.NCZYKLEN.sql.
  • Verification: Test — insert each cycle type and confirm it appears in the operation list and NC output.

FR-PUNCH-031 — Idle strokes (Leerweg)

  • Requirement: The system shall let the user create, parameterize and delete idle (non-cutting) strokes (Leerweg), e.g. to lift the head over formed features.
  • Priority: Optional
  • Rationale: Idle strokes avoid collisions of the ram with existing raised features.
  • Source: GRIT aPnLasStartLeerweg, aPnLasParamLeerweg, aPnLasDeleteLeerweg; E_tb_art::leerweg, E_techno_art::t_leerweg; techno/Leerweg.h, TcLeerwegMemento.h.
  • Verification: Test — insert an idle stroke and confirm it produces no cut.

FR-PUNCH-032 — Measuring cycles

  • Requirement: Where the machine supports measuring, the system shall let the user place measuring operations (measure point / measure with presser foot) to check sheet position or thickness.
  • Priority: Conditional
  • Rationale: In-process measurement supports accuracy and repositioning reference but depends on machine sensors.
  • Source: E_tb_art::e_tb_measureWithPresserFoot, TeSchaltFunktionTyp::e_mess_punkt (stz_scht.hpp); GRIT tPnLasMeasureWithPresserFoot (tc_bof/aPnLasPunch.gritx), aPnLasCreateMesspunkt; techno/Messen.h, TcMeasureWithPresserFoot.h; stz_asm/stz_measureWithPresserFoot.h.
  • Verification: Test — place a measuring cycle and confirm it is emitted in the program.

FR-PUNCH-033 — Processing patterns (Bearbeitungsmuster)

  • Requirement: The system shall let the user store parameterized processing patterns and reapply them to matching geometry, filtered by machine, sheet-thickness range and pattern type/group.
  • Priority: Optional
  • Rationale: Reusable patterns speed up recurring feature programming and standardize technology.
  • Source: GRIT aPnLasSetMuster (mini_sql SELECT :BM_NAME FROM BEARBMUSTER, asm_call(t2_muster …)), aPnLasShowMusterManagement, tc_bof/muster.gritx (M_BearbMusterAuswahl, group management); tc_stz/stz_tech/bearbeitungsmuster/ (TcBearbMuster, TcMuster*); Databases/…/Punch.BEARBMUSTER.sql (BM_BEARB_TYP, BM_DICKE_VON/BIS, BM_MASCH_NAME, BM_DREHBAR), Punch.MUSTERGRUPPE*.sql, Punch.MUSTERKONTUR.sql.
  • Verification: Test — save a pattern and reapply it to a matching contour.

FR-PUNCH-034 — Copy, divide, merge and delete processing

  • Requirement: The system shall let the user copy processing to unprocessed geometry, copy-with-delete, divide, merge, and delete individual operations, parts' operations or whole-tool operations.
  • Priority: Conditional
  • Rationale: Editing existing technology is required for corrections and for reusing programmed content.
  • Source: GRIT aPnLasCopyProcToUnprocessed, aPnLasCopyProcWithDelete, aPnLasDivideBearb, aPnLasMergeBearb, aPnLasDeleteBearbeitung, aPnLasDeleteBearbTeil, aPnLasDeleteBearbTool (tc_bof/aPnLasProcess.gritx); tc_stz/stz_asm/stz_chng.hpp.
  • Verification: Test — copy processing to an unprocessed identical part and confirm the result.

FR-PUNCH-035 — Consistency checking of the punch program

  • Requirement: When the user runs the check-up, the system shall verify the punch program for issues (e.g. unprocessed geometry, contours not removed, collisions) and report them for correction.
  • Priority: Essential
  • Rationale: Detecting unprocessed geometry and collisions before NC output prevents machine faults and bad parts.
  • Source: GRIT aPnLasCheckup (FUNC_StartPruefungen, c_all, c_reset), aPnLasShowGeoNotProcessed, aPnLasShowContoursNotRemoved; tc_stz/stz_tech/bearb_chk/, ProcessingIntimeChecker/, stz_asm/stz_chk.hpp.
  • Verification: Test — leave geometry unprocessed and confirm the check reports it.

FR-PUNCH-036 — Machine, material and sheet configuration for punching

  • Requirement: The system shall let the user select/change the punch (or combi) machine, material and sheet size for the active sheet and shall load machine-specific tooling, clamps, disposal and rule data for that machine.
  • Priority: Essential
  • Rationale: All punch technology is machine- and material-specific; the correct machine dataset is a precondition for valid output.
  • Source: GRIT aPnLasChangeMachine, aPnLasChangeMaterial, aPnLasChangeSheetSize, aPnLasSelectMachine, aPnLasCreateNewSheet (tc_bof/aPnLasAllg.gritx); Databases/…/Punch.MASCHINE.sql, Punch.MAS_GRUND.sql, Punch.MAS_ALLG.sql, Punch.BLECHTYPEN.sql; tc_stz/stz_tech/maschine/.
  • Verification: Test — switch machine and confirm the tool/clamp datasets change accordingly.

FR-PUNCH-037 — Reduced feature set for ToPs 100 Lite

  • Requirement: Where the running edition is ToPs 100 Lite, the system shall present the reduced punch feature/menu set defined by that edition's configuration.
  • Priority: Conditional
  • Rationale: Lite is a licence-limited edition; feature exposure must follow its configuration.
  • Source: ini_files/ToPs100Lite/Grit100Lite.ORG, ToPs100Lite.ORG (vs. ini_files/ToPs100/Grit100.ORG); edition directories ToPs100, ToPs100Lite, ToPs2000. (inferred — exact per-feature differences not fully read)
  • Verification: Inspection — compare the Lite menu/feature configuration against the full ToPs 300 configuration.

5. External Interfaces (area-specific)

  • Punch technology database (Punch schema) — punch rules (STANZ_REGELN, REGEL_*), disposal rules (ENTSORGE_REGELN), machine data (MASCHINE, MAS_GRUND, MAS_ALLG, MAS_PRATZEN/PRAKONT, MAS_NACHSE, MAS_KLAPPE, MAS_AUSSCH, MAS_SCHMIER), tools/dies (DIE, GEWINDEFORMER, SAUGER, GRIP), sheets (BLECHTYPEN), patterns (BEARBMUSTER, MUSTERGRUPPE*, MUSTERKONTUR), AutoCut (AUTOCUT_KONFIG), NC cycles (NCZYKLEN, NCZYKLUS_STV), sorting (SORT_EINHEIT/FACH/PALETTE, KLEINTEILSORTIEREINHEITEN). See [[19 - FR - Tools, Machines, Materials & Technology]] and [[30 - External Interface Requirements]].
  • NC / control interface — the technology produces machine hits, cycles and repositioning consumed by NC generation and post-processing; see [[18 - FR - NC Generation & Motion Optimization]]. Control-version tables STEUERUNGSVERSIONEN* gate control-specific behaviour.
  • Combi punch-laser machines — this area shares the aPnLas* framework and processing model with laser cutting; laser-specific technology is in [[14 - FR - Laser Cutting (ToPs 100)]].
  • Sheet layout / multi-up (MFN, Mehrfachnutzen) — the aPnLasBeleg masks populate the sheet with parts and blocks; this overlaps [[17 - FR - Nesting & Palletizing]] (see Open Questions).
  • Configuration files — ini_files/ToPs100/*.ORG, ini_files/ToPs100Lite/*.ORG, ini_files/ToPs2000/*.ORG.

6. Assumptions & Constraints

  • The punch technology model is shared with laser through one document model and one interactive framework (aPnLas* = "a Punch-Laser"); some masks referenced here also serve laser and combi processing. Cross-cutting constraints are in [[50 - Constraints & Assumptions]].
  • All technology is machine- and material-specific; requirements assume a valid machine dataset in the Punch database is loaded (FR-PUNCH-036 is a precondition for most others).
  • The interactive layer is the legacy MMK/GRIT interpreter with embedded mini_sql; behaviour is defined partly in mask CDATA and partly in the compiled tc_stz ASM (asm_call(...)). Exact algorithm details (e.g. optimization heuristics) reside in compiled C++ not fully read here.
  • German is the source domain language; English terms in this document are translations kept alongside the original (see [[04 - Domain Model & Glossary]]).
  • Feature availability differs by edition (ToPs 100 / 100 Lite / 2000) and by licence/machine capability; such requirements are marked Conditional.

7. Open Questions & Ambiguities

  • Sheet layout / MFN ownership. aPnLasBeleg.gritx (multi-up MFN, part placement, mirroring, replace/compare parts) sits inside the punch UI but overlaps nesting/step-and-repeat. It may belong to [[17 - FR - Nesting & Palletizing]]; ownership should be confirmed.
  • GTS operations. aPnLasStartGts / aPnLasSmashGts and stz_tech/gts/ reference a "GTS" concept (TeSpecialTbArt::e_specialGts) whose exact meaning (a special scrap/gap-cut technology?) could not be determined from headers alone.
  • Twin-line / two-head machines. aPnLasTwinLineFlexible, TcEntsorgungTwinLine, TcReststreifen…VonLinks/VonRechts indicate dual-processing-zone machines; the precise programming model was not fully traced.
  • Exact Lite feature delta. FR-PUNCH-037 is inferred from the presence of separate ToPs100Lite configuration; the specific punch features removed in Lite were not enumerated from the .ORG files.
  • Master/slave and 2-axis disposal modes. TcMasterSlaveModus, stz_modEntsorgung2AchsMaschine suggest special machine kinematics for disposal not detailed here.
  • punchSelectionModel. The interactive selection model (TcPartSelectionItem, TcCatchDataSelectionItem) is used across operations; its precise selection semantics were not deeply analysed.
  • E_techno_art vs E_tb_art mapping. Two parallel enums exist (technology art and TB art); the exact one-to-one mapping and where each is authoritative was not exhaustively verified.
  • ToPs 2000 scope. The ToPs2000 edition directory exists but its relationship to the punch area (superset/variant of ToPs 300?) was not established.
