CAD Detail — Geometry Creation Commands

Detailed reverse-engineered requirements (Tier: command/algorithm level). Child of [[10 - FR - CAD Geometry & Drawing Editing]]. Reconstructed intent from static source analysis, not an authoritative spec.

1. Purpose & Scope

This document is the command/algorithm-level refinement of the geometry-creation slice of the TruTops CAD editor. It sits beneath the system-level summary [[10 - FR - CAD Geometry & Drawing Editing]] and gives every interactive GRIT creation mask and its supporting geometry-kernel command its own verifiable SHALL requirement, together with modes, parameters, defaults, units and degenerate-case behaviour.

It refines the following parent requirements: FR-CAD-001 (basic primitives — points, lines, circles, arcs, rectangles), FR-CAD-002 (rectangles with configurable corners and tabs), FR-CAD-003 (parametric hole/pattern macros) and FR-CAD-004 (TrueType text). Profile and bend-geometry creation additionally support the bending area ([[16 - FR - Bending (ToPs 600)]]) and the tube/profile area ([[15 - FR - Tube & Profile Machining (ToPs 400)]]).

Overlap note. The corner/edge feature commands fillet (Rundung), chamfer (Fase), notch (Klinkung), relief groove (Freistich) and equidistant (Äquidistante) are geometry-creation commands but are also editing operations that consume existing elements; the parent suite assigns their editing facet to [[10.2 - CAD Detail - Editing & Transformation Commands]] (FR-CAD-EDT-030..037). This document specifies them from the creation angle (the aCadCreate… masks in aCadCreateFunc.gritx and the shapes/parameters they add) and cross-references 10.2 for the editing/selection facet rather than restating it.

Architecture note (applies throughout). Each creation command is a GRIT dialog mask (tc_bof/aCadCreateFunc.gritx, tc_bof/cad_assi.gritx) whose EnterFunction runs the MMK interpreter and issues one or more asm_call( <module> <sub-command> … ) strings to the cad automat in tc_cad/cad_asm. The automat is a token state machine: init_<module>_befehl() builds states with ASM_new_state/ASM_set_data, where ASM_POINT consumes a picked/typed coordinate, ASM_REAL a numeric value (length/angle/distance/radius/diameter), ASM_INTEGER a count and ASM_TEXT a string; leading YACC_* tokens select the sub-command. Geometry work is delegated to a database command object in tc_dbase/dbase_command (TcDbase…Command), which is the transactional unit for undo/redo (TcDbaseActionManager/TcDbaseActionFactory). Coordinate input passes through the snapping engine (Fangen, see [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]]). Units follow environment variable GRITUNIT (0 = metric/mm, 1 = inch); angles are in degrees unless stated. German domain terms are linked to [[04 - Domain Model & Glossary]].

3. Detailed Requirements

FR-CAD-CRE-001 — Create point

  • Requirement: The CAD editor SHALL provide a point-creation command (aCadCreatePoint → asm_call(cad_point)) that, when the user picks or types a position, snaps the position through the selection controller (e_selectSingle/e_selectPick) and creates a point element at the snapped coordinate; the command SHALL remain active for repeated point entry until the user exits.
  • Parameters & options: one position per point (X, Y in current unit); position optionally snapped to existing geometry via the position selector (e_position). No further parameters.
  • Priority: Essential
  • Rationale: Points are the simplest construction primitive and a snapping/reference target for later commands.
  • Source: aCadCreateFunc.gritx mask aCadCreatePoint; tc_cad/cad_asm/point.cpp (store_point → bilde_punkt, undo via TcDbaseActionFactory::createdElements).
  • Verification: Test — enter a point at a typed coordinate and at a snapped intersection; assert a point element exists at the expected position.

FR-CAD-CRE-002 — Line by two points

  • Requirement: The CAD editor SHALL create a straight line segment between two entered points (aCadCreateLine2Points → asm_call(line two_pts)), chaining so that the end point of one segment MAY start the next.
  • Parameters & options: start point p1, end point p2 (both snappable). Repeated ASM_POINT entries continue a connected chain.
  • Priority: Essential
  • Rationale: Two-point line is the fundamental linear element.
  • Source: mask aCadCreateLine2Points; line.cpp init_line_befehl state YACC_TWO_PTS (store_geo_p1 → store_line).
  • Verification: Test — draw a line between two coordinates; assert endpoints.

FR-CAD-CRE-003 — Horizontal line

  • Requirement: The CAD editor SHALL create a horizontal (X-axis-parallel) line from a start point (aCadCreateLineHorizontal → asm_call(line horizontal)), where the second definition is EITHER a typed length (ASM_REAL, line_hor_laenge) OR a picked end point (ASM_POINT, line_hor) whose Y is forced to the start Y.
  • Parameters & options: start point; then length (signed, current unit) or end point.
  • Priority: Essential
  • Rationale: Constrained horizontal entry avoids accidental slope and supports numeric length entry.
  • Source: mask aCadCreateLineHorizontal; line.cpp YACC_HORIZONTAL (store_geo_p1, line_hor_laenge, line_hor).
  • Verification: Test — create by length and by point; assert the line is horizontal and of the requested length.

FR-CAD-CRE-004 — Vertical line (incl. perpendicular onto a round element)

  • Requirement: The CAD editor SHALL create a vertical (Y-axis-parallel) line from a start point (aCadCreateLineVertical → asm_call(line vertical)), the second definition being a typed length or a picked end point (X forced to start X). Where the user first selects a round element (circle/arc, token YACC_ROUND), the command SHALL instead create a line perpendicular from that round element through a picked point, optionally to a typed length (store_rundung/store_punkt/create_vert_line[_pt]).
  • Parameters & options: start point; length or end point; alternative round-element pick + point (+ optional length).
  • Priority: Essential
  • Rationale: Vertical constraint plus the radial-line-from-circle variant covers both drafting and radial construction.
  • Source: mask aCadCreateLineVertical; line.cpp YACC_VERTICAL, YACC_ROUND branch.
  • Verification: Test — vertical by length/point; and perpendicular line from a circle; assert geometry.

FR-CAD-CRE-005 — Line by point and angle

  • Requirement: The CAD editor SHALL create a line from a start point at a defined angle (aCadCreateLineAngle → asm_call(line pt_ang)). The direction SHALL be given EITHER as a typed angle (degrees, store_winkel) followed by a typed length (line_ang_laenge) or picked through-point (line_ang_pkt), OR by a second point that itself defines the angle (store_geo_p2) followed by a length/point (line_pkt_laenge/line_pkt_pkt).
  • Parameters & options: start point; angle (deg) or defining second point; length (current unit) or destination point.
  • Priority: Essential
  • Rationale: Angular line entry supports both numeric-angle and geometric (point-derived) workflows.
  • Source: mask aCadCreateLineAngle; line.cpp YACC_PT_ANG state graph (store_winkel, line_ang_laenge, line_ang_pkt, line_pkt_laenge, line_pkt_pkt).
  • Verification: Test — create at 30° with a length, and via two points; assert slope and length.

FR-CAD-CRE-006 — Parallel line (multiple offsets)

  • Requirement: The CAD editor SHALL create lines parallel to a selected linear element (aCadCreateLineParallel → asm_call(line parallel)). The offset SHALL be given by a picked side/point (line_parallel) or by one or more typed distances; the command SHALL accept up to MAX_LINE_ABST = 10 distances entered in sequence and create a parallel at each (store_abstand fills abstand[0..9]).
  • Parameters & options: reference element; side (pick) or 1..10 signed distances (current unit); parallels created relative to the reference on the picked side.
  • Priority: Essential
  • Rationale: Batch-offset (up to 10) supports laying out stiffener/rib patterns without repeating the command.
  • Source: mask aCadCreateLineParallel; line.hpp #define MAX_LINE_ABST 10; line.cpp YACC_PARALLEL (store_abstand, line_parallel_abst, line_parallel_elem).
  • Verification: Test — enter 3 distances against a reference line; assert 3 parallels at the correct offsets and side.

FR-CAD-CRE-007 — Perpendicular line onto an element

  • Requirement: The CAD editor SHALL create a line perpendicular to a selected element (aCadCreateLinePerpendicular → asm_call(line perpendic)): the user identifies the reference element, picks the foot/through point, and gives the line either by a destination point or by a typed length (line_perpendic/line_perpendic_laenge).
  • Parameters & options: reference element; base point on/near the element; destination point or length.
  • Priority: Essential
  • Rationale: Perpendicular construction is a standard drafting aid.
  • Source: mask aCadCreateLinePerpendicular; line.cpp YACC_PERPENDIC (ident_rechtw_elem, store_geo_p_rechtw, line_perpendic[_laenge]).
  • Verification: Test — drop a perpendicular from a point to a line; assert 90° and foot point.

FR-CAD-CRE-008 — Tangent line through a point

  • Requirement: The CAD editor SHALL create a line tangent to a selected round element (circle/arc) passing through a picked point (aCadCreateLineTangentPoint → asm_call(line tan_pt)): identify the round element, then pick the point/side to resolve the tangent (ident_elem_rund_pos → line_tan_pt).
  • Parameters & options: round element; through-point (also disambiguates which of the two tangents).
  • Priority: Essential
  • Rationale: Tangent-through-point is required for laser lead-ins and tangential connections.
  • Source: mask aCadCreateLineTangentPoint; line.cpp YACC_TAN_PT.
  • Verification: Test — tangent from an external point to a circle; assert tangency (distance from centre = radius at the touch point).

FR-CAD-CRE-009 — Tangent line to two round elements

  • Requirement: The CAD editor SHALL create a common tangent line to two selected round elements (aCadCreateLineTangentTangent → asm_call(line tan2)): identify the first round element, then the second (ident_elem_rund_rnd → line_tan2), with the picks selecting inner/outer tangent branch.
  • Parameters & options: two round elements; pick positions select the tangent branch.
  • Priority: Conditional
  • Rationale: Two-circle common tangents build slot/racetrack outlines and belt-like geometry.
  • Source: mask aCadCreateLineTangentTangent; line.cpp YACC_TAN2.
  • Verification: Test — build the outer common tangent of two circles; assert tangency to both.

FR-CAD-CRE-010 — Polygon (connected line chain)

  • Requirement: The CAD editor SHALL create a connected chain of line segments (aCadCreateLinePolygon → asm_call(line polygon)): after the first point, each further point appends a segment; alternatively the user MAY type an angle then a distance (store_winkel → poly_wink_abst) or an angle then a through-point (poly_wink_pkt) to append a segment by polar input.
  • Parameters & options: start point; subsequent points, or (angle deg + distance) / (angle + point) pairs; open or closed chain.
  • Priority: Essential
  • Rationale: Polyline entry is the primary way to draft open/closed contours quickly.
  • Source: mask aCadCreateLinePolygon; line.cpp YACC_POLYGON (cad_line_polygon, store_winkel, poly_wink_abst, poly_wink_pkt).
  • Verification: Test — draw a 4-segment polygon mixing point and polar entry; assert vertices.

FR-CAD-CRE-011 — Polygon by tracing existing geometry (Nachzeichnen / construct)

  • Requirement: Where the polygon command is in construct mode (aCadCreateLinePolygonConstruct → asm_call(line polygon construct), token YACC_CONSTRUCT), the CAD editor SHALL let the user trace along existing (help) geometry by picking a start and successive points, generating polyline segments that follow the traced elements (store_construct_p1 → cad_line_construct, TcCadTraceConElemSelector).

  • Source: mask tCadCreateHole; macro.cpp YACC_ROW (f_row, f_anzahl, f_abstand_*, f_row_win*, f_richten_yes/no); TcDbaseHoleRowCommand::setHoleCount/setRowIncrement/setAlignment.
  • Verification: Test — 5 holes at 20 mm pitch along 0°; assert 5 holes at correct spacing.

FR-CAD-CRE-042 — Hole grid (Lochgitter)

  • Requirement: The CAD editor SHALL create a 2-D hole grid (tCadCreateHole with c_grid → asm_call(macro grid …) → TcDbaseHoleRowCommand) extending a hole row into multiple rows: after the row parameters the user gives a row count (setRowCount, f_row_count) and a row distance (setRowDistance, f_row_distance); the grid MAY be inverted/offset per assistant (f_gridInvert).
  • Parameters & options: row parameters (per FR-CAD-CRE-041); number of rows (integer); distance between rows; alignment flag; invert flag.
  • Priority: Essential
  • Rationale: Grids of holes model perforated panels and mounting arrays.
  • Source: mask tCadCreateHole; macro.cpp YACC_GRID (f_grid, f_row_count, f_row_distance); TcDbaseHoleRowCommand::setRowCount/setRowDistance.
  • Verification: Test — 4×3 grid; assert 12 holes at the row/column spacings.

FR-CAD-CRE-043 — Hole circle (Lochkreis) by centre / points / angle

  • Requirement: The CAD editor SHALL create a hole circle (tCadCreateHole with c_circle → asm_call(macro hole_circle …) → TcDbaseHoleCircleCommand) from a centre, a hole count (setHoleCount), a radius (setCircleRadius) and a start angle + angle increment (setCircleAngles). The angular layout SHALL be definable three ways corresponding to the assistant masks: by centre (…LochkreisMitte), by points (…LochkreisPunkte — start/end points derive angles) and by angle (…LochkreisWinkel — explicit angles). Holes MAY be aligned (rotated to follow the circle, setAlignment, tokens YACC_YES/YACC_NO).
  • Parameters & options: centre; hole count; radius (value or point); start angle + increment (or end angle, or defining points); align-holes flag; tool-rotate flag.
  • Priority: Essential
  • Rationale: Bolt-circle patterns are ubiquitous; the three definition modes match how a user knows the geometry (count, points, or angles).
  • Source: masks tCadCreateHole, F_CadMacroDatenLochkreisMitte/Punkte/Winkel; macro.cpp YACC_HOLE_CIRCLE (f_circle, f_anzahl, f_anf_win*, f_end_win*, f_radius*, f_rotate_yes/no); TcDbaseHoleCircleCommand::setHoleCount/setCircleRadius/setCircleAngles/setAlignment.
  • Verification: Test — 8 holes on r=50 from 0° every 45°; assert positions; repeat via points and via angle mode.

FR-CAD-CRE-044 — Macro assistant (interactive pattern editor with local coordinate systems)

  • Requirement: The CAD editor SHALL provide an interactive macro assistant (F_CadMacro* masks + asm_call(macro new/on/off/…)) that maintains a pattern of holes with support for: activating/deactivating the assistant (YACC_ON/YACC_OFF), defining one or more local coordinate systems / origins (YACC_UNIT with origin point, absolute vs. reference-shift, X/Y inversion, and iterate/reset/suspend/remove of origins), rotating holes by an offset (YACC_ROTATE), previewing/creating (YACC_CREATE), highlighting and iterating over placed holes (last/previous/remove/restore), and editing single/row/grid/circle sub-patterns in place.
  • Parameters & options: origin point(s); absolute/relative; invert X, invert Y; rotate offset + on/off; per-pattern parameters (single point, row start/end/count/step/angle, grid count/distance, circle …).
  • Priority: Conditional
  • Rationale: The assistant lets users build and adjust complex multi-origin hole layouts before committing them.
  • Source: cad_assi.gritx F_CadMacro*, FUNC_CadMacro*; macro.cpp init_macro_befehl assistant section (f_assistentNew/On/Off/Copy, f_unit, f_origin, f_invertX/Y, f_reference*, f_rotate*, f_highlight*, f_single/row/grid/circle editor states).
  • Verification: Demonstration — build a two-origin pattern, rotate, preview and create; assert holes match the assistant preview.

FR-CAD-CRE-045 — Single hole with boolean merge into a contour

  • Requirement: Where the single-hole command is invoked in boolean mode (tCadCreateHole with c_bool → asm_call(macro single fit)), the CAD editor SHALL merge the hole shape into the contour it touches (TcDbaseSingleHoleCommand::joinSingleHole), optionally keeping only the largest result contour; if the hole touches no contour, no hole SHALL be created; and the invocation SHALL require the parameter drawing to consist of exactly one closed contour, otherwise error 11100 SHALL be raised.
  • Parameters & options: position; single-mode (largest-result-only) flag; precondition: one closed macro contour.
  • Priority: Conditional
  • Rationale: Boolean-merging a punch into an edge creates open notches/cut-ins rather than isolated holes.
  • Source: mask tCadCreateHole (c_bool, macro single fit, meldebox 11100); TcDbaseSingleHoleCommand::joinSingleHole/findJoinContour.
  • Verification: Test — merge a circle into an edge; assert the edge is cut. Test — invalid multi-contour parameter drawing → error 11100.

FR-CAD-CRE-046 — Rectangle assistant: new base rectangle (length, width, type)

  • Requirement: The CAD editor SHALL provide a rectangle assistant (F_CadRechteck* + init_rect_befehl, asm_call(… rect …), TcDbaseRectangleAssistant) that creates a rectangle/face from a length, a width and a base type (YACC_NEW → rectLength/rectWidth/rectType), and SHALL be activatable/deactivatable (YACC_ON/YACC_OFF), confirmable (YACC_CONFIRM/rectConfirm) and closable (YACC_CLOSE).
  • Parameters & options: length, width (current unit); base type (integer); assistant on/off; confirm/close.
  • Priority: Essential
  • Rationale: The assistant is the entry point for corner-treated, tabbed rectangles (blanks and bent-part blanks).
  • Source: cad_assi.gritx masks M_CadRechteckAssistent, F_CadRechteckZeileFormat/Flaeche/Typ; rect.cpp init_rect_befehl YACC_NEW (rectLength, rectWidth, rectType). Parent FR-CAD-002.
  • Verification: Test — create a 100×60 rectangle via the assistant; assert dimensions.

FR-CAD-CRE-047 — Rectangle assistant: per-corner treatment

  • Requirement: The rectangle assistant SHALL allow each corner to be independently set to one of the corner treatments — plain (setPlain/e_cornerPlain), notch/Klinkung (setNotch(p1,p2,diameter)/e_cornerNotch), chamfer/Fase (setChamfer(d1,d2)/e_cornerChamfer), rounding/Rundung (setRounding(radius)/e_cornerRounding) or undercut/Freistich (setUndercut(diameter)/e_cornerUndercut) — via corner-type + parameter entry (YACC_SET → rectCornerType/rectCornerParam), with iteration over corners (YACC_POINT start/next), per-corner preview (YACC_CHECK → rectShowChange), accept/reject (YACC_CONFIRM/YACC_REMOVE) and apply-to-all (YACC_ALL → rectChangeAllCorners).
  • Parameters & options: per corner: treatment type + its parameters (radius; two chamfer distances; two notch params + diameter; undercut diameter); iterate/preview/accept/reject/all.
  • Priority: Essential
  • Rationale: Independent per-corner treatment is the defining capability of the corner-configurable rectangle (FR-CAD-002).
  • Source: cad_assi.gritx F_CadRechteckZeileEckeSet{Rund,Fase,Klink}, …SetAll{R,F,K}, F_CadRechteckDatenRundung/Fase*/Klinkung*; rect.cpp YACC_SET/YACC_CHANGE/YACC_ALL; TcDbaseRectangleAssistant::setPlain/setNotch/setChamfer/setRounding/setUndercut, enum TeCornerType.
  • Verification: Test — set corner 1 rounded r=8, corner 2 chamfer 4×4, corner 3 notch; assert each corner geometry independently.

FR-CAD-CRE-048 — Rectangle assistant: per-edge element notch

  • Requirement: The rectangle assistant SHALL allow element notches to be placed along an edge (YACC_ELEMENT edge iteration + F_CadRechteckDatenElem*) with shape rectangle (setRectangle(height,width,radius)), triangle (setTriangle(height,angle,radius)), oblong/Langloch (setOblong(height,width)) or circle (setCircle(diameter)), and SHALL set the notch reference (local vs. global, and which side of the edge) via setElementNotchReference and edge-side flags.
  • Parameters & options: edge selection; element-notch shape + dimensions; reference (local/global, upper/lower side); centre offset along the edge.
  • Priority: Conditional
  • Rationale: Edge notches on a rectangular blank create tabs slots and locating features in one assistant.
  • Source: cad_assi.gritx F_CadRechteckZeileElem{Rechteck,Langloch,Kreis,Dreieck}, F_CadRechteckDatenElem*; rect.cpp YACC_ELEMENT edge/corner iteration; TcDbaseRectangleAssistant::setRectangle/setTriangle/setOblong/setCircle/setElementNotchReference.
  • Verification: Test — add a rectangular edge notch 10×5 on one edge; assert placement and reference.

FR-CAD-CRE-049 — Rectangle assistant: corner collision / overlap handling

  • Requirement: The rectangle assistant SHALL detect and let the user resolve collisions where adjacent corner/edge features overlap: it SHALL expose the overlap/collision form via get/set (YACC_FORM → rectGetCornerForm/rectSetCornerForm), show collisions (rectShowCollision/rectShowAllCollisions), iterate collision corners (rectFirstCollision/rectNextCollision) and support collision types (dominant/equal via setCollisionType, corner forms e_cornerDoubleAfter/Before/Equal, e_cornerSingleAfter/Before[Long], e_cornerMultiple).
  • Parameters & options: collision form selector; dominant/equal flags; iterate/show collisions.
  • Priority: Conditional
  • Rationale: Corner treatments on short edges can overlap; explicit collision resolution keeps the contour valid.
  • Source: cad_assi.gritx F_CadRechteckZeileKollision, FUNC_CadRechteckKollision, F_CadRechteckZeileEckeKoll{LO,LU,RO,RU}; rect.cpp YACC_FORM/collision states; TcDbaseRectangleAssistant::setCollisionType, corner-form enums.
  • Verification: Test — force two large adjacent corner treatments to overlap; assert a collision is reported and the chosen form resolves it.

FR-CAD-CRE-050 — Rectangle assistant: tabs (Lasche) creation and management

  • Requirement: The rectangle assistant SHALL create bend tabs (Laschen) on the rectangle with a bend direction (up/down via setBendData(top, tool)) and an associated bending tool, and SHALL manage them: create a new tab (F_CadRechteckZeileLascheNeu, with edge/side type L/O/R/U and margin), detect tab-vs-tab collisions, delete the last N tabs (F_CadRechteckZeileLascheDelete), iterate deletable/deleted tabs, and restore deleted tabs (F_CadRechteckZeileLascheWieder); tab tool data SHALL be settable (setToolData(first, toolType, values…)).
  • Parameters & options: tab edge/side (L/O/R/U); tab margin/width; bend up/down; bending tool; delete-count; restore-count; collision-free check.
  • Priority: Conditional
  • Rationale: Tabs turn a flat rectangle into a bent-part blank; managed create/delete/restore supports iterative design.
  • Source: cad_assi.gritx F_CadRechteckZeileLasche*, F_CadRechteckDatenLascheNeu, FUNC_CadRechteckErzeugeLasche/UndoLasche; rect.cpp Lasche states; TcDbaseRectangleAssistant::setBendData/setToolData and tab collision/delete/restore methods.
  • Verification: Demonstration — add two tabs (up/down), delete one, restore it; assert tab geometry and bend data.

FR-CAD-CRE-051 — Rectangle assistant: factor and tool management

  • Requirement: The rectangle assistant SHALL let the user manage the correction factors and tools it uses (M_CadRechteckFaktorVerwalten, M_CadRechteckWerkzeugVerwalten, F_CadVerwalten* masks): select/create factor and tool table entries (with a distinct set where machine ≠ 600, …No600/…NeuN6), and select upper/lower tools for corner notches (M_CadRechteckOberWzgAuswahl, M_CadRechteckUnterWzgAuswahl).
  • Parameters & options: material; factor value(s); tool identifiers (upper/lower); machine-dependent variant (600 vs. non-600).
  • Priority: Optional
  • Rationale: Corner/tab treatments depend on tooling and correction factors that must be selectable/maintainable per material and machine.
  • Source: cad_assi.gritx M_CadRechteck{Faktor,Werkzeug}Verwalten, F_CadVerwaltenZeile/Daten*, FUNC_CadRechteckUWzgVorschlag.
  • Verification: Demonstration — pick a tool and factor and apply to a corner notch; assert the values are used.

FR-CAD-CRE-052 — Group elements (block)

  • Requirement: The CAD editor SHALL group the currently selected elements into a single group/block attribute (aCadCreateGroup → asm_call(attribute block) → createGroup): the user boxes/picks elements (groupSelectStart/groupSelect), confirms (groupSelectConfirm) or selects all (groupSelectAll), and the elements are bound into one group; if only a single element is selected the command MAY warn that Ctrl (multi-select) was possibly forgotten.
  • Parameters & options: element selection (box/pick/all); group attribute created over the selection.
  • Priority: Conditional
  • Rationale: Grouping lets related elements (e.g. a logo or sub-assembly) be selected and transformed as a unit.
  • Source: mask aCadCreateGroup; tc_cad/allg_asm/attribut.cpp (createGroup, groupSelect*, single-element warning).
  • Verification: Test — group three elements; assert they select/move together as one group.

FR-CAD-CRE-053 — Profile creation editor (bent-profile cross-section)

  • Requirement: The CAD editor SHALL provide a profile-creation editor (aCadCreateProfile → dialog M_ProfilErstellung → profile automat YACC_CAD_PROFILE) that builds a bent-profile cross-section as a chain of straight line segments each defined by an angle and a length (store_lineAngle → generateLine_angle_length), with quick-key direction entry (N/S/E/W and diagonals YACC_NORTH/SOUTH/EAST/WEST/NORTHEAST/… → store_lineAngleOption), a horizontal-constrained segment (generateLine_angle_horizontal) and a vertical-constrained segment (generateLine_angle_vertical), and a BACK step to revert the last angle (YACC_BACK → setOldInitAngle).
  • Parameters & options: per segment: angle (deg, or quick-key direction) and length; horizontal/vertical constraint; back/undo of last segment.
  • Priority: Conditional
  • Rationale: The profile editor is how bent-part and tube profiles are drafted segment-by-segment.
  • Source: mask aCadCreateProfile; tc_cad/cad_asm/profile.cpp init_profile_befehl (store_lineAngle, generateLine_angle_length/horizontal/vertical, direction tokens). Cross-refs [[15 - FR - Tube & Profile Machining (ToPs 400)]].
  • Verification: Demonstration — draft a U-profile via angle/length segments; assert the cross-section.

FR-CAD-CRE-054 — Profile bumping segment

  • Requirement: Within the profile editor the CAD editor SHALL add a bumping (rolled-arc) segment (aCadCreateProfileBumping → asm_call(profilebumping)): the user gives a bumping angle (store_bumpingAngle, also via quick-key directions) and a radius (generateBumping), producing a curved profile segment approximating a bumped/rolled bend.
  • Parameters & options: bumping angle (deg); radius (current unit); direction quick-keys.
  • Priority: Conditional
  • Rationale: Bumping models roll-formed curved transitions in a profile.
  • Source: mask aCadCreateProfileBumping; profile.cpp YACC_PROFILEBUMPING (store_bumpingAngle, generateBumping).
  • Verification: Demonstration — add a bumping arc of radius r over angle a; assert the curved segment.

FR-CAD-CRE-055 — Profile Falzung (hemming) segment

  • Requirement: Within the profile editor the CAD editor SHALL add a Falzung/hemming (folded-back) segment (aCadCreateProfileFalzung → asm_call(hemming)): the user gives a hemming radius (store_hemmingRadius) and a direction/side (hemmingDirection), generating a fold-back with a following short line (generateHemming/generateHemmingOnPickedSite/generatePickedHemming + generateLine_angle_length).
  • Parameters & options: hemming radius (current unit); fold direction/side (typed value or picked); following line length.
  • Priority: Conditional
  • Rationale: Hems (folded edges) are common on sheet-metal profiles for stiffness/safety.
  • Source: mask aCadCreateProfileFalzung; profile.cpp YACC_HEMMING (store_hemmingRadius, hemmingDirection, generateHemming*).
  • Verification: Demonstration — add a hem of radius r; assert the folded-back geometry.

FR-CAD-CRE-056 — Profile XY segment

  • Requirement: Within the profile editor the CAD editor SHALL support an XY input mode (aCadCreateProfileXY → asm_call(xy)) that switches segment entry to Cartesian X/Y so a profile segment can be defined by coordinates rather than angle/length.
  • Parameters & options: X, Y for the next profile node (current unit).
  • Priority: Optional
  • Rationale: XY entry suits profiles dimensioned by coordinates rather than by turn angles.
  • Source: mask aCadCreateProfileXY; profile.cpp YACC_XY option shift.
  • Verification: Demonstration — define a segment via XY; assert node placement.

FR-CAD-CRE-057 — Create bend line (Biegelinie)

  • Requirement: The CAD editor SHALL create bend lines (aCadCreateBending → dialog M_SetBendLineParameter → bend automat YACC_BEND → create_bend_line) carrying the bend data: type/Art, method/Methode, technique/Technik, bend angle (win), V-angle (vwin), start radius (srad), end radius (erad), bend-allowance factor (afak), and upper/lower bend tools (wzgO/wzgU); the user then identifies bend-line positions by picking (create_bend_line), confirming (YACC_CONFIRM) or applying to all (YACC_ALL). The command SHALL also support changing an existing bend line's data (YACC_CHANGE), unfolding (YACC_SMOOTH, Abwicklung) and creating/stretching a bend profile (YACC_CONTOUR).
  • Parameters & options: type, method, technique (integers); angle, V-angle, start/end radius, factor (reals); upper/lower tool (strings); identify by pick/confirm/all; change/unfold/profile sub-modes.
  • Priority: Essential
  • Rationale: Bend lines drive unfolding and bending NC; the full parameter set defines the bend allowance and tooling.
  • Source: mask aCadCreateBending; tc_cad/cad_asm/cad_bieg.cpp init_bend_befehl (set_bend_type/method/tech/win/vwin/srad/erad/afak/wzgO/wzgU, create_bend_line[_confirm/_all]); TcDbaseCreateBendingCommand. Cross-refs [[16 - FR - Bending (ToPs 600)]].
  • Verification: Test — create a bend line at 90°, r=2, with tools; assert the bend attribute values and placement.

FR-CAD-CRE-058 — Automatic corner relief at bend intersections (bend round)

  • Requirement: The CAD editor SHALL create automatic corner reliefs/notches where bend lines meet edges (aCadCreateBendNotch → asm_call(bend round) → autoKlinkung): after selecting bend(s) (bend_multi_bend_selector) the user picks corners (autoKlinkung), confirms (YACC_CONFIRM) or applies to all (YACC_ALL) to insert the relief geometry required for the bend.
  • Parameters & options: bend selection; corner pick/confirm/all; relief geometry derived from the bend/material.
  • Priority: Conditional
  • Rationale: Bend corners need relief to avoid tearing; automating it from the bend data reduces manual notching.
  • Source: mask aCadCreateBendNotch; cad_bieg.cpp YACC_ROUND (bend_multi_bend_selector, autoKlinkung[Confirm/All]).
  • Verification: Demonstration — auto-relief a bent corner; assert relief geometry at the bend/edge junction.

FR-CAD-CRE-059 — Create bend tool (Biegewerkzeug) geometry

  • Requirement: The CAD editor SHALL create bend-tool cross-section geometry via an assistant (aCadCreateBendtool → dialog M_CadBendToolCreateAssistant → asm_call(bendtool …) then bendtool confirm): supporting tool type (YACC_SET integer), size/height (YACC_SIZE), angle + tip radius (YACC_ANGLE → bendToolAngle/bendToolTipRadius), a full form definition (YACC_FORM: total width, angle, groove radius, width, radius, with-radius flag), a horizontal/Horn form (YACC_HORIZONTAL: width, total width, horn flag), a polygon segment (YACC_POLYGON: angle, Z-length), an adapter/extension (YACC_EXTENSION), a start point (YACC_START), plus NEW/MODIFY iteration (angle, relative flag, length) with preview; on completion it SHALL create the front/side tool drawing and write the tool info (name from ST_CadBendToolSide: Front vs. Seite).
  • Parameters & options: type; height; angle + tip radius; form parameters (5–6 values + flag); horn form; polygon (angle, Z-length); adapter; start point; new/modify with angle/relative/length; side (front/side).
  • Priority: Conditional
  • Rationale: Bending simulation and collision checks need accurate tool cross-sections; the assistant parameterises common tool shapes.
  • Source: mask aCadCreateBendtool; tc_cad/cad_asm/bendtool.cpp init_bendtool_befehl (bendToolType/Height/Angle/TipRadius/TotalWidth/GrooveRadius/Width/Radius/WithRadius/Horn/ZLength/Adapter/New/Modify); MMK body writes tool info and fits window. Cross-refs [[16 - FR - Bending (ToPs 600)]].
  • Verification: Demonstration — create a punch tool with angle/tip-radius and form values; assert the generated cross-section and stored tool info.

FR-CAD-CRE-060 — Create parametric variant (creation aspect)

  • Requirement: The CAD editor SHALL let the user define a parametric variant during drawing creation (aCadCreateVariant → dialog M_CadVarVariante → asm_call(variant create <art> <condition>) with up to 7 parameters, then confirm): the variant SHALL carry an art/kind and an optional condition, up to seven parameter strings, an optional designation (variant 0 <name>), and SHALL bind to selected elements (variant 0 set element) unless the variant kind is one that needs no elements (kinds 9, 15–17, 19 → needElements = 0).
  • Parameters & options: variant kind (integer); condition (string); 0–7 parameters (strings); designation; element binding (conditional on kind).
  • Priority: Optional
  • Rationale: Variants parameterise a drawing for family-of-parts generation. The full variant/scripting model is specified in [[10.5 - CAD Detail - Parametric Variants & Scripting]]; this requirement captures only the creation entry point.
  • Source: mask aCadCreateVariant; MMK body asm_call(variant create …), variant 0 …, variant refresh, variant 0 set element. Parent FR-CAD-028; detailed in [[10.5 - CAD Detail - Parametric Variants & Scripting]].
  • Verification: Test — define a variant of a kind that binds elements; assert the variant and its parameters are stored.

4. Open Questions & Ambiguities

  1. Degenerate-input handling for 3-point circle/arc (collinear points) and 2-tangent circle (no solution / concentric elements) is asserted from geometric necessity but the exact error codes/messages were not confirmed in the read sources; the rejection behaviour is marked (inferred).
  2. Line pt_ang sign/orientation convention (positive angle direction, reference axis) is taken from winkel_vektoren/gerade_mit_winkel usage; the precise zero-reference (global X vs. picked element) should be confirmed against line.cpp helper winkel().
  3. Elliptical arc mask (FR-CAD-CRE-025): the arc ellipse sub-command exists in init_arc_befehl but no dedicated aCadCreate… mask was found in aCadCreateFunc.gritx; it may be invoked from another gritx (e.g. a macro/pattern mask) — entry point unconfirmed.
  4. Chamfer/fillet/notch CREATE (convert) options (YACC_CREATE) overlap with editing (converting existing lines/arcs into chamfers/fillets); the split between "creation" (this doc) and "editing" ([[10.2 - CAD Detail - Editing & Transformation Commands]]) is a documentation convention, not a code boundary.
  5. Units are assumed to follow GRITUNIT (mm/inch) as in sibling docs; per-command default values (e.g. default radius/distance seeds) were not exhaustively traced and may be read from ini/state variables (ST_Zeichnung…).
  6. Macro tool value count: TcDbaseHoleCommand::setTool exposes 8 tool values in its signature but m_toolValues[6] stores six; whether values 7–8 are persisted or transient is unclear.
  7. Rectangle assistant collision enum (TeCornerType/corner-form enums) was read partially; the full set of collision/overlap resolution rules (dominant vs. equal, single-before/after-long) needs behavioural confirmation against TcDbaseRectangleAssistant.cpp.
  8. Text reference-point and writing-direction codes (ST_TextRefPunkt, ST_TextSchreibrichtung) enumerations were not fully decoded; the 9-anchor interpretation is inferred from typical CAD text anchors.
