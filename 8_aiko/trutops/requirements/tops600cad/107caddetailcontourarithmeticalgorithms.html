CAD Detail — Contour Arithmetic Algorithms

Detailed reverse-engineered requirements (Tier: command/algorithm level). Child of [[10 - FR - CAD Geometry & Drawing Editing]]. Derived from static source analysis — reconstructed intent, not an authoritative spec.

1. Purpose & Scope

This document specifies, at the command and algorithm level, the contour arithmetic tool tc_contourArithmeticTool — the native C++ 2D boolean/hull/sweep engine of the TruTops CAD editor. It refines the following system-level requirements of the parent summary [[10 - FR - CAD Geometry & Drawing Editing]]:

  • FR-CAD-015 — Boolean contour arithmetic (union / intersection / subtraction).
  • FR-CAD-016 — Convex hull and sweep (Minkowski-style dilation) operations.
  • FR-CAD-013 — Equidistant/offset contour (the circle sweep is the round-joined offset/dilation primitive on which offsetting builds).

Where the parent doc states each capability in a single SHALL, this document decomposes each into the underlying façade commands (TcCatMainCommandHandler), the command/model architecture (TcCatModel, the action/visitor pattern, the administrator), the boolean algorithm (intersection→segmentation→classification→path assembly→nesting), the path-finder (TcCatBoolPathFinder), the convex hull construction (TcCatActCreateConvexHull), the sweep construction (TcCatActSweepBase/Circle/Rectangle), and the basic model-mutation actions (cat_action/cat_basic/*). Inputs/outputs, tolerances, robustness handling and degenerate cases (touching / coincident / contained / empty) are captured per requirement and substantiated against the extensive tc_contourArithmeticToolTest suite.

Scope boundary. The managed geometry kernels (GeoAlgorithmsKernel/GeoKernel, the third-party 2DBooleanLibrary and its Trumpf.TruTops.BooleanLibraryAdapter wrapper) are a separate, newer boolean/hull path used by nesting/technology code; they are documented under [[10.6 - CAD Detail - Geometry Kernel Algorithms]]. This document covers the legacy tc_contourArithmeticTool implementation. See Open Questions for the relationship. Domain terms are linked to [[04 - Domain Model & Glossary]]; contour-approximation feeding these operations is in [[10.8 - CAD Detail - Curve Approximation & Fourier Analysis]].

Model vocabulary (used throughout). The tool represents geometry as a tree held by an administrator: e_catRoot (top) → e_catList (unordered collection) / e_catEnvelope (a shell contour plus contained content contours = a face with holes / Kontur mit Löchern) → e_catSequence (an ordered, connected chain of primitives = one contour/Kontur) → primitives e_catLine, e_catArc, e_catCircle; e_catCluster is a non-arithmetic grouping (rejected by boolean/sweep). Source: tc_contourArithmeticTool/cat_element/TeCatElementType.h.

3. Detailed Requirements

FR-CAD-CAT-001 — Command handler façade (public tool surface)

  • Requirement: The contour arithmetic tool SHALL expose a single public façade class TcCatMainCommandHandler providing all externally callable operations — model creation, entity creation, three boolean operations (each in in-place and copy form), convex hull, circle sweep, rectangle sweep, deletion, and milestone control — and SHALL delegate every operation to a shared internal command center (M_centerPtr, reference-counted by M_handleCount), returning e_catCenterNotAvailable if the center is not available.
  • Parameters & options: Methods: createModel, createRoot{Contour,Collection}, createArc/Circle/Line/Contour/Collection, unite/intersect/subtract, createUnion/createIntersection/createSubtraction, createConvexHull, createCircleSweep, createRectangleSweep, deleteEntity, {disable,enable}AutomaticMilestones, setMilestone, getLastError. All return bool (success) with the typed error retrievable via getLastError.
  • Priority: Essential
  • Rationale: A single façade over an internal center is the tool's only supported integration contract; all higher-level CAD commands route through it.
  • Source: tc_contourArithmeticTool/TcCatMainCommandHandler.h (full API); .cpp lines 438–752 (delegation pattern, if( M_centerPtr ) … else e_catCenterNotAvailable).
  • Verification: Inspection of the façade header; Test — call any operation with no initialised center and confirm e_catCenterNotAvailable.

FR-CAD-CAT-002 — Model handle lifecycle (reference-counted smart pointer)

  • Requirement: The tool SHALL represent a geometry document by the value-type handle TcCatModel, which SHALL use reference counting (incrementReference/decrementReference) so that the underlying TiCatGeometry is destroyed only when the last handle referencing it is destroyed; a default-constructed handle SHALL be undefined (isDefined()==false) and usable only as an assignment target.
  • Parameters & options: Copy constructor, assignment, operator==/operator!=, isDefined(). The private TiCatGeometry* may only be set through the protected constructor callable by TcCatCenterBase (friend).
  • Priority: Essential
  • Rationale: Deterministic destruction of geometry without exposing internal geometry types to callers.
  • Source: tc_contourArithmeticTool/TcCatModel.h (reference-counting doc + friend TcCatCenterBase, m_geometryPtr).
  • Verification: Test — create/copy/destroy handles and confirm geometry is freed exactly once at last release.

FR-CAD-CAT-003 — Contour model structure (element hierarchy)

  • Requirement: The tool SHALL model geometry as a tree of typed elements — e_catRoot, e_catList, e_catEnvelope (shell + content), e_catSequence (ordered connected primitives), e_catCluster, and primitives e_catLine, e_catArc, e_catCircle — where a closed contour is a closed Sequence/Circle, a face-with-holes is an Envelope whose first child is the shell and remaining children are holes, and unordered results are collected in a List.
  • Parameters & options: Element types enumerated in TeCatElementType.h. Envelope shell is obtained via getShellElement; content via TcCatEnvelopeContentIterator.
  • Priority: Essential
  • Rationale: All arithmetic results are expressed in this structure (union of an outer square containing a hole becomes an envelope; multiple disjoint results become a list).
  • Source: cat_element/TeCatElementType.h; boolean result construction in TcCatActBoolOperation::execute (envelope-vs-list decision, lines 271–299) and createEnvelope/createResult.
  • Verification: Test — TcCatActBoolUnionTest::testClosedCut2 unions four rectangles into an outer ring "containing an inner square" and asserts the resulting collection/element structure.

FR-CAD-CAT-004 — Action pattern with undo/redo

  • Requirement: Every model mutation SHALL be an action implementing execute/unexecute/reexecute/getResult; composite operations (boolean, hull, sweep) SHALL be implemented purely by executing sub-actions through the administrator so that their unexecute/reexecute require no dedicated logic (undo/redo is realised by the recorded sub-actions), and SHALL raise e_catErrorActionHasNotBeenExecutedYet if undo/redo/getResult is called before execution and e_catErrorDoubleExecutionOfAction on re-entry.
  • Parameters & options: execute(errorStack, administrator, element); state guarded by m_administratorPtr and m_isUndone. Composite actions report no events from getResult to avoid double notification.
  • Priority: Essential
  • Rationale: Uniform, invertible mutation model enabling correct undo/redo of complex arithmetic.
  • Source: TcCatActBoolOperation.cpp unexecute/reexecute/getResult (lines 348–442); TcCatActSweepCircle.cpp m_isUndone guards (lines 177–290); TcCatActCreateConvexHull.cpp (lines 165–239).
  • Verification: Test — execute a boolean, undo, redo, and confirm geometry round-trips; Demonstration of double-execution error.

FR-CAD-CAT-005 — Undo/redo milestones

  • Requirement: The tool SHALL support milestones as undo/redo synchronisation points; when automatic milestones are enabled (default) a milestone SHALL be set after every model alteration, and when disabled milestones SHALL be set only by explicit setMilestone (in which case setMilestone while automatic milestones are enabled has no additional effect).
  • Parameters & options: disableAutomaticMilestones(model), enableAutomaticMilestones(model), setMilestone(model).
  • Priority: Conditional
  • Rationale: Allows callers to group several operations into one undo step.
  • Source: TcCatMainCommandHandler.h lines 329–361 (method contracts).
  • Verification: Test — disable auto milestones, run two operations, set one milestone, undo once, confirm both operations reverted.

FR-CAD-CAT-006 — Error reporting and empty-result semantics

  • Requirement: The façade SHALL store the last error as a typed TeCatClassError retrievable (and flushed) by getLastError; a boolean operation whose result is geometrically empty SHALL be reported as e_catBoolResultIsEmpty and SHALL be treated as a non-error successful outcome (not a failure), while genuine failures map to e_catInternalError, e_catInvalidEntityData, e_catEntityCouldNotBe{Created,Inserted,Removed,Deleted}, e_catUseOfUndefinedModel, or e_catCenterNotAvailable.
  • Parameters & options: Enum TeCatClassError (values 0–8, 99). Empty-result branch: if( e_catBoolResultIsEmpty == t_error ) { /* empty result is not an error */ }.
  • Priority: Conditional
  • Rationale: An intersection of disjoint contours (or a subtraction that removes everything) is a valid empty answer, not an exception.
  • Source: TcCatMainCommandHandler.h enum (lines 55–68); TcCatMainCommandHandler.cpp lines 951–995 (e_catBoolResultIsEmpty → not an error).
  • Verification: Test — intersect two non-overlapping rectangles; expect success with empty result (TcCatActBoolIntersectionTest::testClosedNoCut).

FR-CAD-CAT-007 — Entity creation commands

  • Requirement: The façade SHALL create primitive and collection entities into a specified father — createArc(centerX, centerY, radius, startAngle, arcAngle) (signed arc angle), createCircle(centerX, centerY, radius), createLine(startX, startY, endX, endY), createContour(), createCollection() — and SHALL create root-level containers via createRootContour/createRootCollection; a primitive's father MUST be a contour or collection and a collection's father MUST be a collection, else the call SHALL fail with e_catInvalidEntityData/e_catEntityCouldNotBeInserted.
  • Parameters & options: Units are drawing units; angles in radians; arc angle sign encodes orientation. Father-type constraints per method doc.
  • Priority: Essential
  • Rationale: Callers must be able to build the operands of arithmetic operations.
  • Source: TcCatMainCommandHandler.h createArc/Circle/Line/Contour/Collection/RootContour/RootCollection (lines 81–186).
  • Verification: Test — build a rectangle from four lines under a contour and confirm closure; Inspection of father-type constraints.

FR-CAD-CAT-008 — Boolean union command

  • Requirement: The tool SHALL compute the boolean union (Vereinigung) of a source entity with a closed tool entity via TcCatActBoolUnion, producing the region covered by either operand: it SHALL keep source/tool boundary segments that lie outside the other operand and discard segments lying inside the other operand, and SHALL reassemble the kept segments into result contour(s).
  • Parameters & options: unite(source, tool) (in-place) / createUnion(source, tool, result) (copy). Tool id passed to TcCatActBoolUnion(errorStack, errorCount, toolId).
  • Priority: Essential
  • Rationale: Core boolean capability refining FR-CAD-015.
  • Source: cat_boolean/TcCatActBoolUnion.cpp validateSegment (INSIDE→bad, OUTSIDE→good, lines 120–133), validateElement (INSIDE→bad, line 244).
  • Verification: Test — TcCatActBoolUnionTest::testClosedCut1 unions two overlapping 20×20 squares and asserts the exact retained-segment sums and collection count.

FR-CAD-CAT-009 — Boolean intersection command

  • Requirement: The tool SHALL compute the boolean intersection (Schnitt) of a source entity with a closed tool entity via TcCatActBoolIntersection, producing the region covered by both operands: it SHALL keep boundary segments lying inside the other operand and discard segments lying outside, and SHALL report an empty result when the operands do not overlap.
  • Parameters & options: intersect(source, tool) / createIntersection(source, tool, result).
  • Priority: Essential
  • Rationale: Core boolean capability refining FR-CAD-015.
  • Source: cat_boolean/TcCatActBoolIntersection.cpp validateSegment (INSIDE→good, OUTSIDE→bad, lines 122–133), validateElement (OUTSIDE→bad, line 245).
  • Verification: Test — TcCatActBoolIntersectionTest::testClosedCut1..6 (overlap cases) and testClosedNoCut (disjoint → empty).

FR-CAD-CAT-010 — Boolean subtraction command

  • Requirement: The tool SHALL compute the boolean subtraction (Differenz, source − tool) of a source entity with a closed tool entity via TcCatActBoolSubtraction, keeping source segments outside the tool and tool segments inside the source (the tool boundary becomes the new inner boundary/hole), and discarding source segments inside the tool and tool segments outside the source.
  • Parameters & options: subtract(source, tool) / createSubtraction(source, tool, result).
  • Priority: Essential
  • Rationale: Core boolean capability refining FR-CAD-015; asymmetric (order matters).
  • Source: cat_boolean/TcCatActBoolSubtraction.cpp validateSegment (INSIDE→bad iff source; OUTSIDE→bad iff tool, lines 122–134), validateElement (source outside-tool kept / tool inside-source kept, lines 257–266).
  • Verification: Test — TcCatActBoolSubtractionTest::testClosedCut1..7, testClosedNoCut, testOpen.

FR-CAD-CAT-011 — In-place vs copy result variants

  • Requirement: For each boolean operation the tool SHALL provide two variants: an in-place variant (unite/intersect/subtract) that MAY alter the source entity while leaving the tool entity unchanged, and a copy variant (createUnion/createIntersection/createSubtraction) that SHALL leave both source and tool unchanged and deliver the result as a newly created entity; in all variants the tool element itself SHALL never be modified.
  • Parameters & options: Copy variants add a result out-parameter. The base action never alters the tool element (documented invariant).
  • Priority: Essential
  • Rationale: Non-destructive workflows require preserving both operands.
  • Source: TcCatMainCommandHandler.h method docs (lines 198–285, "tool entity remains unchanged"); TcCatActBoolOperation.h header ("The tool element is not altered.").
  • Verification: Test — run createSubtraction and confirm source and tool entities are byte-identical afterward while result holds the difference.

FR-CAD-CAT-012 — Tool element must be closed

  • Requirement: A boolean operation SHALL require the tool element to be closed; if the tool is not itself closed but is a collection containing exactly one closed child, that child SHALL be adopted as the effective tool, otherwise the operation SHALL fail with e_catErrorBoolToolElementMustBeClosed.
  • Parameters & options: Checked in getToolElement: isClosed, else single-child fallback via TcCatConstIterator.
  • Priority: Essential
  • Rationale: Half-plane / open tools have no well-defined inside for classification.

  • Verification: Test — TcCatActSweepCircleTest::testLine.

FR-CAD-CAT-042 — Arc sub-sweep geometry

  • Requirement: For an arc the circle sweep SHALL build a band from an outer arc (radius + sweepRadius), an end loop, and either an inner arc (radius − sweepRadius) or, when the inner radius is below the 1e-4 weak tolerance, a straight line replacing it; when the sweep radius exceeds the arc radius (radius − sweepRadius ≤ 1e-9) there SHALL be no inner ring and the end loop SHALL be computed by intersecting with the centre/start line; an arc spanning > π whose endpoints are within 2·sweepRadius SHALL be split into two half-arc sub-sweeps so self-overlapping end loops are resolved by the boolean union. A full-circle arc (|arcAngle| within 1e-9 of 2π) SHALL be treated as a circle sweep.
  • Inputs/Outputs & tolerances: weak tolerance 1e-4; big-arc split when |arcAngle| > π and end-to-end distance < 2·radius + 1e-9.
  • Priority: Essential
  • Rationale: Arc bands have variable inner geometry and can self-intersect at their ends; splitting delegates the hard case to the union.
  • Source: TcCatActSweepCircle.cpp executeOnArc (447–557), addArcSweep (745–927).
  • Verification: Test — TcCatActSweepCircleTest::testArc.

FR-CAD-CAT-043 — Full-circle sweep (ring / envelope)

  • Requirement: For a full circle (or 360° arc) the circle sweep SHALL produce an outer circle of radius (circleRadius + sweepRadius); if (circleRadius − sweepRadius) > 1e-9 the result SHALL be an Envelope whose shell is the outer circle and whose single content child is an inner circle of radius (circleRadius − sweepRadius) — i.e. an annulus/ring; otherwise (sweep radius ≥ circle radius) the result SHALL be the filled outer disc only. The rectangle sweep of a circle SHALL analogously build an outer rounded-rectangle-of-arcs boundary and, when large enough, an inner boundary within an envelope.
  • Inputs/Outputs & tolerances: Inner ring threshold 1e-9 (circle) / based on rectangle half-diagonal sqrt(L²+W²)/2 (rectangle).
  • Priority: Essential
  • Rationale: A closed swept circle is a ring with a hole unless the tool is large enough to fill it.
  • Source: TcCatActSweepCircle.cpp addCircleSweep (943–1029); TcCatActSweepRectangle.cpp addCircleSweep (981–1219).
  • Verification: Test — TcCatActSweepCircleTest::testCircle (ring result).

FR-CAD-CAT-044 — Sequence-continuity optimisation

  • Requirement: When sweeping the elements of a Sequence, the tool SHALL set m_isInSequence so that each sub-sweep after the first omits its start cap (which is already covered by the previous element's end cap), and for a closed sequence the first element's start cap SHALL also be omitted; this optimisation MUST NOT change the resulting swept region (only reduce redundant overlapping geometry to be unioned).
  • Inputs/Outputs & tolerances: executeOnCollection toggles m_isInSequence per collection; closed-sequence flag from isClosed.
  • Priority: Conditional
  • Rationale: Reduces the number/overlap of boolean unions along a connected contour for performance while preserving the result.
  • Source: TcCatActSweepCircle.cpp executeOnCollection (1043–1104); line/arc start-cap suppression (396–411, 885–899).
  • Verification: Test — TcCatActSweepCircleTest::testSequence vs testList (same primitives, different continuity).

FR-CAD-CAT-045 — Singular sweep parameter rejection

  • Requirement: The tool SHALL reject singular sweep parameters at construction and at execution: a circle-sweep radius below 1e-9 SHALL raise e_catErrorSingularCircleRefused, and a rectangle-sweep length or width below 1e-9 SHALL raise e_catErrorSingularElementRefused; double execution of a sweep action SHALL raise e_catErrorDoubleExecutionOfAction.
  • Inputs/Outputs & tolerances: Threshold 1e-9 on radius/length/width.
  • Priority: Conditional
  • Rationale: A zero-size tool has no dilation effect and would create degenerate geometry.
  • Source: TcCatActSweepCircle.cpp ctor (90–96) + execute guard (140–159); TcCatActSweepRectangle.cpp ctor (98–110) + execute guard (154–167).
  • Verification: Test — create sweeps with zero radius/length/width and expect the singular-refused errors.

FR-CAD-CAT-046 — Element create / delete actions

  • Requirement: The tool SHALL provide basic actions to create an element of a given type with default values (TcCatActCreateElement, id retrieved via getLastCreatedId), to delete an element together with all its children (TcCatActDeleteElement), and to delete a single element without recursing into children (TcCatActDeleteSingleElement, used after a collection has been dissolved); deletion of a non-root or non-deletable element SHALL raise the corresponding error (e_catErrorDeletionOfNonRootElement, e_catErrorElementIsNotDeletable).
  • Parameters & options: TcCatActCreateElement(errorStack, errorCount, type); type ∈ TeCatElementType.
  • Priority: Optional
  • Rationale: These are the atomic mutations that the composite arithmetic actions are built from.
  • Source: cat_basic/TcCatActCreateElement.{h,cpp}, TcCatActDeleteElement.{h,cpp}, TcCatActDeleteSingleElement.{h,cpp}; used throughout TcCatActBoolOperation.cpp.
  • Verification: Test — TcCatActCreateElementTest, TcCatActDeleteElementTest, TcCatActDeleteSingleElementTest.

FR-CAD-CAT-047 — Child collection actions

  • Requirement: The tool SHALL provide actions to add a child (TcCatActAddChild) or list of children (TcCatActAddChildren) to a collection, remove a child (TcCatActRemoveChild) or children (TcCatActRemoveChildren), and replace a child (TcCatActReplaceChild) or children (TcCatActReplaceChildren); adding an element already present SHALL raise e_catErrorDoubleInsertionOfElement and removing an absent element SHALL raise e_catErrorElementNotContainedInCollection.
  • Parameters & options: Actions take the child id or an id list; executed against the father id.
  • Priority: Optional
  • Rationale: Collection reshaping is used by result construction, hull re-parenting and dissolving.
  • Source: cat_basic/TcCatActAddChild(ren).{h,cpp}, TcCatActRemoveChild(ren).{h,cpp}, TcCatActReplaceChild(ren).{h,cpp}.
  • Verification: Test — TcCatActAddChildTest, TcCatActAddChildrenTest, TcCatActRemoveChildrenTest.

FR-CAD-CAT-048 — Primitive data setters, clip and flip

  • Requirement: The tool SHALL provide actions to set the geometric data of primitives (TcCatActSetLineData, TcCatActSetArcData, TcCatActSetCircleData), to clip/shorten a primitive by a given amount (TcCatActClipElement), and to flip a primitive's normal/orientation (TcCatActFlipElement); these support hull construction (shrinking, line insertion, orientation) and shall reject singular results (e_catErrorSingularLineDirection, e_catErrorSingularArcRefused).
  • Parameters & options: Set-data actions take the new geometric parameters; clip takes the length to remove.
  • Priority: Optional
  • Rationale: Used by hull element shrinking/orientation and general editing.
  • Source: cat_basic/TcCatActSet{Line,Arc,Circle}Data.{h,cpp}, TcCatActClipElement.{h,cpp}, TcCatActFlipElement.{h,cpp}.
  • Verification: Test — TcCatActFlipElementTest; hull tests exercise clip/shrink.

FR-CAD-CAT-049 — Envelope shell actions

  • Requirement: The tool SHALL provide actions to set the shell of an envelope (TcCatActSetEnvelopeShell) and to remove it (TcCatActRemoveEnvelopeShell); using an envelope whose shell is unset SHALL raise e_catErrorUseOfUninitialisedEnvelope, adding a non-shell element as a shell SHALL raise e_catErrorElementIsNotAShellElement, and content operations on the shell SHALL raise e_catErrorElementIsNotAContentElement as appropriate.
  • Parameters & options: Set-shell action takes the contour id to install as shell (first child).
  • Priority: Optional
  • Rationale: Envelopes (faces with holes) are the representation of boolean results with holes and swept rings.
  • Source: cat_basic/TcCatActSetEnvelopeShell.{h,cpp}, TcCatActRemoveEnvelopeShell.{h,cpp}; used in TcCatActBoolOperation::createEnvelope/removeShell and sweep envelope creation.
  • Verification: Test — boolean/sweep tests producing envelopes; Inspection of shell errors.

FR-CAD-CAT-050 — Element creator factory

  • Requirement: The tool SHALL provide a static factory TcCatElementCreator offering convenience creation of lines, arcs, circles, sequences and envelopes directly against an administrator (CreateLine, CreateArc, CreateCircle, CreateSequence, CreateEnvelope), returning the created element's id, so that composite actions (sweep, hull) can build geometry without assembling individual create/set actions.
  • Parameters & options: e.g. CreateArc(errorStack, administrator, center, radius, startAngle, arcAngle, id); CreateEnvelope(errorStack, administrator, shellId, envelopeId).
  • Priority: Optional
  • Rationale: Centralised, reused creation logic for the algorithmic actions.
  • Source: cat_action/cat_basic/TcCatElementCreator.{h,cpp}; used by TcCatActSweepBase::addLine/addArc and both sweep subclasses.
  • Verification: Test — sweep tests (which construct all geometry through the factory).

4. Open Questions & Ambiguities

  1. Relationship to the managed Trumpf.TruTops.BooleanLibraryAdapter / 2DBooleanLibrary. The task named this GeoKernel adapter as a primary source, but the snapshot contains it only as a distributed binary (Common/3rdParty/dist/win/.NET4.0/2DBooleanLibrary/{Debug,Release}) referenced from GeoAlgorithmsKernel/GUIGeoAlgorithmsKernel/Benchmarks/TcBooleanLibraryBenchmark.cs (using Trumpf.TruTops.BooleanLibraryAdapter;). It appears to be a newer, parallel boolean engine used by nesting/technology (TcGeoArea, TcScrapFinder). Which engine the interactive CAD boolean commands actually call at runtime (legacy tc_contourArithmeticTool vs the managed adapter) is not determinable from source alone. (inferred)
  2. No rectangle-sweep unit test. The test project contains only TcCatActSweepCircleTest (and TcCatSweepPackageTest referencing only it); TcCatActSweepRectangle has no dedicated CppUnit test in this snapshot, so FR-CAD-CAT-039/041(rect)/043(rect) are verified by analysis only. This is a coverage gap worth confirming.
  3. e_catErrorBoolSegmentPathCountExceeded trigger conditions. The error exists in TeCatErrorType.h and the path-length-limit machinery (limit = 6) is present, but the exact combinatorial condition under which a boolean is abandoned as "too many paths" was not traced end-to-end. (inferred)
  4. Point-classification tolerance. Segment classification relies on TcCatVisitGetPointClassification, whose internal on-boundary tolerance was not read here (it lives in cat_visitor/cat_general); the 1e-9/1e-7 constants documented are those in the boolean/sweep/hull actions themselves. Confirm the classifier's tolerance is consistent.
  5. Interactive mask / gritx binding. This slice is a pure C++ library with a programmatic façade; the parent doc binds the user-facing masks (e.g. aCadMeltContours, hull/sweep commands) in tc_bof/*.gritx. The precise gritx mask → façade-method mapping (and any parameter dialogs for sweep radius / rectangle length-width-angle) was not verified in this document and should be cross-checked against [[10.2 - CAD Detail - Editing & Transformation Commands]].
  6. Cluster semantics. e_catCluster is explicitly rejected by both boolean (executeOnCluster → e_catErrorInvalidElementTypeForAction) and sweep (returns error). Its intended role (a non-arithmetic grouping) is inferred from usage; no positive requirement was written. (inferred)
