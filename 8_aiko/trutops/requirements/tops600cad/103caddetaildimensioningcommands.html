CAD Detail — Dimensioning Commands

Detailed reverse-engineered requirements (Tier: command/algorithm level). Child of [[10 - FR - CAD Geometry & Drawing Editing]]. Reconstructed intent from static source analysis, not an authoritative spec.

1. Purpose & Scope

This document specifies, at the command and algorithm level, the dimensioning (German: Bemaßung) subsystem of the TruTops 2D CAD drawing editor. It refines the parent system-level requirements:

  • FR-CAD-020 — Linear dimensioning (between two points / between elements / along contour / short; horizontal / vertical / aligned / free).
  • FR-CAD-021 — Angular, radius, diameter, arc-length and ordinate (X/Y) dimensioning.
  • FR-CAD-022 — Dimension text / tolerance / format editing, move, delete, defaults.

The subsystem is driven by a single interpreter/state-machine module (tc_cad/cad_asm/dim.cpp, entry init_dim_befehl()), invoked from 29 GRIT masks in tc_bof/aCadDimFunc.gritx via asm_call( dim … ). All persistent geometry lives in dimension attribute objects in tc_dbase/dbase_dim/ (TcDim*Attribute), created and mutated through command objects (TcDim*Command), with undo mediated by per-attribute memento objects and a TcDbaseActionManager action-sequence stack.

Terminology (see [[04 - Domain Model & Glossary]]): Bemaßung = dimension; Kontur = contour; Fangen = snapping; Rundung = fillet; Fase = chamfer; Toleranz = tolerance; ausgerichtet = aligned; Extensionslinie = extension/witness line; Zwilling = twin (duplicate); Nachkommastellen = decimal places.

Scope boundary: the visual generation of arrows/witness lines/text glyphs (TcDimDrawGenerator) is treated as a downstream renderer and is referenced only where it affects behaviour. Snapping/selection infrastructure is refined in [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]]. The mask-driven text dialog integration ties into [[10.5 - CAD Detail - Parametric Variants & Scripting]].

Sibling detail documents: [[10.1 - CAD Detail - Geometry Creation Commands]] · [[10.2 - CAD Detail - Editing & Transformation Commands]] · [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]] · [[10.5 - CAD Detail - Parametric Variants & Scripting]] · [[10.6 - CAD Detail - Geometry Kernel Algorithms]] · [[10.7 - CAD Detail - Contour Arithmetic Algorithms]] · [[10.8 - CAD Detail - Curve Approximation & Fourier Analysis]].

3. Detailed Requirements

FR-CAD-DIM-001 — Two-point linear dimension

  • Requirement: When the user invokes two-point linear dimensioning, the system SHALL prompt for a first point and a second point, and upon receiving two distinct points create a linear distance dimension whose orientation is either (a) aligned to the connecting line of the two points, or (b) fixed to a given angle of 0° (horizontal), 90° (vertical) or a free user-entered angle; if the two picked points are closer than 1×10⁻³ (drawing units) apart the command SHALL reject the creation and re-prompt.
  • Parameters & options: dim two_pts (aligned; m_aligned = true); dim two_pts angle 0 / angle 90 / angle <free> (non-aligned; free angle read as a real). Each picked point is snapped to a part/element and classified (see FR-CAD-DIM-024). Both points must lie in the same part (FR-CAD-DIM-028). After creation the dimension enters move/offset placement (FR-CAD-DIM-031). Prompts: msg 10770 (first point), 10771 (second point, with RUBBER_LINE feedback anchored at point 1).
  • Priority: Essential
  • Rationale: Two-point distance is the most general linear annotation and underpins all four orientation masks.
  • Source: aCadDimFunc.gritx masks aCadDimPointsLinear{Aligned,Horizontal,Vertical,Random}; dim.cpp dimPoint1(), dimPoint2() (min-distance guard abstand_pkte(...) > 0.001, lines ~4592–4700), state wiring z17..z20 (YACC_TWO_PTS); TcDimTwoPointsCommand::dimTwoPoints (aligned + angle overloads).
  • Verification: Test — dimension a known distance in each of the four orientations; verify displayed value equals the true distance and orientation matches; attempt a zero-length pick and verify rejection.

FR-CAD-DIM-002 — Element linear dimension (aligned / angled)

  • Requirement: When the user invokes element linear dimensioning and picks a single eligible element, the system SHALL create a linear length dimension of that element, oriented either parallel to the element ("aligned") or fixed to 0°, 90° or a free angle; when a fixed angle is chosen the command SHALL support dimensioning a box/ALL selection of elements sharing one part.
  • Parameters & options: dim size (aligned, single pick only — see p_dim/m_aligned); dim size angle 0|90|<free> (angle first via dimAngleElem, then element selection with pick/CONFIRM/ALL). Aligned mode picks exactly one element (getSingleSelectedElement); angled mode dimensions the confirmed selection (dimElementSize(angle,…)) and reports msg 10835 if elements span multiple parts.
  • Priority: Essential
  • Rationale: Element-based linear dimensioning is the primary way to annotate a single edge's length.
  • Source: masks aCadDimElemLinear{Aligned,Horizontal,Vertical,Random}; dim.cpp dimSizeExecute(), dimSize(), dimOptionElem(), wiring z14/z14a/z15/z16 (YACC_SIZE,YACC_ANGLE); TcDimSizeCommand::dimElementSize (both overloads).
  • Verification: Test — dimension a line of known length in each orientation; box-select several parallel edges under a fixed angle and confirm one dimension per element; verify multi-part rejection message.

FR-CAD-DIM-003 — Contour linear (extent) dimension

  • Requirement: When the user invokes contour linear dimensioning and picks a contour, the system SHALL first (re)build contours from the active geometry, then create a linear dimension of the contour's extent along a horizontal (0°), vertical (90°) or free angle.
  • Parameters & options: dim size contour angle 0|90|<free>; the mask first calls delete contour end (or delete part contour end when ST_CAD_ContourDeleteOverAll is not set) to consolidate contours before dimensioning. Contour mode forces single-pick selection (p_dim: m_dimContour ⇒ e_selectPick, e_selectNoInfo, prompt 10767). No "aligned" contour variant exists.
  • Priority: Conditional — applicable only when closed/joined contours exist.
  • Rationale: Annotating overall part/contour extent is required for bounding-size documentation.
  • Source: masks aCadDimContourLinear{Horizontal,Vertical,Random} (EnterFunction includes the contour-build preamble); dim.cpp dimContour() (YACC_CONTOUR, createSelector(e_selContour)), TcDimSizeCommand::dimContourSize.
  • Verification: Test — build a contour, dimension its extent horizontally and vertically; verify value equals the contour's bounding span along the chosen axis.

FR-CAD-DIM-004 — Short (open) linear dimension

  • Requirement: Where short-dimension mode is selected, the system SHALL create a two-point linear dimension rendered as a shortened/open dimension (one full witness/arrow, abbreviated dimension line) in aligned, horizontal, vertical or free orientation.
  • Parameters & options: dim open [angle 0|90|<free>]; sets m_short = true (dimOpen). Uses the same two-point acquisition as FR-CAD-DIM-001 (z17a..z20a, dimPoint1/dimPoint2) but passes t_isShort = true to TcDimTwoPointsCommand::dimTwoPoints; the attribute stores m_isShort and a m_shortLength.
  • Priority: Conditional
  • Rationale: Short dimensions are needed where space is limited or only one reference edge is available (e.g. symmetric parts).
  • Source: masks aCadDimShortLinear{Aligned,Horizontal,Vertical,Random}; dim.cpp dimOpen() (YACC_OPEN); TcDimTwoPointsAttributeMemento fields m_isShort, m_shortLength.
  • Verification: Test — create a short dimension in each orientation and verify shortened rendering plus correct value.

FR-CAD-DIM-005 — Angular dimension between two lines

  • Requirement: When the user invokes angular dimensioning and picks two distinct straight-line elements in the same part, the system SHALL create an angular dimension of the angle enclosed by the two lines.
  • Parameters & options: dim angle (top-level YACC_ANGLE at start state); selector restricted to lines (e_selElemLine). Rejects picking the same element twice (a_elementPtr != m_elementPtr) and rejects cross-part pairs (msg 10835). Then enters offset placement.
  • Priority: Essential
  • Rationale: Angle between edges is a fundamental GD annotation.
  • Source: mask aCadDimAngle; dim.cpp dimLine1(), dimLine2(), dimOptionLine() (z26..z28); TcDimAngleCommand::dimAngle; TcDimAngleAttribute.
  • Verification: Test — dimension the angle between two lines of known included angle; verify value; verify same-element and cross-part rejection.

FR-CAD-DIM-006 — Radius dimension

  • Requirement: When the user invokes radius dimensioning and picks a single round element (arc, fillet or circle), the system SHALL create a radius dimension of that element.
  • Parameters & options: dim radius; selector e_selElemRound (dimOptionRound). Creation via TcDimCircularCommand::dimRadius; then offset placement. Radius display angle can subsequently be rotated (FR-CAD-DIM-020).
  • Priority: Essential
  • Rationale: Radius callouts are required for arcs and fillets.
  • Source: mask aCadDimRadius; dim.cpp dimRadius() (z23, YACC_RADIUS); TcDimRadiusAttribute.
  • Verification: Test — dimension an arc of known radius; verify displayed value and "R" prefix rendering.

FR-CAD-DIM-007 — Diameter dimension

  • Requirement: When the user invokes diameter dimensioning and picks a single round element, the system SHALL create a diameter dimension of that element.
  • Parameters & options: dim diameter; selector e_selElemRound (dimOptionDiameter). Creation via TcDimCircularCommand::dimDiameter; then offset placement. Diameter display angle can subsequently be rotated (FR-CAD-DIM-020).
  • Priority: Essential
  • Rationale: Diameter callouts are required for holes and circles.
  • Source: mask aCadDimDiameter; dim.cpp dimDiameter() (z11, YACC_DIAMETER); TcDimDiameterAttribute.
  • Verification: Test — dimension a circle of known diameter; verify value and "⌀" prefix rendering.

FR-CAD-DIM-008 — Arc-length dimension

  • Requirement: When the user invokes arc-length dimensioning and picks a single arc element, the system SHALL create a dimension whose value is the developed length of that arc.
  • Parameters & options: dim length; selector e_selElemArc (dimOptionArc, single pick). Creation via TcDimArcLengthCommand::dimElementArcLength; the command rejects a second identical arc-length dimension on the same element. Then offset placement.
  • Priority: Conditional
  • Rationale: Arc length is needed where the developed (unwound) length of a curved edge matters (e.g. bending, unfolding/Abwicklung).
  • Source: mask aCadDimArcLength; dim.cpp dimLength() (z21, YACC_LENGTH); TcDimArcLengthCommand/TcDimArcLengthAttribute.
  • Verification: Test — dimension an arc of known radius and sweep; verify value equals r·θ.

FR-CAD-DIM-009 — Ordinate dimension (X / Y axis)

  • Requirement: When the user invokes ordinate dimensioning against the X or Y axis and picks a reference point, the system SHALL create a dimension of that point's coordinate distance from the drawing origin along the selected axis, implemented internally as a two-point dimension whose start point is locked to the origin.
  • Parameters & options: dim x_axis sets angle 0°; dim y_axis sets angle 90° (dimOrdinateAxis). Creation via TcDimTwoPointsCommand::dimOrdinate(point, elem, additional, angle{0|90}, …); the resulting attribute's start type is forced to e_dimLockedPoint and the end type reflects the snapped point. Then offset placement.
  • Priority: Conditional
  • Rationale: Ordinate/datum dimensioning references features to a common origin, common on sheet-metal layouts.
  • Source: masks aCadDimOrdinateX/aCadDimOrdinateY; dim.cpp dimOrdinate(), dimOrdinateAxis() (z45, YACC_X_AXIS/YACC_Y_AXIS); TcDimTwoPointsCommand::dimOrdinate; TcDimTwoPointsAttribute::e_dimLockedPoint.
  • Verification: Test — set an origin, dimension a point's X and Y ordinates; verify each equals the point's coordinate relative to origin.

FR-CAD-DIM-010 — Edit dimension text content

  • Requirement: The system SHALL allow the user to change a selected dimension's text, either (a) inline by picking a dimension and entering a new text string, or (b) via the M_ZeichnungDimText dialog which reads back the dimension's current text (split around the <> value placeholder into leading/value/trailing parts), tolerance type, tolerance values, text height and direction, and writes the edited set back atomically.
  • Parameters & options: Inline: dim dim_text change → pick (msg 10757) → new text (msg 10779) → TcDimTextCommand::setText. Dialog: dim read 'M_ZeichnungDimText' populates mask variables (dimTextTypeVar returns 1 if text contains <> else 2, dimTextBeforeVar/dimValueVar/dimTextBehindVar, tolerance type/top/bottom, size, angle); dim write applies text + size + direction + tolerances inside one action sequence (dimTolWrite); dim write stop cancels (dimTextStop).
  • Priority: Essential
  • Rationale: Overriding the auto-computed text (adding notes, symbols, fixed strings) is a core drafting need.
  • Source: mask aCadChangeDimText; dim.cpp dimText(), dimTextMask(), dimTextTypeVar()…dimTextAngleVar(), dimTextWrite(), dimTolWrite(), dimTextStop() (z29..z43, YACC_READ/YACC_WRITE/YACC_STOP); TcDimTextCommand::setText.
  • Verification: Test — edit a dimension's text inline and via the dialog; verify persistence, <> round-trip, and cancel behaviour.

FR-CAD-DIM-011 — Change dimension text direction

  • Requirement: When the user changes text direction and confirms a target direction, the system SHALL set the text writing angle of the selected dimension(s) to right (0°), up (+90°) or down (−90°).
  • Parameters & options: dim dim_text angle <dir> with dir ∈ {0,1,−1} mapped to {0°,+90°,−90°} (dimTextAngle switch). Direction value supplied by dialog M_ZeichnungDimTextDirection via #ST_DimTextDirection; applies to a picked dimension or box/ALL selection (dimTextAngleSelMulti, dimTextAnglePick/Confirm/All) through TcDimTextCommand::setTextDirection.
  • Priority: Optional
  • Rationale: Vertical/rotated text placement improves legibility on tall dimensions.
  • Source: mask aCadChangeDimTextDirection; dim.cpp dimTextAngle() (cases 1→90, −1→−90, 0→0), dimTextAngleExecute() (z3h/z3i, YACC_ANGLE under text option); msg 10793.
  • Verification: Test — apply each direction and verify text rotation on rendered dimension.

FR-CAD-DIM-012 — Change dimension text (font) size

  • Requirement: When the user changes dimension text size, the system SHALL apply a new positive font height to the picked dimension or to a box/ALL selection, rejecting non-positive sizes.
  • Parameters & options: dim dim_text size → real height (dimTextSizeMulti, guarded t_size > 0) → pick / CONFIRM / ALL (dimTextSizePick/Confirm/All → TcDimTextCommand::setTextSize(list,size)). Font height persists per attribute (TcDimAttribute::setFontHeight).
  • Priority: Conditional
  • Rationale: Per-dimension text sizing is needed to fit dense drawings and match standards.
  • Source: mask aCadChangeDimTextSize; dim.cpp dimTextSize(), dimTextSizeMulti(), dimTextSizeExecute() (z3c/z3d, YACC_SIZE); msg 10780.
  • Verification: Test — set a new size on one and on all dimensions; verify rendered height; verify a zero/negative entry is rejected.

FR-CAD-DIM-013 — Apply / edit tolerances

  • Requirement: The system SHALL allow application of a top and bottom tolerance value and a tolerance presentation type to a dimension, where the type is one of: none (1), upper only (2), lower only (3), both (4), symmetric/equal (5), or applied limits (6).
  • Parameters & options: Interactive path dim tol → pick → top tolerance (msg 10760) → bottom tolerance (msg 10761) → type 1–6 (msg 10762) → TcDimToleranceCommand::setTolerances(attr,type,top,bottom). Same triple is also written by the text dialog (FR-CAD-DIM-010, dimTolWrite). Type mapping via getToleranceType(); stored on the attribute (m_toleranceType, m_topTolerance, m_bottomTolerance).
  • Priority: Essential
  • Rationale: Tolerancing is mandatory for manufacturing drawings.
  • Source: dim.cpp dimTopTol(), dimBottomTol(), dimTolType(), getToleranceType() (z6..z9, YACC_DIM_TOL); TeDimEnumTypes.h TeDimToleranceType; TcDimToleranceCommand.
  • Verification: Test — apply each of the six presentation types with sample values; verify rendered tolerance block matches type.

FR-CAD-DIM-014 — Move (offset) a dimension

  • Requirement: When the user picks a dimension and then a new position, the system SHALL recompute the dimension's offset so that its dimension line passes through (or as near as possible to) the new position, without altering the measured value.
  • Parameters & options: dim move → pick dim (msg 10758) → new position (msg 10759, live preview) → TcDimOffsetCommand::setOffsetPoint(attr,position). If the moved attribute is the one just created (chained move) the move action is merged into the creation action sequence and the affected elements are refreshed. Offset interpretation is attribute-specific.
  • Priority: Essential
  • Rationale: Placement control (standoff distance) is required for readable drawings and is the mandatory final step of every creation command.
  • Source: mask aCadMoveDim; dim.cpp dimMove(), dimMoveSingle(), dimPickAndHide() (z4/z5, YACC_MOVE); TcDimOffsetCommand::setOffsetPoint; TcDimAttribute::setOffset/setOffsetPoint.
  • Verification: Test — move a dimension line and verify offset changes while value is unchanged; verify chained move undoes together with creation.

FR-CAD-DIM-015 — Move dimension text

  • Requirement: When the user picks a dimension and then a new text position, the system SHALL store the text position as an offset relative to the dimension centre without changing the dimension geometry or value.
  • Parameters & options: dim dim_text move → pick text (msg 10757) → new position (msg 10756, live preview) → TcDimTextCommand::setTextPosition(attr,position); stored via TcDimAttribute::setTextVector (relative to getElementMiddle).
  • Priority: Conditional
  • Rationale: Repositioning text avoids clashes with geometry and other annotations.
  • Source: mask aCadMoveDimText; dim.cpp dimTextMove(), dimTextPickAndHide() (z2/z3a/z3b, text YACC_MOVE).
  • Verification: Test — drag a dimension's text to a new location; verify text moves while dimension line/value are unchanged.

FR-CAD-DIM-016 — Delete dimension(s)

  • Requirement: When the user selects one or more dimensions (by pick, box or ALL) and confirms, the system SHALL delete the selected dimension attributes; the operation SHALL be undoable.
  • Parameters & options: dim remove → multi-selection (dimOptionDimMulti) → pick / CONFIRM / ALL (dimDelete/Confirm/All) → TcDimDeleteCommand::deleteDimAttributeList. A separate API deletes all dimensions of a drawing (deleteAllDimAttributes). Prompt msg 10766; selection info level = count.
  • Priority: Essential
  • Rationale: Removing obsolete/incorrect dimensions is a basic edit.
  • Source: mask aCadDeleteDim; dim.cpp dimDeleteExecute(), dimDelete()/Confirm()/All() (z10, YACC_REMOVE); TcDimDeleteCommand.
  • Verification: Test — delete via pick, box and ALL; verify removal and undo restore.

FR-CAD-DIM-017 — Set default dimension text height

  • Requirement: When the user sets a default dimension text height, the system SHALL store it as the default font size applied to subsequently created dimensions.
  • Parameters & options: dim dim_text size default <size> (value #ST_DimFormatDefaultTextSize from dialog M_ZeichnungDimDefaultTextSize); dimDefaultTextSize() → setDimDefaultTextSize() → TcDimDrawManager::setFontSize.
  • Priority: Conditional
  • Rationale: A consistent default height avoids per-dimension sizing effort.
  • Source: mask aCadSetDimDefault; dim.cpp dimDefaultTextSize() (z3k, YACC_DEFAULT); TcDimDrawManager::setFontSize/getFontSize.
  • Verification: Test — set a default, create a new dimension, verify its text height equals the default.

FR-CAD-DIM-018 — Set decimal precision (value & tolerance)

  • Requirement: When the user sets the dimension format, the system SHALL set the number of decimal places used to render dimension values and tolerances independently, and SHALL invalidate existing dimension visualizations so they re-render at the new precision.
  • Parameters & options: show dim_show <valuePrecision> <tolerancePrecision> (#ST_DimFormatValuePrecision, #ST_DimFormatTolerancePrecision from dialog M_ZeichnungDimFormat); realized by TcDimDrawManager::setPrecision(value,tolerance) where value = −1 means "no override" and tolerance = −1 means "same as value"; invalidateAttributes() forces recompute.
  • Priority: Essential
  • Rationale: Decimal precision governs conformance to drawing standards and rounding of displayed measurements.
  • Source: mask aCadSetDimFormat (wraps calls in undo sequenz start/stop); TcDimDrawManager.h setPrecision/getPrecision/invalidateAttributes.
  • Verification: Test — set value precision 2 and tolerance precision 3; verify rendered strings; change precision and verify existing dimensions re-render.

FR-CAD-DIM-019 — Set dimension arrow size

  • Requirement: When the user sets the dimension format arrow size to a positive value, the system SHALL set the length of dimension arrows for the drawing and record an undo action; a non-positive value SHALL be rejected.
  • Parameters & options: dim vertex <arrowSize> (#ST_DimFormatArrowSize); dimArrowSize() guards t_size > 0, registers changeDimArrowSize() undo action, then setDimArrowSize() → TcDimDrawManager::setArrowLength.
  • Priority: Conditional
  • Rationale: Arrow sizing is a drawing-standard/legibility setting.
  • Source: mask aCadSetDimFormat; dim.cpp dimArrowSize() (z44, YACC_VERTEX); TcDimDrawManager::setArrowLength/getArrowLength.
  • Verification: Test — set arrow size, verify rendered arrow length and undo; verify zero/negative rejected.

FR-CAD-DIM-020 — Rotate radius / diameter display angle

  • Requirement: Where a radius or diameter dimension is selected, the system SHALL allow rotating its display angle (the leader/callout orientation) to a new user-supplied angle without changing the measured radius/diameter value.
  • Parameters & options: dim radius … rotate / dim diameter … rotate → pick existing radius/diameter dim (type-checked e_dbaseDimRadiusAttribute / e_dbaseDimDiameterAttribute) → new angle (real or picked point, msg 10763/10764) → TcDimCircularCommand::setRadiusAngle / setDiameterAngle.
  • Priority: Optional
  • Rationale: Callout direction control avoids overlaps on dense circular features.
  • Source: dim.cpp dimRadiusPick()/dimRadiusRotate() (z24/z25) and dimDiameterPick()/dimDiameterRotate() (z12/z13), both under YACC_ROTATE; TcDimCircularCommand.h.
  • Verification: Test — rotate a diameter callout and verify orientation changes while value is constant.

FR-CAD-DIM-021 — Set dimension layout style

  • Requirement: The system SHALL support two dimension layout styles — standard (text breaks the dimension line) and enhanced (text sits on the dimension line) — and SHALL position dimension text accordingly for linear dimensions.
  • Parameters & options: dim form <style> with style 1 ⇒ e_dimEnhancedLayout, else e_dimStandardLayout (dimLayout); TcDimDrawManager::setLayoutStyle/getLayoutStyle. TcDimAttribute::setTextLayoutPosition() places text above/below the line in enhanced style.
  • Priority: Optional
  • Rationale: Layout style matches differing regional/company drawing conventions.
  • Source: dim.cpp dimLayout() (z46, YACC_FORM); TcDimDrawManager.h TeDimLayoutStyle {e_dimStandardLayout=1, e_dimEnhancedLayout=2}; TcDimAttribute::setTextLayoutPosition.
  • Verification: Demonstration — toggle layout style and verify text placement relative to the dimension line.

FR-CAD-DIM-022 — Dimension visualization colour

  • Requirement: On activation of the dimensioning subsystem, the system SHALL display dimension visualizations in the colour configured in the system ruleset, and SHALL keep this colour synchronized when set via dim set.
  • Parameters & options: start_dim fetches SRW_DimensioningColor via DBInterface::GetValue and applies it (setDimColor, showDimAttributes, drawAllDimAttributes) if dimensions were not already visible; dim set (dimSet) re-reads the ruleset value and applies it via TcDimDrawManager::setColor.
  • Priority: Conditional
  • Rationale: Consistent, configurable dimension colour distinguishes annotations from geometry.
  • Source: dim.cpp start_dim() (lines ~3279–3295), dimSet() (YACC_SET); TcDimDrawManager::setColor/getColor; ruleset keys SRW_DimensioningColorPtr/DMV.
  • Verification: Inspection/Test — change the ruleset colour; enter dimensioning and verify dimension render colour.

FR-CAD-DIM-023 — Dimension attribute object model

  • Requirement: Every dimension SHALL be represented as a TcDimAttribute (subclass of TcDbaseAttribute) carrying: overridable text (with <> placeholder), relative text vector, offset, tolerance type + top/bottom tolerance, font height, text direction (deg), a validity flag for its cached visualization, and an element-type hint for rendering; each concrete type SHALL implement getValue(), recalculate(), getElementStart/Middle/End(), getStart/EndNormal(), getExtensionType() and isIdentical().
  • Parameters & options: Element-type hints: e_linearElement, e_arcElement, e_shortLineElement, e_linearNoArrows. Concrete attributes: TcDimTwoPointsAttribute (incl. ordinate), TcDimSizeAttribute, TcDimAngleAttribute, TcDimRadiusAttribute, TcDimDiameterAttribute, TcDimArcLengthAttribute, TcDimStaticArcAttribute.
  • Priority: Essential
  • Rationale: A common base defines the polymorphic contract the renderer, snapper and undo rely on.
  • Source: TcDimAttribute.h (full interface); concrete TcDim*Attribute.h.
  • Verification: Inspection — confirm each concrete attribute implements the pure-virtual contract; Test — read/write round-trip of the base fields.

FR-CAD-DIM-024 — Element-anchored points and auto-recalculation

  • Requirement: For dimensions anchored to geometry, each anchor point SHALL be classified by type, and the dimension SHALL automatically recalculate its value and geometry when the referenced elements change (move, split, merge, edit); on element split the dimension SHALL choose the best-fit sub-segment to keep dimensioning.
  • Parameters & options: Point types (TcDimTwoPointsAttribute::TeDimPointType): e_dimLockedPoint (0, no element), e_dimEndPoint (1), e_dimMiddlePoint (2), e_dimDegree0/90/180/270Point (3–6, arc cardinal points), e_dimVirtualCorner (7). Lifecycle hooks: prepareRecalculation(), adjustInternalElements(old,new), getBestFit(orig,new,useOrig,useNew), recalculate().
  • Priority: Essential
  • Rationale: Associative dimensions must track edited geometry to stay correct.
  • Source: TcDimTwoPointsAttribute.h (point-type enum + lifecycle methods); TcDimAttribute::recalculate (pure virtual).
  • Verification: Test — dimension an edge, move/trim it, and verify the dimension value and endpoints update; split an edge and verify best-fit segment is retained.

FR-CAD-DIM-025 — Duplicate ("twin") dimension avoidance

  • Requirement: Before creating a dimension, the system SHALL check for an existing identical dimension (same elements / points / angle) via getTwin()/isIdentical(); if a twin exists the new attribute SHALL NOT be created and the creation action sequence SHALL be aborted, with the existing dimension reported as the result.
  • Parameters & options: Each creation command returns getLastAttribute(bool& isTwin); when isTwin is true the caller aborts the action sequence (abortActionSequence) and suppresses feedback (m_feedbackAttributePtr = 0). Applies to size, two-points, arc-length, angle, radius, diameter creation.
  • Priority: Conditional
  • Rationale: Prevents clutter and redundant/ambiguous annotations.
  • Source: TcDimCommand::getTwin, TcDimAttribute::isIdentical; dim.cpp dimSizeExecute, dimPoint2, dimLength, dimLine2, dimRadius, dimDiameter (a_twin handling / abortActionSequence).
  • Verification: Test — dimension the same feature twice identically; verify only one dimension exists and no spurious undo step.

FR-CAD-DIM-026 — Eligible-element constraint

  • Requirement: The system SHALL permit dimensioning only of eligible element types: lines, chamfers (Fase), arcs (Bogen), fillets (Rundung) and circles; ineligible picks SHALL be rejected. Point acquisition for two-point dimensions additionally accepts point (PUNKT) and text (DB_TEXT) reference geometry.
  • Parameters & options: TcDimCommand::isValidDimElement (lines/chamfers/arcs/fillets/circles). getDimElement accepts LINIE, FASE, KREIS, BOGEN, RUNDUNG, DB_TEXT, PUNKT for endpoint snapping. Round-only selectors (e_selElemRound) gate radius/diameter; arc-only (e_selElemArc) gates arc length; line-only (e_selElemLine) gates angular.
  • Priority: Essential
  • Rationale: Restricting to measurable geometry prevents undefined dimensions.
  • Source: TcDimCommand.h isValidDimElement; dim.cpp getDimElement() type switch (lines ~4415–4421), selector types in TeDimSelectorType.
  • Verification: Test — attempt to dimension each ineligible/eligible type; verify acceptance/rejection.

FR-CAD-DIM-027 — Snap acquisition algorithm for two-point dimensions

  • Requirement: For two-point dimensioning, when the user picks near geometry the system SHALL first attempt to catch an element in the active part, then (on failure) in the configured catch range, and SHALL snap the picked coordinate to the nearest of the caught element's characteristic points; if no element is caught it SHALL attempt to catch a circle/arc/fillet centre point and identify the owning element.
  • Parameters & options: getDimElement(x,y): sets catch mode e_catchElements, range AKTIV_TEIL then falls back to m_fangBereich; retrieves up to three element points (holeElementPunkte) and selects the minimum-distance point (betrag_vektor); centre fallback uses e_catchPoints and matches index 0 (circle) or 2 (arc/fillet). Catch mode/range are saved and restored around the operation. dim restricts snapping to the active part when dimPart set m_fangBereich = AKTIV_TEIL.
  • Priority: Essential
  • Rationale: Robust snapping to true endpoints/centres is required for accurate, repeatable dimensions.
  • Source: dim.cpp getDimElement() (lines ~4379–4553), dimPart(); catch API db_setze_fang_modus/db_setze_fang_bereich, cad_fange_pick_punkt.
  • Verification: Test — pick near an endpoint and near a circle centre; verify the snapped coordinate equals the true endpoint/centre.

FR-CAD-DIM-028 — Same-part constraint for two-element/two-point dimensions

  • Requirement: If the two references of a two-point or angular dimension do not belong to the same part, the system SHALL reject the creation and inform the user.
  • Parameters & options: dimPoint2 and dimLine2 compare the resolved part pointers (S_dimDataPtr->m_partPtr == a_partPtr); on mismatch they emit info message 10835 ("Elemente befinden sich nicht im selben Teil" — elements are not in the same part) and do not create the dimension.
  • Priority: Conditional
  • Rationale: Cross-part distances are generally undefined for the associative model.
  • Source: dim.cpp dimPoint2() (line ~4613/4684), dimLine2() (line ~5044/5091), db_get_text(10835).
  • Verification: Test — pick references in two different parts; verify rejection and message.

FR-CAD-DIM-029 — Value placeholder substitution in text

  • Requirement: When a dimension's overridable text contains the token <>, the renderer SHALL substitute the token with the computed dimension value; the text editor SHALL split stored text into leading text, the <> value marker, and trailing text so the value part remains dynamic.
  • Parameters & options: TcDimAttribute::setText documents <> replacement; dimTextTypeVar returns type 1 (dynamic, contains <>) vs 2 (literal); dimTextBeforeVar returns the substring before <>, dimTextBehindVar the substring after (index("<>")), dimValueVar returns the current computed value.
  • Priority: Conditional
  • Rationale: Preserving a dynamic value while adding prefixes/suffixes (e.g. "R<>" , "<> ±0.1") keeps text correct after edits.
  • Source: TcDimAttribute.h setText doc; dim.cpp dimTextTypeVar(), dimTextBeforeVar(), dimTextBehindVar(), dimValueVar() (lines ~5138–5214).
  • Verification: Test — set text "⌀<> H7", edit the geometry, verify the value portion updates while prefix/suffix remain.

FR-CAD-DIM-030 — Measured value semantics per dimension type

  • Requirement: Each dimension's reported value (getValue()) SHALL equal the correct geometric quantity for its type: linear/two-point → straight distance along the dimension direction; angular → included angle between the two lines; radius → element radius; diameter → 2×radius; arc length → developed arc length; ordinate → coordinate offset from origin along the selected axis.
  • Inputs/Outputs & tolerances: Inputs are the anchored geometry/points; output is a double consumed by text rendering and precision formatting (FR-CAD-DIM-018). Two-point value uses the projected/aligned length per m_angle/m_aligned; memento stores m_length, m_angle, m_shortLength.
  • Priority: Essential
  • Rationale: The measured value is the entire purpose of a dimension; correctness is critical.
  • Source: TcDimAttribute::getValue (pure virtual) with per-type implementations in TcDim{TwoPoints,Size,Angle,Radius,Diameter,ArcLength}Attribute.cpp; TcDimTwoPointsAttributeMemento (m_length,m_angle).
  • Verification: Analysis + Test — for each type, compare getValue() against an independently computed reference for known geometry.

FR-CAD-DIM-031 — Offset / placement control

  • Requirement: The system SHALL store, per dimension, a placement offset that positions the dimension drawing relative to the dimensioned geometry, settable either directly (scalar offset) or by supplying a point through which the dimension line should pass; offset interpretation SHALL be attribute-specific.
  • Parameters & options: TcDimAttribute::setOffset(double), setOffsetPoint(TcVector) (pure virtual per type), getOffset(); TcDimOffsetCommand::setOffsetPoint(attr,position) is the command wrapper used by all move/placement flows.
  • Priority: Essential
  • Rationale: Every creation ends in placement; offset defines standoff and side.
  • Source: TcDimAttribute.h (setOffset/setOffsetPoint/getOffset); TcDimOffsetCommand.h.
  • Verification: Test — set offset by point and by scalar; verify dimension line passes through / stands off as specified.

FR-CAD-DIM-032 — Extension (witness) line type

  • Requirement: Each dimension SHALL declare an extension-line type governing whether witness lines are drawn and how far: none, short, or long (extended to the dimensioned point); the type SHALL in general be determined by the dimension kind.
  • Parameters & options: TeDimExtensionType {e_dimExtensionNone=0, e_dimExtensionShort=1, e_dimExtensionLong=2}; TcDimAttribute::getExtensionType() (virtual); stored per two-point attribute (m_extensionType).
  • Priority: Conditional
  • Rationale: Witness-line behaviour is part of drawing-standard compliance and readability.
  • Source: TeDimEnumTypes.h; TcDimAttribute::getExtensionType; TcDimTwoPointsAttributeMemento::m_extensionType.
  • Verification: Inspection/Demonstration — verify each dimension type renders the documented witness-line style.

FR-CAD-DIM-033 — Undo / memento model for dimensions

  • Requirement: All dimension create/modify/delete operations SHALL be undoable via a memento capturing the attribute's internal state (excluding associated elements and cached visualization, which are regenerated), and SHALL be grouped into atomic action sequences via TcDbaseActionManager (start/end/abort), so that a compound operation (e.g. create-then-place, or format change) undoes as one step.
  • Parameters & options: Per-type mementos (TcDim*AttributeMemento) store geometry/value/angle/tolerance/short-length etc.; startActionSequence/endActionSequence/abortActionSequence; format mask wraps precision+arrow changes in undo sequenz start/stop; chained move merges into the creation sequence (FR-CAD-DIM-014).
  • Priority: Essential
  • Rationale: Reliable, correctly-grouped undo is required for an interactive editor.
  • Source: TcDimTwoPointsAttributeMemento.h (and sibling *Memento.h); dim.cpp action-sequence calls throughout; aCadSetDimFormat undo sequenz start/stop.
  • Verification: Test — undo/redo each operation; verify create+place and format changes each undo as a single step.

FR-CAD-DIM-034 — Mode and licensing gating

  • Requirement: The dimensioning subsystem SHALL be unavailable in Lite mode and when TruTops runs on-machine, and SHALL require the dimensioning password/dongle authorization; if authorization fails at command start the command SHALL terminate without side effects.
  • Parameters & options: init_dim_befehl returns error (disabling registration) when ST_Lite_Modus == "1" or ST_TOPS_RUNS_ON_MACHINE == "1", and only registers states if TcAppStatePassword::SetPasswordDimensioning(isLite) succeeds; start_dim re-checks SetPasswordDimensioning() and pops the automaton (ASM_POP) if it fails.
  • Priority: Conditional
  • Rationale: Licensing/feature gating must prevent use of an unlicensed capability.
  • Source: dim.cpp init_dim_befehl() (lines ~5597–5620), start_dim() (lines ~3271–3276); TcAppStatePassword::SetPasswordDimensioning.
  • Verification: Inspection/Test — run in Lite/on-machine and unlicensed configurations; verify dimensioning is disabled/aborts cleanly.

FR-CAD-DIM-035 — Selection modes for multi-target operations

  • Requirement: Dimension edit operations that can target multiple dimensions (text size, text direction, delete) SHALL support single-pick, box (rubber-box) and ALL selection with a confirm step, while creation and per-object operations SHALL use single-pick selection.
  • Parameters & options: Multi selectors dimMultiSelector with e_selectInfoCount and pick/confirm()/all() handlers (…Pick/…Confirm/…All); single selectors dimSingleSelector (e_selectSingle,e_selectPick); contour/aligned modes force single pick (p_dim). Selector kinds by target: e_selDim, e_selDimText, e_selDimDiameter, e_selDimRadius, e_selElem/Round/Line/Arc, e_selContour.
  • Priority: Conditional
  • Rationale: Batch editing of many dimensions is essential for productivity; creation must stay unambiguous.
  • Source: dim.cpp dimSingleSelector/dimMultiSelector/dimElemSelector/dimPointSelector/dimPosSelector, TeDimSelectorType; delete/size/direction Confirm/All handlers.
  • Verification: Test — box-select and ALL-select for delete and text size; verify batch application; verify creation accepts only single picks where required.

FR-CAD-DIM-036 — Interactive live feedback / preview

  • Requirement: During point acquisition and placement the system SHALL provide live visual feedback: a rubber-band line from the first to the moving second point, and a live preview of the dimension following the cursor during offset/text placement, with the persisted attribute temporarily hidden while its preview is shown.
  • Parameters & options: p_dimPoint2 sets RUBBER_LINE feedback anchored at point 1; placement uses cad_free_define_feedback(resetOffset/resetTextPos, nextSegment); createFeedback()/hideAttributeForFeedback()/cleanFeedback() manage the preview attribute (m_feedbackAttributePtr). Prompts guide each step (msgs 10753/10754/10756–10780/10793).
  • Priority: Optional
  • Rationale: Live feedback makes placement predictable and reduces rework.
  • Source: dim.cpp p_dimPoint2(), p_dimMove(), p_dimTextPosition(), createFeedback/hideAttributeForFeedback/cleanFeedback; cad_define_feedback(RUBBER_LINE,…).
  • Verification: Demonstration — observe rubber-band and preview during creation and placement.

4. Open Questions & Ambiguities

  1. Free-angle entry unit and range. dim … angle <free> reads a real (ASM_REAL) as the dimension angle; the source does not constrain units/range here. Assumed degrees, unbounded, normalized downstream. (Needs confirmation against TcDimSizeAttribute/TcDimTwoPointsAttribute recalculation.)
  2. No aligned contour variant. The mask set provides contour dimensioning only in horizontal/vertical/free (aCadDimContourLinear{Horizontal,Vertical,Random}), with no aligned counterpart, whereas points/element/short families all have an aligned variant. Whether "aligned contour" is intentionally excluded or simply not exposed is unclear.
  3. Tolerance interactive entry (dim tol). The YACC_DIM_TOL path (dimTopTol→dimBottomTol→dimTolType) is fully wired in init_dim_befehl but no mask in aCadDimFunc.gritx calls dim tol; tolerance entry appears to be reached only through the M_ZeichnungDimText dialog (dim write). Confirm whether a separate tolerance mask exists elsewhere.
  4. dim form (layout) exposure. dimLayout/YACC_FORM and TeDimLayoutStyle exist, but aCadSetDimFormat only calls show dim_show and dim vertex; the mask/dialog that issues dim form <style> was not found in this slice. FR-CAD-DIM-021 is therefore an inferred capability with uncertain UI binding.
  5. Precision sentinels. TcDimDrawManager::setPrecision documents value -1 = "no override" and tolerance -1 = "same as value", but the value ranges supplied by M_ZeichnungDimFormat (min/max decimal places) are defined in the dialog mask, not here.
  6. Diameter/radius twin semantics. dimDiameter/dimRadius treat a twin as success-with-abort (returns the existing attribute, aborts the sequence). It is unclear whether the UI then re-enters placement on the pre-existing dimension or silently no-ops. (inferred)
  7. TcDimStaticArcAttribute role. A TcDimStaticArcAttribute/memento exists in dbase_dim but is not referenced by any dim.cpp creation handler in this slice; its trigger (possibly bend/unfolding annotation, or import) is unconfirmed.
  8. Ordinate additional element. dimOrdinate passes an a_element2Ptr "additional" element for a virtual reference point, but the acquisition of that second element for ordinates is not evident in the single-pick dimOrdinate flow; its population path needs confirmation.
  9. Message-ID text. Prompt/behaviour is inferred from db_cad_meldung/cad_selector_prompt numeric IDs and German code comments; the exact user-facing strings live in a resource catalog not read here.
