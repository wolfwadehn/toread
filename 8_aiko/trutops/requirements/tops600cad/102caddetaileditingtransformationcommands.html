CAD Detail — Editing & Transformation Commands

Detailed reverse-engineered requirements (Tier: command/algorithm level). Child of [[10 - FR - CAD Geometry & Drawing Editing]]. Derived from static source analysis — reconstructed intent, not an authoritative spec.

1. Purpose & Scope

This document is the command/algorithm-level refinement of the editing and transformation slice of the CAD editor. It sits beneath the system-level summary [[10 - FR - CAD Geometry & Drawing Editing]] and gives each interactive editing mask and each supporting geometry-kernel command its own verifiable requirement, together with its modes, parameters, defaults, units and degenerate-case behaviour.

It refines the following parent requirements: FR-CAD-005 (transformations move/rotate/mirror/scale), FR-CAD-006 (stretch), FR-CAD-007 (extend/trim), FR-CAD-008 (split/merge), FR-CAD-009 (delete), FR-CAD-010 (fillet), FR-CAD-011 (chamfer), FR-CAD-012 (notch/relief-groove), FR-CAD-013 (equidistant), FR-CAD-014 (close open contours), FR-CAD-017 (melt/merge overlapping contours), FR-CAD-018 (smooth/thin), FR-CAD-019 (integrity checks / highlight), FR-CAD-023 (colour & line-style — shared with [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]]), FR-CAD-030 (whole-drawing scale), FR-CAD-031 (foil removal), FR-CAD-032 (hatch) and FR-CAD-033 (extract parts from sheet). Boolean contour arithmetic (FR-CAD-015/016) and curve approximation (FR-CAD-025) referenced by the smooth/melt/equidistant algorithms are specified in [[10.7 - CAD Detail - Contour Arithmetic Algorithms]] and [[10.8 - CAD Detail - Curve Approximation & Fourier Analysis]] and only cross-referenced here.

Architecture note (applies throughout). Every interactive editing command is a GRIT dialog mask whose EnterFunction runs the MMK interpreter and issues one or more asm_call( … ) strings to the cad automat (module tc_cad/cad_asm). The automat resolves the geometry work to a database command object in tc_dbase/dbase_command (class family TcDbase…Command), which is the transactional unit for undo/redo. Masks are defined in tc_bof/aCadFunc.gritx, tc_bof/aCadCreateFunc.gritx and tc_bof/tec_cad.gritx. Units follow the environment variable GRITUNIT (0 = metric/mm, 1 = inch); angles are in degrees unless stated. German domain terms are linked to [[04 - Domain Model & Glossary]].

3. Detailed Requirements

FR-CAD-EDT-001 — Translate (move) elements: 2-point, horizontal, vertical

  • Requirement: The CAD editor SHALL provide a translate command for the current element selection in three interaction modes: 2-point (tCadMoveElem2Points, free vector from a reference point to a target point), horizontal (tCadMoveElemHorizontal, X-only) and vertical (tCadMoveElemVertical, Y-only). When invoked without the copy modifier the command SHALL move the originals (asm_call( cad modify no_keep move two_pts|horizontal|vertical )).
  • Parameters & options: reference point and target point (or single distance in the constrained axis for horizontal/vertical); copy modifier Par0 == c_Kopieren with copy count Par1 (see FR-CAD-EDT-005). Distances in current unit (mm/inch).
  • Priority: Essential
  • Rationale: Translation is the most-used editing operation and the axis-constrained modes prevent unintended drift on the free axis.
  • Source: tc_bof/aCadFunc.gritx masks tCadMoveElem2Points, tCadMoveElemHorizontal, tCadMoveElemVertical; asm_call( cad modify … move … ); kernel TcDbaseTransformCommand.
  • Verification: Test — move a selection by a known vector and by axis-constrained deltas; assert final coordinates.

FR-CAD-EDT-002 — Rotate elements: about centre and by 2 points

  • Requirement: The CAD editor SHALL rotate the current selection either about a picked centre by an entered angle (tCadMoveElemRotateCenter → cad modify … rotate center) or by two points defining the rotation (tCadMoveElemRotate2Points → cad modify … rotate two_pts).
  • Parameters & options: rotation centre; angle (degrees) for centre mode, or two reference points for the 2-point mode; copy modifier and count per FR-CAD-EDT-005.
  • Priority: Essential
  • Rationale: Distinct centre-and-angle vs. two-point interactions cover both numeric and geometric rotation workflows.
  • Source: masks tCadMoveElemRotateCenter, tCadMoveElemRotate2Points; TcDbaseTransformCommand (m_angle).
  • Verification: Test — rotate a selection by 90° about a known centre; verify transformed coordinates and preserved shape.

FR-CAD-EDT-003 — Mirror elements: 2-point axis, centre, horizontal, vertical

  • Requirement: The CAD editor SHALL mirror the current selection about a mirror axis defined in one of four modes: 2-point (tCadMoveElemMirror2Points → cad modify … mirror), centre (tCadMoveElemMirrorCenter → mirror center), horizontal (tCadMoveElemMirrorHorizontal → mirror horizontal) and vertical (tCadMoveElemMirrorVertical → mirror vertical).
  • Parameters & options: mirror-axis definition per mode (two points, a centre point, or an implicit horizontal/vertical line through a picked point); copy modifier and count per FR-CAD-EDT-005; TrueType-text mirror handling per FR-CAD-EDT-007.
  • Priority: Essential
  • Rationale: Mirroring produces left/right symmetric parts; the four axis-definition modes match the four menu entries.
  • Source: masks tCadMoveElemMirror2Points, tCadMoveElemMirrorCenter, tCadMoveElemMirrorHorizontal, tCadMoveElemMirrorVertical.
  • Verification: Test — mirror across each axis type and assert reflected coordinates and reversed orientation.

FR-CAD-EDT-004 — Scale elements: about centre and by 2 points

  • Requirement: The CAD editor SHALL scale the current selection either about a picked centre by an entered factor (tCadMoveElemScaleCenter → cad modify … scale center) or by two points whose distance ratio defines the factor (tCadMoveElemScale2Points → cad modify … scale two_pts).
  • Parameters & options: scale centre; uniform factor (dimensionless) for centre mode or two reference distances for the 2-point mode; copy modifier and count per FR-CAD-EDT-005.
  • Priority: Essential
  • Rationale: Element-level scaling adjusts feature sizes without redrawing.
  • Source: masks tCadMoveElemScaleCenter, tCadMoveElemScale2Points.
  • Verification: Test — scale a circle by factor 2 about its centre; verify radius doubles and centre is fixed.

FR-CAD-EDT-005 — Copy-while-transform modifier (keep + count)

  • Requirement: Where a transformation mask is entered with the copy modifier (#…_Par0 == c_Kopieren), the command SHALL retain the original elements and create #…_Par1 transformed copies via asm_call( cad modify keep <count> <op> <mode> ); otherwise (ELSE) it SHALL transform the originals in place via cad modify no_keep <op> <mode>.
  • Parameters & options: keep/no_keep flag; integer copy count Par1 (>= 1 in copy mode). Applies uniformly to move, rotate, mirror and scale.
  • Priority: Essential
  • Rationale: A single copy flag on every transform yields array/duplicate workflows without separate commands.
  • Source: IF( #…_Par0 == c_Kopieren ) branches in all tCadMoveElem* masks; keep #…_Par1 argument.
  • Verification: Test — rotate-copy with count 5 about a centre; assert 5 new copies plus the untouched original.

FR-CAD-EDT-006 — Attribute-preserving transformation kernel

  • Requirement: The transformation kernel SHALL apply a single TcTransformationMatrix to every affected object class so that geometry and its attributes remain consistent: strokes, models, TrueType text, hole rows (Lochreihe), hole circles (Lochkreis), notches (Klinkung), profile sides, ellipses, reference positions, forms, bumping, bend links and all dimension attributes (linear, two-point, angle, radius, static-arc) SHALL be transformed by the same matrix.
  • Inputs/Outputs & tolerances: input — transformation matrix (setMatrix) or setGlobalMove() for whole-drawing; per-class isValidFor…/applyTo… pair decides eligibility and executes; output — transformed part database. moveOrigin(x,y) and scaleDrawing(drawing,factor) are specialisations of the same kernel.
  • Priority: Essential
  • Rationale: Transforming geometry without carrying attributes (dimensions, hole patterns, bends) would corrupt downstream NC and drawing data.
  • Source: tc_dbase/dbase_command/TcDbaseTransformCommand.h (setMatrix, setGlobalMove, moveOrigin, scaleDrawing, applyToHoleRow/HoleCircle/Notch/ProfileSide/Dim*).
  • Verification: Analysis + Test — transform a part carrying dimensions and a hole pattern; verify dimensions and pattern follow the geometry.

FR-CAD-EDT-007 — TrueType-text handling under mirroring

  • Requirement: Where a transformation mirrors TrueType text and the polygonize option is set (setFntTextMirrorOption(true)), the kernel SHALL convert the affected text to polygonal geometry so that the result is not rendered as illegible mirror-reversed glyphs.
  • Parameters & options: boolean polygonize flag on the transform command.
  • Priority: Conditional
  • Rationale: Mirrored font glyphs are not manufacturable/legible as text; polygonization preserves the visual outline.
  • Source: TcDbaseTransformCommand::setFntTextMirrorOption( bool t_polygonize ).
  • Verification: Demonstration — mirror a text element with the option on; confirm it becomes outline geometry.

FR-CAD-EDT-008 — Stretch elements: free (2-point), horizontal, vertical

  • Requirement: The CAD editor SHALL provide a stretch command that moves selected element end-points by a vector while keeping unselected end-points fixed, in three modes: free 2-point (aCadMoveElemStretch2Points → cad modify no_keep stretch), horizontal (aCadMoveElemStretchHorizontal → stretch horizontal) and vertical (aCadMoveElemStretchVertical → stretch vertical). Stretch SHALL always operate on originals (no_keep).
  • Parameters & options: crossing/window selection of end-points; stretch vector (free) or axis-constrained delta (horizontal/vertical).
  • Priority: Essential
  • Rationale: Stretch resizes a contour region without decomposing it, preserving element connectivity.
  • Source: masks aCadMoveElemStretch2Points/Horizontal/Vertical; kernel TcDbaseStretchCommand.
  • Verification: Test — window a rectangle's right edge and stretch +10 mm in X; verify only the selected edge moves.

FR-CAD-EDT-009 — Stretch kernel (vector, end-point selection, bend correction)

  • Requirement: The stretch kernel SHALL move each selected point by the stretch vector (setStretchVector(dx,dy)), decide per element whether its first and/or last point participates (stretchElementList(…, stretchFirst, stretchLast)), and SHALL correct any bend line whose reference points are affected (correctBending) so that bend geometry stays consistent with the stretched flat pattern. A silent mode SHALL be available for scripted/parametric use.
  • Inputs/Outputs & tolerances: inputs — point list (defineStretchPoints), stretch vector; outputs — repositioned points, corrected bendings; m_silent suppresses interaction.
  • Priority: Essential
  • Rationale: Stretching a sheet-metal flat must keep bend lines attached to the moved edges.

  • Parameters & options: element/contour pick.
  • Priority: Conditional
  • Rationale: The foil marking must be reversible.
  • Source: mask aCadDefoilElem; foil_removal off; TcDbaseFoilRemovalCommand.h (removeFoilRemovalAttribute).
  • Verification: Test — defoil a marked element; verify attribute removed.

FR-CAD-EDT-045 — Create foil spikes on an element

  • Requirement: The CAD editor SHALL create spike (Zacken) geometry along a picked element (aCadFoilSpikeElem → asm_call( foil_removal create )) using the current spike parameters (FR-CAD-EDT-047), closing resulting gaps (closeGaps).
  • Parameters & options: spike height/angle/bottom-radius/top-radius/count/rotation; contour-gap.
  • Priority: Conditional
  • Rationale: Spikes score the foil so it can be peeled after processing.
  • Source: mask aCadFoilSpikeElem; foil_removal create; TcDbaseFoilRemovalCommand.h (createSpikes, closeGaps).
  • Verification: Test — create spikes on a line; verify spike geometry with configured count.

FR-CAD-EDT-046 — Create foil spikes on a contour

  • Requirement: The CAD editor SHALL create spike geometry along a picked contour (aCadFoilSpikeContour → asm_call( foil_removal create contour )), determining spike orientation for arc vs. line starts (getSpikeType).
  • Parameters & options: as FR-CAD-EDT-047; contour pick.
  • Priority: Conditional
  • Rationale: Spikes are typically distributed around a whole contour.
  • Source: mask aCadFoilSpikeContour; foil_removal create contour.
  • Verification: Test — spikes on a closed contour.

FR-CAD-EDT-047 — Foil spike parameters

  • Requirement: The foil-removal parameter dialog (M_CadFoilRemovalParameter) SHALL set the spike shape via asm_call( foil_removal create set <height> <angle> <bottomRadius> <topRadius> <count> ), and SHALL provide a create set default reset. Metric defaults: height 10 mm, angle 15°, bottom radius 2 mm, top radius 0.0 mm, count 3 (inch: height 0.4, bottom radius 0.08). A spike rotation angle (setSpikeRotation, adjustable via the mouse wheel) and a contour gap (setContourGap) SHALL be supported.
  • Inputs/Outputs & tolerances: setSpikeParameters(height, angle, bottomRadius, topRadius, …), m_rotation, m_contourGap.
  • Priority: Conditional
  • Rationale: Spike geometry must be tunable to foil thickness and peel behaviour.
  • Source: M_CadFoilRemovalParameter (ST_CadAktSpikeHeight/Angle/BottomRadius/TopRadius/Count); TcDbaseFoilRemovalCommand.h (setSpikeParameters, setSpikeRotation, setContourGap); foil_rem.cpp.
  • Verification: Inspection of defaults; Test parameter round-trip.

FR-CAD-EDT-048 — Hatch closed contours / elements

  • Requirement: When the user confirms the hatch dialog (M_ZeichnungSchraffur), the editor SHALL create hatch (Schraffur) lines at a given angle and spacing, either along picked elements (asm_call( marking element <angle> <distance> )) or filling picked contours (marking contour <angle> <distance>), and in ToPs 400 (per-part) via marking contour part ….
  • Parameters & options: angle ST_CadSchraffurWinkel (default 45°; preset buttons 45°, -45°, 0°, 90°); spacing ST_CadSchraffurAbstand (default metric 20 mm / inch 1); selection mode ST_CadSchraffurAuswahl (1 = elements, 2 = contour). Kernel TcDbaseHatchCommand(angle, distance).
  • Priority: Conditional
  • Rationale: Hatching visually marks regions (e.g. engraving/annotation) with controllable line direction and density.
  • Source: mask aCadHatchContour; M_ZeichnungSchraffur (marking element/contour [part]); TcDbaseHatchCommand.h.
  • Verification: Test — hatch a rectangle at 45°, 10 mm spacing; verify parallel line set within the contour.

FR-CAD-EDT-049 — Change circle diameter

  • Requirement: The CAD editor SHALL change the diameter of a picked circle to an entered value (aCadChangeCircle → asm_call( circle change )), setting radius = diameter/2 (store_change_diameter → setRadius), with options to apply to a single confirmed circle or to all circles (cir_change_all).
  • Parameters & options: new diameter (mm/inch); scope single/all.
  • Priority: Conditional
  • Rationale: Resizing holes to a standard diameter is a frequent edit.
  • Source: mask aCadChangeCircle; tc_cad/cad_asm/circle.cpp (store_change_diameter, cir_change, cir_change_all).
  • Verification: Test — change a Ø8 hole to Ø10; verify radius 5.

FR-CAD-EDT-050 — Snap circle sizes/positions to a grid

  • Requirement: When the user confirms the circle-grid dialog (M_CadKreiseRastern), the editor SHALL snap circles to a grid of the entered size (asm_call( circle change grid <gridSize> ) → snapCircle). The grid size default SHALL be metric 0.1 mm / inch 0.01.
  • Parameters & options: ST_CadCircleGridSize/tmp_gridSize; auxiliary-geometry option O_AlsHilfsgeo.
  • Priority: Conditional
  • Rationale: Snapping near-standard hole sizes to a grid corrects import inaccuracies so holes match standard tools.
  • Source: mask aCadChangeCircleGrid; M_CadKreiseRastern (ST_CadCircleGridSize); circle.cpp (cir_change_grid, snapCircle).
  • Verification: Test — a Ø7.98 hole with grid 0.1; verify snapped to Ø8.

FR-CAD-EDT-051 — Scale the whole drawing (metric ↔ inch unit conversion)

  • Requirement: When the user confirms the scaling dialog (M_Skalierung), the editor SHALL scale the entire drawing to convert its unit system (asm_call( cad modify scale unit <O_SkalierungMetrischInch> )) in the selected direction (metric→inch or inch→metric). Before scaling, if attributes are locked (attribute check returns LOCKED) the command SHALL temporarily release them (attribute no_keep), scale everything, then re-lock (attribute keep), and refresh the drawing info.
  • Parameters & options: direction selector O_SkalierungMetrischInch (1/2; buttons O_MetrischInch, O_InchMetrisch, default 2). Global scaling is performed via the transform kernel's scaleDrawing/setGlobalMove.
  • Priority: Conditional
  • Rationale: Converting a drawing between mm and inch must scale all geometry and attributes consistently, including locked ones.
  • Source: mask aCadScaleDrawing; M_Skalierung (cad modify scale unit, attribute lock handling); TcDbaseTransformCommand.h (scaleDrawing, setGlobalMove).
  • Verification: Test — convert a metric drawing to inch; verify all coordinates scaled by 1/25.4 and dimensions updated.

FR-CAD-EDT-052 — Move drawing origin (Nullpunkt)

  • Requirement: The CAD editor SHALL move the drawing origin/zero point to a picked location (aCadMoveOrigin → asm_call( cline move )), repositioning the coordinate reference without altering geometry. Full origin/coordinate handling is specified in [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]].
  • Parameters & options: new origin point.
  • Priority: Optional
  • Rationale: A correct origin is needed for downstream nesting/NC coordinate reference.
  • Source: mask aCadMoveOrigin; asm_call( cline move ); cross-ref [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]].
  • Verification: Demonstration — move the origin; verify coordinate readout re-references.

FR-CAD-EDT-053 — Enter sheet-layout / part-extraction mode

  • Requirement: When the user confirms the sheet-layout dialog (M_ZeichnungLayoutTafel) with a non-empty part name, the editor SHALL enter part-extraction (Layout-Assistent) mode by starting the store/laser-preparation automat (asm_call( store las_prep )) and, if the delete-old option is set (tmp_layoutDelOld), remove prior parts before browsing the sheet.
  • Parameters & options: layout part name tmp_layoutPartName; delete-old flag tmp_layoutDelOld.
  • Priority: Conditional
  • Rationale: A sheet drawing containing many nested parts must be entered in a dedicated extraction mode before individual parts can be saved.
  • Source: mask tCadExtractSheet; M_ZeichnungLayoutTafel; asm_call( store las_prep ).
  • Verification: Demonstration — enter extraction mode on a multi-part sheet.

FR-CAD-EDT-054 — Reduce twins (identical parts) during extraction

  • Requirement: The editor SHALL let the user enable/disable twin reduction (tCadExtractSetTwins → asm_call( store_par common on|off ), storing ST_ZeichnungLayoutTwins), and SHALL provide a reduce action (aCadExtractSheetReduce) that, after verifying a sheet is selected (asm_call( check ) returns 0), removes duplicate/twin parts (asm_call( remove )); if no sheet is selected it SHALL show message 10852.
  • Parameters & options: twins on/off flag; guard message 10852 ("select the sheet first").
  • Priority: Conditional
  • Rationale: Identical nested parts need be saved only once; twin reduction avoids redundant part files.
  • Source: masks tCadExtractSetTwins, aCadExtractSheetReduce; store_par common on/off, check/remove, meldebox(10852).
  • Verification: Test — a sheet with duplicate parts; enable twins and reduce; verify one instance kept.

FR-CAD-EDT-055 — Extract a part (browse / by contour)

  • Requirement: The editor SHALL extract a part from the sheet (tCadExtractPart → asm_call( store del_mtl las_prep select )), honouring twin reduction (if ST_ZeichnungLayoutTwins == 1, also asm_call( common )), opening a browser for selection ('ST_MenueZeichnungDateinameAuswahl' 'M_OpenBrowserForSelection'), and when Par0 == c_Contour extracting by contour (asm_call( contour )).
  • Parameters & options: extraction mode Par0 (default vs. c_Contour); twin reduction; selection via browser; opens the message list afterwards.
  • Priority: Conditional
  • Rationale: Parts are identified either by selection/browse or by their outer contour.
  • Source: mask tCadExtractPart; store del_mtl las_prep select, common, contour.
  • Verification: Demonstration — extract a part by contour from a sheet.

FR-CAD-EDT-056 — Edit file attributes of a single part during extraction

  • Requirement: The editor SHALL allow editing a single part's file properties during extraction (aCadExtractSheetSingleAttribut) by suspending the layout automat (asm_call( suspend )), opening the file-attributes dialog (M_MenueZeichnungDateiAttribute) and then resuming (asm_call( store single resume )) so that no extraction state is lost.
  • Parameters & options: file-attribute fields (delegated to [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]]).
  • Priority: Conditional
  • Rationale: Each extracted part needs correct metadata before saving; suspend/resume protects the automat.
  • Source: mask aCadExtractSheetSingleAttribut; suspend / store single resume.
  • Verification: Demonstration — edit properties of one part; verify extraction continues.

FR-CAD-EDT-057 — Advance to the next part during manual extraction

  • Requirement: In manual-save extraction mode the editor SHALL advance to the next part (aCadExtractSheetSingleNext → asm_call( next )) while the layout automat is active.
  • Parameters & options: none.
  • Priority: Conditional
  • Rationale: Manual extraction iterates part-by-part.
  • Source: mask aCadExtractSheetSingleNext; asm_call( next ).
  • Verification: Demonstration — step to the next part.

FR-CAD-EDT-058 — Save-as a single extracted part

  • Requirement: The editor SHALL save an individual extracted part under a chosen name (aCadExtractSheetSingleSaveAs): suspend the automat, present the geometry file selector (GEO type with correct default path/extension resolved via FUNC_GetInfoForFileType/FUNC_GetDefaultPathForNewFType), optionally auto-prompt for properties (ST_CadAutoGetProperties), resume, and then pass the chosen name to the automat (asm_call( @DATEINAME )).
  • Parameters & options: target path/name; file type GEO; auto-properties flag.
  • Priority: Conditional
  • Rationale: Extracted parts are persisted as individual GEO files with the correct type/path.
  • Source: mask aCadExtractSheetSingleSaveAs; file-selector flow; store single resume.
  • Verification: Demonstration — save one part; verify a GEO file is written.

FR-CAD-EDT-059 — Zoom to the selected sheet during extraction

  • Requirement: The editor SHALL zoom the view to the selected sheet (aCadExtractSheetZoom) after verifying a sheet is selected (asm_call( check ) == 0 then asm_call( zoom )); otherwise it SHALL show message 10852.
  • Parameters & options: guard message 10852.
  • Priority: Optional
  • Rationale: Zooming aids inspection of the selected sheet region.
  • Source: mask aCadExtractSheetZoom; check/zoom, meldebox(10852).
  • Verification: Demonstration — select a sheet and zoom.

FR-CAD-EDT-060 — Show extracted part names

  • Requirement: The editor SHALL display the names of the parts on the sheet (aCadExtractShowName → asm_call( show name )) as a non-persistent overlay (the change flag is restored so the display toggle does not mark the drawing dirty).
  • Parameters & options: none.
  • Priority: Optional
  • Rationale: Naming overlay helps the operator identify parts before extraction.
  • Source: mask aCadExtractShowName; show name; getsomethingchanged/somethingchanged restore.
  • Verification: Demonstration — toggle part names.

FR-CAD-EDT-061 — Highlight intersecting / overlapping contours

  • Requirement: The CAD editor SHALL highlight intersecting/overlapping contours (aCadShowIntersectingContours): it SHALL first (re)build contours (asm_call( delete contour cancel )), search overlaps (asm_call( split auto )) and, if any are found (ST_ERROR > 0), display the resulting open points (asm_call( show point open )).
  • Parameters & options: none (whole-drawing integrity check).
  • Priority: Essential
  • Rationale: Overlapping/self-intersecting contours cause cutting errors and must be found before processing.
  • Source: mask aCadShowIntersectingContours; delete contour cancel, split auto, show point open.
  • Verification: Test — a drawing with overlapping contours; verify open/intersection points highlighted.

FR-CAD-EDT-062 — Highlight outer contour

  • Requirement: The CAD editor SHALL determine and highlight the outer contour of the part (aCadShowOuterContour): clear/redraw (asm_call( cancel redraw )) then create/show the outer contour (asm_call( show create contour )).
  • Parameters & options: none.
  • Priority: Conditional
  • Rationale: Confirming which contour is the outer boundary is essential for correct inside/outside cutting.
  • Source: mask aCadShowOuterContour; cancel redraw, show create contour.
  • Verification: Demonstration — verify the outer boundary is highlighted.

FR-CAD-EDT-063 — Highlight double holes

  • Requirement: The CAD editor SHALL highlight duplicated/concentric ("double") holes (aCadShowDoubleHoles → asm_call( show single )) as a non-persistent overlay, so the operator can review them before deletion (FR-CAD-EDT-026).
  • Parameters & options: none; change flag restored when unchanged.
  • Priority: Conditional
  • Rationale: Reviewing double holes before removing them prevents accidental loss of intended concentric features.
  • Source: mask aCadShowDoubleHoles; show single.
  • Verification: Test — a drawing with double holes; verify highlight.

FR-CAD-EDT-064 — Highlight short elements below a length

  • Requirement: When the user confirms the element-highlight dialog (M_CadElementeHervorheben), the editor SHALL highlight all elements shorter than or equal to the entered length (asm_call( cancel redraw ) then asm_call( show element 0 <length> )), applying the same 0.0000001 rounding tolerance.
  • Parameters & options: length threshold ST_CadHighlightElementLength (default metric 2 mm / inch 0.1).
  • Priority: Conditional
  • Rationale: Highlighting short elements lets the operator inspect before deleting them (FR-CAD-EDT-024).
  • Source: mask aCadShowSmallElem; M_CadElementeHervorheben; show element 0 <len>.
  • Verification: Test — highlight elements <= 1 mm; verify only short elements marked.

FR-CAD-EDT-065 — Change element colour

  • Requirement: The CAD editor SHALL change the line colour of the current element selection (aCadChangeElemColorSelection/tCadChangeElemColorSelection) or of the whole drawing (aCadChangeElemColorAll) via asm_call( end color change <color> ), where <color> is one of the supported named ToPs colours (white, red, green, blue, cyan, magenta, yellow, black, …). Colour attribute semantics are shared with [[10.4 - CAD Detail - Attributes, Snapping, Selection & Lifecycle]] (parent FR-CAD-023).
  • Parameters & options: target colour (named / index 0–15, mapped to text); scope selection vs. all.
  • Priority: Conditional
  • Rationale: Line colour encodes processing meaning (e.g. cut/mark/construction), so it must be editable per selection.
  • Source: masks aCadChangeElemColor{Selection,All}, tCadChangeElemColorSelection; end color change <color>; TcDbaseChangeColorCommand.h (setColor, execute).
  • Verification: Test — change a selection to red; verify colour attribute.

FR-CAD-EDT-066 — Change element line style

  • Requirement: The CAD editor SHALL change the line style of the current element selection (aCadChangeElemStyleSelection/tCadChangeElemStyleSelection) or of the whole drawing (aCadChangeElemStyleAll) via asm_call( end line_type change <style> ), where <style> is one of solid, dash, dot or dash_dot.
  • Parameters & options: target style (c_solid/c_dash/c_dot/c_dash_dot, default solid); scope selection vs. all.
  • Priority: Conditional
  • Rationale: Line style distinguishes real geometry from construction/auxiliary lines.
  • Source: masks aCadChangeElemStyle{Selection,All}, tCadChangeElemStyleSelection; end line_type change <style>; TcDbaseChangeStyleCommand.h (setStyle).
  • Verification: Test — set a selection to dashed; verify style attribute.

FR-CAD-EDT-067 — Copy elements from the predecessor variant

  • Requirement: In variant mode the CAD editor SHALL adopt elements from the predecessor variant (aCadCopyVariantElem): after checking a variant is active (variant check) and that a predecessor exists (variant last), it SHALL either take control elements automatically (variant 0 set element last control) or, where both originals and copies exist (ST_ERROR == 2), prompt (M_CadVarElementAuswahl) to take originals (control), copies (copy) or both (all), then refresh (variant refresh); it SHALL show message 10865 if no variant is active and 10866 for the first variant. Full variant behaviour is specified in [[10.5 - CAD Detail - Parametric Variants & Scripting]].
  • Parameters & options: selection tmp_auswahl (1 = originals, 2 = copies, else both); guard messages 10865/10866.
  • Priority: Conditional
  • Rationale: Building a variant chain requires carrying geometry forward from the previous variant.
  • Source: mask aCadCopyVariantElem; variant … set element last control/copy/all; cross-ref [[10.5 - CAD Detail - Parametric Variants & Scripting]].
  • Verification: Demonstration — adopt predecessor elements in a variant chain.

4. Open Questions & Ambiguities

  1. macro clear vs. double-strokes geometric criterion. The double-hole deletion (aCadDeleteDoubleHoles → macro clear) and the TcDbaseDeleteDoubleStrokesCommand kernel were located, but the exact coincidence tolerance and whether "double hole" means strictly concentric-equal-diameter or merely overlapping holes was not confirmed from the read slice (macro.cpp handler not fully traced). (inferred)
  2. scale unit factor and direction mapping. M_Skalierung passes O_SkalierungMetrischInch (1/2) to cad modify scale unit; it is assumed 25.4 / (1/25.4) with the two buttons selecting direction, but the numeric factor is not literally in the mask. A free-factor whole-drawing scale (arbitrary ratio) was not found as a separate mask — whole-drawing scaling appears limited to unit conversion plus per-selection scale (FR-CAD-EDT-004) applied to all. (inferred)
  3. Hatch vs. marking. Hatch (aCadHatchContour) issues marking element/contour …, and a separate TcDbaseHatchCommand(angle, distance) class exists; which of the two actually executes at runtime (marking module vs. dedicated hatch command) was not disambiguated in the read slice.
  4. Thin "similar" arc parameter vs. kernel maxRadius. The dialog's card 3 sets thin similar set <arcDistance>, while TcDbaseThinCommand::setGeneralParameters(maxRadius) (default 10000) also exists; the exact relationship between the user "arc distance" and the kernel maxRadius/segmentAngle (default 40) is unconfirmed.
  5. Trim vs. split naming. aCadSplit2Elem uses split two_elem yet the two-element behaviour is trim (adjust-to-intersection via TcDbaseTrimCommand), while aCadExtend2Elem uses equidistant fit all. The precise runtime routing of split two_elem to TcDbaseTrimCommand vs. TcDbaseSplitCommand::splitTwoElements should be confirmed against the automat command table.
  6. Copy-count semantics. keep #Par1 is taken as the number of transformed copies; whether the count is total copies or repeat-offset multiples (arrayed transforms) was not verified from the interpreter.
  7. Equidistant self-intersection handling. TcDbaseEquidistantCommand offsets contours/circles, but behaviour for offsets that would self-intersect or collapse (large inward offset) was not established from the read slice.
  8. Colour index range. end color change accepts named colours; masks map indices 0–15, but whether custom/extended palette indices are accepted by TcDbaseChangeColorCommand::setColor(long) is unconfirmed.
