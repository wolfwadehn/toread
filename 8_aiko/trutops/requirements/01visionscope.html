Vision & Scope

[!info] About this document This is the top-level scope statement for the reverse-engineered Software Requirements Specification (SRS) of the TRUMPF TruTops CAD/CAM suite. It establishes why the product exists, who it serves, what it does, and — importantly — where the boundaries lie. It frames the twelve functional-requirement documents (FR-CAD … FR-AUTO) and the cross-cutting interface, non-functional and constraint documents. All statements are derived from static analysis of the legacy source snapshot; open boundary questions raised by the functional analysts are recorded in [[50 - Constraints & Assumptions]] and the individual FR documents.

1. Product Purpose & Business Context

1.1 The problem it solves

Sheet-metal fabricators turn flat raw stock (steel, stainless, aluminium sheets and tubes) into finished parts by cutting, punching, bending and forming on CNC machines. Between an incoming part drawing and a running machine sits a large body of technical work that TruTops automates:

  • interpreting or drawing the 2D part geometry;
  • deciding how the machine should make each cut or hole — which tool, which laser power, which lead-in, where to hold the part while it is cut free (the technology);
  • arranging many parts economically on a raw sheet to minimise material waste (nesting);
  • ordering the thousands of individual machine motions so the job runs fast and collision-free, then emitting the controller-specific NC program;
  • organising all of this into orders, projects and production plans, and handing them to the shop floor and to loading/unloading automation.

Done by hand, this is slow, error-prone and demands deep machine-specific expertise. TruTops encodes that expertise as reusable master data (machines, tools, materials, technology tables and rule sets — see [[19 - FR - Tools, Machines, Materials & Technology]]) and applies it automatically, so a programmer can go from a customer drawing to a proven NC program in minutes and a shop can run its machines at high utilisation.

1.2 Business context

TruTops is TRUMPF's legacy 2D CAD/CAM offline-programming suite for sheet-metal fabrication. It is an offline programming system: it prepares programs on an office/planning workstation and transfers them to the machine control (e.g. Siemens SIN840D) and to a Manufacturing Execution System (external TruTops Fab), rather than running the machine directly. It targets TRUMPF's own punch presses, laser cutters, tube lasers, press brakes and their loading/unloading automation (LiftMaster, SortMaster, TrumaGrip), while also importing geometry from third-party CAD systems.

The suite is a mature Windows product (with a legacy HP-UX heritage visible in the code) built on the in-house GRIT UI framework ([[22 - FR - UI Framework, Dialogs & Interaction (GRIT)]]), backed by SQL Server master databases (deployable as locally attached Access/MDB files), integrated with the TRUMPF.NET / PDM vault, protected by dongle / Wibu licensing, and extensible through an embedded Python 2.5 interpreter and external component APIs ([[23 - FR - Automation, Scripting & Integration]]).

1.3 Vision statement

For sheet-metal fabricators and their CAM programmers, TruTops is an integrated offline CAD/CAM suite that transforms a part drawing into an optimised, machine-ready NC program — covering drawing, technology assignment, nesting, sequencing and production planning across TRUMPF punching, laser, tube and bending machines — so that material is used efficiently, machines run productively, and machine-specific expertise is captured once and reused everywhere.

2. Product Family & Editions

TruTops is not a single application but a family of editions built from one shared C++ code base (tcolib) and one shared master-data model. Each edition is a distinct executable and configuration set that exposes a subset of the same underlying modules. The snapshot confirms per-edition build targets (t100, t300, t400, t400cad, tcad, tnest) and per-edition configuration directories (ini_files/ToPs100 … ToPsNest), each shipped in a metric and an inch variant.

The technology areas layer on top of a common foundation shared by every edition: the CAD geometry kernel and drawing editor ([[10 - FR - CAD Geometry & Drawing Editing]]), file import/export ([[11 - FR - Import, Export & File Formats]]), part & data management ([[12 - FR - Part & Data Management]]), master data ([[19 - FR - Tools, Machines, Materials & Technology]]), visualization ([[21 - FR - Visualization, Viewing & Plotting]]), the GRIT UI ([[22 - FR - UI Framework, Dialogs & Interaction (GRIT)]]) and scripting ([[23 - FR - Automation, Scripting & Integration]]). Terms below are defined in [[04 - Domain Model & Glossary]].

How the editions relate. The database confirms one shared master-data model partitioned into technology schemas (Punch, Laser, Tube, Bend, Nest, plus the cross-cutting Common, CAD, Text, DATADICT), each mirrored in an _inch schema for the metric/inch duality described in [[12 - FR - Part & Data Management]]. A part authored in ToPsCad flows into a technology edition (ToPs 100/300/400/Tube), is arranged by nesting (embedded, or the stand-alone ToPsNest), sequenced and emitted as NC ([[18 - FR - NC Generation & Motion Optimization]]), and organised into projects and production plans ([[20 - FR - Production Planning & Projects]]). The ToPs 2000 and Lite variants are configuration-limited subsets of the punch/laser editions. Architecture details are in [[03 - System Context & Architecture Overview]].

3. In Scope

The suite's capabilities group into the twelve functional areas below. Each links to its detailed FR document; interfaces are catalogued in [[30 - External Interface Requirements]] and quality attributes in [[40 - Non-Functional Requirements]].

3.1 CAD geometry & drawing editing → [[10 - FR - CAD Geometry & Drawing Editing]]

Interactive 2D drawing and a geometry kernel: primitives (line/arc/circle/rectangle/text), parametric hole and pattern macros, transformations, trim/split/merge, fillet/chamfer/notch, equidistant offset, boolean contour arithmetic, dimensioning, snapping, curve approximation, geometry comparison and parametric variants. This is the core of ToPsCad and the drawing front end of the technology editions.

3.2 Import, export & file formats → [[11 - FR - Import, Export & File Formats]]

Reading and writing external and native geometry: DXF, DWG, IGES, ME10/MI, DSTV import; raster-to-vector import; native GEO/GMT/TAF; export to DXF/ME10/IGES/SVG/HPGL/XML/XCAD; a shared converter framework with standalone batch executables (tc_conv.exe, pdmConvert.exe) and a conversion post-processing pipeline. Per-format dongle/Wibu licensing applies.

3.3 Part & data management → [[12 - FR - Part & Data Management]]

Persistence of parts, drawings, sheets and orders across two storage worlds: TRUMPF-native versioned geometry files (MI/GEO/TAF over file system or PDM vault) and the relational database. Includes the DATADICT data dictionary, DB versioning/migration, metric/inch database duality, the system rule set (Regelwerk), the binary geometry interface DLL, and PDM/ODBC access.

3.4 Punching / nibbling (ToPs 300) → [[13 - FR - Punching (ToPs 300)]]

Automatic and manual punch/nibble tool assignment, punch/nibble along contours, common cutting, micro-joints, forming and thread forming, marking, sheet clamping and repositioning, tool-hit optimization and simulation, scrap/skeleton handling, switching cycles and reusable processing patterns.

3.5 Laser cutting (ToPs 100) → [[14 - FR - Laser Cutting (ToPs 100)]]

Cutting-technology and ruleset assignment to nested contours, lead-in/lead-out and piercing geometry, part-retention (micro-joints, micro-welds, bridges), marking/engraving, kerf/corner correction, sheet dividing and remainder handling, gas/cooling parameters, cutting-sequence and path optimization, collision detection and cut simulation, and part-removal automation (unloading, sorting, ejection). Includes a water-jet (H2O) variant.

3.6 Tube & profile machining → [[15 - FR - Tube & Profile Machining (ToPs 400)]]

3D tube modelling and unrolling (Abwicklung), a profile library and cross-section families (round, rectangular, flat-oval, custom, open L/U/C), machining-case assignment (planar/perpendicular/end cuts, insert, mount, through-penetration), corner treatment and weld-seam positioning, tube technology lookup, machine guiding/support elements, collision checking, sequence optimization, measuring cycles, and SolidWorks/PDM/TEO integration.

3.7 Bending (ToPs 600) → [[16 - FR - Bending (ToPs 600)]]

Defining bends (kind, method, technique, angle, radius), computing bend-deduction factors and flat patterns from the ToPs 600 bend database, assigning punch/die tools, the interactive profile editor, bumping bends and corner reliefs, and the bend tool assistant. (Automatic bend-sequence and press-brake collision checking are delegated to the separate ToPs 600 / TruTops Bend product — see §4.)

3.8 Nesting & palletizing → [[17 - FR - Nesting & Palletizing]]

Automatic true-shape (GSSL NestLib), rectangular and tile nesting; nesting to order quantities and priorities; rotation/mirroring and grain constraints; clustering/mini-nests; common-cut nesting; part-in-part nesting; web/border configuration; sheet-utilization optimization; remnant/offcut management with stock deduction; nesting reports; and automatic/interactive palletizing of parts, scrap and skeleton for LiftMaster/SortMaster automation.

3.9 NC generation & motion optimization → [[18 - FR - NC Generation & Motion Optimization]]

Constrained-TSP processing-order sequencing, per-tool travel-time optimization, collision-free rapid-traverse path finding, jerk-limited cycle-time estimation, data-driven controller-specific NC post-processing (cycles/formats), setup-plan and multiple-up (MFN) generation, NcLink/DNC transfer, and machine-simulation data export.

3.10 Tools, machines, materials & technology → [[19 - FR - Tools, Machines, Materials & Technology]]

The shared master-data foundation: machine definitions (work area, axis dynamics, peripherals, control-version compatibility, rule sets, loading strategies), tool catalogues (punch tools, dies, multi-tools, thread formers, cassettes, tool lists, XML import/export, ITM/SW06 central tool management), material/thickness/stock definitions, and technology tables (laser LTT, AutoCut, micro-joints, tube technology). This data drives every processor across every edition.

3.11 Production planning & projects → [[20 - FR - Production Planning & Projects]]

The organisational layer: programming projects (PPJ workbooks binding order→machine→material→sheets→parts), production plans assembled/generated via the external NcLink tool, grouping of captured parts into nesting orders with quantities/priorities/due dates, master-sheet part overviews, and job hand-off to production (auto-run, TruTops Fab).

3.12 Visualization, viewing & plotting → [[21 - FR - Visualization, Viewing & Plotting]]

On-screen 2D rendering of drawings/parts/nests, view navigation, toggleable display content classes (tool paths, technology, micro-joints, scrap, etc.), a display-attribute model, and three output paths — raster screenshots, Windows GDI printing, and HPGL/HPGL2 plotting — plus an embeddable/standalone GeoViewer (ActiveX/OCX).

3.13 Cross-cutting foundations

  • UI framework (GRIT) → [[22 - FR - UI Framework, Dialogs & Interaction (GRIT)]]: masks/dialogs, the MMK interpreter with mini_sql data binding, input validation, finder lists, interactive graphical selection, transaction-based undo/redo, unit and multi-language rendering (up to 30 languages incl. CJK), and the Qt front-end bridge.
  • Automation, scripting & integration → [[23 - FR - Automation, Scripting & Integration]]: embedded Python 2.5 with a ToPs module, the ASM/MMK command interpreters, per-edition external component APIs, the TruTops Fab (MES) adapter, and headless P/Invoke DLLs for batch nesting and laser shop-floor programming.

4. Out of Scope

The following are outside the boundary of this reverse-engineered SRS, either because they live in separate products, are absent from the readable snapshot, or are lower-level infrastructure. Boundary uncertainties are tracked in [[50 - Constraints & Assumptions]] and the relevant FR documents.

  • Real-time machine control / on-machine execution. TruTops is an offline programming system; it emits NC programs and transfers them, but does not run the CNC controller. Controller firmware and on-machine motion execution are out of scope (interface only — see [[18 - FR - NC Generation & Motion Optimization]], [[30 - External Interface Requirements]]).
  • Automatic bend-sequence determination and press-brake collision checking. Not present in the readable ToPs 600 source; these appear to reside in the separate ToPs 600 / TruTops Bend application, which is out of scope beyond its data interface ([[16 - FR - Bending (ToPs 600)]]).
  • Production scheduling / MES. True due-date-to-machine-time-slot scheduling across machines lives in the external TruTops Fab MES; TruTops captures orders, quantities and due dates and hands jobs off, but does not schedule ([[20 - FR - Production Planning & Projects]], [[23 - FR - Automation, Scripting & Integration]]).
  • PDM/PLM vault internals. The TRUMPF.NET / PDM server contract (check-in/out, versioning, locking) lives in framework code (OmAdapter.dll) outside this snapshot; only the client-side facade is in scope ([[12 - FR - Part & Data Management]]).
  • Third-party engines and external tools. The GSSL NestLib nesting engine, the external DWGConverter, ToPsVectorize raster vectorizer, NcLink plan generator, and the SolidWorks tube add-in are integrated but not specified here (interfaces only — [[30 - External Interface Requirements]]).
  • 3D solid modelling / shaded rendering. TruTops is fundamentally a 2D CAD/CAM system (with a specialised 3D tube model and an unfolded-bend model); a general 3D solid modeller and a real-time shaded/hidden-line 3D renderer were not found ([[21 - FR - Visualization, Viewing & Plotting]]).
  • True 3D STL / additive manufacturing. No stereolithography/STL 3D file exchange exists in the snapshot (tc_stl is punch-laser combi technology, not STL) ([[11 - FR - Import, Export & File Formats]]).
  • Build, source-control and DevOps tooling. Perforce/Red Gate hooks, makefiles and the DATADICT deployment scripts are developer tooling, not runtime product features.
  • Table/content ownership of technology databases. The content semantics of the bulk of technology tables are owned by the per-technology FR documents; [[12 - FR - Part & Data Management]] owns only their persistence and schema mechanics.

6. Assumptions & Dependencies

The following assumptions and dependencies frame the specification; formal constraints are enumerated in [[50 - Constraints & Assumptions]].

6.1 Platform & runtime assumptions

  • Windows is the runtime platform (a legacy HP-UX/X11 path exists in the source but is not a current deployment target). The modern front end bridges the GRIT layer to a Qt GUI ([[22 - FR - UI Framework, Dialogs & Interaction (GRIT)]]).
  • An embedded Python 2.5 runtime (python25.dll) ships in every executable for scripting and customization ([[23 - FR - Automation, Scripting & Integration]]).
  • The suite is built from one shared C++ code base (tcolib); editions are executables + configuration, not separate products.

6.2 Data & environment dependencies

  • A SQL Server database (or a locally attached Access/MDB equivalent), accessed over ODBC, holds all master and technology data, organised into per-technology schemas with parallel _inch variants ([[12 - FR - Part & Data Management]], [[19 - FR - Tools, Machines, Materials & Technology]]).
  • The DATADICT data dictionary defines and provisions the schema and drives versioning/migration.
  • Deployment presumes a TRUMPF.NET file layout (drives, shared/data/template/tool/profile paths) configured via .ORG/.ini files, optionally routed through a PDM vault.
  • Configuration and feature exposure per edition are driven by the ini_files/<edition>/*.ORG files.

6.3 Licensing dependency

  • Functionality is gated by dongle / Wibu hardware/software licensing with per-format and per-edition keys and password files (TC_DONGLE_ACCESS local/network modes, TOPS_PWD_PATH). Superuser bypass exists for service ([[11 - FR - Import, Export & File Formats]], [[30 - External Interface Requirements]]).

6.4 External-system dependencies

  • Machine controls (e.g. Siemens SIN840D) consume the generated NC via file transfer / NcLink DNC.
  • TruTops Fab (external MES) provides order import and receives job-completion feedback.
  • The GSSL NestLib engine performs true-shape nesting; DWGConverter, ToPsVectorize, and the SolidWorks tube add-in are external helpers.
  • Loading/unloading automation (LiftMaster, SortMaster, TrumaGrip) is programmed and driven from the laser/nesting/palletizing areas.
  • All external interfaces are catalogued in [[30 - External Interface Requirements]].

6.5 Method & provenance assumptions

  • This SRS is reverse-engineered by static analysis of a single source snapshot (files dated May 2024); it describes the system as built, not as originally specified. Behaviour not evidenced in readable source (e.g. compiled-only libraries, external products) is flagged, not invented.
  • Domain terminology is German in the source and is translated throughout while preserving the original terms; see [[04 - Domain Model & Glossary]].
  • Cross-edition boundary questions (e.g. MFN ownership between nesting and NC, AutoCut shared between punch and laser, tube-vs-CAD profile ownership) remain open and are recorded per FR document and consolidated in [[50 - Constraints & Assumptions]].
