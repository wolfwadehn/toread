WriteBackEndpointsGrippersRegripStationsBackGauges

product: psb tags: [code-review, PSB, azure-pr, api, dto, write-back, spike, flux-core] project: PlatformServiceBend branch: spike/write-data-back-to-flux ticket: none (spike — no linked work item) pr: 234386 author: Abdulaziz Morad reviewer: Aiko Radlingmayr date: 2026-07-17 status: active vote: not-voted (pre-merge deep review) source: azure-devops

Code Review — Write-Back Endpoints (Grippers, Regrip-Stations, Back-Gauges)

Deep review of Azure DevOps PR !234386 — "Added Get and Put Endpoints for Grippers, Regrip-Stations and Back-Gauges", by Abdulaziz Morad, spike/write-data-back-to-flux → main, merge head eb5fb091, still active. Findings verified against Flux source (~/dev/trumpf/Flux, Flux 667 ca45fee873) with file:line evidence; 35 candidate findings, 31 confirmed / 4 refuted.

Scope

First write-back path in PSB (until now the service was read-only over Flux). 15 files, +515/−5:

  • Back-gauge stage params — PUT /bend/tech/stages/{stage}/backgauges/{bg}, partial update (SetBackGaugeStageRequest, all fields optional; unknown-property rejection).
  • Regrip-station step positions — GET/PUT /bend/tech/stages/{stage}/steps/{step}/regrip-station.
  • Gripper — GET/PUT /bend/tech/gripper (current), GET /database/bend/grippers (available list).
  • New BendGripperService, BendGripperAdapter, DTOs, DI registration, endpoint wiring.

Layering (DTO → Adapter → Service → Endpoint) and instincts (partial-update, unknown-prop rejection, validation, Dispatcher.Run marshalling) are right. But two issues make the feature non-functional/unsafe on its primary path.

Verdict

Critical 1
High 2

CRITICAL

C1 — Regrip PUT throws NotSupportedException for every real bend stage

src/PlatformServiceBend.Adapter/Part/Bend/Step/RegripStationStepParametersAdapter.cs (SET method)

var simStage = bendStage.Q0;               // Q0 is typed Flux.IBSimStage
if (simStage is not Flux.BCStage stage) {  // ← excludes BendOp
  throw new NotSupportedException("Regrip station positions cannot be updated with the available Flux API.");
}

Flux.BCStage is the base class only for BCPickup / BCRegrip / BCDeposit. A normal bend stage is Flux.BendOp, declared public sealed partial class BendOp : ISheafSite, IBSimStage (Flux Src/Core/Bend/BendOp.cs:34) — it does not derive from BCStage. GetBendStage(stageIndex) indexes bendTech.Stages, which wraps every Flux.BendOp (Flux Src/API/Bend/BendTech.cs:251), so a normal bend step flows straight into the cast and hits the throw.

The paired GET (From) only requires bendStage.Tech.Robotic and happily returns From/To ranges for those same stages — so a client GETs data, edits it, PUTs it back, and gets NotSupportedException. The write-back is non-functional for its primary case, and GET/PUT are asymmetric.

The cast is also unnecessary: Waypoints is declared on the IBSimStage interface itself (Flux Src/Core/Bend/Ops/BSimulate.cs:37 Dictionary<EBPhase, BWaypoint> Waypoints { get; }), and BWaypoint's ctor takes IBSimStage.

Fix: operate on simStage.Waypoints directly (works for BendOp and all BCStage subclasses), or gate on Tech.Robotic to exactly mirror the GET. Drop the BCStage narrowing.

HIGH

H1 — Back-gauge Position GET↔SET use non-inverse coordinate transforms (round-trip drift)

GET: src/PlatformServiceBend.Adapter/Part/Bend/Stage/BendStageAdapter.cs:61 SET: src/PlatformServiceBend.Adapter/Part/Bend/Stage/BackGaugeStageParametersAdapter.cs (bgDatum.Position = request.Position.ToApiPoint3();)

  • GET.X = backGauge.Vec.X + bendOp.MappingPt.X - ncxCenter. The API MappingPt.X resolves to XPosition = coreMappingPt.X + (XFullSpan.Min+XFullSpan.Max)/2 + NCXCenter (Flux Src/API/Bend/BendOp.cs:380, 562-565). The NCXCenter cancels ⇒ GET.X = Vec.X + coreMappingPt.X + span (span = half the X-span).
  • SET writes BGDatum.Position, whose setter forwards to mOp.SetBGPos (Flux Src/API/Bend/BendOp.cs:1018-1019, Src/Core/Bend/BendOp.cs:3747+). The setter's true inverse is the BGDatum.Position getter (line 1015), which uses +NCXCenter, not +span.

So GET and the setter differ by span − NCXCenter in X. Feeding a GET value back through SET yields a next GET of x + (span − NCXCenter) — silent, accumulating drift on every GET→edit→PUT cycle. In Y, the setter applies a −DY shift the GET never adds, so Y drifts by DY on bump ops. Z round-trips correctly.

Fix: make the two layers share one convention — have the GET read BGDatum.Position (the API getter, which is the inverse of the setter the SET drives) instead of the hand-rolled Vec.X + MappingPt.X − ncxCenter. Do not mix a hand-rolled GET transform with the BGDatum.Position setter.

H2 — Writes perform no invalidation → CAM/NC output and dependent values stay stale

Regrip SET (end of method) and, by the same reasoning, all three write paths.

The regrip SET ends at stage.Waypoints[step.Phase] = waypoint; with no invalidation. Flux's own write path (Src/UI/BCell/BWaypointUI.cs:679-681) does three things after assigning the waypoint:

  1. mStage.IDirty(EBInput.Waypoint) — resets cached _steps / robot path,
  2. DirtyNext() — invalidates the next stage when the last step is edited (a step's To feeds the next step's From),
  3. sets Tech.CodeDirty.

None of that runs here. A GET of the same step's To reflects the change (the reader reads the live dict), but generated NC/simulation, the part's dirty-for-save flag, and the next step's From do not update until some unrelated edit invalidates the stage. (The gripper SET has the analogous gap — see M3.)

Fix: after writing, call simStage.IDirty(EBInput.Waypoint), replicate DirtyNext for last-step edits, and set Tech.CodeDirty (mirror BWaypointUI.Update); or use a settable API that self-marks dirty.

MEDIUM

M1 — Back-gauge PUT never bounds-checks backGaugeIndex → 500 + partial mutation

BackGaugeStageParametersAdapter.cs SET indexes bendOp.BGData[backGaugeIndex] and later bendOp.Q.Gauges[backGaugeIndex].SetRetraction(...) with no validation, whereas the GET's InternalGetBgPos validates index < 0 || >= Gauges.Length and throws ErrorCode.ValidationError (→ 400).

  • Negative / too-large index throws raw IndexOutOfRangeException → UnhandledException → 500 (GET returns 400).
  • BGData length is Math.Max(Gauges.Length, 2) with modulo mapping (Flux Src/API/Bend/BendOp.cs:317,320). On a 1-gauge machine, backGaugeIndex=1 is a valid BGData slot aliasing gauge 0: Position/Surface/Speed apply to gauge 0, then Gauges[1].SetRetraction (no modulo) throws → 500 with the model already partially mutated.

Fix: reuse the GET's Gauges.Length guard at the top of the SET, before any mutation.

M2 — Gripper WristToTip convention differs between "current" and "available"

GripperParameterAdapter.cs — From(BCComponent) (current) subtracts GetTrumpfOffset (default ≈ −34.5 mm) from Z and uses the mounted pickup GripConfig. The new From(BGripper) (available/catalog) uses InternalGetWristToTip, which for cup grips builds Matrix3.Translation(Midpoint.X, Midpoint.Y, ZCup + DefaultConfig.DZCup) with no Trumpf offset and the default config.

⇒ The same physical gripper reported via GET /bend/tech/gripper vs GET /database/bend/grippers yields WristToTip.Z differing by ≈34.5 mm (and possibly a different DZCup). All members are valid and the null WristToTip(null, DefaultArgs) call is safe (the is ICupGrip guard steers every comp-dereferencing gripper away from it) — so this is a convention bug, not a crash.

Fix: apply the same coupling-offset + config source in the catalog path, or document that catalog WristToTip is a raw design-time value.

M3 — Gripper PUT does not recompute bend tech after the swap

BendGripperAdapter.SetCurrentGripper does only fluxCellTech.Gripper = gripper;. The core setter swaps the item and clears two caches, and BCComponent.Item fires ItemChanged/PFire — but in a headless HTTP service there are no subscribers. Flux's real gripper-swap path RedoGripper (Flux Src/UI/BCell/BGripperToolUI.cs:263-273) clears BendTechMemo, calls PrepareToGAPModel(), runs BendTooler.Process(...), sets CodeDirty, redraws. None of that runs, so computed poses/collision/payload/NC stay consistent with the old gripper.

Fix: trigger a reprocess equivalent to RedoGripper (or set CodeDirty), or document that a subsequent GenerateBendTech is required. Acceptable to defer for a spike if flagged.

M4 — Back-gauge PUT documents 422 for unknown properties but returns 400

BendTechStagesEndpoints.cs — the handler rejects unknown JSON props by throwing new ErrorException(new ValidationError { … }) and declares .ProducesWithDescription(Status422UnprocessableEntity, …). But a ValidationError is forced to HTTP 400 (ErrorExtensions.cs:82-84; FromCode maps ValidationError → 400). So at runtime this case is 400, never 422 — the OpenAPI contract is wrong. It also collides with the group-level 422 (BendTechMissing) entry: the operation filter skips a status already declared on the endpoint, so the genuine 422 case loses its description here.

Fix: declare this case as 400 (matching runtime), or throw an error whose code maps to 422 if 422 is truly intended — and don't reuse the 422 slot for a different semantic.

M5 — Tool-catalog gripper collection is dead code (and does wasted disk I/O)

BendGripperAdapter.InternalCollectFromToolCatalogs and the second loop of InternalFindGripperByName iterate every installed bend-tool library looking for grippers, but can never add one: grippers (Flux.BGripper : BCellItem) and bend tools (BTool : BPunch/BDie/BAdapter) are disjoint hierarchies, so tool.GetType().Name.Contains("Grip") never matches the API.BPunch/BDie/BAdapter wrappers and (object)tool is Flux.BGripper (API wrapper → core type) is always false. Both loop bodies are unreachable. Worse than inert: BToolLibrary.Get(catalog.Id, true) loads each library from disk on every call, for zero benefit, and misleads readers into thinking catalogs are a gripper source.

Fix: delete both catalog paths; Flux.BGripper.GetAll(includeHidden: true) already returns the full gripper library.

LOW

  • L1 — Pullback + RetractionPath in one request silently discards Pullback. SET applies Pullback (→ SetPullback → SetRetraction([v,0,0])) then, if RetractionPath is present, Gauges[i].SetRetraction(path) overwrites the same mRetract. GET.Pullback then returns the path sum, not the requested pullback. Fix: reject both-supplied, or define/document precedence.
  • L2 — Position-then-Surface ordering can override the just-set Position. The BGDatum.Surface setter isn't a plain field write — on a changed value it calls BGPlacer.AutoPlaceOne, which re-places the gauge and can move Vec (Flux Src/API/Bend/BendOp.cs:1065-1068). SET writes Position before Surface, so a combined request may discard the explicit Position. Fix: apply Surface first, or reject combined Position+Surface.
  • L3 — GetCurrentGripper ReferenceEquals predicate is dead. cellTech.Gripper and c.Item allocate fresh API wrappers per access (BGripper.Wrap/BCellItem.Wrap both new), so ReferenceEquals(gripper, currentGripper) is always false; control always falls to the fallback. Harmless today (one gripper component) but the intended disambiguation never happens. Fix: drop the predicate or compare via Equals/.Q.
  • L4 — StepChangePoint out-of-range enum → 500 instead of 400. JsonStringEnumConverter allows integer values, so {"stepChangePoint": 999} binds; the switch default throws ArgumentOutOfRangeException without Data["ErrorCode"] → UnhandledException → 500. Fix: tag the exception with ErrorCode.ValidationError (or throw ErrorException(ValidationError)).
  • L5 — Unknown-property rejection only on back-gauge PUT. SetBackGaugeStageRequest has [JsonExtensionData]
    • a guard; the regrip (RegripStationStepParameterRequest) and gripper (GripperSelectionRequest) PUTs have neither, so a typo like "positionToo" is silently dropped and writes 0. Inconsistent strictness across the three new write endpoints. Fix: make the three consistent.
  • L6 — 404 undeclared in OpenAPI for regrip endpoints. GetBendStage/GetBendStep throw BendStageNotFound/BendStepNotFound (codes contain "NotFound" → 404), but the regrip GET/PUT declare only 400. The sibling tip-pose GET correctly declares both. Fix: add .ProducesWithDescription(Status404NotFound, …). (The back-gauge PUT's stageIndex is a route param whose ArgumentException maps to 400 — so that one is fine.)
  • L7 — German "Validierung:" in English API descriptions (two gripper endpoints). Fix: "Validation:" or drop it.
  • L8 — {stepIndex} lacks :int while {stageIndex:int} is constrained in the same regrip route templates. A non-int segment matches then fails binding (framework 400) instead of not matching. Copies the pre-existing tip-pose route rather than the constrained back-gauge one. Fix: {stepIndex:int}.
  • L9 — Duplicated gripper enumeration/lookup logic across GetAvailableGrippers and InternalFindGripperByName (once dead catalog code is removed). The list path filters blank names + dedupes case-insensitively; the by-name path does neither, so listable vs selectable sets can drift. Fix: one shared name → BGripper source.

⚠️ Contested (one verifier confirmed, another refuted with an empirical repro)

  • Regrip PUT null-body → NRE/500. The concern: a JSON body of literal null binds to the non-nullable RegripStationStepParameterRequest[] param and [.. regripStationParameters] NREs before the adapter's IsDefaultOrEmpty guard. However, a repro on the pinned SDK (.NET 10.0.300) showed minimal APIs infer a non-nullable complex body as required and return 400 before the handler runs (handler never entered, zero NREs). So this is likely a non-issue in practice. Still worth hardening for intent: bind as RegripStationStepParameterRequest[]? and reject null explicitly rather than relying on framework behavior + a guard that sits after the spread.

NITs

  • N1 — MovementStrategy raw enum cast (Flux.Sheaf.EBGMovePath)request.MovementStrategy.Value. Values align 1:1 today (EBGMovePath { ASV=0, ZthenX=1, ASW=2 } vs DTO 0/1/2), so not a live bug, but there's no compile-time safety and no range validation — an out-of-range int is cast and stored silently. The PR already uses an explicit switch for StepChangePoint (whose enums are ordered differently); MovementStrategy should do the same.
  • N2 — Gripper-name empty/null validation duplicated in both the endpoint and SetCurrentGripper (different ParamName/Data → different 400 response shape). Keep it in one layer.
  • N3 — Gripper endpoint tag bend/tech/gripper (singular) vs plural siblings / new database/bend/grippers. Arguably intentional (single active gripper); note the intent or align.
  • N4 — Private helper GetType(API.BGripper) shadows object.GetType, also called in the same class; the PR adds a second caller. Rename to MapGripperType.
  • N5 — Inconsistent lambda indentation in BendGripperService.GetAvailableGrippers (body at 4 spaces vs 6 in the sibling methods). Run the formatter.

Considered and dismissed (verified NOT defects)

  • "new BendOpSettings(bendOp.Q) is a copy → lost writes." Refuted. It's a live write-through view (Flux Sheaf), so the settings-backed fields (ParallelRetraction, MovementStrategy, StepChangePoint, StepChangeDelay, Speed) do persist. This was the biggest initial worry and it's fine.
  • "PUT used for partial/merge is inconsistent with siblings." Refuted. The sibling press-beam write is itself a nullable/all-optional partial merge (PressBeamSettingsAdapter guards every field with if (… != null)). The new endpoints follow the existing convention.
  • "Public GetRegripStationStepParameters is a redundant pass-through." Refuted. The internal From overload is internal to the Adapter assembly; the caller is in the separate Core assembly with no InternalsVisibleTo, so the public wrapper is the necessary cross-assembly surface.
  • "Gripper endpoints have a phantom 404 / undocumented 422." Refuted. 422 is declared at the group level; the 404 is the real "Session not found" path. Only residue: GetCurrentGripper throws InvalidOperationException("Gripper not found.") tagged BendCellTechMissing, so the response title differs in wording from the detail — a cosmetic nit.

Recommended actions before this leaves spike status

  1. C1 — fix the BCStage cast (blocks the whole regrip feature).
  2. H1 — unify the back-gauge Position convention so GET↔SET round-trips.
  3. H2 / M3 — add invalidation/recompute after writes (or explicitly document that a GenerateBendTech is required).
  4. M1 — add the backGaugeIndex bounds check before any mutation.
  5. M4 — reconcile the 422-vs-400 contract.
  6. M5 — delete the dead tool-catalog code (also removes per-call disk I/O).
  7. Sweep the LOWs (L1/L2 data-loss surprises, L4/L5 validation gaps) and NITs as a cleanup pass.
