PSB — DevOps & CI/CD

How PlatformServiceBend is built, versioned, packaged, and released. Azure DevOps org TrumpfCorp, project Flux. All pipeline YAML lives in build/pipelines/; reusable templates in build/pipelines-templates/.

[!info] The big picture PSB's CI builds Flux from source on the agent and subst-mounts it to the X: drive, then builds PSB against it. Releases are tag-driven: a SemVer PSB tag release/<x.y.z> on a release/<fluxVersion> branch. Output = three UIF .tciz packages (Standalone / Touchpoint / PLB) pushed to SCAPS, a PlatformServiceBend.DTO NuGet, a CycloneDX SBOM, and OpenAPI specs + generated changelog/user-docs committed to the PSB-Doc repo.

Pipelines at a glance

Pipeline (build/pipelines/…) Trigger Purpose
azure-pipelines-platform.yml push to main; PR on *; manual (alpha) Main CI. PR build + test + SonarCloud; on main, produces beta UIF+NuGet packages, SCAPS upload, beta OpenAPI + changelog to PSB-Doc.
azure-pipelines-release.yml manual, on a refs/tags/release/<x.y.z> tag Production release. Build, UIF packages, SCAPS upload, release OpenAPI + docs/changelog to PSB-Doc.
azure-pipelines-changelog.yml manual (two modes by Build.Reason) OpenAPI diff/changelog + usage docs between two versions (PR base↔head, or arbitrary tags/commits).
azure-pipelines-usage-documentation.yml manual Build OpenAPI from HEAD and render user documentation.
azure-pipelines.ai-review.yml PR on *, scoped to PlatformServiceBend/** LLM inline PR code review (posts ADO PR comments; not a build gate).

Shared: variable groups BendService, PlatformServiceBend, FluxVersions; SDK 10.0.x; BuildConfiguration=Release; FluxProjectDir = X:/src/bin. External repo resources: metamation/Flux (GitHub), Flux/MetamationPipelines, Flux/FluxServiceUsageDocument, Flux/PSB-Doc.

How Flux is provisioned on the agent

The flux-setup.yaml template is the heart of it (consumed by platform/release/changelog/usage-doc):

  1. Clean Sonar residue — remove stray .sonarqube dirs (incl. X:\Src\.sonarqube), unset SONAR* env vars — because the Flux build and PSB's Sonar run share the self-hosted agent.
  2. checkout: Flux (LFS) → git fetch/checkout the resolved Flux ref (resolve-flux-version.ps1 maps the FluxVersion param → a git ref via the FluxVersions variable group).
  3. mount-flux.ps1 — subst X: <sourceDir>/flux-source maps the Flux checkout to X:.
  4. Mesa3D — extract MesaDlls.zip into X:\src\bin, Unblock-File them (software GL for headless render).
  5. prepare-flux-nugets.ps1 — dotnet nuget add source 'X:\Src\Lib' --name FluxLocal.
  6. get-flux-version.ps1 — scrape AssemblyVersion from X:/Src/App/Properties/AssemblyInfo.cs → BuildVersion.

flux-build.yaml then just runs build-flux.ps1 = dotnet build "X:\src\Flux.sln" -c Release. So Flux is built from source into X:\src\bin, not consumed as a prebuilt drop. (At dev time you instead reference prebuilt Flux DLLs from X:\Src\bin — see the [[01_Introduction_and_Goals|Arc42]].)

Main CI — azure-pipelines-platform.yml

  • BuildAndTest (pool FluxBuildAzureHosted): validate release-PR Flux version → flux-setup/build → fix NuGet.Config lib path (relative → absolute) → NuGetAuthenticate (JFrog Trumpf-License-Nuget) → restore → SonarCloud (PR vs branch variant by Build.Reason) → build PlatformServiceBend.App.csproj → set TZ to Vienna → run tests sequentially: Background suite first, then Default (avoids port conflicts) with opencover coverage → SonarCloud analyze/publish → publish TRX + coverage.
  • PackageAndPublish (on main, or manual+PublishAlphaPackages): VersionCalculation computes the next X.Y.Z-<beta|alpha>.<counter>+<build> from the highest release/* tag (patch+1) and per-version counters stored in variable group 8622; BuildAndPackage does dotnet publish with version props, CycloneDX SBOM, builds the three UIF .tciz (swap config JSON per flavor, token-replace component.tcix, zip) and dotnet pack the DTO NuGet; publishes OpenAPI + changelog to PSB-Doc (tufin/oasdiff for the diff); uploads DTO to JFrog snapshot + ADO feed.
  • UploadToSCAPS (pool Bend_SelfHosted): install the Trumpf.Hmi.Uif tool from the ADO CAMBridge feed, then uif push <tciz> -k $(ScapsApiKey) -cg PlatformServiceBend for each flavor.

Release — azure-pipelines-release.yml

  • trigger: none. Run manually on the refs/tags/release/<x.y.z> tag; set the FluxVersion param to the branch's Flux line.
  • ResolveReleaseContext regex-matches the tag and fails the run if not on a release/* tag. psbVersion (= fullVersion) comes from the tag; fluxVersion comes from the parameter.
  • Build stamps fixed versions: /p:Version=$(fullVersion), /p:AssemblyVersion=$(psbVersion).0.
  • Same UIF/DTO/SBOM/OpenAPI flow; docs committed to PSB-Doc under releases/<psbVersion>/….

Cutting a release (from RELEASE.md / VERSION.md)

  1. On a release/<fluxVersion> branch (e.g. release/26.4.0), create + push a SemVer PSB tag release/<psbVersion> (e.g. release/1.3.0).
  2. Two version axes: branch = Flux SDK line, tag = PSB version. VERSION.md policy — PATCH = internal fix; MINOR = new Flux version or an added API version; MAJOR = breaking/removed API.
  3. Run the release pipeline manually on the tag with the matching FluxVersion.

Quality gates

  • SonarCloud — org trumpfcorp, key trumpfcorp_platform-service-bend, dotnet scanner, opencover coverage, PR decoration. Suppresses csharpsquid:S1135 on //TODO: Flux.Core markers.
  • AI PR review (azure-pipelines.ai-review.yml) — self-hosted, diffs hunks, calls an OpenAI-compatible API, posts inline PR comments; dedupes already-reviewed hunks on reruns via content hashes + a 🤖 AI Review thread marker. Config from the PlatformServiceBend variable group.
  • Changelog — tufin/oasdiff changelog (Docker) diffs OpenAPI per API-major line; runs automatically for beta (main) and release, manually via the changelog pipeline.
  • Usage docs — FluxServiceUsageDoc renders user docs from the head OpenAPI spec → PSB-Doc.
  • SBOM — CycloneDX sbom.json bundled into every UIF package.

Packages & SDK

  • global.json — SDK pinned 10.0.0, rollForward: latestMinor, allowPrerelease: false.
  • NuGet.Config — nuget.org (catch-all); Trumpf-Licensing-local = lib (relative → rewritten to absolute at build) for Trumpf.Licensing; Lantek.Artifactory = X:\Src\Lib for Protection.Key.Standard — note this "Artifactory" source is actually a local path on the mounted X: drive (there's a TODO to wire the real Artifactory URL). packageSourceMapping routes each package to its source.
  • Uploads — DTO nupkg → JFrog tatcadcam-local-nuget-snapshot (cURLUploader) + ADO feed 7447b8c2-…; uif tool from ADO CAMBridge feed.

Gotchas (verified in the pipeline files)

  • 🐞 /p:AssemblyInformationalVersion is a no-op. The SDK reads InformationalVersion. It happens to come out right only because /p:Version is also set (InformationalVersion defaults to Version) — so the +<build> metadata survives via Version. Don't "fix" it by dropping the Version arg.
  • 🐞 Relative lib NuGet source must be rewritten to an absolute path each build ("Fix local NuGet source path" step); restoring without it 404s Trumpf.Licensing.
  • 🐞 Lantek.Artifactory is a local X:\Src\Lib path, not a feed — restore of Protection.Key.Standard depends on the Flux X: mount, not a remote Artifactory (despite the name).
  • 🐞 Everything depends on subst X: succeeding (Flux build, Mesa3D, OpenAPI gen, local NuGet). The agent must allow subst and have X: free.
  • 🐞 Version counters need a PAT + hardcoded group 8622. BuildCounter / Version{Alpha,Beta}Counters are mutated via az pipelines variable-group variable update (AZURE_DEVOPS_EXT_PAT=$(PAT)); if the PAT expires, counters silently stop advancing.
  • 🐞 Inconsistent FluxVersion defaults across pipelines (platform 26.6.0, release 26.2.0, changelog/usage-doc 26.1.0) — a manual run can target the wrong Flux line unless overridden.
  • 🐞 Release doc pushes have no retry. Beta jobs retry PSB-Doc pushes 3× with rebase; the release PublishReleaseOpenApi/PublishReleaseDocs do a single git push — concurrent doc writes can fail.
  • ❓ OpenAPI gen reads PlatformServiceBend.exe from X:/src/bin (the Flux build output), not the publish dir — implicit coupling worth verifying.
