TruTime

product: trukit org: trumpf title: TruTime status: released tags: [trukit, tool, trutime, jira, sap, worklog, timebooking] updated: 2026-07-15

TruTime

Part of [[TruKit]]. A monthly time-booking cockpit that puts your SAP work time and your Jira worklogs side by side, so you can see — and fix — where the two don't line up, and how your hours split across Internal Order numbers.

Status: released — latest 5.0.32 (2026-07-15). 5.0.31 shipped the tool (P0–P6); 5.0.32 (aef63b9) adds two things: IO targets can group several internal orders under one shared % (e.g. IO-A 45% + [IO-B, IO-C] 50% = 95%), and IO resolution follows an "is in package" issue link when an issue has no parent. Both cross-built + published to OneDrive + broadcast via the self-update manifest; main pushed. Still wants real-machine validation (live Jira worklogs + SAP SSO; confirm the Internal Order BEND field type + that the link phrase is literally "is in package"). (planned) (P7) items still open. See the Implementation log at the bottom.

What it does

  • Monthly calendar — one cell per day, weekends greyed. Each day shows the SAP-booked hours (imported like [[TruWork]]) next to the Jira-logged hours, with a badge when the two don't match.
  • SAP import — reuses the [[TruWork]] SAP path; read-only, nothing written back to SAP, no credentials stored. Stores per-day SAP totals for comparison.
  • Jira worklog import — pulls the user's worklogs per issue per day via the Jira REST API, and shows how much was booked on what.
  • Internal Order (IO) resolution — reads the IO number from the issue; if empty, walks up to the parent issue to find it.
  • Target vs actual — a settings block to set a target % per IO number, driving a monthly diagram of should-be vs actual hours per IO, with the running delta.
  • Worklog CRUD — add, edit, and delete worklog entries directly from the tool (written back to Jira).
  • Quick add — paste a Jira key like BENDCAM-1245 and it immediately opens an add-worklog dialog for that issue.

Planned extensions

  • SAP ↔ Jira reconciliation (planned) — a per-day and per-month "unaccounted hours" figure (SAP booked but not covered by Jira worklogs, or the reverse); click a day to distribute the missing time across issues.
  • Realistic targets (planned) — base target hours on actual working days (minus holidays, vacation, part-time factor / contracted weekly hours), not a flat month, so the % targets stay accurate for non-full-time schedules.
  • IO caching (planned) — cache the resolved IO per issue so the parent lookup isn't repeated on every load, with a manual refresh IO action.
  • Smart quick-add (planned) — recent/favorite issues, autocomplete by summary, prefilled IO and duration, and shorthand like BENDCAM-1245 2h "unit tests".
  • Bulk & repeat entries (planned) — copy a day's worklogs to another day, template a typical week, or split a block across issues by percentage.
  • Validation & warnings (planned) — flag days over/under contracted hours, worklogs on closed issues, and issues whose IO can't be resolved.
  • Reporting / export (planned) — monthly CSV/Excel grouped by IO for controlling, plus a printable monthly summary.
  • Filters (planned) — filter the calendar by IO or project; optional read-only team view (respecting Jira permissions).

Availability

Proposed archetype: local-backend — like [[TruJira]], the Jira API access and worklog write-back most likely need TruKit's Rust backend, so it would run on the desktop app. (SAP import can reuse [[TruWork]]'s client-side flow.) Final archetype to be confirmed during design.

Notes

  • Overlaps with [[TruWork]] (SAP import, work-time view) and [[TruJira]] (Jira API, worklog sync) — reuse those code paths where possible.
  • SAP is strictly read-only; all write-backs go only to Jira worklogs.
  • Handle Jira's paginated worklog responses and rate limits.

Design log — 2026-07-14

Status moved proposed → planning. Grounded against the real TruKitV5 codebase (~/dev/trumpf/TruKitV5). This section is updated as the design firms up; the plan/roadmap lands at the bottom once verified.

Reuse surfaces confirmed in code

  • SAP import is already solved. Tauri command sap_time_import(from, to) → DayEvents[] (apps/desktop/src/sap_time.rs) opens a visible zero-IPC sap-auth webview (SSO/MFA against saperp.corp.trumpf.com), then fetches per-day time events + mobile/leave via the pure crates/sap-time (fetch/parse/model) over jkit-core's WinHTTP transport. TruWork and TruHomo already consume it client-side — TruTime reuses it verbatim to get per-day SAP hours. DayEvents = { date, blocks:[{start,end,status?,label?}], notes?:[{label,status?}] }.
  • Jira client is the pure crate crates/jkit-jira/src/client.rs (JiraClient::new, get_issue, search_jql, find_custom_field_id, edit_issue, set_field, comments, request_json/send helpers). IssueBean.fields is a generic serde_json::Map, so parent and any customfield_XXXXX (the IO field) are reachable without codegen changes. ⚠️ No worklog methods exist yet — worklog CRUD + a "my worklogs" path must be added here.
  • Jira credentials already exist in TruJira's plugin (crates/trujira, namespace plugin:trujira|): AppState.jira_store = machine-encrypted <data_dir>/TruJira/credentials/jira.enc. TruTime should reuse the same single Jira config (not a second credential prompt).
  • Tools plug in via one registry.ts entry + a Svelte module under packages/ui/src/tools/<id>/; shared tokens/theme from trukit-ui-kit; all tool UIs are English only.
  • Austrian holidays (Computus) already computed in TruHomo, and net-hours / break math (Austrian AZG) already in TruWork — reuse for realistic targets and the SAP↔Jira comparison basis, don't reinvent.

Archetype — confirmed

local-backend, available: () => true — like [[TruJira]]. Needs the Rust backend for Jira worklog CRUD and reuses the desktop-only sap_time_import, so it's desktop-only by nature. Every backend call is still runtime-guarded with isTauri() + a not-desktop empty state (TruWork's pattern), so a browser dev tab degrades gracefully instead of erroring.

Verified findings (design workflow wf_9bccedf9-583, 5 designers + 4 adversarial verifiers)

  • ✅ "My worklogs for a month" has no single Jira endpoint — CONFIRMED. The sanctioned path is JQL worklogAuthor = currentUser() AND worklogDate >= from AND worklogDate <= to → stream matching issues → per-issue paginated GET /rest/api/3/issue/{key}/worklog → re-filter client-side by author.accountId == me and started in range (JQL matches the issue, not the worklog, so a coarse match can slip in other authors / out-of-range logs). Add GET /rest/api/3/myself for the caller's accountId (Cloud hides emails, so email lookup is unreliable). Do NOT read the embedded issue.fields.worklog — it's capped at ~20 entries; use the dedicated endpoint. Pass startedAfter/startedBefore (epoch ms) to shrink pages.
  • ⚠️ Worklog DELETE needs a tiny jkit-core change — REFUTED the "no new infra" assumption. GET-worklogs / add / update reuse the existing request_json / request_no_content helpers verbatim (same shape as get_comments/add_comment), but the Method enum only has GET/POST/PUT (crates/jkit-core/src/http/mod.rs). Add a Delete variant (+ as_str + the reqwest arm; WinHTTP auto-works via as_str). ~3 lines, but it is a cross-crate change.
  • ⚠️ started write format is load-bearing — Jira Cloud rejects RFC-3339 +00:00 (colon) and needs RFC-822 +0000: %Y-%m-%dT%H:%M:%S%.3f%z (millis mandatory). Comment is ADF on read and write — reuse adf::text_to_adf for writes, add an adf_to_text flattener for display.
  • ⚠️ The "reuse TruWork/TruHomo math" is only half-true — the net-hours / 06:00-floor math and the Austrian-holiday Computus live inline in the .svelte $derived, not as importable functions. They must be extracted into shared pure modules (packages/ui/src/lib/worktime.ts + austrianHolidays.ts) — a small refactor touching TruWork & TruHomo — or TruTime copies them and they silently drift. No per-day SAP total helper exists today.
  • ✅ Sharing TruJira's jira.enc from a second reader is sound — CONFIRMED. The AES key derives from machine UUID + OS username, not the file path (jkit-core/src/cipher.rs), and FileBackend::load() re-reads+decrypts every call (no cache, no stale reads). Guard rail: TruTime stays read-only on jira.enc (writes to it happen only in TruJira's settings, and the save is a non-atomic in-place write) — a read racing that rare write returns a recoverable Err, never corruption.

Architecture decision — backend placement ✅ decided: new trutime plugin crate

New trutime plugin crate (option A — matches the repo's one-plugin-per-tool convention, see [[trujira-crate-rename]]). It opens TruJira's jira.enc read-only, owns its own non-Jira state (IO cache, IO targets, settings), and namespaces its commands plugin:trutime|…. Scaffolding to add: crates/trutime/ (Cargo.toml, src/lib.rs init() -> TauriPlugin, src/state.rs, src/commands.rs, build.rs, permissions/), the workspace-member + app Cargo.toml deps, .plugin(trutime::init()) in apps/desktop/src/lib.rs, and "trutime:default" in apps/desktop/capabilities/default.json. Use a shared path constant for TruJira's data dir so a layout change can't silently blank TruTime's creds.

The worklog client methods go in the shared jkit-jira crate (reused by both), and credential writes stay solely in TruJira — TruTime only reads jira.enc and, if Jira isn't configured, shows a CTA pointing the user to TruJira's settings.

Never persisted: Jira token, SAP cookies, or full worklog bodies (re-fetched live per month).

Math — targets & reconciliation (calc.ts, integer-minute arithmetic)

  • dailyHours = weeklyHours / workdaysPerWeek (default 38.5/5 = 7.7). Part-time is just a smaller weeklyHours — no separate factor to special-case.
  • availableHours(month) = availableDays × dailyHours, where availableDays = (Mon–Fri, minus Austrian public holidays) − SAP full-day absences (Vacation / Sick / Flex day / Pflegefreistellung, read from notes).
  • shouldBe(IO) = availableHours × pct/100; Σpct ≠ 100 → warn + show an "unallocated" bucket, never silently normalize.
  • actual(IO) = month's worklogs grouped by resolved IO; unresolved → a (unresolved) bucket kept in the total but excluded from per-IO deltas.
  • Reconciliation (per day, minutes): diff = sapNet − jira; unaccountedSap = max(0, diff), excessJira = max(0, −diff); |diff| ≤ toleranceMin (default 5) → reconciled. Two month totals: day-wise Σ max(0, diff) (actionable "still needs a worklog") and aggregate Σsap − Σjira (sanity). Skip future days.
  • SAP net basis: Σ over closed blocks of max(0, end − max(start, 06:00 floor)); open blocks (end=="") count 0 and flag the day incomplete (except today → extend to now); labels Mobile/Business trip/Travel count as work; full-day notes contribute 0 and zero the day's target. (06:00 floor and net-vs-gross exposed as settings — see decision below.)
  • Distribute missing time: distributeMissing(missingMin, issues[]) uses largest-remainder rounding so the split sums exactly to the gap (the day reconciles to 0 after the writes).

Phased roadmap (backend-first, each phase shippable)

  • P0 — jkit-jira worklog foundation. worklog.rs DTOs, the 4 client methods
    • get_myself, Method::Delete, adf_to_text, 429/Retry-After backoff. Unit-testable in the crate.
  • P1 — shared-lib extraction. lib/worktime.ts + lib/austrianHolidays.ts; refactor TruWork/TruHomo to import them (green svelte-check + existing tests).
  • P2 — backend commands + IO resolution. trutime_my_worklogs, trutime_resolve_io + parent walk + cache; wire the plugin (per the placement decision). Verify against a real BENDCAM issue.
  • P3 — read-only cockpit. Registry entry + MonthGrid + SAP import button + Jira refresh; per-day SAP-vs-Jira badges; not-configured / not-desktop states.
  • P4 — day detail + worklog CRUD. DayDetail + WorklogEditor + quick-add (paste a key); confirm-gated writes, refetch-verify, adjustEstimate=leave.
  • P5 — targets & IO diagram. IoTargets settings + IoChart (theme-aware inline-SVG bullet chart) + running delta.
  • P6 — reconciliation & validation. Unaccounted-hours figures, distribute- missing planner, warnings (closed issues, unresolved IO, missing clock-out).
  • P7 — planned extras. IO caching refresh UX, smart quick-add (KEY 2h "note", autocomplete), bulk/repeat entries, CSV/Excel export, filters.

Risks / watch-items

  • 429 backoff is a hard P0 dependency, not optional — the month import fans out N per-issue calls and Retry-After is currently dropped.
  • Timezone: Jira started is in the author's profile tz; bucket by instant → machine-local date, and pad the JQL/startedAfter window ±1 day so midnight-boundary logs aren't lost. Do the local-date derivation backend- side; the frontend must not re-derive from an ISO string.
  • DST on write: from_local_datetime can be None/ambiguous twice a year — pick a deterministic resolution (.single() else earliest).
  • Net ≠ SAP payroll net if a break sits inside a block (no clock-out) — our figure can read higher than SAP's official net (we only have raw punches). Document as a known limitation.
  • sap_time_import re-authenticates every call (visible SSO/MFA webview, 240 s timeout) — keep it an explicit button, never on month-nav.
  • Interval overlap (Mobile block vs. terminal punches on a mixed day) — merge overlapping intervals before summing to avoid double-counting.
  • Cross-crate path coupling (if option A) — reference TruJira's data dir via a shared constant so a layout change doesn't silently blank TruTime's creds.

Locked decisions — 2026-07-14

  1. ✅ Backend placement — new trutime plugin crate (plugin:trutime|), reading TruJira's jira.enc read-only. (see architecture section above)
  2. ✅ IO custom-field name — Internal Order BEND (official Jira field name). Default in settings; still overridable. Value type + parent-walk behaviour confirmed against a real issue during P2.

Post-implementation review (2 bugs found + fixed)

Adversarial review (parallel reviewers over Rust backend, Svelte reactivity, the JS↔Rust contract, and calc logic) confirmed 2 real bugs, both fixed:

  1. IO parent-walk aborted the whole month import — resolve_io_for_issue used client.get_issue(parent).await?, so an unreadable ancestor (deleted / restricted Epic → 403/404) failed all worklogs for the month. Fixed: the walk now stops on a parent-fetch error and leaves the IO unresolved (a warning), matching the other graceful-degradation paths.
  2. Stale worklogs leaked into the reconciliation totals on month change — worklogs wasn't cleared on nav, so the recon bar briefly (or permanently, if the refetch errored) mixed the previous month's Jira with the new month's SAP. Grid/DayDetail were unaffected (keyed by ISO). Fixed: month nav clears worklogs (not refreshJira, so a same-month manual refresh doesn't blank the view). The contract (all 7 commands), the two $effects, the request-token race guard, the 429 retry loop, and the timezone/DST math were all reviewed and cleared. Re-verified green after the fixes.

Implementation log — 2026-07-22 (branch feat/send-time-booking, merged to main)

Added send-time-booking (preview / dry-run only) — the ability to fill out a Mobile / Travel / Office time booking and preview the exact SAP OData request(s) that would be sent, without ever submitting. This deliberately stops short of the live POST: sending a booking triggers SAP notifications the user doesn't want, so the feature is "build-up-to-send + analyze how to send" only. The SAP services and field shapes are captured in [[SAP Time-Booking OData Reference]] (live-verified via read-only Playwright $metadata/entity GETs — no writes).

Curated scope (this pass): Mobile (0406), Travel (9800 Passive Reisezeit / 0800 Dienstreise), and Office time (P10/P20 clock events). Full-day/quota types (Vacation, Gleittag, …) and a data-driven full absence-type form are deferred.

What shipped

  • crates/sap-time/src/write.rs (new) — typed BookingRequest (Mobile/Travel/Office), SAP date/time formatters (/Date(ms)/, HHMMSS, PTnnHnnM00S), spec builders leave_request_spec (→ LeaveRequestSet) and time_event_specs (→ two TimeEventSet P10+P20), and a dry-run prepare() returning serializable PreparedRequests (method/url/body). Reuses the existing generic WriteSpec + odata_write primitive (which is never called — verified branch-wide).
  • crates/trutime/src/commands.rs — sap_book_preview (live-path DRY RUN, returns the built request(s)) + sap_file_book_time (disconnected bridge: drops OP_ODATA_WRITE command files for TruKitSync to execute on the connected PC — TruTime itself never POSTs). Bridge write is best-effort rolled back on partial failure so a lone clock-in can't be left orphaned.
  • packages/trutime/src/BookingForm.svelte + api.ts bindings — a preview-only form (type / start / end / note); no submit button.

Process / verification. Brainstorm → spec (docs/superpowers/specs/…) → plan (docs/superpowers/plans/…) → 6 TDD tasks via subagent-driven development, each reviewed. Final whole-branch review: no Critical issues, confirmed the no-live-POST invariant holds across the whole branch. Rust 59/59 + svelte-check 0/0 green. Merged to main (--no-ff).

Open follow-ups. Wiring the live SendMode/submit is a separate, explicitly-authorized step (intentionally not built — no live-submit code to mis-wire). BookingForm isn't mounted in a view yet (plan scope = create only). SAP_ORIGIN is duplicated between trutime/commands.rs and sap-tauri/lib.rs — could share one const in sap-time.
