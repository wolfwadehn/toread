ARVTablesDiesSpecialBendTools

product: trukit org: trumpf title: "ARV Tables — Dies & Special Bend Tools" tags: [trukit, truarv, arv, bend, reference] source: "TruTopsCAD legacy source — Bend DB schema (ToPs 600), files dated May 2024" status: reverse-engineered-draft related: ["[[ARV Format & Value Mapping]]", "[[TruARV]]", "[[ARV Value Legends (consolidated)]]"]

ARV Tables — Dies & Special Bend Tools

This cluster documents the lower-tool / special-forming-tool tables of the TRUMPF Bend database (ToPs 600) as they appear in an .arv export: the die catalogue (WZG_GESENK), folding/hemming leaves (WZG_FALZ), flat-processing tools (WZG_FLACH), Z-bend tools (WZG_ZBIEG), hinge tools (WZG_SCHARNIER), swivel benders (WZG_SCHWENKBIEGER), radius/wave shafts (WZG_WELLE), angle-measuring combinations (WZG_MESS_BEREICHE / WZG_MESS_SCHENKEL) and sensor disks (WZG_TASTSCHEIBEN). In an ARV [ENTRY_i], table: names one of these tables and each attribnameN/attribvalueN pair is a column name + value. Many *ID / *Flag / *Form* columns are coded integers that resolve against the (un-exported) ENUMWERTE table; where the code→meaning legend is knowable it is given inline below, otherwise it is marked undetermined (needs ENUMWERTE data).

Source of truth: each column's German MS_Description (extended property) in Databases/SQLServerDatabase/Tables/Bend.<TABLE>.sql. English is a translation, German kept in parentheses. Legends are tagged with SOURCE (INFO_TEXTS = legend already shipped in TruARV infotexts.ts; MS_Description; CHECK; code-crossref = tc_dbase/benddef.h; inferred) and CONFIDENCE.

Schema-only caveat: this is a DDL snapshot with no seed data, so ENUMWERTE is empty. All the die/tool shape enums (GesenkformID, GesenkartID, FlachBearbID, WellenformID, MessformID) have a known meaning but an unknown numeric legend — their column defaults (21, 28, 24, 36, 34…) do not fall in the ToPs600 shape ranges shown in the legacy resx (e.g. MatritzenformID 58–71), so those legends are not assumed to transfer. See Open questions.

Shared columns (present in nearly every tool table)

Almost all main tables below share a common tool-header block. It is documented once here; per-table sections list only the columns that differ or that carry a table-specific meaning. (WZG_MESS_BEREICHE, WZG_MESS_SCHENKEL and WZG_TASTSCHEIBEN are structured differently and are fully documented in their own sections.)

Open questions

  • TypGreifnut legend conflict. The DB MS_Description says 0 = B06; 1 = B23, but the shipped TruARV/resx legend says 0 None; 1 A0; 2 A1; 3 A2; 4 S1; (?) L0. These are two different code systems (grip-groove standard designations vs. named grooves). Needs a live ENUMWERTE / groove-catalogue export to reconcile; current tables default TypGreifnut = 0.
  • Die/tool shape enums have known meaning but unknown numbers. GesenkformID (default 21), GesenkartID (28), FlachBearbID (24), WellenformID (36), MessformID (34) all reference ENUMWERTE, which is empty in this DDL snapshot. Their defaults lie outside the resx MatritzenformID (58–71) / StempelformID (54–57) ranges, so those shipped legends cannot be assumed to apply. Legends undetermined until ENUMWERTE seed data is obtained.
  • TypMesswerkzeug default mismatch. WZG_TASTSCHEIBEN defaults 19 (matches WZG_TYP_ID "measuring tool"), but WZG_MESS_BEREICHE defaults 90. Whether TypMesswerkzeug uses the WZG_TYP_ID code space, a MessformID-style space, or its own is unconfirmed.
  • WerkstoffID, EndbearbeitungID, EinbauSafetyClickID, WerkzeugwechslerFlag codes — no legend derivable from schema (no CHECK, no INFO_TEXTS entry). WerkzeugwechslerFlag is only bounded 0..3 by CHECK. All need ENUMWERTE (and for the finishing/material tables, the SPRACHEN_ENG text join).
  • RichtungNachUnten (WZG_GESENK) — legend inferred (4=yes / 5=no) from the DB's consistent 4/5 yes-no convention (BiegenImGesenk, BohrungMoeglich, Falzspalte, ZudrueckFlag), not directly documented. Default 5.
  • ToPs600 vs. tc_dbase enum divergence. The ARV/ToPs600 Biegeart (1 Folding / 2 Air / 3 Bottom) is not the tc_dbase benddef.h Biegeart (0 Normkantung … 9 Hilfsbiegung); likewise FlachBearbID is only loosely related to benddef.h Biegetechnik (10 Prägung / 11 Fügung / 12 Umformen). Treat benddef.h strictly as cross-reference, not as the code source for ARV columns.
  • MinWzgRadius / MaxWzgRadius (WZG_MESS_BEREICHE) carry an MS_Description that reads "min/max Festigkeit" (strength) although the column names say radius — likely a copy-paste error in the schema comment; treated here as tool radius (mm) per the column name.
  • MatritzenformID has no DB column in this schema. It appears only as a legacy resx/ToPs600 attribute name; the physical die-shape column is GesenkformID (WZG_GESENK) or the WZG_MA die table. Confirm which table the ARV exporter emits MatritzenformID for.
