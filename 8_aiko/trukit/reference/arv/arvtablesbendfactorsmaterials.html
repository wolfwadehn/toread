ARVTablesBendFactorsMaterials

product: trukit org: trumpf title: "ARV Tables — Bend Factors (AKF) & Materials" tags: [trukit, truarv, arv, bend, reference] source: "TruTopsCAD legacy source — Bend DB schema (ToPs 600), files dated May 2024" status: reverse-engineered-draft related: ["[[ARV Format & Value Mapping]]", "[[TruARV]]", "[[ARV Value Legends (consolidated)]]"]

ARV Tables — Bend Factors (AKF) & Materials

This cluster documents the ToPs 600 Bend database tables that an .arv export carries for bend factors / bend deduction (Abkantfaktor) and for material master data. In an ARV entry, table: names one of these tables and each attribnameN/attribvalueN pair is a DB column name and its (often coded) value. Meanings below come from the authoritative MS_Description extended properties, CHECK constraints and FKs in the schema; coded-value legends are the priority output.

A structural note on this schema dump: in the Bend schema every table in this cluster is actually a view over base tables that physically live in the Common schema. So Bend.AKF_BENDFACTORS, Bend.MAT_MATERIAL, Bend.MAT_RAWMATERIAL, Bend.MAT_GRP, Bend.MAT_SHEET are 1:1 pass-throughs (SELECT * FROM Common.<table>) and inherit the base-table column descriptions. AKF_ABKANTFAKTOR, MATERIAL, MATERIAL_BEND, MATERIAL_4_15 and AKF_ABKANTFAKTOR_4_15 are derived join/rename views (no new columns, no own MS_Description). The value legends are therefore identical whether the ARV table: says Common.* or Bend.*.

The single most important legend in this cluster is AKF_VERFAHREN (the ToPs 600 bend method for a bend-factor row): 0 = folding with gap; 1 = folding without gap; 2 = air bending; 3 = coining. Note this numbering is different from the tc_dbase/benddef.h Biegemethode enum — see Open questions.

AKF_BENDFACTORS

Purpose: the bend-factor / bend-deduction table — one row per (material, thickness, foil, coating, upper-tool group, die group, bend method, angle) giving the Abkantfaktor and correction values Tops uses to compute the developed (flat) length. Base table Common.AKF_BENDFACTORS; Bend.AKF_BENDFACTORS is a pass-through view. Primary key = (AKF_WS_ID, AKF_MATERIAL_DICKE, AKF_FOIL, AKF_COATING, AKF_OW_GRUPPE, AKF_MA_GRUPPE, AKF_VERFAHREN, AKF_WINKEL). FK AKF_WS_ID → MAT_MATERIAL.WS_ID.

AKF_ABKANTFAKTOR

Purpose: convenience view that is AKF_BENDFACTORS joined to MAT_MATERIAL, adding the human-readable material name so a bend-factor row carries its material name instead of only the numeric ID. Definition (Common.AKF_ABKANTFAKTOR): SELECT MAT_MATERIAL.WS_NAME AS AKF_MATERIAL_NAME, AKF_BENDFACTORS.* FROM AKF_BENDFACTORS INNER JOIN MAT_MATERIAL ON AKF_WS_ID = WS_ID. Bend.AKF_ABKANTFAKTOR is a pass-through of that view. All AKF_* columns and their legends are exactly as in AKF_BENDFACTORS above; only the extra column is listed here.

AKF_WS_ID … AKF_KORREKTUR_FAKTOR (inherited from AKF_BENDFACTORS) — — see AKF_BENDFACTORS — high

AKF_ABKANTFAKTOR_4_15

Purpose: legacy "4.15" compatibility view — a reduced column set of AKF_ABKANTFAKTOR filtered to the plain case AKF_FOIL = 0 AND AKF_COATING = 0 (no foil, not galvanized). Drops AKF_WS_ID, AKF_FOIL, AKF_COATING, AKF_MIN/MAX_DICKE and keys on AKF_MATERIAL_NAME instead. No new columns; legends inherited from AKF_BENDFACTORS.

MATERIAL

Purpose: legacy view = MATERIAL_BEND plus the best-matching bend-factor key for each raw material. Definition (Bend.MATERIAL): SELECT MATERIAL_BEND.*, AKF_WS_ID, AKF_FOIL, AKF_COATING FROM MATERIAL_BEND LEFT JOIN SELECT_BEST_KEYS_FOR_BEND_FACTOR_SELECTION ON MATERIAL_BEND.RM_NAME LIKE …RM_NAME. SELECT_BEST_KEYS_FOR_BEND_FACTOR_SELECTION ranks bend-factor rows per raw material by matching WS_ID, coating, foil (using only RM_FOIL & 2, i.e. the two-sided-foil bit) and thickness distance, keeping the best row. Bend-factor selection (how the view derivation works)

AKF_BENDFACTORS is the raw factor table; AKF_ABKANTFAKTOR = it + material name; SELECT_BEST_KEYS_FOR_BEND_FACTOR_SELECTION picks, per raw material, the single best AKF_* row using this priority (see the view SQL): (1) AKF_WS_ID = RM_WS_ID, (2) AKF_COATING = RM_COATING, (3) AKF_FOIL = (RM_FOIL & 2), (4) smallest thickness distance ABS(AKF_MATERIAL_DICKE − RM_THICKNESS)*5000 + (AKF_MIN_DICKE−RM_THICKNESS)² + (AKF_MAX_DICKE−RM_THICKNESS)², then smallest AKF_MATERIAL_DICKE. Candidate rows must satisfy RM_THICKNESS BETWEEN AKF_MIN_DICKE AND AKF_MAX_DICKE, AKF_FOIL IN (RM_FOIL&2, 0), AKF_COATING IN (RM_COATING, 0), and the material must match AKF_MATERIAL_NAME IN (WS_NAME, WS_BEND_FACTOR_ALIAS). Takeaway for ARV readers: only the two-sided-foil bit (&2) of RM_FOIL participates in bend-factor matching, and WS_BEND_FACTOR_ALIAS lets a material borrow another material's factors.

Open questions

  • AKF_VERFAHREN vs benddef.h Biegemethode divergence (important). The ARV/ToPs 600 AKF_VERFAHREN legend (from MS_Description) is 0 = folding with gap, 1 = folding without gap, 2 = air bending, 3 = coining. The tc_dbase/benddef.h Biegemethode enum is a different numbering for a related concept: 0 Freibiegen (air), 1 Praegen (coining), 2 Falz mit Spalt (folding w/ gap), 3 Zudruecken (hemming), 4 Schwenkbiegen (swivel). They are NOT interchangeable — do not map AKF_VERFAHREN through the benddef.h codes. Use the AKF_VERFAHREN legend for these tables (confidence high, MS_Description). The benddef.h enum is cross-reference only (confidence code-crossref).
  • "Biegeart" ARV attribute is not in this cluster. The existing INFO_TEXTS Biegeart legend (1 Folding, 2 Air Bending, 3 Bottom Bending) and Verwendung legend (usage) belong to the tool/fixture (WZG_*) tables, not to the AKF/material tables here. No column named Biegeart or Verwendung exists in any of these ten tables. Keep those legends where they are; the bend-method analog in this cluster is AKF_VERFAHREN (different values). Coincidentally both use 2 = air bending, but the rest of the scale differs.
  • ARV attribute aliases vs schema column names. The parent's fixture list uses names WerkstoffID, FestigkeitVon, FestigkeitBis which are ToPs 600 export-layer labels, not literal column names in this schema. Best mapping: WerkstoffID → WS_ID (MS_Description "lfd. Nr des Werkstoffes"/"Werkstoffkennung"); FestigkeitVon/FestigkeitBis → WS_MIN_ZUGFESTIGKEIT / WS_MAX_ZUGFESTIGKEIT (min/max tensile strength). Confirm against a real ARV sample if available.
  • LOCKSTATE codes undetermined. All *_LOCKSTATE columns document only 0 = not locked; the non-zero lock-reason codes live in CONST_TRANSLAT_CUSTOMER, which is customer-specific and not in this schema-only dump. Needs live data / a customer DB to legend.
  • WS_BEM_LINK / WS_PCS_FORMEL are foreign-key/id references (into TEXTE and a formula table) whose value ranges cannot be enumerated from the schema alone.
  • RM_ISITINCH = −1 is permitted by the CHECK constraint but not covered by the MS_Description legend (0/1/2). Meaning inferred as "undefined/unset"; unconfirmed.
  • Units for several physical properties (density, thermal conductivity, resistivity, coining force) are not stated in the schema; the units shown above are the conventional ToPs values and should be treated as medium confidence.
  • These are metric (Common / Bend) definitions. The inch variants (Common_inch / Bend_inch) carry the same columns and legends but express lengths/thicknesses in inches; an ARV from an inch database will report inch values with the same coded enums.
