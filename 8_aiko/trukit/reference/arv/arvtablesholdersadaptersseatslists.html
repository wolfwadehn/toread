product: trukit org: trumpf title: "ARV Tables — Holders, Adapters, Seats & Tool Lists" tags: [trukit, truarv, arv, bend, reference] source: "TruTopsCAD legacy source — Bend DB schema (ToPs 600), files dated May 2024" status: reverse-engineered-draft related: ["[[ARV Format & Value Mapping]]", "[[TruARV]]", "[[ARV Value Legends (consolidated)]]"]

ARV Tables — Holders, Adapters, Seats & Tool Lists

This note documents the ToPs 600 Bend-DB tables that describe bending tool holders (Halter), adapters (Adapter), tool seats/mounts (Aufnahme), the tool-catalog registry (WZG_TABELLEN) and tool-assembly lists (WZG_LISTE / …_STUECKELUNG = "sectioning"). In an ARV archive each [ENTRY_i] carries a table: naming one of these tables; the attribnameN values are the DB column names below and attribvalueN are the column values — usually a coded integer whose meaning is given in the "Value legend" column. Meanings come from each column's MS_Description extended property (authoritative German meaning, translated here with the original kept in parentheses); coded-value legends come from MS_Description inline lists, CHECK constraints, the shipped TruARV INFO_TEXTS legends, and — as cross-reference only — tc_dbase code enums.

Snapshot caveat: the SQL here is schema-only. The ENUMWERTE value table (and EXPORT_CLASSNAME_TABLE_MAP, CONST_TextToInt) contain no seed rows, so several coded columns (WerkstoffID, MaschinenTypID, EndbearbeitungID, and the full AufnahmeID/WzgAufnahmeID seat catalog beyond what INFO_TEXTS already ships) have no determinable legend from this snapshot and are marked "undetermined (needs ENUMWERTE data)".

Shared seat catalog: AufnahmeID and WzgAufnahmeID both reference the same tool-seat/mount catalog. The WZG_HALTER.WzgAufnahmeID column is CHECK-validated against ENUMWERTE ANZEIGE_ART group 481 (via checks.tsf_CheckBendEnums(WzgAufnahmeID, 481)), i.e. the same enum the shipped AufnahmeID legend (0 Sensors … 110 EHT_OWH01) enumerates. Semantically: AufnahmeID = the seat this part has; WzgAufnahmeID = the seat a tool must have to be mounted on this holder/adapter (or, for an adapter/seat, the seat it presents upward).

Open questions

  • table:WZG_TYP has no DDL in this snapshot. ARV archives were observed to carry a table:WZG_TYP entry, but there is no Bend.WZG_TYP.sql (nor CAD view) in the Tables/Views folders. The class→table mapping that would resolve it (EXPORT_CLASSNAME_TABLE_MAP) is schema-only (no seed rows), so the WZG_TYP column set and its relationship to WZG_TYP_ID/WzgAttribTyp cannot be documented from this snapshot. WZG_TYP is almost certainly the tool-type master keyed by the WZG_TYP_ID (16–26) enum used in WZG_*_ATTRIBUTE and WZG_LISTE_STUECKELUNG, but that is unverified here.
  • TypGreifnut legend conflict. The MS_Description on both WZG_HALTER_ATTRIBUTE and WZG_ADAPTER_ATTRIBUTE states 0 = B06; 1 = B23 (gripper-groove hardware codes). The shipped TruARV INFO_TEXTS TypGreifnut legend instead lists 0 None; 1 A0; 2 A1; 3 A2; 4 S1; L0. These are two different code systems for the same-named attribute (the INFO_TEXTS one likely came from a different tool subsystem/context, e.g. the OW/punch gripper-groove list). For these two Bend tables, treat the schema's 0=B06 / 1=B23 as authoritative; keep the INFO_TEXTS list only where its source context applies. Needs confirmation of which viewer field maps to which.
  • WerkstoffID, MaschinenTypID, EndbearbeitungID, Eignung legends undetermined. These are ENUMWERTE-backed coded columns, but ENUMWERTE ships no seed rows in this snapshot. Defaults observed: WerkstoffID=1, MaschinenTypID=2, EndbearbeitungID=52 (Halter) / 51 (Adapter), Eignung=0. EndbearbeitungID ("Art der Endbearbeitung") is a separate enum from BeschreibungID, despite its default values (51/52) numerically overlapping the BeschreibungID catalog — do not conflate.
  • AufnahmeID / WzgAufnahmeID seat catalog is only partially legended. The full list lives in ENUMWERTE group 481 (confirmed via checks.tsf_CheckBendEnums(WzgAufnahmeID, 481) on WZG_HALTER); only the entries already in the shipped INFO_TEXTS AufnahmeID legend (0 … 110) are known, and even that list is truncated. Note that INFO_TEXTS presents the same catalog as AufnahmeID; there is no separate WzgAufnahmeID legend — they share group 481.
  • WerkzeugwechslerFlag is CHECK-constrained to 0–3 but the schema gives no per-value meaning (0 is presumably "not suitable"; 1/2/3 unknown, possibly encoding which changer/orientation). Undetermined.
  • WZG_TABELLEN flags (OW_COMBOBOX, UW_COMBOBOX, OW_KATALOG, UW_KATALOG, WERKZEUGFILTER) have no MS_Description; meanings above are inferred from column names (OW=upper/punch, UW=lower/die; COMBOBOX vs. KATALOG visibility). Value encoding (assumed 0/1 flags) is unverified.
  • WZG_LISTE.Werkzeugfilter — MS_Description says "tool-type number (for table selection)"; it plausibly reuses the BeschreibungID (38–51) catalog but this is not confirmed for this specific column.
  • tc_dbase vs. ToPs600 enum divergence. The tc_dbase code enums (benddef.h: Biegeart 0 Normkantung … 9 Hilfsbiegung, Biegemethode, Biegetechnik) are a different subsystem from the ToPs600 ARV attribute enums documented here (e.g. ToPs600 Biegeart 1 Folding / 2 Air Bending / 3 Bottom Bending). None of the columns in this holder/adapter/seat cluster are Biegeart-typed, so there is no direct conflict inside this cluster, but do not assume shared numbering when cross-referencing.
