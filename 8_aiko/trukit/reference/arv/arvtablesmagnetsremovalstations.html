ARVTablesMagnetsRemovalStations

product: trukit org: trumpf title: "ARV Tables — Magnets, Removal & Turn Stations" tags: [trukit, truarv, arv, bend, reference] source: "TruTopsCAD legacy source — Bend DB schema (ToPs 600), files dated May 2024" status: reverse-engineered-draft related: ["[[ARV Format & Value Mapping]]", "[[TruARV]]", "[[ARV Value Legends (consolidated)]]"]

ARV Tables — Magnets, Removal & Turn Stations

This note documents the automation-fixture tables of the TRUMPF Bend database (ToPs 600, T600_V100) as they appear in an .arv export: magnet grippers (WZG_MAGNET*), the bending-die tool family that was grouped into this cluster (WZG_MA*), removal / unloading stations (WZG_ENTNAHMESTATION*), turn stations (WZG_WENDESTATION), re-gripping consoles (WZG_UMGREIF*), the conveyor (FOERDERER), the backlight/transillumination table (DURCHLEUCHTTISCH) and pallets (PALETTEN). In an ARV [ENTRY_i] block, table: names one of these tables and each attribnameN/attribvalueN pair is a DB column and its value — often a coded integer whose meaning is the "Value legend" column below. Meanings come from each column's MS_Description extended property; German originals are kept in parentheses. Coded-value legends are marked with a source (INFO_TEXTS = legend already shipped in TruARV infotexts.ts; MS_Description / CHECK / code-crossref / inferred) and a confidence. The SQL here is schema-only — the ENUMWERTE legend rows are not present — so many coded columns (material, finishing, pallet-type catalogs) cannot be resolved to labels and are marked "undetermined".

A recurring TRUMPF idiom in this cluster: yes/no flags are encoded as 4 = yes/active, 5 = no/inactive (seen in BohrungMoeglich, Falzspalte, and inferred for Seitenwand, Druckueberwachung).

Individual magnet/sucker placed on a magnet plate (Sauger = sucker), with its position, task and hold-timing. FK ID → WZG_MAGNETPLATTE.

Open questions

  • Material / finishing / pallet-type catalogs are undetermined. WerkstoffID (WZG_MAGNETPLATTE, WZG_MA, WZG_MA_SCHWENK), EndbearbeitungID (WZG_MA, WZG_MA_SCHWENK), BeschreibungID-as-pallet-type (WZG_ENTNAHMESTATION, PALETTEN), Separierungstyp and Eignung (WZG_MAGNETPLATTE), and BezeichnerID (GRIPPER_PARAMETER, ENTNAHMESTATION_PALETTE) are coded integers whose label sets live in the ENUMWERTE table — which is schema-only here, so no legends could be read. Needs an ENUMWERTE data dump.
  • WZG_MAGNET.Aufgaben — MS_Description lists the five tasks (grip / separate / grip+separate / weigh / sensor) but not their codes. Could be an enumerated 1..5 or a bitmask (grip+separate = 3 = 1|2). Default 1. Needs ENUMWERTE.
  • WZG_UMGREIFBELEGUNG.SaugarmTyp — three arm kinds named (sliding / rotatable / rotatable+telescope); numeric assignment (assumed 0/1/2) unconfirmed.
  • TypGreifnut divergence. Schema MS_Description for the die tables (WZG_MA_ATTRIBUTE, WZG_MA_SCHWENK_ATTRIBUTE) says 0 = B06, 1 = B23, but the TruARV-shipped TypGreifnut legend is "0 None, 1 A0, 2 A1, 3 A2, 4 S1, ? L0" (gripper/sucker groove types). These are two different attributes sharing a name — the shipped legend must be scoped to the sucker/gripper tables, not to the MA die tables. Recommend splitting the legend per table in infotexts.ts.
  • WZG_MAGNET_TYP_VIEW vs Saugertyp enum. The view selects WZG_SAUGER_TYP rows with Saugertyp = 2 OR 3 (= separation cylinder / weighing module) and aliases them as Magnettyp, whereas the authoritative Saugertyp legend maps 4 = Magnetsauger (magnet sucker). The view appears to predate an enum renumbering. Confirm which codes actually denote magnets in current data.
  • LageID / MontageID are overloaded across subsystems. For the MA die tools they use the shipped tool legends (LageID 13/14/15; MontageID 8/9). For WZG_UMGREIFKONSOLE the same column names mean right/left (LageID) and table-vs-regrip-unit (MontageID) with different numeric domains (defaults 1 and 3) that are undetermined. Do not apply the tool legend to the console rows.
  • 4/5 yes-no idiom is inferred for Seitenwand (WZG_ENTNAHMESTATION, PALETTEN) and Druckueberwachung (WZG_UMGREIFKONSOLE) from the confirmed BohrungMoeglich/Falzspalte pattern; not independently documented for these columns.
  • 0/1 flags inferred: WerkzeugwechslerFlag, Montiert, SynchronVerfahren, FlagBlechdickenmessung — treated as boolean (0 = no/off, 1 = yes/on) from the German wording; not stated numerically in the schema.
  • WZG_ENTNAHMESTATION.TeilanschlagInXRichtung / InYRichtung ("Ausrichtung in +X/+Y") are coded ints (default 0) with no legend — likely a direction/enable flag; undetermined.
  • WZG_WENDESTATION has ~14 columns whose MS_Description is literally 'NULL' (undocumented) and its Typ description is copied from FOERDERER; meanings above are inferred from column names (medium confidence). FOERDERER.Position{X,Y,Z} descriptions are cyclically transposed vs. the column names.
  • WZG_MA_GRUPPE.WZG_MA_BIEGEART vs WZG_MA.Biegeart. The group table's bend-method code (default 0, "Freibiegen/Prägen") could be 0-based or reuse the ARV Biegeart 1/2/3 (or WZG_OW_BIEGEART 1/2) domain — unresolved. This is also the general ToPs600-vs-tc_dbase/benddef.h Biegeart divergence: the tc_dbase code enum (0 Normkantung, 1 Falzung, …) is a different subsystem and must not be conflated with the ARV Biegeart used in these tables.
