ARVTablesSuctionGrippers

product: trukit org: trumpf title: "ARV Tables — Suction Cups & Grippers" tags: [trukit, truarv, arv, bend, reference] source: "TruTopsCAD legacy source — Bend DB schema (ToPs 600), files dated May 2024" status: reverse-engineered-draft related: ["[[ARV Format & Value Mapping]]", "[[TruARV]]", "[[ARV Value Legends (consolidated)]]", "[[ARV Tables - Upper Tools (Punches)]]"]

ARV Tables — Suction Cups & Grippers

This note documents the ten Bend-database tables that describe the automation gripping tools exported into a TRUMPF .arv archive: the suction-plate family (WZG_SAUGERPLATTE master + its child WZG_SAUGER cup-positions + the WZG_SAUGER_TYP cup-type catalog), the multi-arm gripper (WZG_MULTIGREIFER master + WZG_MULTIGREIFER_ARM swivel-arm records), the tong gripper (WZG_GREIFZANGE master + WZG_GREIFPRATZE jaw catalog + WZG_PRATZENPOSITION clamp positions), and the cantilever/boom (WZG_AUSLEGER master + WZG_AUSLEGER_PARAMETER generic parameter bag). In an ARV [ENTRY_i], table: names one of these and each attribnameN/attribvalueN pair is a column name + value from that table. Where a value is a coded integer, the priority below is the value legend (coded value → meaning). Legends come from inline MS_Description text, the shipped TruARV INFO_TEXTS, and — as cross-reference — code enums. The SQL snapshot is schema-only (no ENUMWERTE, material, or text-catalog rows) and these gripper tables carry no CHECK constraints, so most flag/type columns cannot be legended and are marked undetermined below and listed under Open questions. German MS_Description text is kept in parentheses after the English. The DB is the metric variant (there are _inch siblings elsewhere), so lengths are millimetres, times seconds, angles degrees.

Reconciliation with existing INFO_TEXTS: none of these tables' coded columns (Saugertyp, Aufgaben, Separierungstyp, Eignung, MitAusleger, MitVentilsteuerung, Druckueberwachung, Backentyp, Klasse, Pratzenlage, DefRichtungAussen) currently have an INFO_TEXTS legend — they are all new. The one collision is BeschreibungID on WZG_GREIFZANGE: INFO_TEXTS ships a BeschreibungID legend (38 Punch … 51 Folding Die) but that legend belongs to the punch/die tables (WZG_OW etc.); on a gripper tong its default is 1, outside that 38–51 range, so the shipped legend does not apply here. See Open questions. MitAusleger/MitVentilsteuerung are legended by inference from the documented ToPs600 4/5 boolean convention (INFO_TEXTS: BohrungMoeglich 4=yes,5=no; Falzspalte 4=active,5=not active).

Open questions

  • Aufgaben / Sauger*_Aufgabe numeric codes. MS_Description enumerates the task categories (grip / separate / grip+separate / weigh / sensor; on WZG_MULTIGREIFER_ARM: Vereinzelung / Waegen / WaegenVereinzeln) but not their integer codes. WZG_SAUGER.Aufgaben defaults to 1 while the arm's Sauger*_Aufgabe defaults to 0 — suggesting the two use different encodings (possibly a bitmask on the arm, given the combined "WaegenVereinzeln"). Needs ENUMWERTE seed data.
  • Separierungstyp (Typ der Vereinzelung; WZG_MAGNETPLATTE calls it "Methodentyp"), Eignung (Suitability, default 3), WerkstoffID (material catalog), Klasse (Auslegertyp ID), Backentyp (jaw type), Pratzenlage (upper/lower / left/right) — all coded, none legendable from the schema-only snapshot (no ENUMWERTE, CHECK, or inline value list). Values needed.
  • Druckueberwachung described only as on/off with default 0; presumed 0 = off / 1 = on but not confirmed (does not follow the 4/5 boolean family, unlike MitAusleger/MitVentilsteuerung).
  • MitAusleger / MitVentilsteuerung 4/5 legend is inferred, not confirmed for these tables. It rests on the documented ToPs600 4/5 boolean convention (INFO_TEXTS: BohrungMoeglich 4=yes,5=no) plus the column defaults (MitAusleger=5 "no", MitVentilsteuerung=4 "with"). Confirm against ENUMWERTE.
  • BeschreibungID collision. WZG_GREIFZANGE.BeschreibungID shares a column name with the punch/die BeschreibungID that INFO_TEXTS legends (38–51), but the gripper default is 1 and the tool class is unrelated — the shipped legend must not be applied to tongs. WZG_GREIFPRATZE.Backentyp has an index misnamed …$BeschreibungID, hinting a shared code family, but this is unverified. Separate legend(s) needed.
  • Backentyp unit / Bewegungsintervall. Bewegungsintervall can be either an angle (°) or a linear travel (mm) depending on jaw kinematics; the schema does not flag which, per row.
  • MS_Description copy-paste artefacts. WZG_AUSLEGER.Breite and .Hoehe both read "Länge des Auslegers"; WZG_PRATZENPOSITION.Typ reads "Bezeichnung des Saugers". Meanings above are corrected from column name + context; upstream doc bug.
  • ToPs600 vs. tc_dbase divergence. The tc_lift/TcSauger.h code enums (TeTyp: 1 trag, 2 dreh, 3 abschael, 4 gruppe, 5 koppel; TeArt: 0 gesperrt, 1 beladen, 2 entladen, 3 beUndEntladen; TeEigenschaft: 0 vakuum, 1 magnet, 2 vakuumUndMagnet, 3 holeGripper) and tc_stz/…/steu_def.h Sauger_art are a different subsystem (ToPs CAD/300 loading automation) and do not match the ToPs600 WZG_SAUGER_TYP.Saugertyp numbering (0 Unknown … 5 Blechsensor). Do not conflate.
