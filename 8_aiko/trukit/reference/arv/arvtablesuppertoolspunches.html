product: trukit org: trumpf title: "ARV Tables — Upper Tools / Punches (Oberwerkzeug)" tags: [trukit, truarv, arv, bend, reference] source: "TruTopsCAD legacy source — Bend DB schema (ToPs 600), files dated May 2024" status: reverse-engineered-draft related: ["[[ARV Format & Value Mapping]]", "[[TruARV]]", "[[ARV Value Legends (consolidated)]]"]

ARV Tables — Upper Tools / Punches (Oberwerkzeug)

This note documents the three Bend-database tables that describe upper bending tools = punches (Oberwerkzeug) as exported into a TRUMPF .arv archive: WZG_OW (the punch tool-type master), WZG_OW_ATTRIBUTE (per-length / per-order-number individual-tool records, 1:n under WZG_OW.ID with ON DELETE CASCADE), and WZG_OW_GRUPPE (the punch group that couples tools to a common bend-deduction factor / Abkantfaktor). In an ARV [ENTRY_i], table: names one of these and each attribnameN/attribvalueN pair is a column name + value from that table. Many values are coded integers; the priority below is the value legend (coded value → meaning). Legends come from the shipped TruARV INFO_TEXTS (migrated from the legacy TruNinja Resources.resx), from inline MS_Description text, and from CHECK constraints. The SQL snapshot is schema-only (no ENUMWERTE / material / seat / finishing catalog rows), so several FK-catalog and flag columns cannot be legended here and are listed under Open questions. MS_Description German is kept in parentheses after the English.

Reconciliation note: the INFO_TEXTS legend for TypGreifnut (0 None, 1 A0, 2 A1, …) contradicts the schema MS_Description on that column (0 = B06, 1 = B23). Both are recorded; see Open questions. All other INFO_TEXTS legends in this cluster agree with the schema defaults/descriptions.

Purpose: master record per punch tool-type (Oberwerkzeug); one row per Typ (SSMA source T600_V100.[WZG_OW]). Primary key (ID, Typ). No table-level MS_Description; purpose derived from column descriptions and context.

Open questions

  • TypGreifnut legend conflict (WZG_OW_ATTRIBUTE). Schema MS_Description states 0 = B06; 1 = B23, but the shipped TruARV INFO_TEXTS legend is 0 None; 1 A0; 2 A1; 3 A2; 4 S1; ? L0. These are two different code systems (B-groove IDs vs A/S-groove names). Which applies to ToPs600 ARV export is unresolved; INFO_TEXTS also has an unresolved code for L0. Needs ENUMWERTE rows or a ToPs600 UI cross-check.
  • FK-catalog columns with no legend (schema-only snapshot): WerkstoffID (material), EndbearbeitungID (finishing type), AufnahmeID (seat — a large catalog; INFO_TEXTS gives current entries but it is installation/catalog-dependent, not a fixed enum). These resolve against catalog/ENUMWERTE tables that carry no seed rows here.
  • Undocumented flag columns: EinbauSafetyClickID (default 0) and WerkzeugwechslerFlag (default 0) have no MS_Description and no CHECK; presumed enum/boolean but legends undetermined.
  • Default 0 outside documented ranges: Verwendung (default 0; legend starts at 1) and WZG_OW_GRUPPE.WZG_OW_BIEGEART (default 0; legend starts at 1). The 0 value is likely "unset/none" but is not documented — treat with caution.
  • Units are inferred for load columns (BelastungMax, BelastungMaxZudruecken, WZG_MAXBELASTUNG): typically kN or kN/m per metre of tool; and for strength (FestigkeitVon/Bis): N/mm². Not stated in schema.
  • ToPs600 vs tc_dbase enum divergence: the ToPs600 ARV Biegeart (WZG_OW: 1 Folding / 2 Air Bending / 3 Bottom Bending) and WZG_OW_BIEGEART (1 air / 2 bottom) are not the tc_dbase benddef.h Biegeart enum (0 Normkantung … 9 Hilfsbiegung) nor its Biegemethode. The ARV column numbering is authoritative for ARV files; the code enums are cross-reference only and must not be substituted.
  • NachgiebigkeitXY and NachgiebigkeitXX carry identical German MS_Description text in the schema (both say "in X-Richtung bei der Biegekraft in X-Richtung"); the XY description is presumably a copy-paste error — it should read X-deformation under Y-force by analogy with YX/YY. Meaning inferred, not confirmed.
