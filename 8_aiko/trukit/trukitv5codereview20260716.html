TruKitV5 — Code Review

Date: 2026-07-16 · Version reviewed: 5.0.55 (main @ e6edd4d) Scope: whole repo — 6 Rust crates + desktop host (~22k LOC) and the Svelte/TS frontend + shared packages (~13k LOC). Method: 20 review units (subsystem-focused + cross-cutting lenses), each finding adversarially verified by an independent agent, then deduped and synthesized (41 agents, 0 errors). Findings below are verdict-tagged CONFIRMED / PLAUSIBLE.

Verdict

Solid and unusually security-aware for a solo-maintained internal toolbox — held back by two must-fix issues and an enforcement gap.

Credential encryption at rest (AES-256-GCM, zeroize, redacted Debug, 0600), TLS discipline with no cert-bypass anywhere, capability-based zero-IPC isolation of untrusted webviews, and a genuinely clean panic surface on external input are all thoughtful. The trickiest logic (sync mapping, SAP/Jira reconciliation, geometry parsing) is backed by real tests. Two findings rise above the rest and should be fixed before the next release; beneath them runs a consistent silent-wrong-result theme on the migration/time paths, and there is effectively no CI gate catching regressions.

🔴 Must-fix (High)

1. Self-update runs an unsigned installer with no integrity check; trust root is a personal GitHub gist

apps/desktop/src/update.rs:181,271 · security · CONFIRMED · flagged independently by 4 reviewers

complete_install() spawns whatever landed at the download path — Command::new(installer).args(["/S","/UPDATE","/R"]).spawn() — with no signature and no hash check. The URL comes verbatim from a personal gist manifest (crates/trujira/src/commands.rs:66, UPDATE_MANIFEST_URL = gist .../aikoradlingmayr/eca53bb.../raw); download_url/url are returned unvalidated and passed straight into start_self_update (Shell.svelte). The DownloadEvent::Requested hook captures any download from any origin, and page_url is optional so the payload need not even route through SharePoint. The installer is also unsigned.

  • Impact: one gist-account compromise (or GitHub-side tampering) → set a higher version, repoint download_url → silent arbitrary code execution as the logged-in user on every TruKit machine, disguised as a normal update. HTTPS does not help — authenticity is never verified.
  • Fix: put a SHA-256 (ideally an Ed25519/minisign signature, à la tauri-plugin-updater) of the .exe in the manifest and refuse to launch on mismatch; sign the NSIS installer and verify the Authenticode publisher before spawn; pin download_url's host to the SharePoint tenant (allowlist); move the manifest off a personal gist to an org-controlled endpoint with enforced 2FA. Even a manifest-side hash closes the silent-swap path.

2. ADF HTML tokenizer corrupts all non-ASCII text (UTF-8 read byte-by-byte as Latin-1)

crates/jkit-jira/src/adf.rs:165 · correctness · CONFIRMED

In tokenize() free-text runs are accumulated a byte at a time: text.push(bytes[i] as char). u8 as char maps each byte to code point 0–255 (Latin-1), so every continuation byte of a multi-byte UTF-8 sequence becomes its own bogus char. 🟠 Medium

Silent-wrong-result on the write/migration paths

  • view(case_id) returns the first search hit without confirming the id — jkit-fogbugz/src/client.rs:125. FogBugz cmd=search falls back to full-text matching, so view(999999) for a missing id can return a different, real case. Fix: verify hits[0].id == case_id, else NotFound.
  • IO cache keyed only by issue key, not the resolved field id — trutime/src/io_cache.rs:45. Change the "Internal Order field" setting and worklogs stay tagged with the old field's IO until the user hits Refresh (survives restart via io.json). Fix: fold io_field_id into the cache key.
  • Export-all silently overwrites attachments with the same sanitized name — trukit-ui-kit/src/platform-tauri.ts:121. Fix: de-dupe on write (name (2), …).

Robustness / crashes

  • IO overview crashes on duplicate target labels — IoBreakdown.svelte:43. Two empty target rows (easy accident) → each_key_duplicate throws; no <svelte:boundary>, so the whole overview tears down. Fix: dedupe/skip-empty in ioOverview, or key the {#each} by index.
  • Unbounded ellipse tessellation hangs/OOMs the SAT parser — core/src/sat.ts:181. A corrupt param span → steps ≈ 7.6e15 inside a per-face try/catch that can't stop a hang. The cone path clamps to 64; this one doesn't. Fix: clamp steps, reject non-finite spans.
  • SatViewer never releases its WebGL context — truarv/src/SatViewer.svelte:249. A fresh context per solid ({#key att.id}) with no loseContext() and no context-loss handler → clicking through ~12 3D attachments trips Chrome's context cap and blanks views.

dragDropEnabled regression (from this session's 5.0.54)

  • dragDropEnabled:false broke TruNC drop-to-decode — platform-tauri.ts:87. The OS file-drop premise ("nothing uses it") was wrong: TruNC's .bnc/.gecco drop now silently does nothing and its onDragDropEvent handler is dead code (TruARV survived only via its own HTML5 ondrop). Fix: give TruNC an HTML5 drop fallback, or restore per-webview drag config; correct the now-stale Shell.svelte comment.

Tests & CI

  • ~600 LOC of Jira↔FogBugz migration write-orchestration has no tests — trujira/src/commands.rs:1127. Fix: extract payload-building into pure functions and unit-test the mapping decisions.
  • TruTime IO parent-chain walk untested (only leaf helpers are) — trutime/src/commands.rs:445. It's wiremock-testable like the jkit-jira tests. Add cases: found-on-self, N-parents-up, cache short-circuit, depth cap, 403/404 ancestor → io=None (not Err), cycle terminates.
  • No effective CI gate — .github/workflows/ci.yml. GH Actions is configured but the repo lives on Azure DevOps, so fmt/clippy -D warnings/tests and the assert-capabilities tripwire never run. Fix: port to azure-pipelines.yml (or mirror to GitHub); until then treat the capability audit as a required pre-release step.

Architecture / duplication

  • CredentialStore duplicated near-verbatim across jkit-jira & jkit-fogbugz — jkit-fogbugz/src/credentials.rs:14. ~180 lines of security-relevant persistence maintained twice. Fix: hoist one generic CredentialStore<T> into jkit-core (which already owns cipher.rs); fold atomic-write hardening in once.
  • SAP-import date/type helpers copy-pasted per time-tool; TruTime cross-imports TruWork's private module — truhomo/sapMobile.ts:29. Fix: shared lib/sapImport.ts.

Cross-cutting themes

  1. The self-update supply chain is the sharpest risk — home-grown code replacing what Tauri's signed updater gives for free. A secondary stall-heuristic can even launch a truncated installer over the live install.
  2. Silent data corruption / wrong-result on migration & time paths — the write surface trusts its own transforms and degrades to wrong rather than to error (mojibake, wrong case, wrong IO, overwritten attachments, dropped entity refs).
  3. No enforcement, thin coverage on the write surface — highest-consequence code is the least tested; live/IO tests are #[ignore]d, so green cargo test overstates coverage. "Coverage theater."
  4. Adversarial-input robustness is good but not complete — clean panic surface + defensive geometry core, but a few unbounded edges remain (SAT ellipse, WebGL leak, WinHTTP raw header concat).
  5. Security hardening gaps that are real but proportionate to the trusted-internal, single-user-per-machine threat model (open_external no scheme allowlist, project_key→filename, cleartext frame-src, multipart header interpolation).
  6. Architecture drift as the codebase unifies — jkit-core/sync.rs is a dead stub so the "shared sync layer" is partly fictional; trujira/commands.rs is a 4163-line monolith while the sibling trutime is cleanly split (ambiguous template); dead keyring backend + stale SERVICE id.

Additional observations (completeness critic — verified where noted)

These came from the completeness-critic pass, not the per-finding verifier. I spot-checked the two most serious against the code; both hold.

  • OData $filter injection in sap-time/src/fetch.rs:54-58,107-114 — ✅ verified. EmployeeID eq '{pernr}' and datetime'{iso}' are interpolated raw (same class as the flagged JQL bug, different crate). The full query URL incl. pernr (PII) is logged at tracing::debug. Low exploitability today (pernr is session-derived) but real; needs the same escaping discipline.
  • TruUnlocker ships elevated control-bypass ops — ✅ verified, posture concern. apps/desktop/src/unlocker.rs runs an elevated PowerShell (Start-Process -Verb RunAs) that Remove-Item -Recurse on HKLM\SOFTWARE\Policies\… (Chrome/Edge/Defender/AppInstaller/Outlook policy keys) and, behind the TruUnlocker flag, Add-MpPreference -ExclusionProcess "Flux.exe" — a textbook malware-persistence primitive. Worth a deliberate decision on whether a corporate-managed toolbox should ship this, plus the blast radius of the recursive HKLM policy deletes. Windows-only, untested.
  • Credential-file 0600 is Unix-only — both credentials.rs chmod behind cfg(unix) and ignore the result; the actual Windows target gets default NTFS ACLs, so AES-GCM is the only at-rest defense there.
  • cipher.rs under-examined weaknesses — derive_key() falls back to literal "unknown" when USER/USERNAME is unset (weakens user-binding); the version byte is not fed as AEAD associated data (unauthenticated); machine_uid is world-readable, so off-machine extraction rests on a non-secret + public salt.
  • No frontend error backstop — no window.onerror, no unhandledrejection, no <svelte:boundary> anywhere; one unhandled throw white-screens the Shell with no feedback/telemetry (the individual UI findings are symptoms of this).
  • Concurrency / re-entrancy across Tauri commands not examined — no global in-flight lock on the ~600-LOC migration; double-click Migrate or SAP-fetch-during-sync unassessed for double-writes/cache races.
  • Supply-chain / license posture missing — no deny.toml, no cargo-audit/pnpm audit, no Dependabot, lockfiles unscanned; no LICENSE/NOTICE/third-party attribution despite ported code (earcut = mapbox derivative; a dxf-viewer port).
  • Dual web-build target un-reviewed — platform-web.ts and the platform.ts abstraction (the documented web arm) got no coverage.
  • Windows-only privileged code is validated only by cross-build, never executed — the unsafe WinHTTP FFI, SAP SSO cookie flow, and unlocker elevation run only on Windows, but the build is on macOS with no Windows CI/runtime test.

Strengths (credit where due)

  • Textbook credential handling — AES-256-GCM at rest with an honest threat model, Zeroizing passwords, Debug redaction (with tests), 0600, and a deliberate fb_errors_to_string projection to stop FogBugz echoing the submitted password/email into logs.
  • TLS discipline throughout — no cert-bypass anywhere; WinHTTP uses WINHTTP_FLAG_SECURE and treats cert failures as errors; the ~600-line unsafe WinHTTP FFI is disciplined (RAII handles, correct GlobalFree, bounded auth loop, NULL-cred SSO).
  • Capability-based isolation of untrusted webviews — positive-deny capabilities (teczone-remote.json, sap-auth.json with permissions:[]) keep remote/SSO origins from any IPC command, backed by the assert-capabilities.mjs build-time tripwire. Exemplary trust-boundary design at the IPC layer.
  • Remarkably clean panic surface — network/response parses go through serde Results / ?; slicing only at ASCII boundaries; cipher::decrypt length-guards before indexing. Almost all unwrap/expect are on constants or poison-only locks.
  • Meaningful tests where it counts — cipher (roundtrip + tamper/truncate/version rejection), mapping.rs (22 tests pinning the exact historical sync bugs), SAP punch-pairing, jkit-jira wiremock pagination, and the frontend reconciliation math. Previously-known bugs are fixed and pinned by regression tests.
  • Defensive geometry core — never-throw, iteration guards on every SAT topology walk, bounded earcut recursion, non-finite rejection, tested against real Flux GEO / v500–v1300 SAT solids.
  • Real shared foundation where it holds — one HTTP transport used by both clients; net-hours math genuinely shared in lib/worktime.ts.

Recommended action plan

Before next release

  1. Add installer integrity verification (manifest SHA-256 minimum; signature + host allowlist ideally) and move the manifest off the personal gist. (High #1)
  2. Fix the ADF byte-wise text tokenizer + add a non-ASCII round-trip test. (High #2)
  3. Stand up a real CI gate (Azure Pipelines mirroring ci.yml + assert-capabilities). (Medium)

Soon 4. view(case_id) id-confirmation; IO cache key includes field id; TruNC drop fallback. (Medium) 5. Clamp the SAT ellipse loop; release the WebGL context. (Medium) 6. Tests for the migration payload-builders and the IO parent-chain walk. (Medium) 7. One shared escaping/validation helper for JQL + OData + cache-filename + headers (the systemic string-interpolation pattern). (Low, systemic) 8.
