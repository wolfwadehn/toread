1004 ◉ Trek Command Line reference

[!info]- Revision history

Rev Date Author Note
V1 2016-09-03 AV

The Trek application is a special command-line version of MetaCAM used by Flux and Praxis. This document explains the various command line parameters for Trek.

Command Line

Trek commands take the form action param1 param2 ... The command line parameter naming the action is followed by zero or more parameters required for the action. The action is not case sensitive.

3DtoL3D input output

Converts the input MetaCAM 3D model to the output L3D file (which Flux can then read as a Mesh).

DXFtoPDG input name material thickness output

Converts a DXF file to a PDG file. Here are the parameters. This can also be done as a sub-command of the PraxCMD action. If there is a single file to convert this is much more convenient, while the PraxCMD is designed for use by Praxis when it is converting multiple DXFs to PDGs.

Parameter Meaning
input The full filename (with path) of the input DXF file
name The name to be assigned for the part
material The MetaCAM material to be assigned for the part
thickness The thickness (in mm) to be assigned to the part
output The full filename (with path) of the output PDG file

ExpMCSet mcid output

Exports all the settings for a particular machine, specified by machine ID (these are the settings that we save in the config.dat when we do a Save as default for machine). The settings are exported as an INI file that Flux knows how to read, and these are then written into the settings.curl file for that machine. This command is used by Flux.Migrate when it imports a machine from MetaCAM to Flux

ExpMCMatlSet mcid matlid thickness output

Exports all the settings for a particular <machine, material, thickness> combination into a settings INI file. The machine and material are specified using their integer IDs. The format of this settings file is similar to the one exported by ExpMCSet, and this is also used by Flux.Migrate when it imports a machine from MetaCAM to Flux.

EnumSet output

This enumerates all the various combinations of <machine, material, thickness> tuples for which settings exist in the config file. This can then be the basis for repeated ExpMCMatlSet to extract each of these settings. The output is in a simple INI format, and is used by Flux.Migrate when it imports a machine from MetaCAM to Flux.

ListMC output

This lists all the machines in the config file in a simple INI format

ListMetal output

This lists all the materials in the config file, in a simple INI format

PraxCMD cmdfile

This parses and executes a command file that contains multiple commands in it. The point of the command file is that one can submit a large batch of commands that all get executed during one invocation of Trek. The cmdfile is an INI file that has a [Header] section with a count of actions, and a set of sections called [Action 1] .. [Action N] that provide the data for the action actions. These individual actions are detailed in the section below. In addition, the [Header] section also provides the name of an output resport file. This is an INI file that Trek will create and will populate this INI file with the results for each action. Corresponding to each action, there will be a similarly numbered [Result N] section, and the exact content of the report section will depend on the action. If a client is not interested in the results for a set of actions, this Results file can simply be left blank.

Note: This Results key contains the overall output result for all the actions in the file. It is primarily useful now for the ToolUpPDG actions, since one often requests multiple tool-up actions in one batch, and all the results for all the tool-up actions are reported in a single results file.

Command File Actions

A set of commands can be passed in a command file, and Trek will then execute these commands one by one, and will exit once all the commands are complete. The command file is just an INI file, like this.

[Header]
Count=2
Results=C:\Out\Result.ini
|
[Action 1]
Command=cmd
parameters
|
[Action 2]
Command=cmd
parameters

Each section is a particular command action (identified by the Command key) and the following lines contain parameters specific to that action. These are the command actions availble:

DXFtoPDG

The DXFtoPDG action is used to convert a DXF file to a PDG file

Parameter Example Meaning
Command DXFtoPDG
Input C:\Data\00\Input.dxf The name of the input DXF file
Name Valence The name that should be assigned to the part
Grain H The part grain. A value of H or Horizontal sets a horizontal grain, and a value of V or Vertical sets a vertical grain. Any other value, or a missing key for Grain means that the part has no grain setting.
Material Steel The material that should be assigned when this is saved as a PDG file
Thickness 1.0 The thickness that should be assigned
Output C:\Data\01\Valence.pdg The full path and filename where the output is to be saved
NoDelete 0 If set to 0 (the default), the Part that was loaded is discarded after we have saved it to DXF. If this is set to 1, then the Part is stored as the global CurrentPart and is used as the input for the next operation.

ToolUpPDG

This is used to tool-up a PDG part for a given machine.

Parameter Example Meaning
Command ToolUpPDG
Input C:\Data\01\Valence.pdg The file from which the input PDG should be read in. It is possible to leave this blank if the previous Action in the same command file used the NoDelete flag. In that case, the part that was loaded as part of the previous command would have been stored as the global CurrentPart and is used as the input for this operation.
Machine 1709 The ID of the machine to use for tooling up the part
Material Steel The material to assign when tooling up this part
Thickness 1.0 The thickness to assign before tooling up this part
Output C:\Data\Valence_1709.pdg The output file where the tooled-up part should be saved
ICode C:\Data\Valence_1709.ic Optional: The location where the I-Code for this file should be saved. You can omit this key to avoid generating ICode
NoDelete 0 If set to 0, the part is discarded after saving the output and ICode. If set to 1, the part is stored as the global CurrentPart and can be used as the input for the next operation.

See the entry in the Command File Results section of this document for details on the results returned from a ToolUpPDG operation

DoNesting

This is command is used to invoke a nesting operation using Trek.

Parameter Example Meaning
Input C:\Nest\test.ndf The input file for nesting (should be an NDF file, though a JOB file is also accepted)
Output C:\Nest\results.ini An INI file where the results are written. Note that the DoNesting action does not use the [Header]/Results global results file; it produces a separate results file for each nest.
Folder C:\Nest\ A folder name where the nested layouts, I-Code, NC-Code should be written. Note: it is important for the folder name to end with a \

After nesting, a results file is produced (for each nest). And several other output files (LYT files, NC files etc) are produced. These are just sequentially numbered 1.lyt, 2.lyt etc. So, if you have a command batch with multiple DoNesting operations, it is important to specify a separate Folder for each one, so the outputs don't get mixed up.

Note: It is probably better to submit DoNesting tasks one at a time - create a command file with just one action when you are doing nesting. The intrinsic work involved in nesting is high enough that there is not much benefit by batching nests together.

The output file is an INI file, and it contains a header like this:

[Header]
Error=0
Patterns=3

An error code of 0 means no error, while +ve values mean various different nesting errors. Following the header, is a section like this for each pattern (numbered starting from 1)

[Pattern 1]
Sheet=2500x1500
Thickness=1
Copies=1
Parts=12x1,3x2,8x7,12x8,9x9
ICode=c:\Nest\0.ic
NCCode1=c:\Nest\0.nc
Layout=c:\Nest\0.lyt
PartArea=2833524.89
SlugArea=23976.88
SkeletonArea=892498.24
TotalTime=1101.44
PunchCount=0
CutLength=64416.5
NestBound=27,1473,2464.81,100.492
ToolCount=0

The Parts value is a set of key-value pairs of tuples, and each tuple has a repeat-count x part-index, where the part indexes match the indices from the [Part N] section of the NDF file. Thus, these part indices start from 1.

If this is a nest for a punch machine, the ToolCount is set to the total number of tools used for this layout, and there are Tool entries (matching exactly the Tool1, Tool2 entries produced by the output of ToolUpPDG).

ToolCount=7
Tool1=c7c894d2-5eb6-447d-bed6-f8411bfcbf84,RE, 29.9974;5.0038;0;0;0;0;0;0, 0,6,Yes,A,4,""
Tool2=71292a2b-77a4-49c0-85e5-27e65975f6e1,RE, 56.896;10.414;0;0;0;0;0;0, 0,7,Yes,A,4,""
Tool3=90f7b048-238e-4f9a-9709-b8064528dc78,SQ, 19.05;0;0;0;0;0;0;0, 0,11,Yes,A,48,""
Tool4=e357c5d4-0d69-407c-8fbb-af1fc373f27c,RE, 75.0062;5.0038;0;0;0;0;0;0,0,14,Yes,A,634,""
Tool5=83307323-65c6-41b7-b9f7-f9cc391bf497,RE, 38.1;3.175;0;0;0;0;0;0, 0,19,Yes,A,8,""
Tool6=f1c9cda6-e79a-4e6f-b7a2-6e4bda4c6238,RE, 36.83;13.97;0;0;0;0;0;0, 0,22,Yes,A,4,""
Tool7=3bbc1840-2d02-462b-bdf9-ea6da003a770,RE, 52.07;8.001;0;0;0;0;0;0, 0,34,Yes,A,24,""

See the section below on Command File Results of the ToolUpPDG command to understand the ToolN entries.

Command File Results

Corresponding to each action above, the results file will contain a section with a similar number, called [Result N], that contains the results of the processing. This global results files (for an entire batch of commands) is used only for a few commands, including ToolUpPDG. Other commands such as DoNesting produce a separate results file for each action.

ToolUpPDG

The following results are returned from a ToolUpPDG operation. The results are in a [Result N] section of this results INI file, where N is the corresponding action number (like [Action 3])

Key Value
Material Actual material assigned (might change for laser machines, if they don*t have any cutting condition tables for the input material)
Thickness Actual thickness assigned
Plines Total number of toolable plines in the drawing
Untooled Number of untooled plines in the drawing
PartialTooled Number of partially-tooled plines in the drawing
UntooledLength Total length of untooled segments of plines
TotalTime Total process time (s)
PunchCount Total number of punch hits
CutLength Total cutting length
PierceCount Total number of pierces
PierceTime Total pierce time, s
CuttingTime Total cutting time, s
PunchingTime Total punching time, s
IndexingTime Total tool-indexing time, s
ToolChangeTime Total tool change time, s
RepoCount Number of repositions required
ToolChangeCount Number of tool changes required
TraverseTime Total time spent in rapid traverse, s
ToolCount Total number of tools used
Tool1, Tool2, Tool3, ... Data for each tool, as a set of comma separate values. The values are in this precise order within the CSV string:
- GUID
- Shape (RE/CI/etc)
- Parameters (the shape parameters, as a semicolon separated list of numbers)
- Mounting angle
- Station number
- Indexing flag (Yes/No)
- Tool range (A/B/C etc)
- Hit count (punch hits made with this tool for this part)
- Name (tool name, for special tools, or an empty string). This value is always quoted.
