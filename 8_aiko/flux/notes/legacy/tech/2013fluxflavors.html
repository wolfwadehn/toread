2013FluxFlavors

product: flux org: metamation tags: [metamation, knowledge-base, flux, notes, legacy, tech] type: note project: Flux source: Notes/Tech/2013.FluxFlavors.ftx updated: 2026-07-13

2013 ◉ Flux Flavors

There are several different flavors of Flux. Flux could be installed standalone, or integrated with Boost. Standalone versions could be shipped with Metamation or Trumpf branding. There is a special version that is installed only on the B23 controller. The goal is to use the same binaries (with no different conditional compilations) to represent all these flavors. In addition, we also want to use a single installer that can be configured to install any of these flavors.

Flux flavors

Here are the different flavors, and the basic licensing mechanisms that they use:

Name Description Licensing
Dev Flux that runs only on developer machines Works only on a small number of whitelisted developer machines
Flux MetaCAM branded version of Flux Aegis licensing system (online soft-locking)
Trumpf Trumpf branded version of Flux (standalone) Trumpf WIBU based licensing
Boost Trumpf branded Flux, integrated into Boost Trumpf WIBU based licensing
Engine Flux engine for use by Praxis No UI, works only as a DLL built into
B23 Special edition of Flux for B23 HMI Works only if the PC is identified as a B23 APC
Fold TecZoneFold edition, installed on TruBendCenter HMI Trumpf Sentinel based licensing
Tech Flux-tech demo, for testing by partners like USMM/FAS Time-limited, displays 'Not For Sale' banner on startup

Feature bits

There are various feature bits that control the functionality exposed by each flavor of Flux. Depending on the flavor, some of them are always set. Some of them are not available, and some of them are optional - meaning that the user can order that particular functionality additionally.

Bit Meaning Dev Flux Trumpf Boost Engine B23 Fold Tech
UI This bit is required for any UI to be displayed X X X X - X X X
Fold Panel-bender CAM X O O O X - X X
Bend Press-brake CAM X O O O X X - X
Hoops 3D import module based on HOOPS X O O O X X O X
Laser Laser CAM (and other profile-cutting) X - - - - - - X
Punch Punch CAM X - - - - - - X
BendTSO Bend tool-setup optimizer X - - - - O - X
BendCell Support for bend automation X - - - - - - -
Internal Display 'Internal version, not for sale' warning - - - - - - - X
Trial This is a 'trial version' no NC code possible - O O - - - O -
Report Is the report editor enabled? X X X - - X X X
CAD2D Is 2D CAD enabled (sketch-mode in 2D) X X X - - X X X
Trumpf Is this 'Trumpf' branding (else it is MM branding) - - X X - X X -
Batch Is CMD file processing supported? X O O X X - O X
Developer If this is set, Flux runs in developer mode X O - - - - - -
MachineDB Add/remove/reconfigure machines X X X X - - - X
BendToolsDB Add/remove bend tool catalogs X X X X - - - X
MaterialDB Add/remove/edit materials X X X - - - - X

(In the table above, X: standard feature, O: optional feature, -: not available)

Flux installers

We want to avoid having to ship a number of installers (setup programs) each time there is a new build of Flux. That also means that different flavors of Flux cannot have different binaries. Thus, all the Flux variants are built from the same source code, and have exactly the same final executable. On startup, Flux reads the file Flux.flavor which must be in the same folder as the EXE and uses that decide what flavor it is. This is a simple text file that contains one word like Dev, Flux, Trumpf, Boost etc.

Of course, the user could try changing this (not easily possible by accident since this file will require administrator privileges to edit). But then, Flux will try to use an appropriate licensing mechanism on startup and so it is not really simple to change a more basic Flux installation into a more full-featured one by just editing this file.

The Dev flavor of Flux is never meant to be installed - it is only for use on developer machines, so there is no installer for this. Likewise, the Engine flavor of Flux is packaged as a set of DLLs, and used only internally within Metamation. So again there is no installer for Flux-Engine. The other flavors all require installers. It turns out that the different installers are installing mostly the same files, (except the Flux.flavor file). There are a few other files that are installed or not depending on the flavor - the Trumpf editions of Flux will require the Trumpf licensing libraries to be installed, and may even require the Trumpf License Manager1 to be installed.

Rather than have to package and upload 6 different installers, we use a different mechanism. There is always only one installer we upload to the shared site, and it is always called something like:

Setup.Flux.240.exe

If you just run this installer, it will install the default or Flux flavor of Flux. This is Flux with the Metamation branding, and will require a Metamation Aegis license to work. We expect that this will be used primarily by US-Metamation or by FA-Services. For other situations (including for use by TAT, TW and TITW), we need installers for the other flavors.

And these installers are obtained by just renaming the Setup file to one of these (let's assume we're dealing with Flux Build 240 here):

Installer name Flavor of Flux installed
Setup.Flux.240.exe Flux
Setup.TecZoneBend.240.exe Trumpf
Setup.TecZoneBend(Boost).240.exe Boost
Setup.TecZoneBend(B23).240.exe B23
Setup.TecZoneFold.240.exe Fold
Setup.FluxTechDemo.240.exe Tech

Unattended installation

It is possible to run the Flux installer unattended, and this is useful if Flux is being installed as a component in a larger installation. Here are some command-line switches to the installer that can be used to customize this installation.

/SILENT Installer displays UI showing installation progress, but does not require any interaction from the user

/VERYSILENT Installer displays no user interface whatsoever, and does not require any interaction from the user. Since the installation can take a minute or two (or longer if the .Net Framework is not already installed), the calling application is then responsible for displaying some visual cues to the user

/LOG="filename" Saves an installation log to the specified filename. This can be useful to debug any issues with an unattended installation.

/TASKS="comma-separated list of task names" This specifies the installation tasks that must be performed by the installer. The table below lists the tasks that are possible. Note that the task names must be specified exactly as shown below.

Task name Explanation
desktopicon Creates an icon for Flux on the desktop
prereq2 Installs the Flux Pre-requisites 2018
tlmanager Installs the Trumpf License Manager (Sentinel)
tlexpert Installs the Trumpf License Expert (Wibu)

The TecZoneFold edition of Flux requires the Trumpf License Manager. The Trumpf and Boost editions of Flux require the Trumpf License Expert. If you are installing one of these editions, take care to include the appropriate task to install the TLM or the TLE.

However, if the parent installer is already installing these, there is no need for the Flux installer to attempt installing them again, and these can be safely omitted. It is also fine if the License Expert of License Manager are installed after the Flux installation - the Flux installer itself does not interact with them in any way.
