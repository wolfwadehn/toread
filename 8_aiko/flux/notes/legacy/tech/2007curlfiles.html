2007 ◉ Curl Files

[!info]- Revision history

Rev Date Author Note
V1 2016-01-29 AV

Introduction

Most configuration information in Flux (machine definitions, bend tool catalogues, default settings) are stored in Curl files. These are text files designed to be easy to write or edit by hand. This document explains the Curl file format.

The MetaCAM approach

MetaCAM uses several different file formats to store this kind of configuration information. Many settings are stored in INI files (which are text files, but not as flexible as Curl files). Some settings, especially the newer ones, are stored in XML files. Most settings and configuration information is stored in binary files, however. This means that one needs special programs or applets to edit these settings. There are a large number of such programs that ship along with MetaCAM1. If you need to edit some part of the configuration data for which there is no exporter/importer program, you are out of luck.

Why not XML?

The Curl file format (as you will see) is simpler and cleaner and XML, while being functionally at least as rich . Creating or editing a Curl file requires less typing, and there are fewer failure possibilities than in XML (since there is less redundancy). For example, there are no opening and closing tags (like in Curl), thus eliminating the possibility of tag mismatch.

The Curl file format is very deeply embedded in the Flux Core. Every type of object that Flux knows about (parts, drawings, models, machine definitions, tool systems, auto-tooling settings) can be saved and loaded from Curl files. Normally, Flux parts and models are stored as binary files (since that is more compact and faster to read/write), but one can always save any Flux data in Curl format, and it is then easy to write some external tools to read or even modify this data before asking Flux to import it back.

The structure of Curl files

Curl files represent objects of class types as key-value pairs (this is also known as a dictionary). The key-value pairs making up an object are enclosed in curly braces, and keys are separated from their corresponding values by a colon. For example, here is a fragment of a Curl file:

{ Name:Elan  Manufacturer:"Lotus Racing"  Cylinders:4 }
  • A key is separated from its value by a colon. It is customary that there is no space before or after the colon, though that is permitted.
  • The keys are case sensitive, you cannot type in name where Name is expected.
  • Values can be quoted (enclosed in double-quote characters), though this is not always necessary. Values that don't contain one of the following special characters do not need to be quoted. Even values that are strings do not need to be quoted, unless they contain one of these special characters (for example, see the value Elan in the example above — it is not quoted).
  • Any excess white-space in Curl files is ignored. You can format the Curl files in any manner; lines can be split where needed and you can add spaces between key-value pairs to format the Curl file as desired.

Special characters

These are the special characters in Curl files. Any value that contains one of these characters must be quoted:

 "  {  }  <  >  [  ]  (  )  =  :  ;  #  @  $  %  &  \  ~

If you need to enclose a quote character within a value, you can use the escape sequence ". These are the complete set of escape sequences that are supported :

Escape sequence Character
\" " (quote character)
\\ \
\n Line-feed character, ASCII 10
\r Carriage return character, ASCII 13
\t Tab character, ASCII 8
\u1AB3 Character 1AB3 hex (\u followed by 4 hexadecimal characters encodes a Unicode character)

Composite values

What we have seen so far are simple values. A value can also be a class-type in itself:

{ Name:Elan                    ; Data about the Lotus Elan, (c) 2012 
  Engine:{
    Cylinders:4
    Mounting:Transverse
    Valves:16
  }
  Manufacturer:"Lotus Racing"
}

In this example, the Engine attribute has a value that is itself of class type. In other words, the value is represented as a dictionary.

Comments

The semicolon character starts a comment. The comment extends to the end of the line, and all text within the comment is ignored. For example, in the example above the text in italics is a comment.

Array values

A value can also be an array. This is a simple list of items, and is indicated by starting with a square bracket, rather than a curly bracket. Consider the example below:

Teams:[ 
  { Name:Ferrari
    Headquarters:Italy
    Drivers:[
      { Name:"Fernando Alonso" Nationality:Spanish }
      { Name:"Felipe Massa" Nationality:Brazilian }
    ] 
  }
  { Name:McLaren
    Headquarters:England
    Drivers:[
      { Name:"Jenson Button" Nationality:British }
      { Name:"Lewis Hamilton" Nationality:British }
    ]
  }
]

The Teams attribute contains a list with two elements; each of these is itself of class type, and contains within it an attribute called Drivers, which again is a list. Each driver is again of class type, containing two simple values (Name and Nationality). This way, any arbitrarily complex data structure can be mapped to a Curl file using simple values, dictionaries (key-value pairs) and vectors (lists of elements).

The Flux Schema

In all the Curl files we have seen so far, we never have to specify anywhere the type of the data value. This is because in most situations, the type can be deduced by Flux. We are using Curl files to store data based on some classes that Flux already knows about. For example, suppose these Team and Driver were classes that Flux knew about, it would already know that the Nationality attribute of a Driver is a string. It would also know that the Drivers attribute of a Team is a list. Not only that; it is a list of Driver objects. Armed with this information, Flux can read the Curl file correctly, and can report errors if some data is not as expected.

This internal knowledge that Flux has about these types (Team, Driver etc) is called the Flux Schema. It is embodied in the way we define the internal C# classes that make up Flux.

Schema evolution

It is possible that the Flux Schema will evolve over time. For example, we may add some new fields to the Driver type. If we do this, what happens to old curl files that do not have this field? They will load just fine; the missing field will simply get set to a default value. The converse is also possible — suppose we later remove the Nationality field for the driver. These Curl files will still load correctly; the Nationality will simply be read and discarded.

Polymorphism

Sometimes, even using the schema, Flux cannot determine what type of value to read from a curl file. Consider a Flux internal class definition like this:

class Drawing {
   string Name;
   List<Entity> Ents;
}

Even if you are not familiar with C#, it is easy to see that a Drawing object has just two attributes: a Name (of type string) and a collection called Ents, which is a list of Entity. However, there is not just one Entity type, but several. For example, there could be entity types like Circle, Line and Text. We say that these are all different kinds of entities2. Thus, when Flux is reading in a Drawing object from a Curl file, some hints are needed to tell Flux which kind of entity to construct. Here is how the hints are provided:

(Drawing){
  Name:"Sample drawing"
  Ents:[
    (Circle){ Center:"12,33" Radius:45 }
    (Line){ Start:"0,10" End:"50,25" }
  ]
}

As can be seen, the type hints are provided as class names within parentheses, just before the curly braces indicating the actual start of the class data. The outermost (first) object within a Curl file is always of a class type, and must always be prefixed by such a type hint. This is because when Flux starts reading a Curl file, it has no idea of what kind of data it contains, and needs a type hint to get the process started.

A sample curl file: BendMachine

Here's a practical example of polymorphism: when we define a bend machine, we need to define one or more contact surfaces for each back-gauge. These are of two types — flat surfaces and finger-gauging surfaces. Type hints must be used so Flux can figure out which kind of surface it has to construct. See the example below:

(BendMachine){ 
  Id:1  Brand:Trubend  Name:"5085 (6-axes)" ControlType:TASC6000  NCExtension:BNC 
  TableLength:2210   NCXCenter:1105  Tonnage:85  PunchValency:[50 51]  DieValency:[63]
  OpenHeight:385  ClosedHeight:215
  Gauges:[
    { Surfaces:[          
        (FlatBGSurf){ Support:False  DX:52  DZ:8  Cen:"26,0,0" }
        (FlatBGSurf){ Support:True  DX:31  DZ:17  Cen:"15.5,30,8" }
        (FlatBGSurf){ Support:True  DX:79  DZ:24  Cen:"39.5,260,25" }
        (FingerBGSurf){ Support:False  DZ:8  Cen1:"52,8,0"  Rad1:8  SAng1:"-90"  EAng1:60  
                        Cen2:"82,24"  Rad2:8  SAng2:"-150"  EAng2:0 }
        (FingerBGSurf){ Support:True  DZ:17  Cen1:"31,38,8"  Rad1:8  SAng1:"-90"  EAng1:60  
                        Cen2:"71,54"  Rad2:8  SAng2:"-150"  EAng2:0 }       
      ]                                                                   ; end of surface list for gauge 1
      Stroke:"-765,3,-50:575,600,200"  GapToNext:190  HandlePt:"40,200,25"  
    }                                                                   ; end of gauge 1 definition
    { Surfaces:[
        (FlatBGSurf){ Support:False  DX:52  DZ:8  Cen:"-26,0,0" }         
        (FlatBGSurf){ Support:True  DX:31  DZ:17  Cen:"-15.5,30,8" }
        (FlatBGSurf){ Support:True  DX:79  DZ:24  Cen:"-39.5,260,25" }
        (FingerBGSurf){ Support:False  DZ:8  Cen1:"-52,8,0"  Rad1:8  SAng1:120  EAng1:270  
                        Cen2:"-82,24"  Rad2:8  SAng2:180  EAng2:330 }
        (FingerBGSurf){ Support:True  DZ:17  Cen1:"-31,38,8"  Rad1:8  SAng1:120  EAng1:270  
                        Cen2:"-71,54"  Rad2:8  SAng2:180  EAng2:330 }
      ]                                                                  ; end of surface list for gauge 2
      Stroke:"-575,3,-50:765,600,200"  HandlePt:"-40,200,25"             
    }                                                                  ; end of gauge 2 definition
  ]                                                                  ; end of list of gauges for this machine
}                                                                  ; end of BendMachine definition

The type hints are in blue; comments are in green and the actual keys are bold. From this bend machine definition, one can immediately see:

  • The machine has 2 gauges
  • Each gauge has 5 gauging surfaces; 3 flat and 2 finger surfaces

A few more points can be observed in the example above.

  • The punch and die valences for the machine are both arrays (of integers). There is just one die valency 63, but there are 2 punch valencies: 50 and 51.
  • Points and vectors can be specified using simple notation like "30,40,50". Since this value does not actually contain any of the special characters of curl files, it is not necessary to quote it; however these values are quoted in this example for clarity.
  • The Stroke of a gauge is of type Bound3 (this is a bounding cuboid in 3D). It is made up of 6 values in the form: "x1,y1,z1:x2,y2,z2". The first 3 are the minimum values of X, Y and Z and the next 3 the maximum values.

Editing Curl Files

Curl files as simple text files, and you can edit them using any text editor (such as Notepad). However, it is very convenient to use the Flux application itself to edit Curl files, since it provides an intelligent Curl editor. Just pick a Curl file using the File/Open menu option in Flux and the Flux Curl Editor opens up:

The annotated figure above shows some of the features of the Flux curl editor.

  • Different colors and fonts are used for different syntactic elements of the Curl file. Keys are colored in gray, while values are in bold black text. Type names are in blue text and comments are in green italics.
  • As you type into the Curl file, 'intellisense' windows pop-up to provide you with useful suggestions. For example, when you are typing in the definition of a BendMachine, you can see the intellisense popup displaying some more fields that could be defined for a bend machine. This pops up when you type in a space character to go to the next field. When you type in an open parenthesis character (to define a type override), a list of possible types that could appear at that location is displayed.
  • Errors in the Curl file are highlighted with red underlines, and detailed error messages are also displayed in the error band at the bottom. You could also move the mouse over a red underline to get more information on the error. Various kinds of structural errors in the Curl file are caught by this real-time error checker:
    • Using an incorrect field name.
    • Typing in a value of the wrong type (for example, typing a string when a number is expected).
    • Providing a field value twice for some object.
    • Using an incorrect type of object in a location where polymorphism is permitted.
