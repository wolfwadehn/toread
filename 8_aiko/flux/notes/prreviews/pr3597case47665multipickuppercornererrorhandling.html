PR #3597 — Case 47665: Improve error handling for multi pickup

PR #3597 — Case 47665: Improve error handling for multi pickup

  • Repo/PR: metamation/Flux #3597 · branch Case.47665 → main · state OPEN
  • Author: florian (EngertFlo) · Date reviewed: 2026-07-20
  • Size: +168 / −35, 14 files (8 source + 1 test + 1 test-data + 1 schema + 2 lang) · ~17 commits · Label: bend
  • Verdict: ✅ Approve with follow-ups — core machinery is correct, but one must-fix before merge (test-ID 18532 collides with open PR #3634) plus a real visual-feedback gap (PaintRed) and two convention follow-ups (APIGen, schema version).

Reviewed with a deep manual pass plus a 7-agent adversarial verification workflow (6 dimension attackers + 1 completeness critic). 5/6 dimensions returned CONFIRMED_CORRECT; the i18n/IDs dimension returned BUG_FOUND (test-ID collision). One dimension (rawstate-component-vm) was re-run after an initial empty stub and then surfaced the PaintRed gap. The critic independently confirmed the load-bearing dismissals (re-entrancy, CGamut, FX round-trip) rather than refuting them.

What the PR does

For a multi-pickup stack (a pallet holding an X×Y×Z grid of blanks), the old code error-checked only the currently-simulated pickup part. This PR checks all corner parts for: ImpossibleIK, robot-stroke, robot–cell and gripper–cell collision, plus a new part(stack)–cell collision (EBCStatus.CellPickup). Colliding pickup blanks are drawn red, and clicking an error in the bend grid selects the pickup part (SimIndex) where it occurs.

Key changes

  • BPickup.cs — ExtendedStrokeCheck() (which tested only SimIndex 0 and −1 for stroke) is replaced by ExtendedChecks(mask), which loops over PPlan.Enum().Where(i => i.Corner), sets SimIndex to each corner, runs the crasher for CRASH_CORNER_MASK = RobotStroke | RobotCell | GripperCell + a per-corner ImpossibleIK test, and records each hit's SimIndex in a new Dictionary<EBCStatus,int> ErrSimIndexMap. RawState/CRawState are reworked to drive it (ExtendedChecksNeeded = (CRASH_CORNER_MASK|ImpossibleIK) & ~mCValid, 0 for dispensers). New ErrCellPickup => mCell.CellPickupCrash.AnyTrue().
  • BCellTech.cs — new bool[] CellPickupCrash: builds FlatMeshCollider colliders for on-floor components and each pickup blank and does an N×M crash sweep; caches per-part results and sets each floor component's IsPickupCrash.
  • Model3.cs — new FlatCrashMesh + FlatMeshCollider (mirror of FoldedCrashMesh).
  • BCComponent.cs — new IsPickupCrash; IsColliding = IsStaticCrash | IsDepositCrash | IsPickupCrash.
  • BCellVM.cs — PartForPickupVM gains a colliding flag → Mood => mColliding ? EMood.Error : EMood.Nil (red highlight).
  • BPickupPlan.cs — Enum() drops the dead slice variable and uses z (latent bug: z was declared but never incremented, so Item.Corner ignored the Z-layer and Item.Matrix.Z was always 0).
  • BendOpStatus.cs — new EBCStatus.CellPickup = 1UL<<60; _Last 59→61; added to CellCrashes.
  • BSimulate.cs — click-to-jump via ErrSimIndexMap; message code [CellPickup] = 18512; added to ESRow.Cell.
  • Test/data/schema/lang — FanucUI.cs Test15 [Test (18532, "C47665: …")], C47665.fx, metadata.curl (FluxVersion 662→665.1 + mErrSimIndexMap field), and message 18512 added to cell.txt (EN) + DE/cell.txt.

Correctness analysis (the deep part)

slice→z is a clean latent-bug fix, pickup-only, with no regression

Pre-PR, BumpZ() advanced slice while z stayed 0 — so pickup Item.Corner was true for X/Y-corners in every layer and Item.Matrix.Z was always 0. Both were dead (no pre-PR code read pickup Item.Corner/Matrix.Z), so fixing them can't regress anything. Verified: shift.Z value is byte-identical before/after (z cycles exactly as slice did, for both ByPile/ByLayer and all StartCorner/YFirst combinations), so parts don't move. Deposit is fully isolated — DPlan is BDepositPlan with its own separate Enum()/BumpZ, and the only Item.Matrix.Z consumers are in deposit code. The new Corner set = the up-to-8 bounding-box corners (bottom+top-layer X/Y extremes), never empty (origin is always a corner), and strictly more coverage than the old 2-index stroke check.

ExtendedChecks + SimIndex machinery is sound

  • Re-entrancy is not a real risk: the per-corner SimIndex = item.NOverall fires Redraw + PFire(NVisiblePickupStack), but Redraw is a deferred LazyCall (no-op under FX.Testing), BendAgent ignores NVisiblePickupStack, and the sole VM listener reads only SimIndex, never re-reads CState. The old ExtendedStrokeCheck had the identical structural exposure.
  • ResetSteps(EBCStatus.D180Rotate) in the SimIndex setter is load-bearing: if it still invalidated ImpossibleIK (as the old ResetSteps() did), the per-corner loop would invalidate the very bit it is computing. Not invalidating ImpossibleIK on a SimIndex change is correct because ExtendedChecks now computes it stack-wide (across all corners) — a SimIndex change is a view-only change.
  • Ordering is correct: extendedChecks is captured at the top of CRawState before if (ErrImpossibleIK) state |= ImpossibleIK validates the current-SimIndex result — giving a current-part fast path, then an all-corners sweep for whatever remaining = mask & ~mCState is left. state |= mCState & extendedChecks surfaces only the freshly corner-checked bits, and the state &= ~(CellCell|CellRail|CellTable|CellFrame) middle block touches disjoint bits, so it cannot clobber ImpossibleIK/CellPickup/corner bits. SimIndex restore has no off-by-one (n getter resolves −1→CParts-1).
  • RawState genuinely needs to run ExtendedChecks too (not redundant): the corner bits are in NBendCrash.CGamut, so a "State-read-first" path would otherwise validate them at the current SimIndex only and CRawState would then skip the corner sweep. mCValid |= mask prevents doubling across the State→CState pair.

CellPickupCrash faithfully mirrors CellDepositCrash; collider is co-located with the drawn part

The collider xfm PartRestXfm * Shelf.Xfm * Translation(item.Shift + ZAxis*0.1) is identical to PartForPickupVM.GetXFM() (BCellVM.cs:271) apart from the +0.1 Z clearance nudge — so the collision geometry matches the rendered blank (the apparent "double Shelf.Xfm" is consistent with the VM because Enum() pre-multiplies Shift; the deposit path differs because BDepositPlan.Enum does not pre-multiply, and each collider correctly matches its own VM). crashState[n++] can't go out of range: every pickup-plan mutator routes through Update() → Pickup.Dirty(Steps) → Dirty() → nulls CellPickupCrash, so the cache is rebuilt before the next Enum(). Floor-only component selection is correct — rails/frames/tables are covered by the crasher (TestStatic) and robot/gripper reach by CRASH_CORNER_MASK.

Enum bit / FX serialization / click-to-jump are functionally correct

CellPickup = 1UL<<60 doesn't collide (bit 59/60 free in EBCStatus; _Last is a doc-only sentinel, never a mask), and it's correctly in CellCrashes/AllCrashes/IconExplosion and the message map. Dictionary<EBCStatus,int> round-trips (ulong enum keys via WriteUInt64). The save/load→click flow is safe because mCState/mCValid/SimIndex are not serialized, so the first CState read after load rebuilds ErrSimIndexMap (with in-range NOverall) before the grid becomes clickable. OnClick's cstate is a single bit, so the TryGetValue jump is correct. The dispenser short-circuit (ExtendedChecksNeeded == 0 for BDispenser) is a verified-safe optimization — dispenser pickups use a fixed transfer xfm independent of SimIndex.

Deep-dive: is the mErrSimIndexMap answer correct? → Yes, approve it

Serialization is genuinely gone and the schema-version worry is now moot.

  • Renamed mErrSimIndexMap → private _errSimIndexMap (BPickup.cs:716). Flux's serializer skips any _-prefixed field (AuType.cs:433 NeedField), and it's no longer in the schema (metadata.curl:138). At b2d90711 it was a serialized field (metadata.curl:154, Version left at 13) — so the round-1 point was correct.
  • Removing it reverts the serialized shape to exactly what main already ships as Version 13, so no bump is needed and 13 is correct. Old FX carrying the field loads fine — the serializer stashes the unknown field into an extra bag and drops it (AuType.cs:194-198, 505-511, 371-374).

Why the design is necessary, not just adequate. mCState/mCValid are persisted (proof: the PostLoad version-guards at BPickup.cs:42-49 clear specific mCValid bits — pointless unless mCValid is loaded). So after a load the grid shows the cached error straight from mCState without re-running ExtendedChecks (the valid bit is set), leaving _errSimIndexMap empty. That's why TryGetErrSimIndex clears both mCValid and mCState before the recompute (BPickup.cs:711) — clearing mCState is strictly required because ExtendedChecks uses remaining = mask & ~mCState (:811); if the bit stayed set, remaining == 0, the corner loop exits, and the map would stay empty. Non-obvious, and he got it right.

The "we do not trigger it unnecessarily" claim holds. In-session the grid render reads CState → CRawState runs ExtendedChecks whenever ExtendedChecksNeeded != 0, so the map is already populated and clicks hit the fast path. The on-demand recompute is a rare post-load fallback. The per-corner SimIndex churn inside ExtendedChecks fires Redraw(), but that's a coalesced LazyCall (BendTech.cs:2071-2090) — no repaint storm, no reentrancy, and the churn already existed on the render path.

Original crash concern (StackXfm.First() throw)

  • Cross-load variant (what round 1 flagged): fully closed — the map is no longer loaded from the FX.
  • In-session variant: not reachable via normal flow. Any stack/plan change routes pickup.Dirty(EBDirty.Steps) → Dirty(), which invalidates the full EXTENDED_MASK: RobotStroke\|RobotCell\|GripperCell via Invalidate(…CGamut…), and ImpossibleIK because Dirty() calls no-arg ResetSteps() whose default mask is D180Rotate \| ImpossibleIK (BCellUtil.cs:154). (The SimIndex setter's narrower ResetSteps(D180Rotate) deliberately preserves ImpossibleIK — fine, since changing SimIndex doesn't change the corner set.) Dirty() then Redraw()s → grid re-reads CState → ExtendedChecks repopulates the map with valid indices before a click is possible.

Residual robustness note (low, optional): safety is indirect — it depends on every stack-mutating path going through Dirty()→ResetSteps()→Redraw() before a click. The fast path returns the cached index with no bounds re-validation, the SimIndex setter still has no upper clamp (BPickup.cs:424), and StackXfm still .First()s (throws, :463). A one-liner would make it crash-proof regardless: return … && simIndex < mCell.PPlan.CParts; in TryGetErrSimIndex, or .FirstOrDefault() in StackXfm. Defense-in-depth, not a blocker.

New minor observation: CellPickup click doesn't jump SimIndex

CellPickup (bit 59) is not in EXTENDED_MASK, and CellPickupCrash (BCellTech.cs:537) computes a static per-corner bpart[] that never feeds _errSimIndexMap.
