Step2dFluxAPItonet10

product: flux org: metamation tags: [metamation, knowledge-base, flux, refactor, wpf, architecture, spec] type: spec project: Flux updated: 2026-07-14

Part of the [[WPF Decoupling]] spec · Step 2d · [[Step 2 - Split into Decoupled Assemblies|Step 2 overview]] · after [[Step 2c - Flux.Core to net10]]

10. Detailed change spec — Flux.API → net10.0 + Flux.API.UI

Activate the dormant FLUXSDK scaffold (§0.2): Flux.API.UI hosts the #if !FLUXSDK (WPF) bodies; Flux.API compiled with FLUXSDK defined becomes the WPF-free core with the NLux.cs-style shell.

10.1 Workstream 1 — break API → UI (7 genuine types)

Most apparent UI deps resolve to Core/Base (Hub.Edit(object), EPartView=Core/Enums.cs:112, MiscActors=Base). LayEditor is only a doc-comment (LayoutEditor.cs:16) — drop it. Genuine:

UI type (def) API sites Abstraction (impl in Flux.API.UI/Flux.UI)
PartEditor (UI/Part/PartEditor.cs:20) API/Editor/PartEditor.cs (ctor, Skin, Current, Activate, ShowCutting/Bending) IPartEditor + IPartEditorFactory (constructs → factory)
JobEditor (UI/Job/JobEditor.cs:21) API/Editor/JobEditor.cs IJobEditor + IJobEditorFactory
JobBar.ETab (UI/Job/JobBar.xaml.cs:1208) JobEditor.cs:40, Basic.gen.cs:2282 move enum to Core as EJobTab; regen Basic.gen.cs
SheafEdit (UI/Settings/SheafEdit.cs:26) Part.cs:67, Sys.cs:285/288 ISettingsDialogService.RunPartSettings/RunPreset
LaserDBEditor (UI/Laser/LaserDBEditor.cs:12) Sys.cs:291 ISettingsDialogService.RunLaserDB
GlobActors (UI/Glob/GlobAux.cs:15) LayoutEditor.cs:156 ILayoutActorsProvider.FeedbackActors
DragActors (UI/Mouse/DragOperation.cs:108) LayoutEditor.cs:156 same provider

Register factories via the existing Hub delegate pattern in Library.DoInit (API/Basis/Basis.cs:105). API/Editor/{PartEditor,JobEditor,LayoutEditor}.cs move to Flux.API.UI; Flux.API keeps thin wrappers delegating to the injected interfaces.

10.2 Workstream 2 — lift rendering from the domain partials

IPictureSource/IPageDevice/RIPicture are Core already. The WPF coupling in API is the set of Lux.RenderToFigure/new Scene(...)/HiddenLuxPanel/Figure.Bitmap/System.Windows.* calls. Only 4 API files touch System.Windows: Globals.cs:8 (global using …Imaging), Lux/Lux.cs:8 (HiddenLuxPanel = a Window), Basis/Basis.cs:9, Basis/Sys.cs:10 (MainWin/sWin/Init typed Window). Drop/relocate the global using; adopt the object-typed Library.Init(…, object mainWindow) that already exists under #if FLUXSDK (Basis.cs:48).

The [Rep(666)] reflection catch: several picture properties are discovered by the Core report engine via reflection, so the property must stay on the domain partial while its body leaves the assembly → use a registered PictureHook (mirrors Hub): [Rep(666)] IPictureSource Picture => PictureHook.ForBendOp(this);.

Per-type:

Type / file Draw code Strategy
Garnish.GetThumbnail (AModel.cs:89) new Scene(SurfacesVM…)+RenderToFigure extension method in API.UI; needs Garnish.Q internal
BendOp.GetImage (BendOp.cs:829) new Scene+RenderToFigure, reads Tech.Q, APIVModel extension method; needs BendOp.Q/Tech, BendTech.Q internal
BendOpPicture:IPictureSource (BendOp.cs:1109) Render→GetImage+dev.DrawFigure move class to API.UI; BendOp.Picture (:477)→PictureHook.ForBendOp
BendTech sim glue (BendTech.cs:525/593/631) Lux.Start/StopContinuousRender + 5 private state fields companion controller BendSimController in API.UI (ext methods can't hold state). Note: BCRegrip has no draw code — earlier assumption corrected
FoldTech sim glue (Fold.cs:155/198/235) same pattern companion controller FoldSimController
Drawing2.GetThumbnail (Drawing.cs:54, already #if !FLUXSDK) HiddenLuxPanel+DrawingVM+RenderToFigure extension method; Drawing2.Q internal. FlatPicture (:38)→PictureHook
CellReport.cs 5 IPictureSource classes (:20/107/134/162/183) dev.DrawFigure / RenderToFigure move all 5 + RIUtil to API.UI; CellTech.cs:30-73 [Rep] props→PictureHook.ForXxx
API/Lux/Lux.cs (whole, #if !FLUXSDK) WPF Lux façade + HiddenLuxPanel move whole file to API.UI
API/Lux/NLux.cs (#if FLUXSDK, dormant) WPF-free Lux/VModel/Scene overloads the target shell — keep in API, fill in
API/Gen/Lux.gen.cs APIGen-generated Lux delegators (not WPF itself) split generator output: UI members→API.UI, core wrappers→API. Check Tools/APIGen/Project.cs routing before moving
LayoutEditor.cs GLEditor+LayoutEditor (whole, #if !FLUXSDK) Lux.UIScene, GLMouse, GlobActors/DragActors move whole file to API.UI (consumes ILayoutActorsProvider)

10.3 [InternalsVisibleTo] + accessibility changes on Flux.API

Add [assembly: InternalsVisibleTo("Flux.API.UI")]. Promote to internal: Garnish.Q; BendOp.Q/Tech; BendTech.Q (+ move its 5 sim fields into BendSimController); FoldTech.Q (+ fields → FoldSimController); Drawing2.Q; CellTech.Q (6 [Rep] props → PictureHook); Layout.Lay; Figure.Q. Rewire the [Rep(666)] bodies (Model3.ModelPicture, BendOp.Picture, Drawing2.FlatPicture, the CellTech six) to PictureHook.ForXxx(...), populated by API.UI in Library.DoInit.

10.4 Flux.API.UI project shape

net10.0-windows, UseWPF=true; references Flux.API, Flux.UI, Flux.Core, Flux.Base. Receives: Lux.cs, LayoutEditor.cs, API PartEditor.cs/JobEditor.cs wrappers, the 5 CellReport picture classes

  • RIUtil, BendOpPicture, BendSimController/FoldSimController, the lifted GetImage/GetThumbnail extensions, and all factory/PictureHook registrations. Flux.API (with FLUXSDK) then holds domain + interfaces + the WPF-free Lux shell — but stays net10.0-windows until Base/Core are flipped (§4).
