9. Detailed change spec — Flux.Core → net10.0 + Flux.Core.UI

9.1 The ViewModels are cleanly movable

No *VM type is partial; none is split across assemblies — so every VM moves wholesale. The heavy ones (bulk relocation to Flux.Core.UI): Laser/LaserVM.cs, Model/Entity3VM.cs, Trim/TrimTechVM.cs, Fold/FoldKB40.cs, Layout/LayoutVM.cs, CAM/CutSeqVM.cs, Bend/BendVM.cs, Drawing/DrawingVM.cs, Model/Trim/TrimModelVM.cs, CAM/UnloaderVM.cs, Laser/SliceCut.cs, Punch/PunchVM.cs.

9.2 Five files co-locate a VM with domain code (file-level split)

Cut the VM class out into a new Flux.Core.UI file: BCell/BSeparator.cs (SepSheetVM:353), Bend/BendACB.cs (ACBLaserTraceVM:1279), Bend/Clamp.cs (ClampGroupVM:102, ClampVM:169, ClampXfmVModel:203), Bend/FlexCell.cs (FlexCellGripVM:146), Fold/FoldKB40.cs (7 KB40*VM classes, :1589-1921).

9.3 True upward coupling — small & bounded (~7 sites)

Domain code that holds/calls a VM (the only genuinely hard references):

Site Reference Fix

9.4 The real effort — ~20 RenderToFigure thumbnail methods

Headless domain objects expose "get me a picture" methods that build VM + Scene → Lux.RenderToFigure. These are scattered and are the bulk of the Core work → introduce an IThumbnailRenderer (or move each GetThumbnail to a UI extension) so the domain stays headless and UI supplies the VM+Lux render. Sites: BCell/BCellItem.cs:208, BCell/BCellTech.cs:315-337(obsolete — delete)/1000-1151, Bend/BendMachine.cs:603, Bend/BendSetup.cs:1143, Bend/Ops/BAPlacer.cs:264, Drawing/Drawing.cs:1003, Layout/Layout.cs:569-671, Model/Model3.cs:963, Fold/FoldSection.cs:1106, Fold/7K/Centering7K.cs:910, Fold/Ops/FoldCode.cs:51/1671, Nest/NestJob.cs:617/1024/2178, Report/Pictures.cs:32, Part/Part.cs:1347, Nest/PixelMap.cs:35/225, Fold/FoldMechanism.cs:412-649, Fold/JawMinder.cs:305/319.

9.5 Non-VM WPF service usages

Permit.cs:440/OEMDemoOption.cs:43 MessageBox→IUserPrompt; CutTooling.cs:678 Clipboard→IClipboard; FX.cs:880-893 + WPF/OpenFile.cs (whole FileDialog class, COM IFileDialog)→IFileDialogService (the file moves to Flux.Core.UI); CmdProcess.cs:2039 Key enum→neutral; BendGAPAdjust.cs (builds Border/TextBlock/Brush — view code)→Flux.Core.UI; FoldSectionGrip.cs:197-206 (DrawingVisual/Pen/Rect→mono bitmap)→IImageEncoder; RItem.cs:325/462 FormattedText→ITextMeasure (extend Report.cs's existing device seam); NestJob.cs:2178 BitmapSource Thumbnail→Figure/byte[]; TBSCustomDB.cs:9 dead using→delete.

9.6 Aegis → ILicensing (self-contained)

All Locking.API use is in Core/Permit.cs (class MMAegisLock:1010, AegisLockCB:1197). Full surface: Product/Lock/ILockSrc/LockFile/LockUrl/ELockError/LockException (call sites listed in §6-adjacent survey; Register/Take/Release/GetData("Features")/ShowUI/SessionExpired/Expiry/ IsFloating/IsOK/Status). One leak to fix: AegisLockCB.Lock is a public Locking.API.Lock field (Permit.cs:1216) exposed via Hub.RunAegisDlg (Hub.cs:146) → retype to ILicenseSession. Wrap with ILicensing/ILicenseSession (§6), implement in a small Flux.Licensing.Aegis (or Flux.Core.UI) that references the Aegis.API package; Core drops the Aegis.API PackageReference → unblocks the flip. (Trumpf.Licensing + Protection.Key.Standard are netstandard2.0, not blockers, but deserve parallel abstractions.)
