8. Detailed change spec — Flux.Base → net10.0

After Lux/GL leave, classify every remaining WPF-touching file: A move to Flux.UI; B behind a service interface; C retype to a neutral type; D dead using, just delete.

8.1 Move wholesale to Flux.UI (class A)

Flux.UI already exists and references Base. Move: Base/WPF/Device.cs (KeyNotify, 18 callers), Base/WPF/UIExtensions.cs (WPFExtensions incl. the ToColor/ToImage/ToPoint2/ToPline bridges), Base/WPF/Controls.cs (DragWrapPanel), Base/WPF/CmdRouter.cs (CmdRouter, 8 callers), Base/WPF/Behavior.cs (all window behaviors), Base/WPF/Markdown.cs (21 callers), Base/FText/FTPanel.cs + FTPanelImp.cs (FastTypeface, only UI/Controls/VecdrawPanel.cs uses it), and Base/Base.cs's NeedsEnterProperty attached property. Base/FText/FTextBlock.cs already uses Color32 and stays (it is the template for neutralizing FTDocument.cs).

8.2 Behind interfaces / retype (classes B & C)

File:line Member Class Action
Types/Color32.cs:118 Brush ToBrush() — 35 callers B remove from struct; extension in Flux.UI; then drop using System.Windows.Media. Color32 becomes fully neutral
BClasses.cs:221 BitmapSource Figure.Bitmap C/B keep Figure as neutral pixel buffer; move Bitmap to a UI extension Figure.ToBitmapSource(); route ToBytes/Save through IImageEncoder
BaseExtensions.cs:80-149 BitmapSourceExtensions (ChromaKey/Resize/To{BMP,GIF,JPEG,PNG}) B encoders → IImageEncoder
BaseExtensions.cs:1829/1832 Geometry ToGeometry(Pline / IList<Pline>) — 8 callers B/move inputs are Flux Pline; WPF only internal → move to Flux.UI or IGeometryRasterizer
BaseExtensions.cs:1860/1877 ToMonoBitmap (nesting/NFP raster computation, not display) B IImageEncoder.ToMonoBitmap on Skia — genuinely needs a headless 2D raster backend

IO/PDFWriter.cs:12-13, Geo/Geo.cs:11, Win32.cs:11 dead usings D delete (the "Rect"/"Size"/"Matrix" tokens are PDF string-keys / Flux types / comments)

8.3 Base.cs threading — the critical seam (already half-done)

public static SynchronizationContext SyncContext (:188) is already neutral and captured when MainWin is set (:149). The WPF Dispatcher use is shallow: Post (:673) already prefers SyncContext and only falls back to Dispatcher.BeginInvoke. Concrete changes:

  • UIPost/UIPostOnce (:777/787), PumpMessages (:805) → IUiScheduler (Post/PumpToBackground).
  • MakeTimer():DispatcherTimer (:774, 11 callers) + After (:237) → IUiScheduler.CreateTimer / IUiTimer.
  • MainWin:Window (:144, 4 callers) → object (or IMainWindow marker); setter still captures SyncContext + thread id.
  • DPIScale (:96, 13 callers) → IUiScheduler.DpiScale. GetMousePos (:579) → return Point2 via IUiScheduler.GetScreenMousePos.
  • CtrlPressed/ShiftPressed (:65/185) → IInputState. RunDialog(Window) (:728) → IUserPrompt/IDialogService; ModalDlgs → Stack<object>.

Net: the WPF-thread dependency is not pervasive — a small IUiScheduler + IInputState + startup registration from Flux.UI (at the current MainWin assignment point) covers it. After 8.1-8.3, Base/Flux.Base.csproj drops UseWPF/UseWindowsForms and retargets net10.0 (the existing obj/.../net10.0 build confirms feasibility).
