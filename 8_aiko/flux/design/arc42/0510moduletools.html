05.10 — Module: Auxiliary tools (X:\Tools\)

Nineteen small .csproj projects live alongside the main solution. None are part of Flux.sln; each builds independently. They serve four distinct purposes — build pipeline, content lifecycle, customer ship, and developer tooling — and are grouped accordingly below.

Folder layout

X:\Tools\
├── APIGen\              Generate Flux.API surface from Base/Core/UI assemblies
├── Annotate-C\          CXF→DAT converter for Cybelec controllers
├── FDoc\                Reflective HTML API doc generator
├── FFHoops\             (under MetaCAM\) 3D→IGES converter via HOOPS
├── FFNest\              (under MetaCAM\) experimental "Flux Nest" engine
├── FFSeq\               (under MetaCAM\) laser-fiber sequencer
├── FluxLines\           Code-metrics / LOC counter
├── FMatrix\             Tiny standalone 3D-math library (CoordSystem, Matrix3, …)
├── FShip\               Build orchestration + installer creation
├── FTex\                FTex-format compiler (CLI)
├── FTexVi\              FTex-format editor (WPF GUI)
├── Flux.Log\            Cross-process log receiver (FluxLogPipe server)
├── Git\PreCommit\       Pre-commit hook
├── MakeRes\             (×2, under MetaCAM\) resource-archive builders for FF*
├── MetaCAM\FFSeq\
├── MetaCAM\FFHoops\
├── Sim5K\               Robot bend-cell simulator
├── Sim7K\               Press-brake cell simulator
├── XLate\               Translation-table round-trip tool
└── XNCSign\             XNC password protector

Build pipeline

Tool Purpose
APIGen Generates the public Flux.API surface from Flux.Base / Flux.Core / Flux.UI via manifest-driven code generation. Produces the wrapper classes in Src\API\Gen\*.gen.cs. Run by FShip during a release build.
FDoc Reflective HTML API-documentation generator. Walks the built assemblies, produces cross-linked HTML with type maps, namespace filters, and member extraction. Used to publish internal API docs.
FShip Master build orchestrator. Validates FShip version consistency, manages Version.ini, checks Git working-tree state, recompiles Flux.exe, runs APIGen / FDoc, packages the Inno Setup installer (Setup.Flux.<build>.exe), and publishes binaries to X:\Src\Bin.
MakeRes (FFHoops) Compresses Flux.Base / Flux.Core / Aegis.API / DXF colour table / machine #97 config / laser STAMM.bin into the resource archive that FFHoops embeds.
MakeRes (FFSeq) Same payload, packed for FFSeq and FFNest.

Content lifecycle

Tool Purpose
XLate Translation-table round-trip. xlate make <lang> extracts an Excel spreadsheet from the current .txt lang tables (output to Y:\XLate\New); a translator fills it in; xlate use <lang> writes the result back into Wad\lang\<lang>\. xlate delpics <lang> strips embedded illustration images before commit. See §8.20.
FTex Compiler for the in-house "FTex" markup format used by Notes\Dev\ and Notes\Tech\. CLI; produces HTML with embedded CSS and image resources.
FTexVi WPF GUI editor for FTex documents (.ftx, .ftxproj). Side panel shows the live HTML preview via a WinForms browser control. The "Vi" suffix is "Viewer / IDE", not the Unix editor.
FluxLines Code-metrics tool. Counts LOC, comment lines, file counts, and #nullable enable coverage across X:\Src and X:\Test.

Git hook

Tool Purpose
Git\PreCommit Pre-commit guardrail. Refuses commits that: push to main without COMMIT_TO_MAIN env var; contain conflict markers; contain "summary-to-collapse" flags; check in .fx / .fxjob / .fxlyt files with thumbnails. Warns on .fx files with diagnostic data still attached.

Customer-shipping tools

These are bundled into customer installers under specific flavors:

Tool Ships with Purpose
Annotate-C non-Trumpf installers Converts Cybelec CXF → DAT via CXFtoDAT.dll; appends JPG thumbnails for Cybelec or omits them for Modeva.RA. Installed as annotate-c.exe.
XNCSign Trumpf installers Password-protects XNC files (extracts ZIP, re-zips with a fixed password). Installed as xnc-sign.exe.
FTex / FTexVi conditionally, when bundled docs include .ftx sources Allows customers / on-site engineers to render and edit technical notes.
Flux.Log dev / diagnostic builds Named-pipe server that listens on FluxLogPipe and acknowledges via FluxLogMutex; prints incoming log lines to a console window. The receiver for the cross-process logging mechanism described in §3.2.5.

Developer-only utilities

Tool Purpose
FMatrix Pure-math 3D library: CoordSystem, Point3, Vector3, Matrix3. Standalone; not referenced by Flux.Core. Used by ad-hoc geometry experiments and by Sim5K / Sim7K.

Simulators (training / verification, not shipped)

Tool Targets Reads UI
Sim5K Trumpf robot bend cells (BendMaster series) Delem BNC G-code (START_PROGRAM_ROBOTER sections); maps machine-config IDs (5130, 5170S, V1300X, …) to Flux internal machine IDs WPF
Sim7K Press-brake cells with 6-axis robot integration BNCC code; supports linear / angle / circular / axis-only interpolation modes; gripper / vision / back-gauge commands WPF

Both are dev-only — used to verify cell-code generators end-to-end without burning real hardware time.

Legacy MetaCAM "finisher" tools

These are the in-process "finishers" called by the legacy MetaCAM CLI (when MCAMPath is set). Not Trek; a separate older system. None ship as customer artifacts of Flux itself — they are part of the MetaCAM distribution.

Tool Purpose
FFHoops 3D import / IGES export via Flux.Hula64.dll; converts foreign 3D CAD into IGES that MetaCAM can ingest.
FFNest Experimental nesting engine ("Flux Nest"); customisable corner-selection and hole-nesting; called from MetaCAM's nest workflow.
FFSeq Laser-fiber sequencer — autotools, traces stitch-cuts, tags covered entities, emits .seq files with polyline geometry and cut order.

The MakeRes projects under Tools\MetaCAM\FFSeq\ and Tools\MetaCAM\FFHoops\ build the shared resource archives (Res\*) these three tools embed.

Constraints

  • None of these are part of Flux.sln. Each builds independently.
  • Dependency direction is one-way: tools reference Flux.Base / Flux.Core / Flux.UI, never the other direction.
  • Customer-shipped tools (Annotate-C, XNCSign, FTex, FTexVi, Flux.Log) are wired into FShip and the Inno Setup script; the rest are dev-only and never reach an installer.
