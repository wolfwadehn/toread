05.3 — Module: Flux.UI

The controller layer plus all WPF dialogs. Sits above Flux.Core and below Flux.App.

Purpose

Flux.UI provides:

  • Globs — controller objects per domain. They wrap a domain object, expose its properties via the abstract GElement model, and implement the commands the user can issue.
  • Composite glob machinery — when multiple objects are selected, a single composite controller appears.
  • WPF editors — full-window dialogs like TurretEditor, SheafEditor, LaserDBEditor, MachineEditor, the report designer, the inventory views.
  • Agents — input handlers per domain (BendAgent, LaserAgent, FoldAgent).
  • Sheets — list-grid views over collections (BendSheet for the bend-op sequence).
  • PanelMaker — the translator from abstract GElement properties to concrete WPF controls.

Code volume: 117 .cs files.

Folder layout

Src\UI\
├── Glob.cs           Glob base class + attribute model
├── Editor\           Big WPF dialogs
├── Bend\             BendOpGlob, BendOpsGlob, BendSetupUI, BendMountUI, BendACBUI,
│                     BendAidUI, BendClampUI, BendAgent, BendSheet
├── BCell\            BCellGlob, BPickupGlob, BRegripGlob, BDepositGlob,
│                     BWaypointGlob, BGripperGlob, BJawPickupGlob, BGripperToolGlob,
│                     BFlexiGripperGlob, BRobotStrategyGlob
├── Fold\             FoldUI, FoldKB40UI, FLoadUI, FoldAgent
├── Laser\            LaserUI
├── Layout\           CutNavigator
├── Misc\, Job\, Controls\, …

Key public types

Type Role Stability
Glob (base) Controller wrapping one domain object. Decorated with [Glob (Draw=true, Mouse=EMouse.LDown)] etc. 🟢
GElement Abstract description of a glob property (label, value editor, validation). 🟡
PanelMaker Translates GElement → WPF controls. 🟡
Per-domain *Glob classes The concrete controllers. ~15 classes today. 🟡
Per-domain *Agent classes Mouse/keyboard handlers. 🟡
Editors (TurretEditor, etc.) Full WPF dialogs. 🟡

The Glob lifecycle

  1. Selection happens — the user clicks an object in the 3D scene or a list view.
  2. Glob is constructed wrapping the selected domain object.
  3. PanelMaker reads the glob's properties (GElements) and renders WPF.
  4. User edits a property → setter routes through BA.Set → notify + undo.
  5. Commands invoked via the glob trigger domain operations (e.g. BendOpGlob.AddRegrip).
  6. Multi-select — the system constructs a composite glob (e.g. BendOpsGlob) showing only properties shared across the selection.

Composite globs — the single most distinctive UI pattern

When N objects of the same domain type are selected, the composite glob:

  • Exposes properties whose values agree across all members directly.
  • Marks properties whose values disagree with a "mixed" sentinel.
  • Routes commands to all members in a single undo unit.

BendOpsGlob (in Src\UI\Bend\BendOpUI.cs line 661) is the canonical example.

The composite is auto-built by the glob machinery if your individual glob exposes its properties cooperatively. Per-domain author writes one set of properties; multi-select works for free.

Edit the right thing in the right place

Where What belongs here What does not
Glob properties Per-property edit logic, validation Long-running computation
Glob commands User-intent operations — sequenced through undo Direct UI manipulation
Agent Mouse / keyboard interpretation Domain logic
Editor (WPF dialog) Big modal workflows (machine config, tool inventory) Reusable property edits
Sheet Tabular collection views Single-object edits

Constraints Flux.UI respects

  • No Flux.UI types in Flux.Core. Always.
  • WPF lives here, not in Core. The Engine flavor must be able to skip this assembly entirely.
  • Globs are stateless beyond their wrapped object. State persists on the model, not on the controller.
  • Direct calls into Flux.App — not allowed. App fills Hub slots; UI invokes them.

What surprised me reading this layer

  • BendOpUI.cs is bigger than expected (most of BendOpGlob + BendOpsGlob together). The robot-cell command logic (AddRegrip, the eight-flavor decision tree) lives here, not in BCell\. See Onboarding chapter 02.1 BCell §7.4.
  • BCellGlob is also large; the cell composer / strategy editor lives here.
  • Editor\ contains some heavy old WPF dialogs that pre-date the current Glob conventions. They are stable, but new editors should follow the Glob+PanelMaker idiom rather than write more bespoke dialogs.
