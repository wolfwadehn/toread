🔤 Flux Review — Language Idioms & Flux Helpers

[!abstract] Scope · priority: consider Idiomatic C# and which built-in Flux helper to use instead of open-coding. See also [[Flux Idiom Cheat-Sheet]].

This page has two parts: the official repo rules for this theme (G001, G010, G013, G015, G017, G020, G021, G028, G034, D016, D023) and Arvind's mined additions (16 rules, 10 novel).

⬅ Back to [[Flux — Code Review Guidelines|the review index]].

📘 Official repo rules (source of truth)

[!note] Verbatim from the repo — do not edit here Copied from .github/instructions/pr-review-guidelines.instructions.md and .github/instructions/design-principles.instructions.md (loaded automatically by Copilot/Claude), synced from commit cf7f99c55 on 2026-07-13. The repo is authoritative — edit there and re-run the KB sync.

G001: Null-Conditional Operators — Use ?. and ??= (123 occurrences)

Severity: High — cited in nearly every active PR batch

Always use null-conditional operators instead of manual null checks.

// ❌ Wrong
if (agent != null) agent.SwitchedMaterial ();
var tech = clgrp.Children.FirstOrDefault (); if (tech != null) return tech.Tech;

// ✅ Correct
agent?.SwitchedMaterial ();
var tech = clgrp.Children.FirstOrDefault ()?.Tech;

Also use ??= for lazy initialization:

// ❌ Wrong
if (mPlane == null) mPlane = FindPlane ();

// ✅ Correct
E3Plane Plane => mPlane ??= FindPlane ();

Use ?? 0 / ?? string.Empty / ?? [] for null-coalescing defaults:

features[fi.Name[1..]] = (int)(fi.GetValue (null) ?? 0);
if (allTranslations == null || allTranslations.Any (x => x.Value == null)) return [];

G010: Collection Expressions [] (28 occurrences)

Severity: Medium

Use [] syntax instead of new List<T>(), new[]{}, etc., when the target type is known:

// ❌ Wrong
var list = new List<string> ();
HashSet<int> numbers = new HashSet<int> ();
return new List<Item> ();

// ✅ Correct
List<string> list = [];
HashSet<int> numbers = [];
return [];

Use .. (spread) to flatten collections:

// ❌ Wrong
return items.Where (a => a.IsActive).ToList ();

// ✅ Correct
return [.. items.Where (a => a.IsActive)];

G013: Direct Method References — No Unnecessary Lambdas (22 occurrences)

Severity: Medium

Pass method references directly instead of wrapping in a lambda:

// ❌ Wrong
Dispatcher.Invoke (() => mOverlay.Redraw ());
items.ForEach (x => Process (x));

// ✅ Correct
Dispatcher.Invoke (mOverlay.Redraw);
items.ForEach (Process);

⚠️ Do NOT flag when the target method has optional parameters (or is params/generic-inferred). C# method-group → delegate conversion does not apply optional-parameter defaults: the method's full signature must match the delegate. So if Add is declared void Add (Area a, bool flag = false), then list.ForEach (Add) fails to compile against Action<Area> — the lambda a => Add (a) is required, not redundant. Verify the target method's signature before raising G013; the wrapper is only removable when the method's parameter list matches the delegate exactly. (False positive: PR #3483, BNCXProcessDataWriter.cs — xml.Take (6).ForEach (a => mArea.Add (a)).)

G015: String Range [..] Instead of Substring (19 occurrences)

Severity: Medium

// ❌ Wrong
var prefix = name.Substring (0, 20);
var suffix = name.Substring (5);

// ✅ Correct
var prefix = name[..20];
var suffix = name[5..];

G017: Target-Typed new() (Frequently Missed — R010)

Severity: Medium — often missed even by senior contributors

When the type is already declared on the left-hand side, omit it on the right:

// ❌ Wrong
XForm4 matrix = new XForm4 ();
Point3 pt = new Point3 (x, y, z);
public Point3 Start => new Point3 (x, y, z);
List<Item> items = new List<Item> ();

// ✅ Correct
XForm4 matrix = new ();
Point3 pt = new (x, y, z);
public Point3 Start => new (x, y, z);
List<Item> items = new ();

Also applies in LINQ and collection initializers where type is obvious from context.

G020: Expression-Bodied Members (5 occurrences)

Severity: Low — but clean code standard

Use => for simple single-expression properties and methods:

// ❌ Wrong
public Point3 Start { get { return mStart; } }
public int Count { get { return mList.Count; } }

// ✅ Correct
public Point3 Start => mStart;
public int Count => mList.Count;

G021: Pattern Matching (5 occurrences)

Severity: Low — modern C# idiom

// ❌ Wrong
if (item.Kind == EKind.Hole || item.Kind == EKind.Mark) { }
if (obj is Arc3) { var arc = (Arc3)obj; ... }

// ✅ Correct
if (item.Kind is EKind.Hole or EKind.Mark) { }
if (obj is Arc3 arc) { ... }

// Also:
while (item is not null and not ListBoxItem) item = GetParent (item);
if (thick is >= 3.5 and < 4.5) { }

G028: Spread Operator .. (R009)

Severity: Low

Use the spread operator to flatten collections:

// ❌ Wrong
return Items.Where (a => a.IsActive).OrderBy (a => a.Name).ToList ();

// ✅ Correct
return [.. Items.Where (a => a.IsActive).OrderBy (a => a.Name)];

G034: Switch Expressions Over Long if-else Chains

Severity: Low — code quality suggestion

When a value is selected from multiple enum cases or string keys, prefer switch:

// ❌ Verbose
string result;
if (kind == EKind.Hole) result = "hole";
else if (kind == EKind.Mark) result = "mark";
else result = "other";

// ✅ Cleaner
var result = kind switch {
    EKind.Hole => "hole",
    EKind.Mark => "mark",
    _          => "other",
};

Reviewer feedback: "Why not simply use a switch on SettingsLaserCAM.PointProcess instead of defining process as a parameter?"

D016: Use Path.Join Not String Concatenation for Paths

"We can use Path.Join, cascading of Set, and using to Flush."

// ❌ Wrong
var path = baseDir + "\\" + "options.ini";
var path = Path.Combine (baseDir, "options.ini");  // acceptable but prefer Join

// ✅ Correct
var path = Path.Join (baseDir, "options.ini");

D023: switch Expression Over Long if-else Chains

When selecting a value from multiple enum/string cases, use a switch expression.

"Why not simply use a switch on SettingsLaserCAM.PointProcess instead of defining process as a parameter?"

// ❌ Wrong
string result;
if (pt == EPointProcess.A) result = "a";
else if (pt == EPointProcess.B) result = "b";
else result = "c";

// ✅ Correct
var result = pt switch {
    EPointProcess.A => "a",
    EPointProcess.B => "b",
    _               => "c",
};

🎓 Arvind's additions (mined from PR reviews)

Ordered by importance (severity, then how often he repeated it). Quotes verbatim; links to the source PR.

Use pattern matching for type tests and multi-value comparisons

🟠 consider · ↔ G021

When testing a value's type, capture it once with is T t (or filter a sequence with OfType<T>()) instead of re-checking the type multiple times. Compare one value against several constants with is a or b or c rather than x==a || x==b. Combine a type test with a property check via a property pattern is T { Prop: true }. Replace a ternary that yields a bool with the pattern expression directly (e.g. is not T && (...)).

“This statement does the type check to see if child is T three times. You can make it more efficient (and also less verbose)... An even more elegant way of doing this is by using OfType to filter right when you are enumerating”

// don't
if (child is T && (predicate == null || predicate((T)child))) ...
if (ext == "jupidu" || ext == "gecco" || ext == "fx") ...
if (item is BPallet p && p.IsBasket) ...
// do
if (child is T tc && (predicate == null || predicate(tc))) ...
if (ext is "jupidu" or "gecco" or "fx") ...
if (item is BPallet { IsBasket: true }) ...

— Arvind, PR#31, PR#128, PR#158, PR#788, PR#1129

Use declarative LINQ operators instead of hand-rolled loops

🟠 consider · 🆕 novel

Remove elements from a sequence with Except rather than looping. Find a maximum with Max(selector) instead of manual iteration. Flatten-and-sort with SelectMany(...).OrderBy(...).ToList() instead of nested ForEach loops mutating a list. Collapse collection.Where(pred).Any() into collection.Any(pred). Prefer a single fluent chain (OfType/Select/NonNull/ForEach) over a select-then-filter-then-foreach block.

“You can use the Except method to simplify this”

// don't
collection.Where(x => x.Ready).Any();
// do
collection.Any(x => x.Ready);

— Arvind, PR#34, PR#787, PR#1258, PR#1338, PR#1176

Prefer switch expressions to map values; use a plain switch statement for side effects

🟠 consider · ↔ G034

Replace if/else-if chains that assign a result based on an input with a switch expression, optionally switching on a tuple of conditions with a _ default arm. Do not build a dictionary and catch a key-not-found exception for a small fixed mapping — use a switch expression with a default arm. Conversely, when every branch just performs a side effect, use an ordinary switch statement rather than building and invoking a delegate.

“Replace this with a switch expression, rather than constructing a dictionary, and handling the exception etc.”

// don't
int reason; if (tError && aError) reason = 4926; else if (tError) reason = 4927; else reason = 4928;
// do
int reason = (tError, aError) switch { (true, true) => 4926, (true, _) => 4927, _ => 4928 };

— Arvind, PR#1272, PR#1880, PR#662, PR#974

Use ?? and ??= instead of explicit null-check-then-assign

🟠 consider · ↔ G001

Replace if (x == null) x = ... with x ??= .... Collapse an if/else chain that picks the first non-null candidate into a single a ?? b expression. Collapse Count()!=0 ? First() : fallback into FirstOrDefault() ?? fallback.

“This can be written more cleanly as _entombedPoints ??= Nodes.Where ...”

// don't
if (_points == null) _points = Nodes.Where(...);
// do
_points ??= Nodes.Where(...);

— Arvind, PR#787, PR#2204, PR#2267

Choose the comparison operator by type: EQ for floats, EqualsIC for case-insensitive strings, == for ints/enums

🟠 consider · 🆕 novel

Compare floats/doubles and geometry types with a.EQ(b) (default tolerance 1e-6, or an explicit tolerance). Compare strings ignoring case with a.EqualsIC(b). Compare integers and enums with plain a == b, not a.Equals(b). For multi-value tests use an is X or Y pattern.

“Is there a reason to use Equals for this comparison instead of a simple ==”

— Arvind, PR#223

Use Flux's own extension helpers instead of open-coding equivalents

🟠 consider · 🆕 novel

Filter out nulls with the .NonNull() extension rather than .Where(x => x != null). Do case-insensitive string comparison with the string.EqualsIC extension rather than open-coding StringComparison.OrdinalIgnoreCase. Prefer existing Flux helpers when one exists for the operation.

“Use the .NonNull() extension method from Flux.”

// don't
items.Where(x => x != null);
s.Equals(t, StringComparison.OrdinalIgnoreCase);
// do
items.NonNull();
s.EqualsIC(t);

— Arvind, PR#1176

Prefer a foreach statement, tuple deconstruction, and TryAdd for dictionary/collection work

🟠 consider · 🆕 novel

Iterate with a foreach statement rather than the ForEach LINQ operator for general loops. Deconstruct dictionary/tuple entries directly in the header (foreach (var (k, v) in dict)) instead of accessing .Key/.Value. Add a key/value pair only if absent with dict.TryAdd(k, v) rather than a contains-check-then-add.

“In general, a foreach statement is often cleaner than a ForEach LINQ operator. ... Use TryAdd to add a key/value pair if it does not already exist”

// don't
foreach (var kv in dict) Add(kv.Key, kv.Value);
// do
foreach (var (k, v) in dict) Add(k, v);

— Arvind, PR#1105, PR#118

Use a raw string literal for constant multi-line text

🟠 consider · 🆕 novel

When the content is a fixed constant string, write it as a """ ... """ raw string literal rather than appending line by line with a StringBuilder.

“Why not just use a multiline string (starting with """ triple open quote), since this is just a constant string.”

— Arvind, PR#1511

Replace magic numbers with named framework constants

🟠 consider · ↔ G006

When a literal represents a framework limit, use the named constant (e.g. int.MaxValue) instead of the raw number, so it is self-documenting and stable across platforms.

“It's better to replace it with int.MaxValue, which is guaranteed to never change and will remain as 32-bit even on 64-bit or future systems.”

— Arvind, PR#1729

Prefer concise operator and helper idioms for common expressions

⚪ suggest · 🆕 novel

Use compound-assignment operators (x |= y) for read-modify-write instead of an if/assignment. Express a range test with the value as the subject: value.Between(lo, hi). Bound a loop that must respect two lengths with a single Min(a.Length, b.Length) condition rather than two chained comparisons. When joining with a separator, append the separator before each element when index > 0 (leading-separator) rather than a trailing-separator-plus-last-element check.

“Even better: FX.AdminMode |= mIni.GetB ("Admin");”

// don't
if (mIni.GetB("Admin")) FX.AdminMode = true;
// do
FX.AdminMode |= mIni.GetB("Admin");

— Arvind, PR#592, PR#1156, PR#2640, PR#1199

Use the direct framework API for common operations

⚪ suggest · 🆕 novel

Create a directory with Directory.CreateDirectory(path) rather than constructing a FileInfo and calling .Directory.Create(). Read an environment variable with Environment.GetEnvironmentVariable rather than reading the registry. Read lines with the idiomatic while ((line = reader.ReadLine()) != null) loop rather than checking EndOfStream.

“Just use Directory.Create ("xyz") instead of this complicated way.”

— Arvind, PR#130, PR#860, PR#2252

Remove redundant defensive checks and self-assignments

⚪ suggest · 🆕 novel

If you just assigned a known type to a member (e.g. Button.Tag = someCutMachine), do not later add an is/null check on it — the branch is dead noise. Do not write a redundant self-assignment inside an expression (e.g. tb.Foreground = Brushes.Black inside a ternary branch) when the plain value is what's needed.

“Why do you need this if check? You just set Button.Tag to be a CutMachine, so there is no possibility it is not going to be one.”

— Arvind, PR#2540, PR#211

Reduce member boilerplate: omit implicit modifiers and skip needless properties

⚪ suggest · 🆕 novel

Do not write the private modifier — it is the implied default. For an internal/private class, expose data as public readonly fields rather than get-only properties with separate backing fields. (The omit-private half reinforces G018.)

“Don't need to use private - that is implied by default.”

— Arvind, PR#1948, PR#1179

Use ForEach with a method group for one-call-per-element loops

⚪ suggest · ↔ G013

Rewrite foreach (var x in list) Method(x); as list.ForEach(Method). Caveat (per repo CLAUDE.md / G013): only do this when the target method's full signature matches the delegate — do NOT apply it when the method has optional parameters, is params, or relies on generic inference, since method-group conversion won't fill defaults and it will fail to compile.

“Rewrite as FX.TempDiagnosticFiles.ForEach (FX.Delete);”

// don't
foreach (var f in FX.TempDiagnosticFiles) FX.Delete(f);
// do (only if FX.Delete has no optional/params args)
FX.TempDiagnosticFiles.ForEach(FX.Delete);

— Arvind, PR#130

Use a static collection expression plus Any() for candidate-value checks

⚪ suggest · ↔ G010

Declare the candidates as a static collection expression (static string[] xs = [ ... ];) and test with xs.Any(predicate) rather than repeating the same check for each value.

“static string[] sProcesses = [ "vmtools", "vmtoolsd", .... ]; if (sProcesses.Any (a => Process.GetProcesses (a).Any ())”

— Arvind, PR#1338

Disable image smoothing for pixel-exact bitmaps in WPF

⚪ suggest · 🆕 novel

When rendering a bitmap that must stay pixel-exact, turn off smoothing via RenderOptions: SetBitmapScalingMode(image, BitmapScalingMode.NearestNeighbor) and SetEdgeMode(image, EdgeMode.Aliased).

“Turn off image smoothing... RenderOptions.SetBitmapScalingMode (image, BitmapScalingMode.NearestNeighbor); RenderOptions.SetEdgeMode (image, EdgeMode.Aliased);”

— Arvind, PR#1236
