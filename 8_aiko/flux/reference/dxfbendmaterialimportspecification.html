DXFBendMaterialImportSpecification

title: DXF Bend & Material Import Specification product: flux org: metamation type: reference tags: [flux, dxf, import, bendline, material, thickness, spec, io] source: Src/Core/IO/DXFReader.cs, Src/Core/IO/DXFWriter.cs updated: 2026-07-30

DXF Bend & Material Import Specification (Flux)

How to encode bend-line information, material and thickness in a DXF so that Flux reads them on import. Derived directly from the Flux source — the reader Src/Core/IO/DXFReader.cs and the matching writer Src/Core/IO/DXFWriter.cs (round-trip). Group-code numbers below are literal DXF group codes; in a DXF ASCII file each code is on its own line, followed by its value on the next line.

[!tip] TL;DR Draw each bend as a LINE (or a single-segment polyline) and attach XDATA with a 1000 string BEND_ANGLE:<deg> (its presence is what turns the line into a bend line), plus optional MATERIAL:, THICKNESS:, BEND_RADIUS:, K_FACTOR:, BEND_FACTOR: strings. The sign of the angle is the bend direction (+ = up, − = down).

1. Recommended method — XDATA on a LINE entity (canonical, round-trips)

This is exactly what Flux writes (DXFWriter.Save(E2Bendline), DXFWriter.cs:260–279) and reads (DXFReader.AttachBendData, DXFReader.cs:345–380). It is the reliable, tool-independent method.

Each bend line is a LINE (group 0 = LINE) whose two endpoints are the ends of the bend, with XDATA appended after the normal group codes:

XDATA application id (1001). Flux's reader collects every 1000 XDATA string on the entity regardless of the 1001 app id (DXFReader.cs:218–220) — so the app id is not validated on import. Flux's writer registers the app id ACADANNOTATIVE. TruTops/TRUMPF files use app id TC_BENDDATA with TC_-prefixed keys (e.g. TC_BEND_ANGLE:); Flux strips a leading TC_ and treats TC_BEND_ANGLE: and BEND_ANGLE: identically (DXFReader.cs:353). Any registered app id works, but use ACADANNOTATIVE (Flux-native) or TC_BENDDATA (TruTops) so other tools accept the file.

1.1 Recognised XDATA keys

Each key is a single 1000 string of the form KEY:value (no space after the colon required).

Key (1000 string) Meaning Units-scaled¹ Read Written
BEND_ANGLE: / TC_BEND_ANGLE: Bend angle in degrees. Sign = direction (§3). REQUIRED — its presence makes the line a bend line. no ✅ ✅
MATERIAL: Material/grade name (part-level; §5) no ✅ ✅
THICKNESS: Sheet thickness yes ✅ ✅
BEND_RADIUS: Inner bend radius yes ✅ ✅
BEND_FACTOR: Bend deduction (absolute value taken) yes ✅ ✅
K_FACTOR: K-factor (ANSI convention, used as-is) no ✅ ✅
BUMP_COUNT: Step/bump-bending segment count (integer) no ✅ ✅
BEND_DIE_ID: / DIE: Die tool name no ✅ ✗
BEND_PISTON_ID: / PUNCH: Punch tool name no ✅ ✗
V_WIDTH: Die V-opening width (write only) ✗ ✅

¹ Units-scaled keys are multiplied by 25.4 when the import unit is inch (see §6). Angles, K-factor and counts are never scaled. V_WIDTH is emitted by the writer but ignored by the reader.

1.2 Angle value details (DXFReader.cs:354–359)

  • Value is in degrees. 90 = a 90° bend.
  • Legacy arc-seconds: if |value| > 360, Flux treats it as arc-seconds and divides by 3600.
  • With the interior-angle import option on (§6), Flux converts to the included angle: angle = (180 − |value|) · sign. Leave it off to supply the bend (open) angle directly.

2. Alternative A — annotation text near the line (A…R…K…)

If a bend line carries no XDATA, Flux looks for a TEXT/MTEXT entity within 6 drawing units of an open single-segment polyline matching the regex (DXFReader.cs:912–937, case-insensitive):

A<angle> R<radius> K<kfactor>          e.g.  A90 R2 K0.5
  • A angle in degrees (sign = direction; interior-angle option applies; clamped to ±180).
  • R inner radius (units-scaled).
  • K K-factor; if > 0.501 it is halved (DIN→ANSI conversion).
  • The text and its line are consumed and replaced by a bend line.

3. Bend direction (sign convention)

Direction is encoded by the sign of the bend angle (DXFWriter.cs:266–268):

Angle sign Direction Flux writer layer Line type
positive (+90) up bend BEND dotted
negative (−90) down bend MBEND dash-dot-dot

The BEND / MBEND layer pair is a MetaCAM convention (DXFWriter.cs:70–76). Layers are cosmetic on import — the authoritative direction is the angle sign in BEND_ANGLE:, not the layer.

4. Layers

  • With XDATA/text methods, layer membership does not decide what is a bend — the BEND_ANGLE: key (or the A…R…K… text) does. Put geometry and bends on any layers you like.
  • Flux's writer separates up/down bends onto BEND/MBEND for interchange with MetaCAM.
  • The Cycad format (§7) is the exception — there bends are identified by layer.
  • Import option IgnoreLayers collapses everything onto layer 0 (DXFReader.cs:41, 287–294).

5. Material & thickness resolution (part level)

Material and thickness can be set per bend line (XDATA) and/or at part level via TEXT entities whose string starts with a tag (DXFReader.AddText, DXFReader.cs:301–316):

TEXT prefix Sets Notes
PN: Part name
RM: Material name takes precedence over XDATA MATERIAL:
RV: Revision
NM: Author
GANG: Gang count min 1
THK: Thickness if value < 0.5 it is treated as inches and ×25.4

Precedence

  • Material: RM: text wins; XDATA MATERIAL: fills in only if material is still blank or NONE (DXFReader.cs:361–363).
  • Thickness (part): first value seen wins — THK: text, XDATA THICKNESS:, or Cycad THICK= (each guarded by if not already set, DXFReader.cs:315, 365, 954). If none is given, part thickness defaults to 0 (DXFReader.cs:266).
  • Thickness (per bend line): always taken from that line's XDATA THICKNESS:; if absent, the bend line inherits the current part thickness at creation (new E2Bendline(pts, 0, mThickness)).

6. Import options & units

Controlled via import settings (mKeys, DXFReader.cs:33–52):

  • Units / mScaleFactor (DXFReader.cs:1105): default millimetre (factor 1.0). If the import unit is inch, all units-scaled values (thickness, radius, deduction, V-width) and all geometry are multiplied by 25.4. (Writer inverts this: inch → ×1/25.4, DXFWriter.cs:393.)
  • DXFInteriorAngle — interpret supplied angles as included/interior angles (§1.2, §2).
  • IgnoreLayers — ignore layer definitions, put all entities on layer 0.
  • Other flags (ExplodeBlock2D, DeleteOverlaps, stitching, RemoveNarrowSlits) affect geometry only, not bend/material/thickness parsing.

7. Alternative B — Cycad format

If the drawing contains TEXT entities CYCAD:OUTLINE and CYCAD:BENDS, Flux switches to Cycad mode (DXFReader.ProcessCycad, DXFReader.cs:940–990):

  • CYCAD:OUTLINE / CYCAD:BENDS name the outline and bend layers.
  • On the outline layer, drawing annotations THICK=<value> and NAME=<value> set thickness/name.
  • On the bend layer, each line is a bend; the nearest annotation text supplies the angle and keys, slash-separated: <angle>/R=<radius>/K=<kfactor> — e.g. 90/R=2/K=1.0. The angle is converted to the included angle; K is halved (DIN→ANSI).
